# 造梦机完成任务再次生成计划

日期：2026-11-09  
状态：**已实施（2026-11-09）**；自动化测试与源码版浏览器验收已完成，未提交/未推送。

## 一、目标与交互口径

用户希望完成态的单次生成任务也能再次生成，并可在提交前调整参数。任务卡操作保持精简：

- 完成态单次任务卡增加一个“再次生成”按钮，不另加“编辑”“复制”“重跑”等并列按钮。
- 点击后切换到造梦机生成页，按原任务快照预填工作流、参数覆盖、媒体选择/跳过状态、生成段数及“释放模型”开关。
- 表单仍使用现有控件和校验；用户可直接提交，也可修改后提交。提交创建一条全新的单次任务，跳转到结果页查看新任务。
- 原任务记录、完成状态、历史时间和产物均不变。再次生成不复用失败任务的“重试续跑”，不把已完成段当作续跑进度。
- 仅单次任务显示此操作。批量条目已有自己的重试/编辑语义，本次不改。

## 二、现状与主要缺口

- `public/js/24-comfyui.js::renderTaskCard()` 只给 queued/running 显示“取消”，给 failed/cancelled/interrupted 显示“重试续跑”；completed 只有删除。
- `ComfyUIJobManager.submit()` 把工作流 `prompt`、参数、名称、覆盖、媒体输入、媒体跳过、段数和 `unload_after` 冻结在任务 `input`。`list_tasks()` 的卡片投影没有返回这些生成配置。
- 单次表单从当前工作流详情生成请求；目前没有从某条已完成任务读取快照并回填表单的入口。再次生成不能只把任务 id 传回当前 `/api/comfyui/tasks`，因为用户可能已经切换工作流，原工作流也可能从工作流库删除。
- 已选媒体引用可能因清理或文件移动失效。回填和提交都要复核路径/受管引用，不得把失效状态显示成仍可用。

## 三、实施方案

### 3.1 卡片操作与视图状态

1. 在 `renderTaskCard()` 对 `status === "completed"` 且无 `batch_id` 的任务增加一个“再次生成”按钮。失败态的“重试续跑”维持原行为；活动任务、批量任务不出现新按钮。
2. 点击后读取该任务的完整生成快照，构造独立的再次生成草稿并切到生成页。不要把草稿写回原任务，也不要立即入队。
3. 表单顶部明确显示来源任务名称/时间，并提供“取消”或返回结果列表的现有导航；离开或切换工作流时清理这份草稿，不能把旧任务覆盖串到别的表单。
4. 成功提交后清除再次生成草稿，创建一条全新的任务卡；原任务仍保留并可继续查看/删除。提交失败时保留用户修改，不复位开关或媒体选择。

### 3.2 任务快照读取与新任务提交

1. 为单条任务提供只读的再次生成快照接口，或扩展现有任务详情接口：仅向现有任务所有者/工作台权限开放；返回必要配置，不返回 checkpoint、prompt_ids、事件日志或旧产物写入目标。
2. 前端将快照装入现有工作流详情/参数表单模型。快照至少包含 `workflow_id/name`、`prompt`、`params`、`overrides`、`media_inputs`、`media_skip`、`shots`、`unload_after`。原 workflow_id 仅作来源标识，不能据此直接读取或覆盖当前工作流库记录。
3. 提交采用明确的“从任务快照新建”服务端路径：由服务端读取原任务冻结的 prompt/params/name 作为基底，对用户本次提交的覆盖、媒体输入/跳过、段数和卸载开关重新执行现有校验，然后调用任务创建逻辑生成新 id。可实现为 `POST /api/comfyui/tasks/{task_id}/rerun`，body 仅接受可编辑的当前表单值。
4. 新任务 `input` 保存本次确认后的完整快照，`source_task_id` 记为来源任务；`batch_id` 为空。新任务 checkpoint、progress、result、request key 均从新任务初始化，不复制旧任务执行状态、产物清单或取消状态。
5. 即使原工作流已从工作流库删除，也允许使用旧任务的冻结快照再次生成；整个流程不得重新保存/恢复工作流库条目，也不得改动原工作流。

### 3.3 参数和媒体回填

- 标量覆盖以原任务实际提交值回填；原任务没有覆盖的槽位沿用冻结 prompt 的原值。用户清空 seed 时维持现有随机语义。
- 媒体输入按现有受管引用显示文件名和可用状态。引用有效则保留；引用失效时标明需要重新选择或明确跳过，不能静默改成沿用工作流原值。
- 手动跳过集合原样回填；用户取消跳过时恢复原值/原选文件状态。optional 空槽仍沿用现有判断逻辑。
- 重新选择的媒体必须经过现有上传、类型检查和路径校验。服务端不得信任前端提交的旧绝对路径或任务 id。
- 如果任务快照缺少旧版本字段或结构不完整，返回可读错误并保留原任务，不猜默认值或部分提交。

## 四、范围外

- 不改失败任务的“重试续跑”算法及已完成段收养逻辑。
- 不提供修改原任务输入、覆盖原产物或删除旧产物的行为。
- 不给批量条目增加“再次生成”按钮；不改变批次编辑/重试/删除语义。
- 不自动重跑、不自动提交、不调用付费节点；再次生成仍由用户在预填表单中确认提交。
- 不持久保存未提交的再次生成草稿，不增加新的工作流库条目。

## 五、关键文件与测试

- `public/js/24-comfyui.js`：完成态操作、任务快照加载、表单回填、来源提示、提交与草稿清理。
- `naiba/comfyui/jobs.py`、`naiba/comfyui/service.py`、`naiba/http.py`：快照读取、从快照校验并创建新任务的窄接口；校验任务存在、终态、非批量和允许访问。
- `naiba/comfyui/store.py`：仅在现有任务记录结构不足时补来源任务字段；保持创建、删除和任务投影一致，不复制旧结果/checkpoint。
- `tests/test_comfyui_module.py`：completed 单次任务可生成新任务；原任务不变；快照基底不依赖当前工作流库；失效/非法快照拒绝；批量/活动/失败任务不能走再次生成接口；覆盖值与媒体输入重新校验。
- `tests/test_comfyui_frontend_assets.py`：卡片按钮只在完成态单次任务显示；保留失败“重试续跑”；回填包含原值、覆盖、媒体跳过、段数和卸载开关；失败提交保留草稿。
- 对应造梦机浏览器冒烟：从完成卡点“再次生成”，确认表单预填且可编辑；修改一个标量参数后提交，确认新任务进入队列、旧任务和旧产物仍在；覆盖原工作流已删除、媒体引用失效、取消回表和窄屏布局。

## 六、验证与完成定义

1. 后端单测证明新建任务使用原任务的 prompt/params 快照和用户本次修改值；新任务 id 与来源关系正确；原任务 input、status、checkpoint、result、finished_at 均未变化。
2. 服务端拒绝活动/失败/取消/中断任务、批量任务、未知 id、非法覆盖、越权媒体引用和损坏快照；已删除工作流库条目的完成单次任务仍可从自身快照创建新任务。
3. 前端任务卡只增加一个完成态操作，不出现重复的编辑/复制按钮；失败重试续跑行为不变。回填控件值与任务快照一致，修改后请求只创建新任务。
4. 浏览器验收覆盖桌面和 375px 手机视口。使用隔离服务与假 ComfyUI；不发起真实生成或付费请求。
5. 按项目维护说明运行定向测试、前端语法检查和 Playwright 冒烟；若新增任务 API/字段，补齐对应契约或接口守门。未执行项如实记录。
