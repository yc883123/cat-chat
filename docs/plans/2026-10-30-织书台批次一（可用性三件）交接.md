## 3. 任务一：草稿暂存（设定 + 大纲）

### 3.1 现象与实测

- 设定里输入创意 → 切「大纲」→ 切回「设定」：输入**归零**。
- 切到「对话」再回「工作台 → 织书台」：同样归零。
- 切到别的功能页（如拆书匠）再回来：同样归零。
- 正文是唯一安全的：`renderDraft()` 有 `if (content && !writer.draftDirty)` 守卫（`27-writer.js:683`）。

### 3.2 根因（都在 `public/js/27-writer.js`）

| 位置 | 问题 |
|---|---|
| `renderEditor()`（715） | `if (writer.stage === "setup") fillSetupForm();` 无条件按**已保存值**重填，切阶段即覆盖 DOM |
| `fillSetupForm()`（436） | 只从 `writer.setup` 取值，不读表单现值 |
| `openBook()`（1239） | `if (!keepEdits) writer.setupDirty = false;` 把 dirty 清掉，随后 `renderAll()` 重填 |
| `onStudioPageChange()`（2761） | 每次进页都 `void openBook(writer.bookId)`（不带 keepEdits）→ 进页即丢 |
| `renderOutline()`（588） | 从 `writer.outline.chapters` 重建整列，**没有 dirty 守卫**；手动改的梗概切阶段即丢 |

### 3.3 建议改法（最小可用，不引新状态机）

1. **设定**：`renderEditor()` 的条件改成 `if (writer.stage === "setup" && !writer.setupDirty) fillSetupForm();`
   —— 面板是 `hidden` 切换、DOM 不销毁，dirty 时保留用户已输入的值即可。
2. **进页**：`onStudioPageChange` 调 `openBook(writer.bookId, { keepEdits: writer.setupDirty, keepStage: true })`；
   `openBook` 里当 `bookId !== writer.bookId` 时**强制** `setupDirty = false`（换书必须重填，防串稿）。
3. **大纲**：加 `writer.outlineDirty`（`#writerOutlineList` 的 `input` 事件委托置真），
   `renderOutline()` 开头 `if (writer.outlineDirty) return;`；保存成功后置假再重渲染。
4. **保存后**：现有 `saveSetup` / `saveOutlineManual` 成功路径已置 `setupDirty=false`，补 `outlineDirty=false` 即可。
5. **可选增强（建议做）**：每本书一份 localStorage 草稿（key `naibaWriterDraft:<bookId>`，存 `collectSetup()` 的返回值 + 大纲 rows），
   刷新/进程重启后可恢复，并在页头状态显示「有未保存修改」。换书/保存成功时清理。

### 3.4 验收（逐条写进 smoke）

- 设定输入 → 切大纲 → 切回：值在。
- 切「对话」→ 回「工作台 → 织书台」：值在。
- 切到别的功能页再回：值在。
- 点「保存修改为新版本」后再切页：显示的是**新保存**的值（不是旧值、不是空）。
- 打开另一本书：表单换新书内容，不串上一本的草稿。
- 大纲改一行梗概 → 切正文 → 切回：改动还在。

## 4. 任务二：导出（桌面端点了没反应）

### 4.1 根因链（已核实，别再重复查）

| 层 | 事实 |
|---|---|
| 前端 | `exportBook()`（`27-writer.js:1975-2006`）用 `URL.createObjectURL` + `<a download>`，只走浏览器下载 |
| 桌面壳 | pywebview `ALLOW_DOWNLOADS` 默认 **False**（`.venv/Lib/site-packages/webview/__init__.py:120`） |
| 桌面壳 | WebView2 的 `DownloadStarting` 里 `if not ALLOW_DOWNLOADS: args.Cancel = True`（`webview/platforms/edgechromium.py:316-319`）→ **静默取消** |
| 启动 | `launcher.py:1312` 只传 icon / private_mode / storage_path，从未打开该开关 |

**结论**：浏览器/手机能下，exe 里点了等于没点；页面只把右栏「保存状态」改成「已导出」，没有下载框。
**同源受害点（共 4 处）**：`27-writer.js:1991`（织书台）、`25-novel.js:2925`（拆书匠）、`22-studio.js:1047`（工具集导出 JSON）、`24-comfyui.js:2103`（非图片产物链接）。

### 4.2 第二个坑：0 字节

`naiba/writer/store.py:1130 export_book()` 只拼「有正文」的章，没正文的章连标题都不写。
用户那本 30 章、0 章成稿 → 导出结果 **0 字节**。即使下载修好，也会被当成「又坏了」。

### 4.3 推荐方案（B：后端落盘 + 原生另存为）

1. **store** 新增 `export_to_file(book_id, *, fmt, with_extras)`：
   - 复用 `export_book()` 的拼装；
   - 落到 `writer_root/_exports/<clean_title>-<YYYYmmdd-HHMMSS>.<fmt>`（时间戳防覆盖）；
   - 返回 `{path, filename, bytes, missing_chapters, has_content}`。
2. **service** 新增 `api_export_file(book_id, ...)`；**http** 在现有 `/export` 路由（`naiba/http.py:598`）旁加
   `POST /api/writer/books/{id}/export-file`（有副作用，用 POST；必须放在通用 `/books/` 兜底路由之前）。
3. **前端** `exportBook()`：
   - 先请求导出文件；`bytes === 0` → `setSaveState("没有正文可导出", …)` + toast 建议改选「含设定与大纲」，**不弹保存框**；
   - 桌面：`window.pywebview.api.naibaSaveFileAs(path, filename)`（`launcher.py:545` 已有；取消返回 `cancelled`，不要报错）；
   - 浏览器/手机：`triggerDownload(localFileUrl(path))`（两者都在 `01-core.js`，需要新增 import）。
4. **文案**：`naiba/writer/service.py:414` 的 `export_note` 与 `index.html:1085 #writerExportNote` 目前写死「由浏览器发起下载」，
   改成按端区分（桌面「弹出另存为」/ 手机「保存到下载目录」）。

> 备选 A（不推荐当主方案）：`webview.settings['ALLOW_DOWNLOADS'] = True` 放在 `webview.start` 前，一行治全部 4 处；
> 但它是全局行为、pywebview 的保存框默认名取自 `args.ResultFilePath`（blob 可能拿到临时名）。可作为「拆书匠/工具集」的兜底单独评估。

### 4.4 验收

- exe：三个导出项都弹系统另存为；保存后文件大小 = `payload.bytes`。
- 手机/浏览器：正常下载，文件名正确。
- 没有任何正文的书：不弹框，明确提示；选「Markdown（含设定与大纲）」能导出非空文件。
- 若顺手改了拆书匠/工具集：各自再验一遍（它们目前同样失效）。

## 5. 任务三：「允许删除已被移出大纲的章节」复选框

### 5.1 现状

- 控件在 `public/index.html:1267`（`#writerOutlineAllowDrop`），后端 `allow_drop` 链路**已经通了**
  （`pipeline.py:175` 进 snapshot、`store._sync_chapters_locked(allow_drop=...)`）。
- 但**前端从未读过这个复选框**：`submitPipeline("outline")`（`27-writer.js:2645` 附近）不传 `allowDrop`，
  勾了等于没勾。手动保存大纲 / 同步章节走的是 `window.confirm` 兜底（`saveOutlineRows` / `syncChaptersRequest`）。

### 5.2 改法

```js
$("#writerOutlineGenerate")?.addEventListener("click", () => void submitPipeline("outline", {
  allowDrop: Boolean($("#writerOutlineAllowDrop")?.checked),
}));
```

- 建议手动保存 / 同步也先读同一个框：勾了就直接删（不再弹 confirm），没勾才走现有 confirm。
- 若未勾且会删正文，pipeline 失败文案要可操作（现在只显示后端原文），至少补一句「要删请勾选『允许删除…』后重试」。

### 5.3 验收

- 勾选后点「生成全书大纲」→ `POST /pipelines` body 里 `allow_drop=true`；不勾则不带。
- 有正文的章被移出大纲：勾 = 删除并继续；不勾 = 报错且正文还在。
- smoke 里记录 `recorded.pipelines`，断言 `allow_drop` 字段。
