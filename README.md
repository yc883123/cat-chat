# Naiba Chat 2.5.0 Beta

Naiba Chat 是运行在 Windows 本机的通用 AI 自动化工作台。它把在线或本地模型、内置工具、后台任务、Skill、MCP、视觉工具和文件产物统一到一个对话界面中。

2.5.0 Beta 给「聊天背景」补上了**内置背景图**与**白板式取景编辑器**：内置 6 张跟皮肤色系的渐变图（紫雾晨曦 / 海雾 / 玫瑰石英 / 林间薄雾 / 石墨夜色 / 素纸），设置里点一下即用，不必自己找图（图片由后端幂等生成到 `data/backgrounds/`，随数据目录迁移、不占仓库体积、也不受缓存清理影响）。编辑器里给出「整张图 + 自由取景框」：拖框选区域、拖八个手柄自由改形状（角改两向、边改单向——竖向、横向都能切），滚轮 / 滑杆等比缩放（下限 = 整张图、上限 400%），另有「填满 / 完整显示 / 复位」一键适配；框比例与对话区不一致时，框里那块会被**完整等比**铺进对话区、多余部分用同图模糊底补上（不拉伸、也不二次裁切）；右侧「效果预览」与真实对话区共用同一套渲染规则，所见即所得。**竖图不再尴尬**——以前要么被裁成一条、要么缩成中间一条纸带，现在能看见整张图、自己决定裁哪一段，「完整显示」时没铺满的两侧改用同一张图的模糊放大版补满。另新增**「旋转 90°」**（服务端把图真的顺时针转成新文件，原图不动；编辑器里旋转后按「取消」会把派生文件回收）。取景（裁剪区域）随外观一起保存，多端一致。以下是 2.4.1 Beta 的内容：2.4.1 Beta 修的是「界面在撒谎」这一类问题：**任务面板只列真正的后台作业**——此前面板把 `background_tasks` 里两类记录平铺，`chat` / `plan_execute` ## 2.5.0 Beta 主要能力

- **内置背景图（新增）**：内置 6 张程序化生成的背景（紫雾晨曦 / 海雾 / 玫瑰石英 / 林间薄雾 / 石墨夜色 / 素纸），设置 → 外观 → 聊天背景里点一下即用；后端幂等生成到 `data/backgrounds/`（随数据目录迁移、不占仓库体积、不参与缓存清理，也不会把用户换掉的那张覆盖回来）。
- **白板式取景编辑器（新增，本次重点）**：设置 → 外观 → 聊天背景 → 「调整背景图」打开独立弹层——概览里给出**整张图 + 自由取景框**（框外压暗）：拖框选区域、拖**八个手柄**自由改形状与大小（角改两向、边改单向——竖向、横向都能切，不再有"某个方向切不动"），滚轮 / 滑杆等比缩放（下限 = 整张图、上限 400%），方向键 1px 微调（Shift 10px）；「填满 / 完整显示 / 复位」一键适配。取景框永远是图片内的一个自由矩形，**框里那块会被完整等比铺进对话区**（框比例与对话区不一致时两侧留白，用同一张图的模糊放大版补满；不拉伸、也不二次裁切）。右侧「效果预览」与真实对话区共用同一套取景渲染规则（同一组 CSS 变量、同一段百分比尺寸算法），所见即所得；取景（裁剪区域）随设置保存、多端一致；未选图片时入口置灰。
- **竖图不再尴尬（修复本次报障）**：`cover` 的固有语义是「铺满 + 裁掉溢出」，竖图此前要么被裁成一条、要么缩成中间一条纸带。现在概览里能看见**整张图**并按需裁剪；「完整显示」时没铺满的两侧改用**同一张图的模糊放大版**补满（电视 / 短视频的做法），不再是两条空白。
- **旋转 90°（新增）**：在服务端把图真的顺时针转 90° 另存为新文件（无损 PNG，原图不动），转完**取景跟着一起转**（构图不丢）；在编辑器里旋转后按「取消」会回滚设置并回收派生文件，等于没发生。
- **背景图链路加固**：背景图路径只允许来自 `data/uploads` 或 `data/backgrounds`（防目录穿越），并按图片**内容**过格式白名单（PNG / JPEG / WebP / GIF / BMP / AVIF；TIFF / HEIC 改名也拦得住）；背景图被计入「在用」，缓存自动清理不会把它删掉。

## 2.4.1 Beta 主要能力

- **任务面板只列真正的后台作业（本次重点）**：`background_tasks` 同时装着「每次回答的记录」与「后台作业」——`chat` / `plan_execute` 那些行是用户每发一句话就插入一次的运行记录，`comfyui` / `shell` / `http_poll` / `subagent` 才是真正的任务，`parent_job_id` 只是「我由哪次回答派生」的归属锚点。旧面板平铺两者且不显示归属，用户看到的是「我发过的每一句话都是一个任务」。现在面板只请求后台作业（`/api/tasks?jobs_only=1`，**过滤放在 SQL 层**——默认只返回 50 条且回答记录占绝大多数，先捞再筛会把较早的作业挤出窗口；上限一并提到 200），**按 `parent_job_id` 分组**、组标题取「类型 + 时间」（刻意不引用用户消息原文——那可能含不该复述的内容），组头给出「共 N · 失败 K」。
- **任务计数与新鲜度不再撒谎**：顶栏徽标此前只统计活动状态，全部终态时显示 `0`，于是「库里有 13 条记录」与「0 任务」同时成立；现在没有活动任务时回落为总数并弱化显示。面板顶部常驻统计条（共 N · 运行中 M · 失败 K · 已完成 J），**轮询失败时整条转告警色并显示最后成功更新时间与原因**，不再把上一次的旧状态当成最新状态呈现；任务完成提示改用任务类型（如「ComfyUI 生成已完成」）而不是内部 Agent 名。
- **「停止」真的会停（本次重点）**：① 取消现在同时写入「取消已下发」的**持久标记**——此前 `cancel` 只把状态写成 `stopping`，而状态冻结条件读的是另一个从没人写的标记，那段防护一直在空转，worker 下一次更新就把 `stopping` 打回 `running`（观感是「点了停止它还在跑」）。② `stopping` 属于活动状态，worker 若卡在网络等待或退避里不退出就永久占着活动名额，新增 **90 秒看门狗**强制置为已取消并摘掉线程句柄；该看门狗**只对登记过取消事件的后台作业生效**，被误传到 Job 接口的顶层对话 Run 不会被强行标成已取消。③ 级联取消不再篡改历史——后台任务的常态是「回答早已发出、只剩子任务在跑」，此时父行只是归属锚点，点「停止」不再把已完成的父行改写成「已取消」。
- **输入区「模型」改为可搜索下拉（本次重点）**：中转站未分组时 `/v1/models` 能返回 400+ 个模型，原生 `select` 只能靠滚动定位。现在原生 `select` 降级为**隐藏的值容器**（仍是唯一值来源，既有落库 / 重拉链路完全复用），可视化层是「触发按钮 + 可搜索浮层」：输入即过滤（对模型 id 与显示名做大小写不敏感子串匹配，头部显示「过滤后 / 总数」）、`↑`/`↓` 环绕移动 + `Enter` 确认、`Esc` 关闭并把焦点还给触发按钮、点击浮层外部收起、**重开时定位到当前已选模型并滚入视野**、底部「↻ 重新检测模型」仍是动作不落库。浮层 `position: fixed` 且打开时挂到 `document.body`（不被 `.composer-wrap` 裁剪，也躲开「编辑消息时整个输入区被搬进消息气泡」），**朝上展开时锚底边**——只算 `top` 的话，过滤把候选从 400+ 缩到几条后面板会原地收缩、在按钮上方空出一大截（即用户报的「弹层到处飘」）；高度顶住可用空间后由候选列自己滚动，窄屏不产生横向滚动。
- **暗色可读性**：消息里的行内代码在暗色下沿用浅色配方（浅底 + 浅字），实测对比度约 1.2、等同不可读；改为深底 + 显式文字色。任务状态补「停止中」中文标签。

## 2.4.0 Beta 主要能力

- **视频抽帧工具（本次重点）**：Agent 工具集新增视频抽帧两件套（在「读取与检索」组里手动勾选；亦已并入「只读 / 标准 / 长会话 / ComfyUI 联动」四档预设与新建 Agent 的默认勾选，只读模式只收纯读取的 `probe_video`）。`probe_video` 读元信息（时长 / 帧率 / 分辨率 / 总帧数 / 视频编码 / 是否含音轨）；`extract_frames` 三种模式——`times` 按指定时间点、`interval` 按固定间隔、`keyframes` 按画面切换择优（`threshold` 灵敏度 0-1 可调），单次最多 8 帧（上限 12），可指定起止时间与单帧长边，并额外生成一张拼图**联系表**（先看概览、再抽单帧细看）；抽出的帧与联系表自动进入消息媒体区（带缩略图，会话内可直接点开放大），配合 `vision_analyze` 即可读懂画面内容。视频抽帧结果按「视频路径 + 文件大小 + 修改时间」缓存并限量（同一参数目录 ≤200 张、同一视频跨参数目录合计 ≤600 张），重复调用不重算。
- **本地模型不再「永久卡住」（本次重点）**：「设置 → 运行设置」新增两项——**本地首字节超时（秒）**（默认 120，填 0 = 关闭；本地后端在 prefill 期间可能长时间不吐任何字节，与「永远做不完」在界面上无法区分，连续该时长没有输出即断开并报错，不再干等 30 分钟总超时）与 **Agent 最大步数**（默认 200，填 0 = 不限制；单轮回复允许的模型调用次数上限，达到即停止并说明原因）；**本地上下文窗口自动探测并写回配置**——探测值单独存 `context_window_probed`、绝不覆盖用户手填的 `context_window`，取值优先级「手填 > 探测值 > 兜底」，本地兜底 32k（在线仍 256k，不再对本地模型不设上限）；**统一「谁算在运行」的状态词表**（活动 / 终态两份常量，`stopping` 一并收口）——启动清理、活动列表与取消判定共用同一份定义，重启不再遗留「已取消但线程还没退出去」的僵尸任务（它会让整条会话永久显示「回复进行中」、救援入口全部失效）；**「停止」改为关闭连接来打断卡住的读**（卡在读上的请求点一下就能真停）；**前端点「停止」不再以服务端确认为前提**——轮询超时也照常清空运行态、复位输入框与救援入口，后端其实仍在运行时再次发送会明确提示而不是永久冻结。
- **出站网络重试与设置页下拉修复**：连接器「选择当前实例」与「丢弃旧实例、重建后重试」原本是两张各自独立的 `if/elif` 判定表，「代理已开启但未填地址 + 关系统回退 → 降级直连」这一档在重建侧没有对应分支——落到该档时不丢弃任何连接器、把刚失败的实例原样返回，所谓「连接异常时按当前策略重建后重试一次」实际空转；现在两张表对齐、统一从一个出口重建，并杜绝「缓存一空就静默退回空 ProxyHandler 直连」（以为在走代理比直接报错更危险）。设置页「目标版本」下拉改挂到设置对话框内的 `popover="manual"` 宿主（进入浏览器 top layer，宿主自身 `display: contents`、不产生可拦截点击的画布），同时解决祖先 `overflow` 裁剪与模态 `<dialog>` 层级覆盖——下拉不再被面板切掉一半，也不再被整体盖住。
- **更新检查与出站网络修复（2.3.9 重点）**：① 版本列表**归一化**——「目标版本」只列可自动更新的版本（过滤掉 2.0.0 及更早的大版本迁移版本），按版本号从新到旧排序、并按版本号去重，同一版本重复发布不再出现多条重复项；② 修复「同一版本重新发布后装不上、仍显示已是最新」——是否「当前版本」的判定改为「版本相同**且提交相同**」，同一版本号重发（资产/提交变了）不再被当成已安装，可正常选择并安装；③ **2.0.0 大版本迁移明确不支持自动更新**——清单指向它时更新面板直接提示「2.0.0 属于大版本更新，请前往 GitHub Release 手动下载」并给出链接，安装入口对不可自动更新的版本也会明确拒绝并说明原因；④ 「目标版本」下拉由原生 `select` 改为**自绘下拉框**（原生弹层在桌面内嵌窗口里不可控）——`↑`/`↓` 切换、`Enter`/空格 开合、`Esc` 与点击外部关闭，选中项自动滚入视野，选项带「（当前）」与发布日期；⑤ 手动代理只接受 HTTP/HTTPS（填错时明确提示并回退直连），任何代理设置变更都会让**手动 / 系统 / 直连三种连接器全部失效重建**（含系统代理捕获的旧环境状态），不再出现「改了代理却仍走旧通道」；⑥ 幂等请求（`GET`/`HEAD`/`OPTIONS`）遇连接异常时**按当前策略重建连接后重试一次**——更新检查与下载、联网搜索、模型列表在代理/VPN 抖动时更稳；已拿到 HTTP 状态码的错误不重试，也不会因一次失败就悄悄切换代理模式。
- **修复待发附件被自动清理误删（2.3.8 重点）**：根因是自动清理把「`uploads` + `generated` 的总大小（含被引用、删不动的文件）」当基准，而引用组永不删除 ⇒「降到上限」永不可达 ⇒ 循环退化成「删光所有未引用文件」，把刚上传、还在输入框待发（尚未落库、引用保护对它无效）的附件当场删掉——表现为**附件区缩略图破图、点击图片无法放大、模型 `vision_analyze` 报「未找到图片文件」**（本机实测总缓存约 560MB、阈值 256MB，每次上传都会触发一次全量清扫）。修复三件事：① 自动清理新增 **15 分钟保护窗口**（窗口内落盘或改动过的缓存组一律不删，同时覆盖「工具刚产出、`metadata` 还没写回」的临时态）+ 上传入口**显式保护本次刚落盘的主图与缩略图**，清理结果如实报告跳过数（`skipped_recent` / `skipped_protected`）；② 待发附件缩略图加载失败改为**两级兜底**（缩略图不在但主图还在 → 换主图，与消息气泡同策略；主图也没了 → 降级为文件占位图标并摘掉失效的大图链接），点开大图失败时明确提示「图片文件已不存在」而不是静默关闭；③ **发送前附件校验**：清空草稿前先核对附件是否还在（只判定宿主缓存树 `uploads` / `generated` 内的文件，URL 与工作区等外部路径不参与判定），命中丢失项就剔除该项、保留文字草稿并提示重新上传；服务端 `submit_chat` 用同一判定兜底（缺失直接报「附件文件已丢失（可能已被缓存清理）：xxx。请重新上传后再发送。」），不再把幽灵路径喂给模型。设置页「清理旧缓存文件」（手动清理）语义不变：仍是显式操作、不感知引用。
- **外观主题与皮肤 + 设置导航搜索（2.3.7 重点）**：设置页置顶新增「外观」区块——**主题模式**可选「跟随系统 / 日间 / 夜间」（跟随系统随 Windows 深浅色设置实时切换，无需重启），**界面皮肤**可选「紫藤（默认）/ 海洋 / 玫瑰 / 森林」（只换品牌色相——按钮、选中态、消息气泡、链接等，版式与信息层级不变）；偏好保存到服务端（`config.json` 的 `appearance`），同一实例的电脑与手机端保持一致，浏览器本地另存一份用于首屏无闪烁；面板内可「保存」「恢复默认」，未保存时提示「有未保存的外观更改」，非法或历史配置值自动归一化（`DARK` → `dark`、未知皮肤 → 紫藤）。设置左侧导航同时改为按「常规 / 模型与 Agent / 工具与联网 / 数据与隐私 / 关于」分组，并新增关键词搜索（输入「深色」「代理」「备份」等词只留相关分类，无匹配时提示「没有匹配的设置」）。
- **「编辑」= 完整输入区就地编辑（2.3.6 重点）**：点击「编辑」后，完整的 `.composer-wrap`（输入框、`@`/`/` 引用、图片与文件上传、附件列表、思考设置和 meta 行）从底部移动到该用户气泡内，底部仅留隐藏占位；气泡展开为全宽编辑态，编辑头提供取消按钮。编辑时照常粘贴 / 拖拽上传、增删附件、用 `/` 与 `@` 引用，**Enter 重新发送、Shift+Enter 换行、Esc 取消**；原消息附件随列表带出，可逐项删除，也可继续添加；取消时恢复原草稿与附件，确认时按当前列表重发。**并修掉编辑态里 `/`、`@` 弹层与「正在编辑此消息 / 取消」互压的层级问题**——弹层稳定盖在编辑头部之上，弹层关掉后「取消」恢复可点。底部输入区不再与会话内编辑框同时显示。
- **AI 回复「重新生成」（2.3.5 重点）**：每条完整 AI 回复末尾、「复制」右侧新增「**重新生成**」（操作区顺序：复制 · 重新生成 · 新会话）——点一下就用这条回复对应的**那条提问**原样重新作答，不必再手动复制粘贴重问。**截断点是提问本身、而不是回复**：重发时先删掉那一问及其之后的全部消息，之前的问答**逐字节保持原样**，因此**前缀缓存继续命中**；也正因为截断点落在提问上，反复点「重新生成」不会像「从回复处截断」那样越点越多重复提问。只有**非最后一轮**才弹确认框（并写明「之后还有 N 条会一并删除」），**最后一轮一键直发**、不打断；截断不可逆这点已在确认框里讲明。会话运行中该按钮自动隐藏（与「分支」「新会话」同口径）。
- **用户消息「编辑」回归（2.3.5 重点）**：每条用户消息下方恢复「**编辑**」（操作区顺序：编辑 · 分支）——在该条消息的位置**就地展开编辑框**（不跳到底部输入框），改字后按同一套重发链路重开。原文回填取用户原样文本（含 `/ref` 技能引用与 `@` 工作区引用），附件也在编辑框里带出。
- **编辑 / 重发的引用与附件保真**：`/ref` 技能引用与 `@` 工作区引用**逐字保留**——`@` 引用仍由后端在发送时按该会话工作区替换为绝对路径，重发结果与首次发送一致；编辑框带出该轮原有的图片 / 文件（与「分支」同口径，含缩略图字段），重发原样随行；**纯附件轮次**（只发文件、不写字）也能重发，不再被「内容不能为空」误拒。


- **工作区判定与执行同源**：权限判定与实际读写统一以**当前会话的工作区**（Run 快照 `workspace_dir`）为准——此前判定用当前工作区、实际读写却可能按启动时的工作区解析，切换过工作区的会话会出现「工作区内的文件被判越界、反复弹确认」；现在 `read_file` / `list_directory` / `search_files` / `write_file` / `edit_file` / `read_pdf` 的判定与执行**共用同一个根**。越界确认卡片直接写明「当前工作区：…」，一眼看出是拿哪个目录在比；另新增可选诊断开关（`NAIBA_DEBUG_PERMISSION=1`）输出执行器身份、请求路径（原始与解析后）、当前工作区、允许根与命中结果，用于定位「为什么被判越界」。**语义与安全边界不变**：自动＝工作区内免确认、工作区外（读也算）仍必须确认；工作区内指向外部的链接（junction / 符号链接）一律按真实目标判定、仍算越界（新增路径矩阵护栏测试）。
- **修复：点「允许执行」后运行上下文丢失**：待确认的工具调用现在连同完整运行上下文（工作区、取消信号、任务归属等）一起暂存，批准后按原上下文执行——此前批准后上下文为空，依赖它的能力（产物目录、后台任务归属、上下文重置等）会行为异常；同步确认与「已确认、后台执行」两条路径都已修正。
- **修复：子 Agent 改用会话工作区**：子 Agent 此前按启动期默认工作区判定与执行，会话工作区内的路径会被判越界，解压/安装 Skill 还会直接报「无法确定工作区目录」；现在子 Agent 继承该会话的工作区与审批档位（权限不超出父级），工作目录与产物位置与父会话一致。
- **手机端顶栏可折叠 + 审批文案明确**：手机（≤760px）顶栏新增收起开关——收起后隐藏整条操作区（轮次 / 文件 / 任务 / Skill / MCP / 刷新临时让位，点细条即回），模型与 Agent 两个下拉并回第一行，把被顶栏吃掉的高度还给会话区；选择记在本地、刷新后保留，桌面端不渲染该按钮。审批档位提示文案写明实际边界：自动＝「工作区内自动放行，越界仍确认」、完全＝「不再询问，可访问工作区外」。


- **会话模型下拉可随时重新检测**：会话底部「模型」下拉末尾固定一项「**↻ 重新检测模型**」——选中它即**强制重新拉取**当前 API 的模型目录（绕过「同一 API 本页只拉一次」的缓存限制），拉取完成后**自动还原你刷新前的选择**。供应商新上架的模型因此立刻可选，不必再进设置页 → 编辑供应商 → 点「检查模型」。该入口失败会明确出声：拿不到目录提示具体原因、尚未配置 API 提示去设置页、目录为空提示「该 API 当前没有可用模型」；它只是一次动作、不是模型，会从选择出口被抹掉，**不会被写进会话、也不会发送给服务端**。
- **修复：空模型目录不再被当作「已查过」**：此前判断能否复用目录缓存的条件是「本页有没有查过这个 API」，而不是「缓存里有没有模型」——某些 API 在还没有可用模型时（如本地模型尚未加载）返回空列表，这一页就再也不会重拉，下拉框永久停在「请先在设置中检查模型」，即使模型随后已经可用。现在改为「缓存里确实有模型才复用」，空结果会自动重新拉取。
- **行为变更：未选择模型时不再默认选中目录第一项**：会话没有明确选择过模型时，下拉框不再自动选中检测目录的第一项（该顺序由供应商接口的返回顺序决定、没有任何含义——此前 teynex 这类供应商的新会话会静默用上比你配置更弱的模型），改为显示禁用占位项「请选择模型…」；已保存的模型仍优先展示，不在检测目录里时依旧置顶「已保存：X（请重新检查模型）」。**影响范围**：所有尚未选择过模型的会话（含历史会话）都需先在下拉框里显式选一次才能发送。
- **Skill 删除重构**：删除 Skill 改为确认对话框——明确「移至回收目录（可恢复）」与「彻底删除（不可恢复）」两种方式，并列出该 Skill 被哪些 Agent 引用（删除会一并移除引用）；设置页「已安装 Skill」下方新增**回收目录**列表，显示已回收的 Skill（名称 + 原路径），可一键**恢复**（移回托管目录并重新启用）或**清空回收目录**（永久删除）。**修掉「点了删除却没删掉」**：同一 Skill 在多处目录（或打包内置 + 托管副本）各有一份时，只搬走其中一份会让它立刻从另一份复活——现在这类 Skill 统一按 ID 隐藏（可在「已隐藏 Skill」里恢复），一次点击即从列表消失且重启不回来，内置 Skill 只处理托管副本、程序包原件不动；**启动时的内置同步与旧数据目录合并改为跳过「已删除（隐藏）」的 Skill 目录**，删掉的内置 Skill 不再被重新写回。
- **会话模型选择收紧（行为变更）**：会话底部「模型」下拉**只列当前 API 上检测到的模型**——移除供应商默认模型兜底与手动输入；**未在设置中「检查模型」或选中项不在检测目录里时，发送会被拦下**并提示「请先在设置中检查模型，并在会话底部选择检测到的模型」，不再把未经验证的模型名发给服务端；历史会话保存的模型若不在检测目录里，置顶显示「已保存：X（请重新检查模型）」，点「检查模型」拿到目录后自动刷新会话下拉；切换 API 后清空该会话的模型选择，等待新 API 的检测目录填充。
- **供应商默认模型换代不再影响已有会话**：此前在输入区没主动选过模型的会话，会把供应商当时的默认模型名一并落库成会话级覆盖；供应商之后改了默认模型，这些会话仍会继续发送旧模型名。现在保存 API 配置时若默认模型被改写，只清空「覆盖值恰好等于旧默认模型名」的会话（它们本就在隐式跟随），显式固定成其它模型的会话保持不变；修正为静默处理（不推进会话更新时间、不重排侧栏），并把图像能力重置为待重探。
- **冻结版打包补齐 multipart 解析器**：PyInstaller 显式收集 `python_multipart`——此前它是 `naiba.http` 的懒加载导入、未被自动打进包，可能导致安装版上传附件失败。
- **单文件 Skill 导入宽松化**：单个 `.md` 与 zip 里顶层散放的 `SKILL.md` 不再强制 YAML frontmatter——自动取首个标题作为 `name`、首个非标题段落作为 `description` 补出最小 frontmatter，正文原样保留，裸 Markdown 也能直接安装并在列表里正确显示。
- **异步任务（Job）韧性修复**：ComfyUI 批量生成每轮同时核对 `/history` 与 `/queue`——**既不在历史也不在队列**的 prompt 判定为已被 ComfyUI 丢弃（服务重启或队列被清空），按预算（`max_resubmit`，默认 1，持久化在 checkpoint）**自动重新提交同一工作流**继续生成，预算用尽才记为「ComfyUI 已丢失该任务」并正常收尾，不再空转到 `wait_timeout`（默认 2 小时）——修复「任务面板长期挂着『运行中 · 完成 5/8』且永远不动」；已失败的镜头也计入完成集合，恢复后不会重复轮询、把同一处错误反复累计；队列查询失败时保守处理、不误判。**启动时的中断恢复改为幂等**（`resumed_into` / `resume_skipped` 持久标记），且 checkpoint 完全相同的中断记录视为同一批的重复副本、只恢复最新的一条，杜绝「重启一次任务翻一倍」（实测此前一批 8 段生成被放大成每对话 13 份）。**后台子 Job 不再占用对话的活跃 Run 互斥位**——只有顶层 Run 占用对话，长跑或卡住的异步任务不会再让该会话发不出新消息（此前会 409 拒绝且提示语误导）。任务面板恢复**「停止」按钮**（新增 `POST /api/jobs/{id}/cancel`，走 Job Registry 会真正中止 worker；`chat` / `plan_execute` 仍走原取消接口）。新增 8 例守门测试覆盖上述四条不变量。
- **手机端「功能对等」（不删能力、只换形态）**：手机（局域网访问）不再是「缩小版电脑」——电脑能做的手机都要能做，放不下的控件换等价形态。右侧文件面板从「整体隐藏」改为**全屏抽屉**（与桌面共用同一个面板与开合链路，只换呈现形态），消息末尾「本轮修改的文件」条目在手机上恢复可点（此前被 `pointer-events` 关掉），点开即打开文件抽屉；桌面右侧的「对话刻度轨」换成顶栏**「轮次」下拉**（列出「第 N 轮 · 用户消息摘要」，选中即跳到该轮，滚动时自动显示当前所在轮次，不足 2 轮隐藏；复用刻度轨同一份轮次模型与跳转函数，跳转到未渲染轮次会先扩懒加载窗口再定位）；触摸目标统一 ≥44px（顶栏按钮、侧栏抽屉开关、输入区图标与发送、文件面板关闭）；跨越 760px 边界不再关掉文件面板，「手机端」判定只有唯一来源（CSS 760px 与前端常量同界），窄屏也不隐藏任何文字标签。
- **Skill 安装目录归属修复（防「删一个 Skill，全部消失」的数据事故）**：单文件 `.md` 导入与顶层散放 `SKILL.md` 的 zip 以前会把定义直接写在托管目录根下，导致该 Skill 的 `root` 等于整个托管目录，删除时把**所有 Skill 一起搬走**。现在凡有文件直接落在导入根的上传都先建独立子目录（目录名取 frontmatter `name`），带顶层目录的文件夹上传保持原样、不多包一层；删除前校验归属（移动目标必须严格位于托管目录之下，`root` 等于托管目录时退化为只回收该定义文件），越界一律拒绝；启动时自动把历史裸 `SKILL.md` 迁入同名子目录，并同步 Agent 固定 Skill 引用与隐藏 ID。
- **在线模型稳健性（聚合回填 + 空流重试 + 5xx 取证）**：Codex Responses 流补齐**聚合事件回填**——仅收到 `response.output_item.done` / `response.completed`（没有逐字增量）时也能正确提取正文、思考与 reasoning item id，并把单独出现的 `function_call` 组装为工具调用（同一 message 只回填一次，`response.incomplete` 的被截断内容不作为成功正文）；该格式下「流式消费完但既无正文也无有效工具调用」按瞬时故障退避重试，其它在线格式行为不变；HTTP 5xx（含 500）与 429/502/503/504 同等退避重试（1.5s / 3s，最多 3 次尝试），思考回传类 400/422 与全部 5xx 都把失败请求体落盘取证（超长字段截断、不含 API Key）。
- **界面打磨（审批上拉框 / 模型只从目录选 / 供应商卡片更紧凑）**：审批模式由平铺四段改为**上拉框**——收起态只显示当前档与风险配色，点开才在按钮上方弹出列表（浮层置顶、不被输入区裁剪，贴顶自动下翻、夹在视口内），切换会话、打开其它浮层、Esc、点外部都会收起；输入区「模型」选择器移除手动输入，模型一律从**当前 API 的模型目录**里选，历史会话保存的模型若不在目录里会置顶「已保存：X」并默认选中（避免被静默换掉），并修掉「目录返回时会话已切换」导致旧会话模型被顶到新会话的问题；API 供应商卡片压成两行（名称 + 格式标签与当前角标），模型名不再上卡片，卡片更矮（116px → 88px）。

- **会话级模型选择（API 与模型分离）**：顶栏「模型」下拉改为 **API 下拉**——只负责选连接配置，选项直接显示 API 名称（不再拼「名称 · 模型」），切换后提示「API 已切换」；输入区新增 **「模型」选择器**：打开会话时自动拉取当前 API 的模型目录（`/api/providers/models`），**只列出检测到的模型**（不再回退 API 配置里的默认模型，也没有手动输入入口），下拉末尾固定一项「↻ 重新检测模型」可随时强制刷新目录，未明确选择过模型时显示占位项「请选择模型…」；下拉选择即保存到该会话；模型选择**按会话记忆**（`conversations.model_name`，分支对话继承同一 API 与模型名，互不干扰），顶栏切换 API 时该会话的模型名一并清空重选；**切换 API 或模型名后自动重新探测图像能力**（`chat_supports_images` 重置为待探测，发送时按新模型真实能力判断——换到文本模型不再误发图片、换到多模态模型不再被当作纯文本）。数据库 v17 幂等迁移，升级自动完成。

- **长会话模式（翻历史 + 重置上下文）**：Agent 工具集新增「长会话」一组——`find_conversations`（列出最近会话的 id/标题/时间/条数与末条预览，可按标题匹配）、`recall_history`（按关键词检索：不给会话 id 就全库搜、每个会话最多 3 条片段；给了 id 就只搜那个会话、按时间正序、片段更长）、`read_conversation`（按序号区间读历史会话原文，用于复核片段），加上 `reset_context`。配套新增 **「长会话模式」预设** = 标准模式 + 这四件套。检索结果会明示"检索了全部 N 个会话 / M 条消息"、截断显式、会话 id 不存在直接报错；**当前会话的命中会标注「在上下文中」或「已划出上下文」**——被「新会话」分割线划出去的老消息不会被当成你还记得的内容。
- **长会话懒加载**：打开会话只渲染最近 10 轮，向上滚动时自动往前预渲染（每次 10 轮，视口不跳动）；渲染窗口**以「轮」为边界**，所以「新会话」分割线永远和它下面那条回复一起出现、不会被拆到两段里。右侧刻度轨仍然覆盖全部轮次，点没渲染出来的轮次会先渲染再跳过去。
- **交接文档快捷消息**：快捷消息面板新增内置预设「写交接报告并 reset_context」（在「快捷消息」列表里，带「默认」标签）——点一下即插入到输入框，要求模型把交接报告写进工作区（目标/进度/关键文件路径/已定约束/后台任务/下一步）并用 `read_file` 复核后调用 `reset_context`；**这条预设和用户自建条目同权**：可编辑、可删除，改动与删除都记在你的配置里，软件更新不会覆盖也不会复活。
- **同一窗口内「新会话」分割线**：每条完整 AI 回复末尾、「复制」右侧新增「新会话」按钮——在**任意位置**划一条分割线，**此线以上的消息不再进入模型上下文，线以下的消息仍保留在上下文中**（所以可以只裁掉前面跑题的部分、保留最近的进展），聊天记录一条不删、分割线可逐条撤销；允许多条分割线并存，靠时间与位置区分，最新那条决定当前上下文起点。**模型也能自己重置**：Agent 工具集里勾上 `reset_context` 后，模型可先把交接文档写进工作区、再调用它（**文档不存在或为空会被拒绝**，每轮最多成功一次），本轮立即收尾并在该条回复下画出「模型重置」分割线；随后**种子消息自动填入输入框**（默认含交接文档路径 + 「请先读取再继续」 + 仍在运行的后台任务清单，模板可在「设置 → 运行设置 → 新会话种子消息」里改，占位符 `{handoff_path}` / `{task_count}` / `{task_list}`），由你确认后点发送开始新一段。
- **上下文用量提醒**：输入框旁的上下文圆环随**每次模型请求**刷新（不再等整轮结束），**输入框下方「思考 自动」右侧还常驻一行实时百分比**（如「上下文 8.2%」，达 70% 转黄、90% 转红，悬停看完整 `已用 / 上限`），达到「设置 → 运行设置 → 上下文提醒阈值」（默认 80%，0 = 关闭提醒）时弹窗提醒——**正在运行的会话**涨过阈值即弹，**已结束的会话**改为点发送时才弹（可「继续发送」，被拦下时草稿不清空）；距上次提醒再涨 5 个百分点才再次提醒，换会话后重新计算；弹窗建议让模型撰写交接文档并开始新会话。
- **在线模型 5xx 自动重试**：供应商返回 5xx（如 HTTP 500）时不再直接终止整轮，改为按瞬时故障退避重试（1.5s / 3s，最多 3 次尝试）并在状态栏提示重试进度；失败请求体落盘到进程工作目录的 `naiba-model-error-payload.json`（超长字段截断、不含 API Key），便于复现定位。
- **设置页卡片化**：API 供应商与 Agent 管理改为卡片网格（一行最多三张、末尾固定「添加 API」/「新增 Agent」卡片、卡片右上角 × 删除），点卡片才弹出该条目的设置弹层并加载已有配置；字段与文案保持原样，只换展示方式。**默认 Agent 不再在卡片上标「默认」角标或加高亮**——默认项由顶栏 Agent 选择器体现，卡片上任何强调色都会被误读成「当前选中」；**每张 Agent 卡片在「固定 Skill」下方显示它当前用的工具集名称**（命中内置预设就显示预设名，如「工具集：标准模式」；空配置显示「未限制（全部工具）」，其余显示「自定义 · N 个工具」）。
- **Agent 自动 ID 与自定义头像**：新建 Agent 不再手填 ID（保存时后台分配持久化唯一 ID，已有 ID 显示在弹层副标题）；Agent 编辑弹层新增「自定义头像」，上传图片自动中心裁切为 256px WebP，使用该 Agent 的会话会把助手气泡的「AI」圆标换成这张头像，Agent 卡片上也显示缩略图。
- **内置 Agent 预设下线**：四个内置预设（dsh-standard / dsh-code / dsh-minimal / dsh-cordis）不再自动出现；此前编辑过、已存进配置的副本会摘掉「内置」标记、变成普通可删除的 Agent（内容保留），引用它们的会话自动回退默认 Agent。
- **工具与 Skill 选择器改版**：固定 Skill 改为卡片网格并与工具集等高；工具集分组标题/说明/计数一行呈现，「视觉」分组补说明并前移到「命令执行」之后；展开后的工具卡片更紧凑，只有展开的那一组标题条变浅灰以区分层次；修复列表在弹层里被压成一条线、点不动的问题。**工具集分区改为「卡片态 ↔ 编辑态」两态同框切换**：弹层高度恒定不跳，默认只显示 5 张只读预设卡（只读 / 标准 / 长会话 / ComfyUI 联动 / 全能）与「我的工具集」卡片、末尾一张虚线「添加自定义工具集」卡；点任意一张卡都会先按下、卡片整块向上滑出、工具列表从下方滑入，命名栏自动填上被点卡片的名字，勾选就是该卡的工具（可继续增删；「添加自定义工具集」固定以标准模式为起点）；选完可存成「我的工具集」复用，内置预设只读不可改、自定义工具集可删除。**「我的工具集」存后端 config.json（`tool_sets`），不再存 localStorage**——冻结版 pywebview 默认 `private_mode=True`，WebView2 的 localStorage 每次退出都会被清空，此前保存的工具集重启后会消失；旧版本留在 localStorage 里的数据启动时自动搬到后端一次。
- **设置页右键菜单修复**：设置页文本框右键菜单恢复可用（撤销/重做/剪切/复制/粘贴/删除/全选）——此前被模态弹层整体盖住；同时不再误弹会话页的选区菜单；数字类输入框右键「复制」改为复制整值。
- **桌面壳持久化**：内嵌窗口的 WebView2 改用持久 profile（此前 pywebview 默认私有模式，profile 放在临时目录、退出即删），侧栏宽度、文件面板宽度、顶栏 Skill 勾选、交互模式这些本机偏好不再每次启动重置。

- **暂停/取消竞态修复**：一次暂停立即中断当前事件流、看门狗与待执行重连，并停止轮询恢复；「正在停止」期间禁止发送和恢复旧 Run，服务端确认终态后才恢复；取消父 Run 会级联取消子 Job 与 follow-up Run；完成/暂停并发窗口加锁，取消后不再创建自动 follow-up。

- **启动错误清晰**：数据目录/锁文件不可写等权限/环境问题不再误报为「已在运行」，会给出具体目录与原因；启动失败以简洁中文提示退出，不再输出堆栈。

- **左侧边栏改进**：会话列表虚拟化/懒加载、默认折叠、可拖拽调宽，交互更轻量清晰。

- **图片与视频预览**：聊天内可直接预览常见图片和视频格式，也支持音频播放与文件下载；生成产物会自动缓存并生成缩略图（含内容级去重，避免同图反复显示）。

## 开始使用

### 使用 Windows 版本

1. 下载 `naiba-chat-2.5.0-beta-windows-x64.zip`。
2. 解压到一个可写目录。
3. 运行 `naiba-chat.exe`。
4. 在设置中添加在线 API 或本地模型服务。

首次运行会创建本地数据目录。升级时请直接替换程序文件，不要删除原有 `data` 目录和配置文件。

### 从源码运行

需要 Windows、Python 3.11 或更高版本。

```powershell
git clone https://github.com/yc883123/naiba-chat.git
Set-Location naiba-chat
python -m pip install pywebview pystray pillow "mcp==2.1.1" pymupdf "av==18.1.0" python-multipart
python server.py
```

服务默认地址为 `http://127.0.0.1:8765`。

## 模型配置

在“设置 → 模型”中添加供应商，填写：

- API 地址
- API Key（本地服务通常可以留空）
- 模型名称
- 请求格式
- 是否支持图片输入
- 上下文长度和生成参数

本地模型建议先使用界面中的连接测试确认模型目录、文本推理和图片能力。模型是否能稳定执行工具，仍取决于模型自身的工具调用能力和上下文能力。

## ComfyUI 与 MCP

Naiba Chat 默认连接：

```text
ComfyUI HTTP API:  http://127.0.0.1:8188
```

使用前请确保 ComfyUI 已启动，并且目标节点、模型和素材在 ComfyUI 中可用。

当前内置流程接收 ComfyUI **API 工作流**。前端保存的 UI JSON（通常包含 `nodes` 和 `links`）不能直接提交，需要先在 ComfyUI 中导出 API 格式。

任务提交后由宿主完成以下工作：

1. 校验并规范化工作流参数。
2. 向 `/prompt` 提交任务。
3. 轮询任务历史和执行状态。
4. 自动收集图片、视频或音频产物，缓存到受管理数据目录并生成缩略图。
5. 附加到最终消息（中止/取消的轮次也会展示已生成的产物）。
6. 在聊天界面提供预览或下载。

推荐的工作流修改方式：对已有工作流文件，用 `read_file`/`comfyui_prepare_workflow` 读取结构，用 `edit_file` 做局部精确替换（改提示词/seed/尺寸等），再用 `comfyui_batch` 的 `workflow_paths` 提交文件路径；不要整段内联大工作流 JSON。

这条链路不要求模型读取产物本身。需要评价画面、OCR、定位对象或比较图片时，用户应明确提出分析要求；用户明确要求「保存/复制到指定目录」时模型会实际执行。

### MCP 说明

- 应用启动时自动连接所有已启用的 MCP 服务，并对启动时未连上的服务做周期重试。
- MCP 工具以 `mcp__<server>__<tool>` 形式注册进当前会话的可用工具集；会话工具集在首条消息时固化。
- `call_mcp(server, tool, arguments)` 只能调用**当前会话可用集内**的 MCP 工具；若目标工具不在可用集内，会提示用户重开会话、在 Agent 工具勾选里加上该 MCP 服务后再用。
- `register_mcp` 只是把服务登记进配置，其工具会在**重开会话后**进入新会话的可用集，本会话内不会因注册而新增可用工具。

## 工具、Skill 与 MCP 的关系

- **内置工具**：由当前任务意图直接触发，例如文件操作、命令执行、后台任务、ComfyUI 和视觉处理。
- **Skill**：提供特定领域的说明、模板、脚本和检查清单，不决定工具是否可用。
- **MCP**：接入外部工具服务；只有任务明确需要对应 MCP 服务时才会连接或调用。

因此，生成图片不需要先启动短剧 Skill，普通编程、资料整理、自动化处理和媒体任务也使用同一套运行机制。

## 数据与安全

- 对话、设置、附件和任务状态保存在本地数据目录。
- 缓存文件（用户上传与宿主产物的图片/PDF/视频/音频等）统一存于受管数据目录（用户上传 `data/uploads`、生成产物 `data/generated`），设置页可查看合计大小、按时间清理旧缓存（清理为手动操作，会按时间从旧到新删除最旧文件、不区分是否被引用）并配置自动清理阈值（默认 256MB，自动清理只删未被消息引用的最旧文件）。
- API Key 不应提交到 Git；示例配置不包含真实凭据。
- 局域网访问需要访问口令，默认仅本机访问时不要求口令。
- 文件预览只允许应用工作区和受管理数据目录（`data/uploads`、`data/generated`）中的文件。
- 高风险写入、删除、外部发布和凭据操作仍受权限策略保护。

## 自动更新校验

发布资产包含：

- `naiba-chat.exe`
- `naiba-chat-update.json`
- `naiba-chat-2.5.0-beta-windows-x64.zip`

更新器会验证清单中的仓库、提交、文件名和 SHA-256。下载文件还必须是有效的 Windows 可执行文件；任何一项不一致都会终止安装。

## Beta 说明

这是 2.5.0 Beta，适合实际使用和反馈，但仍有以下边界：

- 不内置 ComfyUI、模型权重或第三方生成服务，需用户自行安装和配置。
- 不同模型的工具调用质量差异较大，小型模型可能无法稳定完成长链任务。
- ComfyUI 自定义节点和工作流输入差异很大，复杂模板仍可能需要一次参数适配。
- 自动化任务应在交付前检查最终文件；涉及发布、删除或覆盖的重要操作应保留备份。
- MCP 工具仅在重开会话后才会进入会话可用集；若模型发现 MCP 服务存在但其工具不在当前会话可用范围，会提示用户重开会话。
- 视频抽帧依赖 PyAV（打包版已内置随附的 FFmpeg 运行库）；从源码运行时需要 `pip install av`，缺失时工具会明确提示安装而不是直接崩溃。
