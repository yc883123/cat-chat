用户反馈：电脑端批量生成里的「展开固定参数」点开后排版特别乱。先在桌面端复现并观察实际布局，再调整固定参数区。当前怀疑点仅供排查：`public/styles.css` 中 `.cbm-fixed-detail.open` 用 `display:flex` + `flex-wrap`，参数块没有明确列宽，`.cbm-fixed-detail .cbm-map-hint` 又占满一行；需要结合现场截图确定是标签/输入控件宽度、换行次序还是参数数量造成的。

重点代码：
- `public/js/24-comfyui.js:3688` `batchFixedMarkup()` 生成固定参数区。
- `public/js/24-comfyui.js:3737` 固定参数栏和展开区域标记。
- `public/js/24-comfyui.js:3996` 展开/收起事件。
- `public/styles.css:6698` 到 `public/styles.css:6705` 固定参数区样式。

先用桌面宽度打开批量生成页，选一份含多个普通参数、枚举、布尔、长文本或 JSON 参数的工作流，点击「展开固定参数」，记录展开前后布局。验证宽屏和较窄桌面宽度；手机也要看，不能让固定参数行撑出横向滚动。不要先改参数控件语义。

## 本轮结论

- 单次参数表单使用 `renderSlot()`，批量固定参数使用 `batchFixedMarkup()`，批量逐条参数使用 `batchExtraCellMarkup()`，当前各自构造控件。
- 参数扫描器在 `naiba/comfyui/params.py` 中识别 bool、number、seed、text、image/audio/video。在线 schema 增强还会识别 combo 候选和 multiline 文本。主提示词、模型角色和分辨率是显示角色，不是新的底层字段类型。
- JSON 数组/对象字符串目前仍是普通 text 字段；本轮独立 HTML 只是 JSON 可视化编辑器方案预览，没有接入生产代码。
- 单次和批量媒体控件建议复用现有单次媒体分组/槽位块样式。用户明确表示现有单次媒体槽样式好用，不要另造一套批量媒体外观。
- 参数行标签保留来源节点号和 `_meta.title` 节点标题，并显示参数名及下游端口映射。当前映射显示目标字段名，不显示下游节点标题。连接输出不是第 0 项时会标输出序号；同名目标端口才补目标节点号。
- JSON 参数摘要按用户要求只显示启用数，例如「2 项启用」，不要显示文件名、提示词或更长摘要。

## 建议的处理顺序

1. 先复现桌面展开错乱并截取展开态。
2. 对照 `batchFixedMarkup()` 的 DOM 结构与 `.cbm-fixed-detail` 当前 flex 排版，明确每个子项的列宽、标签和控件排列。
3. 优先用稳定的响应式 grid 约束固定参数项：桌面多列、窄屏一列或合适的两列；长提示说明单独占整行；避免改变单次参数表单和逐条参数语义。
4. 验证固定参数编辑是否仍写入状态并进入提交数据。此前代码审查发现 `submitBatch()` 读 `scheme.fixed`，但事件委托路径未见 `[data-batch-fixed]` 更新；若当前代码仍如此，需另立为功能 bug 验证，避免和布局修复混在一起。
5. 使用 `.venv` Python 跑相关 ComfyUI 前端/批量测试，按仓库维护说明处理验证；再做真实浏览器桌面和手机视口验收。
