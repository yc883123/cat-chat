# 打标器可选触发词计划

## 目标

在工作台「打标器」任务配置中增加用户可选的触发词前缀。用户启用并填写后，触发词作为每张图最终标注结果的前缀，并进入 LoRA 训练包中的同名 `.txt`；关闭时现有标注与导出行为不变。

触发词由用户明确指定。系统不从图片、模型输出或 caption 首词中推断，也不把它加入发给模型的打标提示词。

## 控件位置与行为

- 控件放在打标器任务配置区的「输出形式 / 输出语言」行下方、「模型配置 / 模型」行上方。
- 控件包含「添加触发词」开关与触发词输入框；默认关闭。关闭时不应用前缀；启用但未填写时显示校验提示，不允许开始任务。
- 触发词作为本次任务配置的一部分随任务保存，暂停、继续和恢复时保持一致。

## 结果处理

- 不改模型 prompt；模型结果照常经过现有置信度、预设过滤和格式处理后，再统一应用触发词。
- 标签类结果（`keywords`、`both`）：将触发词放在标签列表首位，作为一条完整标签；已有相同首标签时不重复添加。触发词不受置信度阈值和预设过滤影响。
- 文本类结果（`phrases`、`description`、`both`）：将触发词放在描述文本最前，使用与输出语言相符的分隔符；文本已以该触发词开头时不重复添加。
- `both` 模式的标签和描述都应用前缀。LoRA caption 导出当前优先使用标签、没有标签时才使用描述，因此训练包会按标签结果包含前缀。
- 触发词启用状态和值参与配置校验及结果复用指纹，确保不同触发词配置不会错误复用旧标注。重试和恢复使用原任务值。

## 修改范围

- `public/index.html`：增加控件并放入打标器配置区。
- `public/js/23-labeler.js`：收集和校验控件值，将其随任务配置提交。
- `naiba/labeler/jobs.py`：规范化、校验配置并纳入配置指纹。
- `naiba/labeler/runner.py`：在模型结果过滤和格式化后，对标签/描述应用前缀；新结果和可复用结果使用同一规则。
- `tests/test_labeler.py`、`verify/studio_ui_smoke.cjs`：覆盖后端结果、复用和导出相关回归，以及控件和用户操作。

## 验收

- 默认关闭时，现有结果、重跑复用和所有导出格式不变。
- 启用后，标签、短语、自然语言、标签加自然语言四种输出都按各自结构正确加前缀，且不重复。
- 相同图像在不同触发词配置下不会错误复用标注；同一任务重试、恢复时不丢失配置。
- `captions` 与 `lora` 导出的逐图 `.txt` 均包含所选前缀；LoRA 图片与文本配对、原图字节和 manifest 语义保持不变。
- 完成相关单测后，最后运行 Playwright 打标器前端冒烟，检查桌面宽屏和窄屏控件布局、开关、输入校验、任务提交及结果导出。

### 实施结果

- 改动文件：`public/index.html`（配置区「添加触发词」开关＋输入框，默认关闭）、`public/js/23-labeler.js`（开关联动输入框禁用态、`collectConfig` 携带 `trigger_word`、启用未填写拦截开始）、`naiba/labeler/jobs.py`（白名单＋`_normalize_trigger_word`：空白折叠、200 字上限、启用必填；`trigger_word` 进指纹但**关闭时按缺省处理**，与旧任务指纹一致，默认关闭不破坏复用）、`naiba/labeler/runner.py`（过滤与格式化之后统一加前缀：标签列表首位＋置信度补 -1 保持按位对齐、描述最前＋按语言分隔符；首标签/描述开头已是触发词时不重复加）、`tests/test_labeler.py`（配置/指纹/执行/复用隔离/captions 导出/继续兼容共 9 例）、`verify/_labeler_mode_smoke.cjs`（本地未跟踪脚本，控件与提交断言）。
- `both` 模式标签与描述都加前缀；`keywords` 只加标签；`phrases` / `description` 只加描述。captions / lora 训练包的逐图 `.txt` 经 tags/description 序列化自动携带前缀，配对与 manifest 语义未动。
- 继续未完成/恢复沿用原任务快照；历史 `mixed` 配置经 `allow_legacy_language` 放行（与语言联动计划共用该开关）。
- 与计划的偏差：冒烟落在 `verify/_labeler_mode_smoke.cjs`（打标器 UI 冒烟正主，本地脚本），计划文中写的 `studio_ui_smoke.cjs` 不覆盖打标器页面。
