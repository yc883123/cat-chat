## 二、用户需求原文（以此为准）

- 素材定义：任何图片、视频、音频。
- 目标：利用造梦机的特点完成批量生成（不限视频产物，图/音/视频工作流都行，档位叫「批量生成」）。
- 需求 1：同一工作流批量生成，每条视频用不同素材、时长、分辨率、提示词/剧本。
- 需求 2：不同工作流、或同一工作流但模型配方有变化，完成批量生成；每条同样可不同素材/时长/分辨率/提示词/剧本。
- 现状痛点：现在造梦机一次提交的所有段共用同一份参数和素材；有时填的是正文剧本，不能直接用于生成。

## 三、设计（方案 A，已拍板）

### 结构模型

- **批量**：批次名 + 逐次卸载开关 + 方案列表。
- **方案**：工作流 + 映射 + 固定参数覆盖 + 条目列表。需求 2 = 批量里加方案（换工作流，或同工作流改固定参数即配方变化）。
- **条目**：名称 + 各素材口文件 + 剧本（可选）+ 提示词 + 时长 + 分辨率 + 条数（默认 1）。

### 映射区口径（方案 A 核心，已拍板）

- 三个写入位下拉：剧本/提示词写进哪个槽（候选=multiline/positive 语义槽）、时长写进哪个数字槽、分辨率写进哪个槽（combo 档位或数字，单槽；宽高分离的本版不做）。没映射的参数按工作流保存值执行，不出现在条目表。
- **装载槽勾选排序**：把工作流的媒体槽勾选出来作为素材口，↑↓ 排序定编号（图1/图2/音1…，编号按用户排序）。**每个口有节点下拉**，列出该工作流全部同类型媒体节点，可换（用户 2026-11-05 补充要求）。未勾选的口不出现在条目里。
- 映射按工作流指纹记 localStorage，下次打开还是这样。

### 素材与既有文件口径（已拍板，与单次生成四态同源，不发明新规则）

- 现状事实（`mediaSlotStatus`，public/js/24-comfyui.js:1318；runner 剔除逻辑 `_remove_unselected_optional_media`）：工作流节点里已垫的文件名是槽位默认值；选了文件→runner 上传受管文件并把返回名写进节点替换；可选口没选→整个口剔除；工作流值为空→「请选择文件」；垫了文件没选→「沿用原文件」。
- 批量口径：
  - **勾了装载槽但某条没给文件**：可选口＝这条剔除该口；必填口＝这条配置不完整，**前端标红拦这条**（补齐或删掉再提交），其他条目照跑。
  - **没勾的口**＝按工作流保存值跑（垫底图/固定风格图走这里，明明白白；想换这张固定图用方案固定参数）。
  - 可选口不勾＝生成时整个剔除，垫了文件也不带。
- 已作废的「强制清空图内默认文件名」（红线 9）**不采用**。

### 剧本转换（已拍板：内置一键转换）

- 条目填剧本后可单条或「全部转换」：前端逐条提交 `POST /api/studio/generate`（http.py:877，body 对齐 studio.prepare_generation 输入），轮询现有 `GET /api/studio/tasks/<id>`（http.py:768）取回文本填进提示词，可手改。
- 转换模板＝内置说明 + 可选提词库自定义模板下拉（`GET /api/studio/custom`，照 28-super-agent.js:1550 fillCustomTemplateOptions 移植）；模型下拉数据 `POST /api/providers/models`（照 28:1566 recipeReverseModelOptions 移植）。

### 其他要点

- 分镜队列导入：把 `comfyui.storyboardQueue`（24-comfyui.js:2502，拆书匠跨页交接）逐条变成条目。
- 提交：前端先逐条自检（缺文件条目标红），全过才 POST；后端探活（`client.reachable`，不可达整单拒绝）+ 全量干跑校验 + 事务式创建（任一失败删已建、整单报错）。
- 跑批视图：整体进度 + 每条目卡片（状态/耗时/失败原因/重试/取消/产物预览）。失败条目「重试」直接调现有 `POST /api/comfyui/tasks/<id>/retry`（续跑未完成段语义现成）。
- 批次提交后不可改（改=新开批次）。批次草稿在弹窗内存里。
- 任务卡显示「批次名 · 条目名」（见后端 label）。
