## 一、目标与验收

1. **剧本场次**：把选中章节（或大纲节点）改编为标准 screenplay 场次（INT./EXT. 场景 - 时间 / 动作 / 对白）。
2. **导出**：全书可导出为 TXT / Markdown（含书名、章节标题、可选要素与大纲附录）。

### 验收标准

| # | 标准 |
|---|---|
| 1 | 选中 1 章生成剧本，输出符合场次格式（场景行、动作、人物、对白可区分） |
| 2 | 场次可逐条编辑、删除、重排，改动落盘 |
| 3 | 大纲已存在时，剧本生成**自动带上大纲约束**，人物称谓与大纲一致 |
| 4 | 导出 TXT 与前端预览一致：无重复标题、无缺章、顺序正确 |
| 5 | 创作场任务仍只在创作场历史出现（延续阶段二分区） |
| 6 | 回归绿：全量单测、studio / topbar smoke、novel smoke |

## 四、设计

### 4.1 数据

作品文件增字段（阶段一 `book.json` 基础上）：

```json
{
  "script": [
    { "i": 1, "scene": "INT. 老宅书房 - 夜", "content": "动作与对白…", "from_chapter": 3 }
  ]
}
```

- `from_chapter` 记录来源章节，便于回溯与「按章重新生成」。
- 解析失败时整段存 `content`，`scene` 留空，**不臆造场次切分**。

### 4.2 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/novel/stage` | `stage="script"`，复用阶段二的提交契约（module/origin_label/novel 字段一致） |
| GET | `/api/novel/books/<id>/script` | 场次列表 |
| PATCH | `/api/novel/books/<id>/script/<i>` | 改单条（scene / content） |
| DELETE | `/api/novel/books/<id>/script/<i>` | 删单条 |
| POST | `/api/novel/books/<id>/script/reorder` | 重排（传有序 `i` 数组） |
| GET | `/api/novel/books/<id>/export?format=txt\|md` | 全书导出（**二选一**：前端 Blob 拼装则不建此接口，见下） |

导出实现二选一，开工时定：

- **前端 Blob**（阶段一已定的风格）：不新增后端接口，前端按章节顺序拼装；优点是零后端改动，缺点是大书全量进前端内存。
- **后端流式**：新增上面那条 export 路由，服务端拼装返回；适合几十 MB 的书。
- 建议：**默认前端 Blob，超过阈值（如 5 MB）走后端接口**。

### 4.3 前端

| 文件 | 改动 |
|---|---|
| `public/js/25-novel.js` | 加「剧本」阶段：素材选择（章节 / 大纲节点）、生成、场次列表（编辑/删除/上移下移）、导出入口 |
| `public/styles.css` | 按总计划 §5.6 复用三栏与主题变量，增加场次卡和等宽正文样式；横屏三栏同屏、竖屏三档可达 | 桌面/手机横屏/竖屏无溢出，场次编辑与重排操作均可达 |

## 五、风险与必须处理项

| 级别 | 项 | 要求 |
|---|---|---|
| P1 | 场次解析不能臆造 | 解析失败整段存原文，UI 明示「未能识别场次结构，已按整段保存」 |
| P1 | 人物称谓一致性 | 剧本 prompt 必带人物槽；不然同一角色会换个名字 |
| P2 | 大书导出内存 | 超阈值走后端接口（§四.2） |
| P2 | 重排后 `from_chapter` 丢失 | 重排只改顺序，保留来源 |
| P2 | 任务分区延续 | 剧本任务同样 `module="novel"`，只在创作场历史出现 |
