# 造梦台优化计划

## 目标

优化 ComfyUI 造梦台的工作流参数编辑、Checkpoint 模型选择、任务删除、结果展示、刷新稳定性和任务时间信息。本文件仅记录计划，不代表实现已开始。

## 实施范围

### 1. 工作流参数默认呈现与编辑

- 导入工作流后，默认只展示常用参数：提示词、种子、步数、采样器和调度器。
- 其余已识别的参数默认不占用主表单空间，但继续保留在工作流参数数据中，避免丢失原工作流设置。
- 在中间栏工作流标题旁增加编辑入口，供用户选择需要加入主表单的其他参数；选择结果按工作流保存并在重新打开后恢复。
- 参数识别优先使用后端已有的 `role`、`field_name`、`class_type`、`node_title` 等信息；提示词沿用现有角色识别。对采样器、调度器等没有专用元数据的字段，按明确字段名及所属节点信息识别，并为未知参数保留手动加入方式。
- 隐藏参数不提交覆盖值，保持工作流内原有默认值；只对用户实际编辑的可见参数提交覆盖。
- 增大提示词输入框的初始高度，并保留拖动调整能力。
- Checkpoint 模型字段提供可搜索的 ComfyUI 模型候选列表；选中后写入现有参数值，同时保留自由输入回退。候选列表暂不可用时，不阻断工作流编辑和提交。

### 2. 删除任务时终止运行

- 终态任务保持现有直接删除流程。
- 对排队或运行中的任务，删除操作先取消任务；确认任务进入终态后，再删除任务记录、事件和产物。
- 删除过程显示处理中状态并防止重复提交；取消或删除失败时明确显示错误，不将任务伪装成已删除。
- 复用现有取消和删除接口；若现有异步状态无法可靠完成“取消后删除”，再评估是否需要后端提供原子化操作。

### 3. 多张图片完整显示

- 画廊构建时将每个输出文件与其所属任务 ID 一并保留，使用正确的任务文件地址加载产物。
- 同一任务的多个图像输出逐项展示，不把输出折叠成单张；继续遵守产品现有排序和数量上限，除非验收确认上限导致用户产物被隐藏。
- 补充单任务多图以及多任务输出文件名相同的回归覆盖。

### 4. 消除工作台闪屏

- 检查当前活动任务轮询及页面定时刷新，合并或串行化同时发生的刷新，避免较旧响应覆盖较新状态。
- 不再在每次轮询时清空并重建整份任务列表和产物网格；仅更新实际发生变化的任务卡片和产物。
- 状态与输出均未改变时保留现有 DOM 和媒体元素，避免图片反复加载或闪烁。
- 活动任务结束后停止高频轮询；无活动任务时，后台定时同步不得反复重建界面。

### 5. 显示任务时间

- 任务卡片显示任务创建时间。
- 任务完成后显示完成时刻；失败、取消等终态可按现有状态文案显示对应结束时刻。
- 确保重试时清除上一次运行的完成时间，进程重启恢复为终态时补齐结束时间，避免时间缺失或沿用旧值。

## 主要涉及位置

- 前端：`public/js/24-comfyui.js`、`public/styles.css`，必要时调整 `public/index.html`。
- 参数识别与参数配置：`naiba/comfyui/params.py` 及相关工作流存储/服务模块。
- Checkpoint 候选列表查询：`naiba/comfyui/client.py`、`naiba/comfyui/service.py`、`naiba/http.py`，前端接入 `public/js/24-comfyui.js`。
- 任务取消、删除、时间状态：`naiba/comfyui/jobs.py`、`naiba/comfyui/runner.py`、`naiba/comfyui/store.py`。
- API 路由：`naiba/http.py`（仅在现有接口不能满足需求时调整）。
- 测试：`tests/test_comfyui_module.py`，以及必要的 `verify/` 前端检查脚本。

## 实施步骤

1. 实施前重新检查工作区状态和上述文件，核实当前代码与本计划依据的实现一致。
2. 实施默认参数识别及按工作流持久化的可见参数配置，调整参数编辑入口和提示词框尺寸。
3. 从 ComfyUI `/object_info` 查询 Checkpoint 加载节点声明的模型候选项，新增只读候选接口；前端增加可搜索选择并保留自由输入。候选查询失败时返回空候选和说明，不影响现有工作流操作。
4. 实现活动任务的取消后删除流程，并处理异步完成、重复点击和失败反馈。
5. 修正输出文件到任务 ID 的映射，改造轮询刷新为有变化才更新对应界面。
6. 补齐任务卡片创建时间、结束时间及重试/恢复时的时间状态维护。
7. 增加针对参数保留与覆盖、Checkpoint 候选提取/搜索/不可用回退、取消后删除、多图输出归属、时间字段和恢复行为的回归测试。
8. 运行 ComfyUI 模块专项测试、前端语法/渲染验证及 `git diff --check`，并复查最终差异。

## 验收标准

- 首次导入时主表单只显示提示词、种子、步数、采样器、调度器等常用参数；用户可通过标题旁的编辑入口加入不常用参数，且配置可恢复。
- 提示词区域明显增大；未显示的参数不会被意外覆盖。
- Checkpoint 模型可从 ComfyUI 候选项中搜索并选择，也允许手动输入；ComfyUI 不可达或候选接口失败时，工作流仍可编辑和提交。
- 删除排队或运行中的任务会终止其工作，并在结束后删除任务及其产物；终态任务可直接删除，失败时用户能看到原因。
- 同一任务产生多张图时全部展示；来自不同任务的产物均使用各自正确的文件地址。
- 任务活动期间以及停止生成后，工作台不再因整页/整块重建出现闪屏；无变化轮询不替换媒体元素。
- 任务卡片能显示创建时间及完成时刻；重试和重启恢复后的时间正确。
- 相关专项测试和前端验证通过；如有环境限制或已有基线问题，单独记录，不将未执行的验证描述为通过。

## 边界与注意事项

- 本次不改变 ComfyUI 工作流本身的节点连接或产物生成逻辑，除非排查确认缺陷位于后端结果采集；Checkpoint 候选只用于辅助选择，保留当前自由输入和现有覆盖提交方式。
- 隐藏参数的编辑配置必须以工作流为粒度，不能影响其他工作流。
- 删除活动任务时保留现有取消逻辑对已下载产物的处理语义；最终删除成功后再清理相应目录。
- 计划审批并开始实施前，不修改代码、不运行测试，也不改变服务或配置状态。
