## 一、目标与非目标

### 1.1 目标

1. 解决「看得见的丑」：对比度崩坏、小字堆砌、信息层级混乱、状态色各说各话、空态卡片占位。
2. 把技术诊断式界面改成普通用户能读懂的任务界面：审核看素材/提示词/数量，不看 JSON、绝对路径、执行指纹。
3. 把「等待确认」「下一步」「产物」「入口」从多处重复收敛成**一个当前主操作 + 按场景给内容的右栏**。
4. 保持与现有主题体系一致，深浅两套主题、桌面三栏与 375px 窄屏都 readable。

### 1.2 非目标（明确不做）

- **不做**审核报告 A01–A08 的 P1 功能/信任整改：失活 LoRA 拦预检、方案保存断链、审核与执行不同源、审批状态守卫、可编辑性边界等，另立功能计划。
- **不换色板**：沿用 `public/styles.css` `:root` 现有 `brand` / `neutral` / 语义层令牌名与紫色主色，不引入第二套设计系统。
- **不改信息架构**：保留三栏（左任务列表 / 中详情 / 右下一步与产物），只调比例、密度、层级；不做双栏改版、不做无限画布。
- **不改文案语义**：通俗化只换说法，不隐藏费用、权限、执行范围，不把「不会重新生成」改成含糊表述。
- **不新增授权、不新开模型调用**：预览中的确认按钮不触发真实提交。
- **不把预览当已验收界面**：预览工具条、占位缩略图、示例任务数据都不是产品实现。

## 三、改版方案（与预览一一对应）

### 3.1 布局与密度

- 三栏保留，比例放宽、中栏留白统一为 26/28px 节奏；右栏在窄屏（≤1100px）收窄而非硬压。
- 字号下限 11px、正文 13.5px、标题 22px；层级靠字重（400/600/700）与 `--muted`，不再靠 10px 灰字。
- 卡片圆角统一 `13px`、阴影只用 `--shadow-1/2`，去掉「每张 section 都带框带阴影」的堆砌感。

### 3.2 主题与对比度（先修 P-01/P-02）

- **具体修复**：`styles.css:6179` 的 `#f6f5fa` 改为 `var(--surface-inset)`；`:6189` 的 `var(--panel, #fff)` 改为 `var(--surface-inset)`（或 `--surface`），文字保持 `var(--text)`。
- **不建议**在 `:root` 全局补 `--panel` 别名：它是未定义变量，全局补值会顺带影响其它未预期的组件；局部替换副作用最小。
- 预览里所有输入框、textarea、代码/摘要块都走 `--surface` / `--surface-inset` + `--text`，深浅主题切换实测可读。
- 验收必须覆盖：配方 textarea、编辑态/禁用态/占位提示/聚焦态、子助手工具审批、拒绝结果、自动续办最终正文（A07 补测点）。

### 3.3 组件体系

- 预览里的 `.btn / .card / .pill / .chip / .metric / .insp-card / .batch` 是**演示简写类名**，落地时统一映射到现有 `.control-button`（`styles.css:682`）体系，或加 `sa-` / `super-agent-` 前缀并限定在 `body[data-app-view="super-agent"]` 作用域，**禁止裸短类名进全局**，避免污染聊天区与工作台。
- **注意 `[hidden]`**：`styles.css:699/708` 已记录作者样式会覆盖 `[hidden]`。预览里用 `[hidden]{display:none!important}`，落地必须保留同等强度的显式规则，否则隐藏面板会漏出来。

### 3.4 三个场景

| 场景 | 预览内容 | 关键变化 |
|---|---|---|
| 任务详情 | 头部标题 + 状态 pill + 三张概览卡 + 一张「现在需要你做的事」主操作卡 + 最近进展 + 阶段时间线 + 时间线；右栏「下一步 / 最近产物 / 关联入口」 | 主操作收敛到一处；已完成项不再重复渲染按钮组；产物带缩略图；空态收成一行而不是一张卡 |
| 可视化审核 | 6 组素材缩略图 + 可编辑提示词 + 每组数量/时长；右栏只读设置摘要 + 就绪检查 + 「确认后会发生什么」；主按钮「确认生成 6 条视频」 | 去掉 JSON、绝对路径、执行指纹、精确槽位；改为「每组图片 → 一条视频」的关系；就绪检查前置，空提示词不再走到最后一步才被拒 |
| 新建任务 | 一个主按钮；两种互斥输入方式「图片＋剧本生成提示词 / 直接使用提示词」；方案按最近使用优先；素材与正文；数量/时长；高级设置默认收起；「创建任务（暂不开始）」 | 只填本次要用的信息；模型/参数继承方案；切换不发模型请求、不启动生成、不恢复任务 |

### 3.5 文案（按审核报告 A15 建议表）

| 当前 | 建议 |

### 3.6 响应式

- 桌面三栏 → ≤1100px 右栏收窄 → ≤760px 单列（左栏抽屉化、中栏与右栏上下堆叠）。

## 五、实施步骤与逐步验收

按依赖顺序拆，每步跑完对应验收再进下一步；不并行改多处以降低定位成本。

1. **主题底座**：修 P-01/P-02（两处硬编码/未定义变量）→ 深浅主题逐框对比，含编辑、禁用、占位、聚焦四态。
2. **组件与布局**：限定作用域的组件类、三栏比例、字号下限、状态 pill 统一 → 桌面/窄屏截图比对，确认聊天与工作台零回归。
3. **任务详情**：头部、概览、单一主操作卡、时间线、右栏按场景内容 → 四种状态（进行中/待确认/已完成/已暂停）逐一走查。
4. **可视化审核**：缩略图 + 提示词 + 数量 + 就绪检查 + 只读设置摘要 → 确认无 JSON / 绝对路径 / 指纹；空提示词在前置检查被拦。
5. **新建任务**：两种互斥输入方式、方案优先、高级设置收起 → 从创建走到确认；切换保留草稿、旧确认作废。
6. **文案与状态口径**：按 A15 表替换，同步守门更新 → 下一步、状态、可用动作三者一致；成功后清除当前错误、保留历史证据。
7. **整体验收**：见 §六。

## 七、风险与边界情况（评审重点）

1. **别把「有样子」当「有能力」**：预览里的播放按钮是占位。真正可播放需要后端给产物补 `output.type`（`recipes.py:914` / `runner.py:841`），属功能整改，是否纳入本轮需拍板（§八 Q1）。
2. **双模式切换同理**：A18 的互斥模式、草稿各自保留、直接使用时反推请求数为 0、空剧本/空提示词就近校验，都是前后端契约与校验，不是 CSS 能解决的。纯视觉层只能提供控件与布局，逻辑需单独确认范围（§八 Q2）。
3. **全局样式污染**：预览用了短类名。真实代码 `.control-button` 是全局基础组件（`styles.css:682`），落地必须限定作用域或加前缀；同时保留 `[hidden]` 的 `!important` 规则（`styles.css:699/708` 的历史坑）。
4. **`color-mix()` 兼容性**：预览与现有 `styles.css` 都用了 `color-mix`，WebView2 现有版本已依赖它，风险低；但深色下的混合结果必须实测，不能只看浅色。
5. **文案改动可能撞守门**：改文案前先搜 golden / 守门测试；不要只改前端让测试红一片，也不要为了过测把语义改弱。
6. **空态收敛 ≠ 丢信息**：右栏空态从「一张卡」收成「一行」时，「暂无产物 / 暂无关联入口」这些信息不能消失。
7. **状态色统一不能误导**：统一 pill 后，「已暂停」「停止中」「失败」不能混成同一种灰；颜色只做辅助，状态文字必须自解释。
8. **预览数据是示例**：4 个示例任务、6 组批次、5 秒时长都不是真实业务数据，落地后必须用真实任务与隔离实例复核。
9. **旧 V1 预览保留**：`docs/design/2026-11-01-任务总管-V1-预览.html` 是历史设计稿，不覆盖、不删除，避免评审时新旧混淆。
