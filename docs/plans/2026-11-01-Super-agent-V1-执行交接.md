## 一、先给结论：有区别，但不是推翻 V1

原始总计划已经确定了 Super-agent 的总体方向：

- 与「对话」「工作台」同级的第三个应用级入口；
- 以 Thread、Task Node、Event、Artifact、Approval 为一等对象；
- 任务总管负责目标、阶段、推进、审批、产物和恢复；
- 首个深度闭环是织书台 / 拆书匠；
- 通过 Adapter 复用现有 Chat、Job、Writer、Novel 和工作台能力；
- 不替换旧的对话、工作台和领域接口。

本次讨论没有改变这些主方向，主要新增了 5 个必须在执行时采用的产品口径：

1. **任务总管是可选增强入口，不是全站强制入口。** 不会用任务总管的用户，继续按原来的对话和工作台习惯使用。
2. **不是把五个模块的全部任务列表搬进任务总管。** 任务总管只收纳用户明确创建、明确关联，或由任务总管创建的执行节点。
3. **五个模块的接入深度不同。** 织书台 / 拆书匠 V1 深度接入；造梦机先做直接 Worker 关联；提词库 / 打标器先做轻量关联和产物引用。
4. **任务总管默认不监听所有对话和工作台操作。** 只收结构化事件；确定性推进走 Fast Path，不因观察状态持续烧 Token。
5. **执行配置和成本边界要显式设计。** 确定的造梦机任务直接调用 ComfyUI Worker，不默认绕一层 Agent；任务创建时冻结执行配置，运行期间不静默换 API / 模型。

如原始总计划与本文出现细节冲突，**本文是对 V1 执行边界的补充和收敛，以本文为准；未被本文改动的原计划继续有效。**

## 二、产品最终口径

### 2.1 三个应用级入口并存

```text
对话       = 普通自由交流和直接使用 Agent
工作台     = 提词库、打标器、造梦机、拆书匠、织书台等专业工具
任务总管   = 可选的跨模块长期任务协调中心
```

任务总管不能变成：

- 当前 Agent 下拉中的一个角色；
- 工作台中的普通分页；
- 所有异步任务的替代页面；
- 使用 Cat Chat 的前置步骤；
- 所有操作日志的总列表。

### 2.2 不会用任务总管的用户不受影响

用户仍可直接：

```text
对话
  → 选择 Agent / 供应商 / 模型
  → 发送消息
  → 继续普通对话

工作台
  → 打开任意模块
  → 编辑、生成、查看历史和产物
  → 独立完成任务
```

旧流程的约束：

- 打开对话或工作台不会自动创建 Thread；
- 普通聊天不会自动转成长期任务；
- 独立造梦机生成不会自动进入任务总管；
- 不因为任务总管存在就额外调用 Router 或 Agent；
- 旧的 Writer、Novel、Studio、ComfyUI 流程继续可独立运行。

任务总管的入口应是新增能力，而不是接管原有能力。

## 三、任务总管到底收纳什么

### 3.1 进入任务总管的条件

只有满足以下至少一条，内容才进入任务总管：

1. 用户从任务总管点击「新建任务」；
2. 用户在对话中明确点击「创建任务」或「加入已有任务」；
3. 用户在工作台明确点击「纳入任务总管」或「关联已有任务」；
4. 任务总管创建了一个 Writer、Novel、Job、Chat 或 ComfyUI 执行节点；
5. 用户明确将一个已有领域任务链接到 Thread。

### 3.2 默认不收纳的内容

以下不应自动进入任务总管：

- 提词库中的每一条提示词；
- 打标器中的每一次普通标注；
- 造梦机中的每一次独立生成；
- 工作台模板浏览、参数编辑等操作；
- 没有任务关联的普通 Chat Run；
- 没有任务关联的后台 Job；
- 已完成模块历史记录；
- 用户没有明确关联的辅助对话。

### 3.3 统一的是目标级投影，不是复制模块数据库

任务总管显示：

- Thread 总目标；
- 当前阶段和依赖；
- 状态和阻塞原因；
- 待确认事项；
- 产物引用；
- 来源模块；
- 返回原模块的入口。

任务总管不复制：

- Writer 的完整正文和版本编辑器；
- Novel 的完整原文、章节和图谱；
- ComfyUI 的完整工作流编辑器和所有节点日志；
- 提词库的全部模板内容；
- 打标器的全部队列和标注细节；
- Worker 内部 Session、工具调用日志和推理过程。

数据关系保持为：

```text
Thread
  └─ Task Node
      ├─ writer_pipeline
      ├─ novel_stage
      ├─ job
      ├─ chat_run
      ├─ comfyui_task
      └─ Artifact 引用
```

模块保留专业详情，任务总管展示统一摘要，两边互相跳转。

## 四、五个工作台模块的 V1 接入边界

### 4.1 统一轻量入口：五个模块都要有，但不是五个模块都重构

五个模块最终都提供同一组轻量操作：

```text
创建任务
关联已有任务
查看任务
返回任务产物
```

建议做成共享的任务关联 UI / 组件，不让每个模块自己发明不同的任务体系。

关联后只展示轻量状态条，例如：

```text
已关联： 《某某小说》改编任务
当前阶段： 大纲复核
[查看任务总管]
```

不把任务总管完整页面嵌进每个模块。

### 4.2 织书台：V1 深度接入

织书台是首个真实闭环的一部分，需要接入：

- Writer Pipeline 阶段；
- 阶段开始 / 完成 / 失败事件；
- 产物引用和版本关系；
- 任务级审批；
- 暂停、继续、取消、重试、恢复；
- 从任务总管跳回编辑器；
- 不影响原有独立织书台流程。

### 4.3 拆书匠：V1 深度接入

拆书匠与织书台共同完成首个垂直闭环，需要接入：

```text
导入原文
→ 整理设定
→ 生成大纲
→ 大纲复核
→ 拆章批次
→ 章节生成
→ 一致性检查
```

需要接入阶段状态、产物、审批和恢复；详细原文与章节编辑仍留在拆书匠。

### 4.4 造梦机：V1 先做直接 Worker 关联

造梦机 V1 只做：

- 从任务总管创建 / 关联 ComfyUI 任务；
- 携带 `thread_id`、`node_id`、`attempt`、幂等键；
- 直接把结构化工作流参数提交给 ComfyUI Worker；
- 接收运行中、完成、失败、取消事件；
- 将图片 / 视频登记为 Artifact；
- 从任务总管跳回造梦机查看或继续编辑。

V1 默认不做：

- 任务总管先调用 Agent，再由 Agent 调造梦机；
- 每个镜头都单独启动一个 Agent；
- 自动视觉质量判断；
- 自动改写提示词后无限重试；
- 自动批准付费生成；
- 复杂任务图和自主循环。

确定工作流的推荐路径：

```text
任务总管
  → ComfyUI / 造梦机 Worker
  → 结构化完成事件
  → Artifact
  → 下一节点
```

如用户只说自然语言目标、需要拆镜头或选择工作流，可以先调用一次 Agent 产出结构化计划；后续批量执行直接走 ComfyUI Worker。

### 4.5 提词库：V1 轻量关联和产物引用

提词库保留自己的模板库、搜索、编辑和收藏。V1 增加：

- 将当前提示词创建为任务产物；
- 将提示词关联到已有 Thread；
- 从任务总管返回提示词详情；
- 必要时把提示词交给造梦机节点。

不把全部提示词条目自动变成任务。

### 4.6 打标器：V1 轻量关联和产物引用

打标器保留队列、配置和结果修订。V1 增加：

- 将标注任务关联到 Thread；
- 标注完成后产生 Artifact；
- 任务总管显示标注结果摘要和返回入口。

不把每次普通标注都自动纳入任务总管。

## 五、如何与任务总管交流

任务总管不是另一个普通聊天窗口，而是目标级控制面板。

### 5.1 新建任务

用户输入长期目标，例如：

> 把这本小说导入，整理人物和世界观，生成大纲，按每批 20 章拆章。发现人物冲突先问我，确认后再生成前三章。

任务总管将目标转成 Thread 和 Task Node：

```text
导入原文
→ 整理设定
→ 生成大纲
→ 大纲复核
→ 拆章批次
→ 生成前三章
→ 一致性检查
```

### 5.2 已有任务的输入框

输入框文案：

```text
补充要求、修改目标，或告诉我下一步怎么做
```

可处理：

- 补充规则；
- 修改目标；
- 暂停 / 继续；
- 取消；
- 重试；
- 指定下一步；
- 将某个对话或工作台操作关联到当前任务。

但按钮动作优先使用确定性接口，不让模型猜：

```text
暂停任务 / 继续任务 / 取消任务 / 重试
```

### 5.3 详细讨论回到关联对话

任务总管展示目标、阶段、状态、审批和产物摘要；人物冲突、创作方向和长篇讨论跳回关联 Conversation。

```text
任务总管：为了什么、做到哪一步、下一步是什么
关联对话：为什么这样做、具体怎么改、详细讨论
```

## 六、API、Agent、模型和 Token 消耗口径

### 6.1 四者要分开

```text
Router        = 任务层协调和路由
Agent         = 角色、提示词、Skill、工具权限
Provider      = API 供应商
Model         = 具体模型
Worker        = 实际执行 Chat / Writer / Novel / ComfyUI 的适配器
```

### 6.2 任务创建时确认执行配置

新建任务应提供执行配置区域，至少能显示或选择：

```text
协调 Agent
执行 Provider
执行 Model
工作区
权限模式
工具和 Skill 策略
视觉能力
费用 / 外部服务策略
```

API Key 仍放在现有设置中的供应商配置里，任务页面不填写或展示密钥。

Thread / Node 创建后冻结：

- Agent；
- Provider；
- Model；
- 工作区；
- permission mode；
- enabled tools；
- Skill policy；
- 视觉能力；
- 费用 / 外部服务策略。

任务运行期间不能静默换 API 或模型。需要换配置时，优先提供：

```text
更多操作 → 复制任务并更换执行配置
```

新任务从已有产物继续，原任务保持可追踪。

### 6.3 Router 不默认调用模型

#### Fast Path：代码直接推进，零 Router Token

以下情况不调用 Router 模型：

- 已有 `thread_id`；
- 已有 `node_id`；
- 已有 `executor_id`；
- 已有 `source_event_id`；
- 用户点击暂停、继续、取消、重试；
- Worker 回报已知节点完成或失败；
- 依赖关系可以由状态机确定。

例如：

```text
Writer 节点完成
→ 更新节点
→ 检查依赖
→ 下一个节点 ready
→ 启动对应 Worker
```

#### Slow Path：只有不明确时才调用轻量 Router

例如：

- 用户说“继续刚才那个”，但有多个任务；
- 用户同时提到两个任务；
- 用户改变总体目标；
- 无法判断消息是补充、暂停、取消还是新任务。

送给 Router 的上下文只包括：

```text
用户当前消息
任务标题
当前阶段
最近摘要
阻塞点
```

不加载全部历史、不加载完整正文、不加载长日志。

### 6.4 造梦机的成本口径

确定的造梦机任务不应走：

```text
任务总管 → Agent → Agent 再调用造梦机
```

而应走：

```text
任务总管 → ComfyUI Worker
```

这样可以避免额外的 Agent 理解、规划、工具调用和结果总结 Token。

成本要区分：

| 类型 | 说明 |
|---|---|
| Router / Agent Token | 只有需要语义规划、判断或调整时才消耗 |
| 本地 ComfyUI | 通常没有 LLM Token，主要消耗 GPU 时间 |
| 云端图像 / 视频服务 | 消耗对应生成额度、积分或 API 费用，不等同聊天 Token |
| Writer / Novel / Chat Worker | 按实际使用的 Provider / Model 消耗模型 Token |

任务总管读取数据库状态、接收 EventBus 事件、刷新进度，均不应因为轮询而调用 LLM。

## 七、统一任务关联 UI 约定

五个模块都可以出现轻量入口，但默认不打扰旧流程：

```text
[创建任务]
[关联任务]
[查看任务]
```

模块内任务项可显示：

```text
任务来源：任务总管
《某某小说》改编任务 · 当前：大纲复核
[查看任务总管] [打开模块详情]
```

任务总管节点可显示：

```text
来源：织书台 / 拆书匠 / 造梦机 / 提词库 / 打标器
[回到模块]
```

不能做成：

- 每个模块重复一套 Thread 数据库；
- 每个模块重复实现审批和恢复；
- 任务总管复制完整编辑器；
- 打开模块就强制选择 Thread。

## 八、以原计划为基础的实际开工顺序

### P0：数据契约和边界先行

1. 复核 HEAD、工作区和现有状态机；
2. 新增 `Thread / Task Node / Event / Artifact / Approval` 模型；
3. 明确 schema version、原子写、迁移和幂等；
4. 明确 Thread 所有权；
5. 明确执行配置快照字段：Agent、Provider、Model、权限、工具、费用策略；
6. 用假 Worker 验证创建、推进、审批、暂停、取消、重试和恢复；
7. 验证重复事件不会重复副作用；
8. 不接五个模块的 UI，不修改旧流程。

### P1：Adapter 和确定性 Router

1. `ChatRunAdapter`；
2. `JobAdapter`；
3. `WriterAdapter`；
4. `NovelAdapter`；
5. 预留 `ComfyUIAdapter` 的结构化直接执行接口；
6. Fast Path 事件路由；
7. Slow Path 轻量语义路由预留；
8. 事件去重、attempt、幂等键和晚到结果 fencing。

### P2：任务总管前端

1. 顶层新增第三个应用入口；
2. 使用单一 `appView = chat | studio | super-agent`；
3. 新增任务列表、任务详情、时间线、审批、产物和关联入口；
4. 对话保留轻量“创建 / 关联 / 查看任务总管”；
5. `#tasksDialog` 保留，并增加跳转任务总管；
6. 工作台先增加共享的创建 / 关联 / 查看入口；
7. 桌面三栏、手机单列；
8. 任务总管不是普通聊天区，不显示内部推理和长日志。

### P3：首个深度闭环

1. 接入织书台和拆书匠；
2. 完成：导入 → 设定 → 大纲 → 复核 → 拆章 → 章节；
3. 验证人工确认和关键版本写回保护；
4. 验证暂停、继续、取消、重试和重启恢复；
5. 验证产物从任务总管回链到模块；
6. 旧的独立织书台、拆书匠流程继续可用。

### P3 同期但低优先级：其他三个模块轻量接入

- 造梦机：关联、直接 ComfyUI Worker、状态事件、Artifact、返回入口；
- 提词库：提示词 Artifact 和关联入口；
- 打标器：标注 Artifact 和关联入口。

不要因为“所有模块都有入口”就把它们都扩展成完整可恢复任务执行器。

### P4：回归和灰度

必须包含：

- 假模型全链路；
- 隔离实例 UI 冒烟；
- 普通对话旧流程；
- 五个工作台模块独立流程；
- 显式创建 / 关联任务流程；
- 不关联时不进入任务总管；
- 不因轮询额外调用 Router；
- 重复事件、失败、取消、重启、重试；
- ComfyUI 直接 Worker 不重复调用 Agent；
- 任务配置冻结和复制任务换配置；
- feature flag 灰度和旧流程回退。

## 九、V1 明确不做 / 停止条件

### 9.1 明确不做

- 不强制所有用户学习任务总管；
- 不自动监听所有对话和工作台操作；
- 不把五个模块全部历史任务自动迁移；
- 不把所有模块列表原样复制到任务总管；
- 不把每个 ComfyUI 任务都包一层 Agent；
- 不因状态轮询而持续消耗 Router Token；
- 不让任务总管动态扩大 Worker 权限；
- 不默认自动批准删除、覆盖、付费生成、发布和外发；
- 不替换现有 Chat、Job、Studio、Novel、Writer、ComfyUI 接口；
- 不在 V1 做 QQ、GitHub、邮件、Webhook、云端常驻、多用户和跨设备；
- 不在 V1 做无限自主循环和复杂任务图。

### 9.2 必须暂停推进的条件

1. 任务取消后无法证明不会继续产生副作用；
2. 重试可能重复计费、重复生成、重复写回或覆盖版本；
3. 普通对话或工作台旧流程受到影响；
4. Thread 所有权、Provider / Model 快照和工具权限无法校验；
5. 任务总管需要读取所有对话才能工作；
6. Router 被设计成每个事件都调用模型；
7. 造梦机确定性任务必须绕 Agent 才能执行；
8. 真实小样本闭环未通过却准备宣称 V1 完成。

## 十一、验收时必须回答的 10 个问题

1. 不会用任务总管的用户，能否完全按旧习惯使用对话和工作台？
