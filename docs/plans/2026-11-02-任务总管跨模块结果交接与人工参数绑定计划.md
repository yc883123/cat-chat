# 任务总管跨模块结果交接与人工参数绑定计划

> 范围提示：本轮仅落地总管内成功依赖正文交接、结果详情、归属/版本/预算/来源隔离，见《2026-11-02-任务总管并行整改与自动续办子助手交接》第 0 节。本计划中的跨独立任务链协作、造梦机人工参数绑定和任意跨领域数据映射仍未完成，不属于 4.0.0-beta 本轮完成声明。

日期：2026-11-02。

状态：待实施。本计划不代表结果绑定、持久交接或跨独立任务链协作已经实现。

## 一 目标与关键决策

让对话产生的提示词或其他文本结果能够进入造梦机，由用户选择具体工作流和目标参数，预览后确认写入；生成必须另行确认。任务总管负责收集结果、组织交接、展示等待状态和跟踪执行，不替用户决定结果应该填到哪个参数。

核心原则是“自动准备，人工指定，确认写入，生成另确认”。参数可能叫 `text`、`caption`、`instruction` 或其他自定义名称，也可能与提示词角色无关。不得把 `positive`、`positive_prompt`、名称相似度或第一个文本槽当成强制写入目标；即使只有一个候选，也不能跳过人工确认。

第一交付完成“对话结果 → 交接草稿 → 人工选择参数 → 确认写入”。第二交付再接通“人工开始生成 → 造梦机执行 → 总管跟踪”。独立任务链之间的结果引用作为后续扩展，不通过放宽现有依赖校验提前开放。

### 首期范围

- 普通对话中明确选中的最终回复、摘录，或同一个总管任务内某个已成功聊天步骤的最终结果。
- 每条交接绑定一个来源结果和一个已导入造梦机的工作流；首期每条交接只写一个用户明确选定的自由文本参数。
- 持久保存来源、待选目标、候选文本、确认状态和写入回执；刷新、切页或重启后仍能查看和继续处理。
- 保留普通聊天、现有造梦机手填参数、拆书匠分镜交接的既有使用方式，不扩大聊天工具权限。

### 首期不做

- 不自动决定参数，不自动生成，不将“按顺序自动继续”解释为已批准写入或生成。
- 不做批量分镜展开、任意 DAG 编排、多条独立链自动联动、循环重试或模型自主修改映射。
- 不把文本转成媒体上传、任意本地路径、工作流连接、模型选择、凭据或脚本执行。
- 不自动触发第二次模型调用来猜测应该提取哪段文字；无法可靠解析时交给用户选择或编辑。

## 三 用户操作流程

### 从普通对话发起

1. 用户在一条已完成的回复上选择“交接到造梦机”，可选完整正文或明确摘录。创建动作只保存候选结果，不写任何参数。
2. 显示交接审核区，提供来源回复、候选文本、目标工作流选择器和目标参数列表。目标参数初始未选中。
3. 用户选择工作流和具体参数，系统展示工作流名、节点 ID、节点标题、字段名、当前值及拟写入值；允许编辑拟写入文本。
4. 用户点击“确认写入所选参数”。服务器复核来源、目标、草稿版本和权限，成功后保存回执并在造梦机交接草稿中回显。
5. 界面明确显示“已确认填入，尚未生成”。第一交付的交接工作区仅支持审核、编辑和确认写入，不提供可执行的生成入口；普通手填造梦机仍按原方式使用。第二交付接通最终草稿提交后，才允许在这里另行点击“开始生成”。

### 从任务总管发起

1. 在聊天步骤后添加“交接到造梦机”步骤，选择来源步骤。可以预先指定工作流，但预设参数只能是待核对候选。
2. 上游成功后，总管准备候选结果，交接步骤进入“等待你选择参数并确认”；用户不必一直打开造梦机。
3. “查看并确认”进入同一交接审核区，不另造一套审批界面或不同的选槽规则。
4. 确认写入完成后，交接步骤显示成功，完成说明为“已确认填入”，不能写成“已生成”。
5. 第一交付的任务到确认交接处结束，不开放新增造梦机生成步骤。第二交付若配置了后续生成步骤，该步骤仍停在单独的生成确认门。

### 两道确认门

| 操作 | 授权范围 | 不包含的动作 |
|---|---|---|
| 确认写入所选参数 | 将预览中的确定文本写入指定任务草稿的确定参数 | 不提交造梦机任务，不修改工作流库原文件，不调用模型或外部 ComfyUI |
| 确认开始生成 | 使用当前确认的最终参数快照创建一次造梦机任务 | 不批准其他交接，不批准下次生成，不放宽聊天工具权限 |

关闭审核区或选择“稍后处理”只保留待确认状态。放弃交接必须是明确操作；取消后不写参数、不自动跳过并推进需要该结果的步骤。当前通用审批的状态映射不能未经调整直接承担这些语义。

## 四 来源结果的读取与提取

新增统一结果读取能力，优先复用同目录《2026-11-02-任务总管子助手链路修复计划》中的结果读取设计；不能在两项工作中各造一套相互矛盾的正文查找逻辑。

来源必须固定到真实消息或真实执行：

- 普通对话入口由服务端核对会话和消息归属，记录被选择的 assistant 最终消息及内容快照。
- 总管入口固定 `source_thread_id + source_node_id + source_attempt + run_id + message_id`，且源节点成功、Run 完成、正文已落库。
- 不取“会话最后一条消息”，不把 `run://` 当正文，不读取思考过程、工具参数、系统提示或其他会话内容作为候选结果。
- 不使用未完成的流式片段；Run 已结束但最终消息尚未可读时，显示“正在等待结果保存”，有限次重查后转为可见异常，不重跑模型。

首期提取方式限定为完整正文、用户选定摘录、显式指定的严格 JSON 字段。摘录必须对应已读取的来源内容；用户后续改写保存为交接草稿修订，不能伪装为原始输出。JSON 解析失败、字段缺失、字段不是字符串或内容为空时停止自动提取，让用户选择或编辑；不静默回退为整段回复。

文本按配置的长度上限校验，超长必须展示提示并允许用户缩减，不能静默截断后写入。原结果、选取结果和编辑后的候选值要能区分；列表只显示摘要，详情按需读取全文，避免大正文重复进入事件和 checkpoint。

来源文本始终是数据。即使其中包含路径、URL、工具调用或“已获授权”说明，也不得改变目标参数选择、触发外部读取或扩大权限。

## 五 目标参数选择与写入规则

### 候选列表与明确身份

从工作流服务返回的完整参数清单构建候选列表，不以当前页面可见的输入框为范围。首期仅允许已扫描、可编辑的自由文本标量槽；模型枚举、数值、布尔、媒体、连接输入和未识别的复杂配置不可选，并解释原因。

P0 必须定义服务端独立的“允许文本交接”能力判定。现有 `text`、`multiline` 或 STRING 类型本身不足以证明该槽不是凭据、代码或表达式。优先使用明确登记并验证过的节点字段能力；仅在可信 schema 提供足够语义时复用其声明，不新增在线猜测发现。未知用途、敏感或可执行字段保守拒绝，后续经验证扩展支持清单；不能只排除媒体和数值后就放行剩余所有字符串。候选接口不返回敏感字段值，不能只在前端禁用选项。

每项显示“节点标题或类型、节点 ID、字段名、当前值预览”。同名字段必须显示节点信息以区分。`positive_prompt` 等角色只作为说明或推荐标签，不能自动选中；名称相同、角色相同也不能替代用户选择。

目标身份固定为 `workflow_id + node_id + field_name`，同时记录影响实际执行的工作流结构、槽位类型和约束指纹。节点标题、展示顺序与角色不是稳定身份。用户换工作流时清除原目标选择；结构改变后必须重新选择或重新核对，不自动迁移到“看起来相似”的参数。

### 原值与隐藏参数

“原值”必须来自当前交接工作区的有效参数值，不能只显示工作流文件默认值。进入交接工作区时，以用户当前表单值或明确选择的工作流默认值建立可见基线，保留普通手填草稿，不将其静默替换。

目标参数即使未加入主表单的显示集合，也应在审核区和交接草稿中可见编辑。确认写入不能暗改用户保存的 `visible_params` 或参数顺序。第一交付验收持久值和可见回显；第二交付接通生成时，最终提交必须包含该参数，不能因为 `collectOverrides` 只扫可见 DOM 而漏掉。

### 写入语义

首期仅支持“替换此参数”，不隐式追加或合并。审核区必须完整展示旧值和新值，并清楚说明将替换哪个参数。

确认时提交草稿 revision、基线 revision 或值指纹以及目标结构指纹；服务器执行版本比较。期间参数被用户修改、目标删除、类型变化、草稿被取消或来源 attempt 失效时，拒绝旧确认，刷新差异后重新确认，不能用最后写入者覆盖前者。

保存映射模板只记住候选工作流和槽位，不记住永久授权。下次仍需看到当前值、新值并确认；模板失配时停止，不自动找第一个 `positive` 或 `text` 字段顶替。

## 六 持久交接与草稿契约

以下字段与接口均为拟新增设计，实施时先登记契约，再修改生产方和消费方。

### 数据分层

| 实体 | 关键内容 | 责任 |
|---|---|---|
| 来源快照 | owner、会话、消息、实际 Run、源任务与节点及 attempt、内容哈希、提取方式、选取结果 | 来源不可变，避免重试或后续回复污染已确认内容 |
| 交接记录 | handoff_id、来源快照引用、目标候选、候选文本、revision、状态、确认人和时间 | 管理待选择、待确认、修订、取消与恢复 |
| 交接参数草稿 | draft_id、owner、handoff_id、工作流指纹、参数基线与覆盖值、revision | 服务器权威的任务专用参数工作区，不与普通手填草稿争用同一个状态 |
| 写入回执 | request_id、handoff_id、确认 revision、精确目标、写入值哈希、草稿新 revision | 重复确认可查，区分“创建交接”与“确实写入草稿” |
| 生成关联 | 生成请求键、已确认最终快照哈希、造梦机 task_id、状态 | 第二交付使用；跟踪已创建任务，不混用普通后台 Job ID |

采用现有应用 SQLite 的独立表或等效持久实体，通过显式迁移增加；不要把可变草稿和大段结果塞进 Run 快照、消息 metadata 或事件全文。来源正文只在权威快照中保存必要份数，摘要和引用用于列表及事件。

草稿主键包含交接或任务身份，不能只用“工作流 ID + 参数”作为全局键。多条链向同一工作流的同一参数交接时，各有自己的草稿和确认记录；用户明确切换当前交接工作区，不能由后台新结果抢走正在编辑的页面。

### 状态和完成判据

建议交接业务状态为 `awaiting_target`、`awaiting_confirmation`、`applied`、`cancelled`、`needs_review`；实际枚举在契约阶段统一。

- 候选准备好但未选参数：等待选择，不写值。
- 参数和候选值已选定：等待确认，不写值。
- 服务器事务完成草稿更新和回执登记：已确认填入，不等于前端一定已经显示，也不等于已生成。
- 页面关闭时可持久保存已确认草稿；再次打开从服务器加载。不得依赖一条前端事件完成恢复。
- 配置变化、来源失效或版本冲突：需要复核，旧确认不能继续使用。

总管节点通过交接适配器投影这些业务状态，不直接新增一套同名但语义不同的通用任务状态。节点只有在拿到有效写入回执后才成功；待选、待确认和可修复冲突均阻断依赖推进。仅交接任务的成功说明必须包含“尚未生成”。

### 幂等和竞态

创建交接使用稳定请求键；同一请求重放返回同一交接。用户主动再次交接同一回复则使用新请求键，不能被全局内容去重错误阻止。

确认写入使用 `handoff_id + revision + request_id`，绑定精确目标和候选值哈希。草稿修改、交接状态推进与回执在同一事务内提交；相同请求返回原回执，相同请求键但不同载荷必须拒绝。网络超时先查回执，不凭客户端超时重新写入。

取消、确认、重试与迟到回调通过事务和版本比较串行化。上游重试后旧 attempt 的未确认候选失效，不能用旧 `output_refs` 回填；已经确认的快照保留历史且不被自动替换。是否采用新结果由用户新建交接决定。

## 七 服务接线与生成确认

### 交接服务

建议新增交接服务与存储模块，由 `naiba/app.py` 组合装配；总管适配器和造梦机门面通过显式接口调用。`naiba/comfyui` 不反向导入总管运行时，低层不依赖 `server.py` 或全局 APP。

建议接口职责为创建交接、读取详情与候选参数、修订候选、确认写入、取消和读取回执；路径可统一为 `/api/handoffs` 及其子资源。该路径是拟定方案，不是现有 API。

所有写接口校验 owner、会话、任务归属和版本；确认接口从服务器草稿重建目标与值，不能相信客户端传入的任意节点、参数或工作流 JSON。跨模块字段、事件、原因码先在 `naiba/core/contracts.py` 登记；只有确需消息字段时才扩展 `naiba/core/messages.py`。

前端新增统一交接审核区，由聊天入口和总管入口复用；造梦机使用显式 setter 或已登记事件刷新交接工作区，不能通过全局 DOM 查询猜目标。应用阶段必须提供成功或冲突反馈，页面显示的状态以服务器记录为准。

### 总管适配器

增加明确的交接执行器及能力声明，不将其伪装成普通 `job`，不放宽“关联已有后台任务”的创建限制。现有运行时的持久关联、恢复和命令分支部分绑定具体适配器类型，新执行器必须接入可恢复能力接口并有对应测试，不能假定注册后就自动具备幂等。

总管启动交接节点只生成待确认记录。自动推进策略可以推进到这个等待点，但不能替用户确认；暂停、取消和恢复均核对当前 attempt 及交接关联。继续任务只恢复调度，不恢复一个已经失效的确认。

### 第二交付的人工生成

人工点击“开始生成”时，展示目标工作流、最终有效参数、数量及会产生外部执行的说明；服务端将确认绑定到最终快照。任何参数、工作流或生成数量变化都要求重新核对，不能沿用旧生成确认。

复用造梦机既有工作流库、参数校验、任务快照和执行器。交接覆盖值与用户手填值要在同一个权威草稿中明确合并优先级；不同来源发生冲突时先解决，不静默覆盖。生成前重新检查文本目标、媒体引用和现有权限。

当前造梦机提交每次创建新任务，总管 SQLite 与造梦机任务 JSON 也不构成同一事务。因此只要接通生成跟踪，即使仍是人工点击，也必须先补以下保证：

1. 在接收端持久化生成请求键和载荷哈希，使同一请求返回同一 task_id；校验与创建需要并发保护，不能只在总管侧标记“已发出”。
2. 先保存提交意图，再向造梦机提交；造梦机先落任务及关联，再排队。队列及执行领取也按持久 task_id 去重，不能同一个任务被重复排队执行；显式重试沿用原任务及检查点。崩溃后按关联对账，不按“没收到响应”创建另一任务。
3. 区分“本地任务创建一次”和“远端 ComfyUI 是否已接收”。远端提交响应丢失时沿用并审查执行器检查点语义；无法确认的执行进入需要恢复，不承诺无条件恰好一次，也不盲目重提。
4. 生成步骤保持等待确认、排队、运行、失败、中断、取消和完成的真实状态。只有实际生成完成才成功，失败不自动回到上游重新生成提示词。

用户尚未确认生成时，必须不存在新的造梦机执行任务及外部 ComfyUI 提交。

## 八 独立链路协作的后续边界

同一总管任务内先通过交接节点串联。后续若需要“链 A 的结果送到链 B”，新增显式结果引用或订阅实体，不能移除同任务依赖校验后直接跨任务挂节点。

扩展至少定义：源和目标的访问权限、固定的结果版本、目标端人工接受、重复事件去重、环路检测、取消传播范围和源记录删除后的行为。源链重试不覆盖目标已确认草稿；源链取消不自动取消独立目标链已开始的任务。

本计划不开放无人确认的参数写入或生成。未来如有自动化要求，另行明确授权范围、精确映射、失效条件与停止机制；保存映射模板不等于用户已经同意自动执行。

## 九 实施阶段与文件范围

| 阶段 | 工作内容 | 进入下一阶段的条件 |
|---|---|---|
| P0 契约与基线 | 统一结果读取、来源身份、状态、文本交接能力判定、权限和迁移方案；与其他总管修复协调 | 目标不依赖 positive，普通文本与敏感或可执行槽有可信区分，来源可固定到当前实际执行 |
| P1 持久交接 | 实现来源快照、交接记录、任务专用草稿、版本控制与写入回执 | 刷新重启可恢复，重复确认幂等，旧 attempt 和取消不能继续写入 |
| P2 人工审核界面 | 对话发起入口、人工选槽、旧新值预览、编辑候选和确认写入；支持隐藏文本槽 | 非 positive 参数可正确写入，普通手填草稿不被覆盖，未生成 |
| P3 总管接入 | 混合链增加交接节点、等待确认展示、适配器恢复和准确完成说明 | 上游成功只创建候选，确认后才完成交接，自动推进不能越过确认 |
| P4 第一交付验收 | 单元、接口、恢复、冲突测试及桌面和手机浏览器验收 | 完成下表首期验收项，交付“自动准备加人工绑定”能力 |
| P5 第二交付 | 人工生成确认、接收端幂等、提交对账、任务关联与生成状态回传 | 本地重复请求不重复建任务，未知远端提交不盲目重提，生成状态真实 |

预计修改入口：

- 契约与存储：`naiba/core/contracts.py`、必要的 `messages.py`、`naiba/storage/` 迁移、新增交接 store。
- 服务与适配：`naiba/super_agent/` 的 service、runtime、domain、models、store 及新增交接适配器；`naiba/app.py`、`naiba/http.py`。
- 造梦机：`naiba/comfyui/service.py`、`jobs.py`、`store.py`、必要的 `params.py` 与 runner 恢复接线。
- 前端：`public/index.html`、`public/js/04-messages.js`、`24-comfyui.js`、`28-super-agent.js`、必要的组合根事件接线和 `public/styles.css`；审核组件优先独立模块。
- 验证：对应 `tests/test_*handoff*.py` 和 `verify/*handoff*_smoke.cjs`。这些是拟新增资产，不能提前当成已有命令执行。

现有拆书匠分镜交接不在首期顺手改造范围内；将来迁移时统一使用人工选槽规则，并单独验收原有逐条处理体验。

## 十 测试与验收标准

| 编号 | 场景 | 通过条件 |
|---|---|---|
| T01 | 工作流没有 positive 字段 | 仍可选择合法的 caption、instruction 或任意自定义自由文本槽；不要求改名 |
| T02 | 多个文本槽及同名字段 | 显示节点身份并由用户选择，不默认填第一个；即使仅一个候选也需确认 |
| T03 | 非正向目标 | 用户选其他文本参数后只修改该参数，正向提示词保持原值 |
| T04 | 未选择或未确认 | 不更新草稿参数，不创建生成任务；关闭页面和自动推进均不能绕过 |
| T05 | 文本选取和 JSON | 完整正文、摘录、字段提取可追溯；解析失败、空值、非字符串、超长均可见处理，不静默回退或截断 |
| T06 | 非文本与不支持槽 | 媒体、枚举、数值、连接、凭据及未扫描配置不能借文本交接写入；伪装成 STRING 的代码或敏感槽及未知能力均被拒绝 |
| T07 | 当前值与隐藏槽 | 首期预览真实草稿旧值，隐藏槽可审核、持久保存并回显，显示集合不被暗改；第二交付另验最终提交不漏项 |
| T08 | 草稿或工作流变化 | 预览后改值、换工作流、删槽或改类型均阻断旧确认；重新预览后才能写入 |
| T09 | 多条链同一工作流 | 交接草稿隔离，不互相覆盖，不自动切换用户当前编辑区 |
| T10 | 刷新和重启 | 待确认与已确认草稿可恢复，来源和回执仍一致；恢复不自动生成 |
| T11 | 来源可靠性 | 不取会话最后一条，不取未完成流；旧 attempt、跨 owner、错误消息或丢失来源不能误绑定 |
| T12 | 重复确认与网络异常 | 双击、多标签页、响应丢失后重试返回同一回执，不重复应用；同键不同载荷被拒 |
| T13 | 取消与迟到回调 | 取消确认竞态有确定结果；已取消、已失效确认不复活节点或推进后续 |
| T14 | 权限和文本隔离 | 文本内的指令、路径、URL 不变成操作授权；界面和接口不泄露秘密 |
| T15 | 总管状态 | 未确认时等待；确认写入后仅声明已填入；生成门独立，不因 auto_advance 自动批准 |
| T16 | 第二交付提交 | 人工生成同键请求仅一个本地 task_id；跨存储崩溃可对账；未知远端结果不自动重提 |
| T17 | 第二交付生命周期 | 真正完成才标成功；失败、中断、暂停、取消均准确，改变最终参数使旧生成确认失效 |
| T18 | 兼容性 | 原手填造梦机、拆书匠分镜、普通聊天 ComfyUI 工具、旧总管链和工具审批不退化 |

浏览器验收使用真实源码服务和隔离数据，至少覆盖桌面 1280px 与手机 375px。通过实际界面完成选来源、选任意文本参数、查看旧新值、确认、刷新恢复及冲突处理；每个关键步骤后立即检查 `pageerror`、`console.error`、JS/PROMISE 错误条，不能只检查按钮存在或脚本语法。

第一交付用测试计数器证明“确认写入前后均没有生成请求”。第二交付使用受控本地 ComfyUI 替身覆盖提交与故障，再进行经用户授权的真实工作流验证；不得拿用户现有任务、付费模型调用或真实作品作默认测试数据。

本功能涉及契约、持久存储及跨模块接线，实际实施按维护说明 C 级验证：项目虚拟环境 Python 运行相关测试及全量单测，执行 `verify/scan_undef_all.py`、`verify/esm_graph_check.py`、`verify/tdz_check.py`、`verify/verify_doc_encoding.py`，最后完成基础与功能专属 Playwright。计划中的验收矩阵不等于这些测试已经通过。

## 十一 兼容发布与回退

新增入口使用独立能力开关，默认不改变旧链、旧任务和既有参数。历史 `output_refs` 不批量补造交接，不从旧消息自动创建待确认项；无交接的工作流保持原行为。

实施前明确数据库升级和旧版本兼容边界。回退时先禁用新增入口和新生成派发，保留交接快照、草稿、回执及已创建生成任务；使用兼容版本查看或导出，不通过删除记录伪装回退。已提交的外部生成不能假定能撤销，取消须走实际任务接口并显示结果。

完成标准以人工可控和结果可追溯为先：用户始终知道“取了哪段内容、写到了哪个参数、是否已经生成”，而不是仅看到任务总管显示一个笼统的成功。
