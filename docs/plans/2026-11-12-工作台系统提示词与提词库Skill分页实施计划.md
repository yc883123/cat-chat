# 工作台系统提示词与提词库 Skill 分页实施计划

日期：2026-11-12
状态：已实施并完成离线验证；实现、测试及交付记录纳入本地提交，未推送、未发版。
范围：提词库、织书台、拆书匠、造梦机提词转换、贴签匠提交修复。**任务总管本次排除。**

## 1. 需求与范围

用户已确认：

- 手写系统提示词用于持续生效的全局规则。
- 模板正文、普通要求和素材属于 user 输入。
- 选用 Skill 时，完整 Skill 主文与手写系统提示词共同进入 system，参考文档按需读取。
- 提词库采用“模板生成 / Skill 生成”两个分页，接近贴签匠的分页和排版，不用下拉框代替分页，不新增工作台模块。
- Skill 分页支持多选；追问延续原系统提示词、Skill 集合与对话上下文。
- Skill 本次主要用于内容，不要求脚本读取或执行，不扩展通用自动化能力。
- 小说模块有多个阶段，系统提示词要放在作品层，不能只在某个阶段可见。
- 拆书匠的分镜提示词生成支持“模板 / Skill”二选一，Skill 可多选；两种模式都继续使用作品系统提示词，其他小说阶段不增加 Skill 选择。
- 检查现有模板是否只有 Skill 说明书，实际正文需要另读却未读取。

| 模块 | 本次内容 |
|---|---|
| 提词库 | 系统提示词、两个生成分页、Skill 多选、连续追问、模板内容检查 |
| 织书台 | 作品级系统提示词，覆盖生成、改写、续写和分段任务 |
| 拆书匠 | 作品级系统提示词；分镜阶段支持模板 / 多选 Skill 二选一 |
| 造梦机 | 仅“剧本 → 提示词”转换增加系统提示词 |
| 贴签匠 | 修复选择 Skill 后漏传手写系统提示词的问题 |
| 任务总管 | 不增加设置入口、配置字段或专门适配 |

Skill 多选用于提词库 Skill 分页和拆书匠分镜的 Skill 模式；两处复用同一套内容加载、文档快照和只读参考机制。贴签匠本次只修已有系统提示词与 Skill 的共同提交。

本计划不包含发版、推送或真实付费生成。

## 3. 输入角色、字段与保存规则

### 3.1 模型输入

| 路径 | system | user |
|---|---|---|
| 提词库模板生成 | 手写系统提示词 | 填好变量的模板正文、本次要求、素材 |
| 提词库 Skill 生成 | 手写系统提示词、所选各 Skill 完整主文 | 本次要求、素材 |
| 织书台、拆书匠其他阶段 | 作品系统提示词、必要阶段执行约定 | 当前阶段任务、作品素材、补充要求 |
| 拆书匠分镜：模板模式 | 作品系统提示词、必要分镜执行约定 | 分镜模板或写法、所选剧本场次、图谱素材、补充要求、场次输出格式 |
| 拆书匠分镜：Skill 模式 | 作品系统提示词、所选各 Skill 完整主文、必要分镜执行约定 | 所选剧本场次、图谱素材、补充要求、场次输出格式；不夹带模板正文 |
| 造梦机提词转换 | 本次转换的系统提示词 | 转换模板、剧本、实际发送的图片、输出要求 |

参考文档通过只读工具返回，留在后续上下文中，不每轮重新追加一遍。选 Skill 不把其正文回填系统提示词框，不覆盖用户手写内容。

保留原有解析与写回需要的 JSON 字段、场次分隔、章节身份等约定。图谱、角色表、故事正文按素材对待，不因进入既有上下文位置就被当成新的用户指令。

### 3.2 字段

- 公开生成字段：`system_prompt`。
- 作品字段：`global_system_prompt`、`global_system_prompt_revision`。
- 提词库及分镜生成来源共用 `prompt_source: template | skill`；多选为有序去重的 `skill_ids`。
- 拆书匠按作品保存独立 `storyboard_prompt_config`（来源模式、模板写法草稿、Skill 选择及配置修订号），与作品全局系统提示词分别保存。请求沿用已有分镜 `system_prompt` 承载模板草稿的兼容入口；进入任务前转换成明确的模板 user 内容，不与 `global_system_prompt` 混用。
- Studio 内部最终系统文本继续使用 `input.system`。提交前统一组合，不重复注入，不破坏旧 Writer/Novel 内部调用。
- 对话链使用 `thread_id`、`parent_task_id`；与既有 retry 的 `source_task_id` 分开表达。
- 新增跨模块字段先登记 `naiba/core/contracts.py`，确需新增消息元数据时再登记 `naiba/core/messages.py`。

空值保持原行为；旧作品、旧任务缺字段按空处理。旧任务重试不能自动补上当前默认提示词。

默认配置用于新生成，任务快照用于已提交任务和追问。提示词全文、参考资料和历史正文只存权威记录，不重复写入状态事件。

## 4. 提词库分页与排版

### 4.1 两个分页

在现有提词库内增加“模板生成 / Skill 生成”，复用贴签匠 `.wb-media-tabs` 的尺寸、选中状态、间距及窄屏换行方式。

- 模板页保留分类、列表、变量、正文预览、自定义模板、参考图片，补系统提示词区域。
- Skill 页提供系统提示词、多选 Skill、本次输入、参考图片、供应商/模型和生成按钮。
- 两页共用提词库系统提示词默认值；各自保留来源选择、输入草稿、素材及当前结果。
- 切页不清空另一页内容；只提交当前分页的来源字段。
- 服务端拒绝同时提交模板和 Skill 的混合来源，防止隐藏控件误入请求。
- 模板页保留现有无模板自由输入兼容路径。

### 4.2 布局

| 区域 | 模板生成 | Skill 生成 |
|---|---|---|
| 左栏 | 模板分类与列表 | 本页最近生成记录，接近贴签匠批次栏 |
| 中栏 | 系统提示词、模板参数、输入与模型 | 系统提示词、多选 Skill、输入与模型 |
| 右栏 | 生成结果、连续追问 | 生成结果、连续追问 |

Skill 多选采用可搜索列表和已选条目，支持逐项移除；不采用原生多选框。长名称省略并可查看完整名称，已选项自动换行。

样式复用贴签匠 16px 内容边距、表单间距、系统词输入框和底部操作区。生成按钮放在设置栏底部；结果与追问共用右栏。整合现有标题与分页，避免重复增加“提词库”标题行。

使用现有 `data-wb-size`：宽屏三栏；中等宽度保留左栏并切换设置/结果；窄屏一次显示一栏。按工作区实际宽度判档，兼容侧栏展开后的可用空间。

主要文件：`public/index.html`、`public/styles.css`、`public/js/22-studio.js`。多选和对话展示按职责拆到同目录小模块，避免继续扩大主文件。

### 4.3 默认值和草稿

扩展 `settings.studio` 的生成设置，保存系统提示词默认值、上次分页和 Skill 选择，复用 `saveStudioPrefs()`、`normalize_studio_prefs()`。

模板收藏、标题别名、`last_selection` 保持原语义。服务端 generate 不自动套用提词库默认值，由前端明确提交，避免其他模块意外继承。

保存失败保留草稿并提示。详情加载、切页和素材加载保留代次校验，加载未完成时不提交旧来源内容。

## 5. 内容型 Skill

### 5.1 执行方式

模板模式继续直接调用模型。提词库 Skill 分页与拆书匠分镜 Skill 模式共用任务级适配层，复用 `SkillAgent.run()` 的工具循环、取消、用量和上下文检查，使用 `exclusive` 策略加载用户选择的多个 Skill。

适配层按冻结的 `prompt_source` 选择执行路径，不依赖 `module=global`；分镜任务仍保留 `module=novel`、作品与场次快照和原完成态写回流程。第 6 节的连续追问界面仅用于提词库，拆书匠本次沿用现有分镜任务交互。

参考 `naiba/labeler/engines/chat.py` 的任务级装配，但 Studio 不反向依赖打标领域。

- 所选 Skill 主文完整加载，保留名称及目录来源。
- 文档按需读取，只提供文档读取、列目录、搜索所需能力。
- 文档访问限定于本次 Skill 文档和素材；脚本、二进制文件不加入文档集合。
- 不增加脚本执行、文件改写、MCP 或其他生成工具。
- 不使用 `skill_bundle()` 已截短的拼接结果充当完整主文。
- 内容过长或上下文不足时明确提示，不能静默裁掉规则。
- 多 Skill 读取步数沿用通用运行设置，不照搬贴签匠单图固定 12 步上限。

### 5.2 版本与文档快照

首轮固定系统提示词、来源、模型选择、Skill ID/名称及文档版本。所选 Skill 主文和可读文档保存为任务链共享的内容快照，按内容摘要复用，不每轮复制整套文件。拆书匠分镜也在提交时创建同类快照，重试继续引用原快照，新生成才采用当前选择和最新文档。

SkillAgent 通过快照目录视图读取主文和资料。原 Skill 被更新或删除后，已有对话仍用原内容，新生成才用最新版本。多个 Skill 中同名文件按各自根目录解析。

快照缺失或损坏时明确报错，不能暗中替换成最新 Skill，也不能降级为只发描述。仍被任何任务链引用的快照和素材保留，删除一条历史记录不能破坏其他轮。

现有 `SkillCatalog` 的主文读取、文档类型和路径检查规则可以复用，但正文不能使用其截断后的 bundle。

## 6. 提词库连续追问

### 6.1 交互

- “追问”改为在结果区输入，继续当前生成。
- 原 `/api/studio/handoff` 能力保留，改称“发送到对话”，放进结果操作菜单，仍按原规则选择 Agent。
- 不创建全局 Agent，不改变普通聊天的 Agent 绑定。

### 6.2 服务端链路

沿用 Studio 任务体系，每轮一个任务，以 `thread_id`、`parent_task_id` 关联。新增追问接口，例如 `POST /api/studio/tasks/{id}/followup`。

前端提交源任务、追问文字、素材及请求标识；服务端从所选结果继承配置和历史，追加新 user 消息。

1. 保存和重放真实 user/assistant/tool 轮次，不把历史拼成一条 user 消息。
2. 保存 SkillAgent `trace_messages`，包括文档读取结果；最终回答只重放一次。
3. 每轮保存足以恢复的输入历史，删除早期任务后当前轮仍可继续。图片保存受管引用，不反复写入大块编码数据；引用保护覆盖历史图片。
4. 同一链运行中不重复提交，复用 `request_key` 幂等校验。取消、失败保留 partial，但不当作成功回答自动带入下一轮。
5. 重试沿用原输入；当前表单、默认模型、模板或系统词变化不修改旧对话。
6. 新配置用于“新建生成”。历史能恢复配置摘要、结果与上下文；迟到加载和轮询不得覆盖新选择。
7. 工具读取过程转换为既有 Studio `status`，不新增一套聊天工具卡。

复用 `StudioStore.create_task()`、`StudioJobManager.retry()`、`StudioRunner._run_task()` 和 `naiba/core/history.py` 的历史重放规则。修改 `service.py`、`jobs.py`、`runner.py`、`store.py`，路由放在 `naiba/http.py`，装配在 `naiba/app.py`。

## 7. 小说分阶段系统提示词

### 7.1 入口和保存位置

织书台、拆书匠都在作品页头“更多作品操作”中增加“作品系统提示词”，独立编辑框提供保存、取消、清空。

说明：“用于本作品各个 AI 生成阶段，保存后对新发起的任务生效。”

入口在阶段面板之外，各阶段均可打开。系统词作为作品 manifest 独立字段，不进入人物设定版本；恢复旧设定或切换阶段不改它。

每本作品独立，新旧作品默认空。从拆书匠导入续写的新作品也默认空，不自动继承原书改编规则。

保存采用独立 `global_system_prompt_revision`，在 store 锁内校验并原子写入，不递增正文生成使用的作品 revision，避免保存系统词导致正在生成的稿件被误判为冲突。多窗口冲突保留草稿并提示。

### 7.2 织书台

在 `start_pipeline()` 创建 `request_snapshot` 时冻结全局系统词及修订号，`_submit_step_task()` 统一组合，各步只读快照。

覆盖设定、大纲、复核、拆章、分段正文、整章正文、连续写章、改写、续写，以及必要的章末状态提取。保留各阶段格式与解析约定。

普通 retry 沿用旧快照；显式 rebase 才更新当前作品系统词。旧流水线无该字段时按空处理。预览与提交使用同一组合函数，预算计入系统词。

文件：`naiba/writer/service.py`、`store.py`、`pipeline.py`、`prompts.py`、`novel_import.py`、`public/js/27-writer.js`。

### 7.3 拆书匠及分镜

覆盖 `_build_stage()`、`_build_adapt()`、`_build_storyboard()`，在预算计算前统一组合。长章分块每轮使用同一系统词。TXT 自动拆章、人工编辑、导入导出等非模型操作不注入。

**分镜阶段增加“模板 / Skill”二选一，作品系统提示词在两种模式下都生效。** 其他阶段只增加作品系统提示词，不扩展 Skill 选择。

#### 分镜入口与排版

在现有分镜“生成设置”内增加与提词库、贴签匠同款的分段按钮，不新增工作台页面，也不挤进五阶段导航。

- **模板**：保留当前手写内容、内置写法、从提词库导入和恢复默认，区域改称“分镜模板 / 写法”。留空继续使用内置写法。
- **Skill**：复用提词库可搜索的多选控件，展示已选名称和移除操作；至少选择一个 Skill 才能生成。参考文档按需读取，主文不回填模板框。
- 切换只改变活动来源，两边草稿保留；Skill 模式隐藏模板编辑区，提交时不夹带模板正文。模板模式不提交 Skill。
- 作品系统提示词仍从页头入口编辑，不在分镜区重复放一个全局输入框。场次选择、补充要求、模型、生成按钮和结果位置沿用现有排版。
- 多选条目可换行，输入区 `min-width: 0`；手机上控件收为单列，不能挤窄模型或场次选择。

#### 保存、导入与兼容

`storyboard_prompt_config` 按作品保存模板/Skill 模式、模板写法草稿及所选 Skill ID，带独立配置修订号；切书切阶段不串值，刷新后恢复。保存使用同一作品锁和原子写入，但不递增正文写回使用的作品 revision，避免影响正在生成的任务。

旧作品默认模板模式。既有浏览器分镜草稿继续可见：仅在当前作品没有已存分镜配置时作为本地草稿显示，不后台批量写入全部作品；用户保存或生成当前作品时才按明确内容固定配置。保留旧请求缺少来源字段时的模板兼容路径。

从提词库执行“发送到分镜生图”时，明确带入模板并切到模板模式，同时保留该作品未启用的 Skill 选择；不把模板偷偷拼进 Skill 主文。

#### 模型输入与结果写回

当前分镜写法放在 system；新模板任务将它放入 user，与所选场次、素材、补充要求一起发送，作品全局规则继续放 system。Skill 模式把作品系统词和各 Skill 完整主文放 system，user 中保留场次、素材和必要输出格式，不再注入内置或手写模板正文。

两种模式均保留图谱素材、场次身份和 `【第 N 场】` 解析格式。模型返回仍经过现有分镜解析、场次对应、版本保存和发送造梦机流程；格式不合格时沿用明确错误/未解析状态，不伪造场次结果。

分镜任务在提交时固定来源模式、模板正文或 Skill 文档快照、作品系统词及修订号、模型和所选场次。Skill 主文计入提交前预算，工具读取新增内容走运行时上下文检查。取消、错误、用量和流式状态复用 Studio 的内容型 Skill 适配，不新建第二套执行器。

新生成使用最新作品设置，重试使用任务原快照。历史任务和旧重试保留原输入，不改历史 system；没有新字段的旧任务不补载当前 Skill。

Novel 增加作品设置保存接口，`_public_manifest()` 返回全局及分镜配置字段。主要文件：`naiba/novel/service.py`、`prompts.py`、`naiba/http.py`、`public/js/25-novel.js`、`public/index.html`、`public/styles.css`；复用第 5 节的 Studio Skill 适配层和快照实现。

## 8. 造梦机与贴签匠

### 8.1 造梦机提词转换

转换设置增加可展开的系统提示词区域，保存到 `batch.convert.system_prompt`，由 `buildBatchConvertRequest()` 传给 Studio。

单条和全部转换都携带；点击全部转换时固定整份设置，同一批前后不能使用不同系统词。运行中修改不改变已提交任务，取消后重新转换才采用新设置。

切换批次恢复本批设置或空值，不继承提词库默认规则。迟到回包校验包含系统词。ComfyUI 图参数、出图和出视频执行不变。

文件：`public/js/24-comfyui.js`、`24a-comfyui-convert.js`。

### 8.2 贴签匠共同提交

将 `collectConfig()` 的自定义档 `system_prompt` 赋值移到 Skill if/else 外，选择 Skill 时两者一起提交。

修改“没选 Skill 时生效”“手输提示词不参与”等旧文案和注释。选择或移除 Skill 不清空手写内容；清空系统词、停用 Skill 各自独立。

保留现有后端组合、配置指纹、并发监督、TXT 输出和重试语义，不扩大引擎范围。

文件：`public/js/23-labeler.js`、`public/index.html`，以及对应过时注释。

## 10. 实施顺序

1. **字段和作品设置**：登记契约、统一 system 组合与默认值；完成小说两模块作品级入口和快照。

5. **全量验证**：输入角色、历史、分阶段行为和前端验收。

## 11. 验收

### 11.1 功能

- 本地假模型捕获实际请求：模板在 user，手写 system 不丢，多 Skill 主文同时进入 system；分镜模板新请求在 user，分镜 Skill 模式的 system 包含作品系统词及全部所选 Skill，user 不夹带模板。
- 两个 Skill 引用同名文档时读取正确，主文不截断，脚本工具不可用，缺文档明确提示；提词库与分镜两入口均验证。
- 分镜切换模板 / Skill 不丢草稿，切书、切阶段和刷新正确恢复；Skill 模式空选、混合提交被拒绝，从提词库导入模板明确切回模板模式。
- 分镜两种模式均按所选场次解析、存版本并发送造梦机；Skill 文档读取不破坏场次身份和输出格式。重试沿用原来源与文档快照，旧任务不补入当前 Skill。
- 至少三轮追问保留首轮规则、正文、参考文档结果与图片身份，回答不重复；改表单不改变旧对话。
- 原 Skill 更新或删除后，已有对话使用快照，新生成采用新内容或提示缺失。
- 刷新、重启、切页、历史查看、取消、重试、重复点击保持正确归属；删除早期任务不破坏仍被引用的资料。
- 小说各模型阶段携带作品系统词；保存不误伤正在运行的流水线；retry 不漂移，Writer rebase 才更新；切书不串值。
- 造梦机全部转换使用点击时配置，后续编辑不被旧返回覆盖。
- 贴签匠真实前端提交同时包含系统词和 Skill，TXT、监督和缓存逻辑保持。
- 旧任务、空系统词、模板自由输入及显式发送到对话继续可用。
