## 1. 再次生成的前端渲染与工作流保存的显示集不一致（BUG，已定位，未修）

### 现象

对一条已完成任务点「再次生成」，表单露出的参数比工作流库保存时多：截图里多出 4 个 LoRA、随机种子、采样器、steps；顺序也变了（LoRA 排到了图片前面）。能正常出图。

### 根因

`public/js/24-comfyui.js:2833` 的 `buildRerunDetail()` 在 2897 行重建可见集：

```js
const visible = defaultVisibleKeys(params);
for (const key of overrides.keys()) visible.add(key);
for (const key of mediaKeys) visible.add(key);
```

它没有沿用工作流保存的 `visible_params`，也丢掉了 `param_order`。而 `defaultVisibleKeys` 的默认集包含 lora / sampler / scheduler / checkpoint / resolution 角色、`seed` 类型、`steps` 字段和媒体槽（同文件 814-828），所以 LoRA、种子、采样器、steps 全被算成可见。排序因为 `param_order` 缺失，退回角色优先级（LoRA 角色排 3，媒体排 4）。

### 实测证据（正式版实例，127.0.0.1:8765）

- 工作流 `cw-4b94f012aa2c`「moss-image Ray-version (图生图)」：`visible_params` 就是三项（图片 437、locked_text 92、presets_data 414），并且存了 `param_order`。
- 对 11:38 的任务 `cf-20261113-f18a20b561ae` 点再次生成，表单渲染 9 项：4 个 LoRA、locked_text、seed、采样器、steps、presets_data；locked_text 是满的（239 字）。
- 对 11:42 的任务 `cf-20261113-064942535953` 点再次生成，同样 9 项，locked_text 为空。这不是渲染丢了文本：那条任务自己的快照里 `overrides` 就有 `locked_text: ""`，是提交时框里就是空的。当天 11:49 从单次生成表单直接提交的任务 `cf-20261113-27c6177bb9c5` 也是空提示词，说明空值是用户填进去的。

### 连带影响

`collectOverrides()`（同文件 2717）会收集表单里渲染出来的**每一个**输入。再次生成提交后，新任务的快照里因此多出 7 条「没改过」的覆盖：4 个 LoRA、sampler、steps、locked_text。值等于原快照默认值，出图不受影响；但这些覆盖会让新任务以后再点再次生成时，这些字段永久可见（覆盖项强制加进可见集），差异会一直传下去。

### 修法（待选）

- A. 提交时把工作流的 `visible_params` / `param_order` 冻结进任务快照。只对新任务生效，老任务仍退回默认集。
- B. 在 `/api/comfyui/tasks/<id>/rerun-snapshot` 响应里带上工作流当前保存的显示集与顺序。老任务立刻变好，但工作流后来改过显示集就按新的。
- C. 纯前端查表不可行：`/api/comfyui/workflows` 列表只返回 id/name/node_count/param_count/时间戳，没有 `visible_params`。

倾向 A + B 兜底，A 为主。这条修不修、怎么修都还没拍板。

## 4. 已批准但暂停的实施方案（单次档清除模式）

用户已经批准，等待恢复执行；如与第 3 节的列表改造合并，方案要重新对一遍。

### 状态

`comfyui` 对象新增：

```js
clearMode: false,          // 单次结果清除模式
clearSelection: new Set(), // 勾选的任务 id
clearDeleting: false,      // 批量删除请求进行中
```

### 结构

`public/index.html` 在 `.comfyui-tasks-head` 与 `#comfyuiTaskList` 之间加默认隐藏的 `#comfyuiClearBar`：已选 N 条 + 说明 + 全选 + 删除所选 + 取消。⋯ 菜单里「清除」文字不变（`tests/test_comfyui_module.py:1980` 钉着 `>清除</button>`），title 改为进入清除模式。

### 渲染

- `renderClearBar()` 按 `clearMode` 显隐、更新计数与按钮状态（全勾满时「全选」变「取消全选」）。
- 清除模式下，非 `queued/running` 的任务卡前置 `data-comfyui-clear-check` 勾选框，卡片加 `is-selected`；活动任务不出勾选框，走卡片上的「取消」。
- `clearMode` 与选中状态拼进 `taskFingerprint`（仅模式下），保证进出模式和勾选时重画；常规轮询仍只重画变化的卡。
- 每次 `renderTasks` 前按 `comfyui.tasks` 收拢选择集。

### 交互

- 入口没有可清除任务时 toast「没有可清除的任务；执行中的任务请先取消」，不进入；进入后关闭 ⋯ 菜单。
- 全选：只勾本次渲染出的已结束单次任务（最多 12 条）。
- 删除所选：确认后 `DELETE /api/comfyui/tasks`，body `{ task_ids, cancel_active: false, exclude_batch: true }`；按 `deleted/failed/skipped` 如实回报，失败的留在选择集；成功后 `refreshTasks()`，无任务自动退出。
- 退出时机：取消、切到批量档、离开结果档、离开造梦机页。
- 卡片原有「删除」保持不动。

### 样式

`.comfyui-clear-bar`（flex wrap、沿用 tasks-head 的内边距与分隔线）、`.comfyui-task-card.is-selected`、`.comfyui-task-select`（44px 触摸命中区）。

### 测试
