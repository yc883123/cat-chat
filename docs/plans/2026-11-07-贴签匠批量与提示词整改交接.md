# 贴签匠批量与提示词整改交接

> 状态：需求已澄清，尚未改产品代码。新对话接手后先读《项目维护说明（修改代码前必读）.md》，再按本文实施；不要把本文的只读调查描述当成已完成修复。

## 用户已确认的需求

1. **单图大于 20 MiB：自动处理，不要求用户手工压缩。** 复用“运行设置”现有图片处理/压缩设置；当前处理后缓存图仍超过 20 MiB 时，贴签匠继续自动降低缓存副本尺寸，直到满足贴签处理上限或检测到不可处理的格式/解码错误。界面说明正在自动压缩。不能悄悄修改用户的全局压缩设置。
2. **原图必须精确保留。** 贴签匠训练包导出用原图；任何缩放、重编码都只作用于处理后缓存副本。原图 SHA-256、原始字节数和导出校验继续指向未修改的源字节。
3. **每批最多 9999 张，批次总量约 20 GiB。** 单图处理后缓存限制仍为 20 MiB；20 GiB 是每批处理后缓存总量上限。上限要贯穿前端预检、上传反馈、任务 JSON 请求体、服务端引用校验、SQLite item 建立、runner 处理、任务详情/继续、统计、导出和结果展示，不能出现只处理前 N 张却显示任务结束的情况。
4. **手写提示词作为 Agent 级 system prompt。** 选择 Skill 时，手写系统提示词与完整 Skill 同时作为规则生效；图片和“处理此图”指令作为 user 输入。不要把系统提示词拼到 user 文本里。
5. **保留批量任务安全边界。** Skill 仍由共享 `SkillAgent` 完整注入并按需读取参考文件；继续只暴露 `read_file`、`list_directory`、`search_files` 等只读工具，不继承普通对话全部工具授权，不启用等待人工确认的动作。
6. **整批结束后可只重试明确失败图片。** 新增清楚独立的“仅重试失败图片”入口，只处理 `failed`，创建关联新任务并跳过成功项。不确定状态 `uncertain` 可能已被供应商处理、可能已计费，不能混入这个按钮；仍使用原有独立确认流程。上传失败的“重试失败”与模型打标失败需用不同文案/区域。

## 已查明现状

- 当前分支为 `master`，HEAD 与 `origin/master` 在 `095c3bc1`（4.1.5-beta 整合提交）。没有做本任务的代码修改、提交或推送。
- 工作区存在用户未跟踪文件（交接文档、截图、反馈 docx/CSV 等）；不要清理、覆盖或批量暂存它们。
- 图片处理相关入口：`public/js/23-labeler.js::acceptFiles()`；服务端引用校验 `naiba/labeler/images.py::validate_image_refs()`；上传服务 `naiba/labeler/service.py::api_upload()`；现有图片处理 `naiba/storage/media.py::_process_uploaded_image()` / `store_uploaded_file()`；全局设置 UI 在 `public/index.html` 的运行设置图片/缓存区，配置默认/结构在 `naiba/config.py`。
- 当前图片处理先读取打标专用 multipart spool，原字节进 `archive_original()`，再按 `config.data["imaging"]` 生成上传缓存副本。当前错误是 `verify_image_bytes()` 在原图上提前应用 20 MiB 校验，导致未调用现有压缩；前端 `acceptFiles()` 也在 File.size > 20 MiB 时拒绝并提示“请先压缩后再试”。通用上传端点传输上限 80 MiB，multipart 请求整体上限 100 MiB，需分别处理，不能把传输上限当缓存上限。
- 现有 `_process_uploaded_image()` 主要按像素上限缩放，不保证输出字节数；运行设置“以原图片尺寸上传/缓存”会绕过缩放；GIF 保留原图/动画；某些处理失败会回退源字节。因此贴签专用缓存要有“压缩后仍超 20 MiB 时继续降低尺寸”的专门循环/策略，不能假定现有一次处理一定达到字节上限。需要针对 JPEG/PNG/WebP/GIF 定义可预期的缓存处理策略，同时原图归档必须先于任何重编码或只复制未修改的原始 data。
- 当前限制包括：`MAX_BATCH_IMAGES=500`、`MAX_BATCH_BYTES=1 GiB`、HTTP `/api/labeler/tasks` 请求体 16 MiB 且错误文案写 500；`LabelerDB.list_items()` 默认 2000，runner 通过 `pending_items()` 只拿默认条数；任务详情只返回 2000 条；继续任务只读 5000 条；annotations API 封顶 2000、导出封顶 5000。以上都要逐项定策略，避免尾部数据丢失。
- `LabelerJobManager.continue_task(mode="failed_only")` 已存在，但其当前筛选是 `{"failed", "uncertain"}`，必须改成只选明确 `failed`，并补覆盖测试。`continue_task()` 当前先查 5000 条 items，亦须兼容 9999 张。
- 前端仅有当前批次“继续未完成”操作（`continueTask()` 固定发 `mode: "unfinished"`），没有 failed-only 模型失败重试入口。页面另有 `labelerRetryUpload`，那只是上传失败重传，不能复用为模型任务重试按钮。
- 手写系统提示词目前由 provider `build_prompt()` 返回为普通字符串，再由 `build_messages()` 放在 user 图片消息里；chat/Skill engine 也只把简单 per-image prompt 放 user，`SkillAgent.run()` 收到的 `agent_system_prompt` 当前是空字符串。要在组装层新增明确的 system-message/prompt 参数通道，并确认 provider 各协议对 system/developer 角色的支持和顺序；保留用户选的 `auto` 语义，不追加隐藏格式规则。Skill + 手写提示词两者并用时，system prompt 是 Agent 级补充规则，Skill block 仍完整独立注入，user 部分只承载图像与任务动作。
- Skill revision 已在 `naiba/labeler/jobs.py::_skill_revision()` 计算完整文本版本，避免超 bundle 截断范围改动不更新指纹。重试时当前会从当前 Skill catalog 重新读 Skill 内容并重算 revision；若原批次后 Skill 文件改变，重试会用新规则。实施时应至少检测原 task snapshot 的 revision 与当前 revision 不同并明确报错/要求用户选择，不要静默重试成另一个 Skill 版本。

## 关键文件与注意事项

- `naiba/labeler/images.py`：20 MiB 当前校验在 `_verify_image()`、`verify_image_bytes()` 和 `validate_image_refs()`。区分“上传源图传输大小”与“最终打标缓存图大小”；任务 refs 校验必须针对压缩后 cache。
- `naiba/labeler/service.py`：保存精确原图、读取运行设置并产出 cache；超过输出上限后的自动二次缩小需清理不合格 cache/thumbnail，不留下可被后续误提交的文件。
- `naiba/storage/media.py`：全局图片压缩逻辑和格式支持。不要直接修改全局默认值或改变其他普通上传用户行为；建议新增可参数化的贴签专用“最大字节目标”处理 helper，复用它的解码/resize/编码逻辑。
- `public/js/23-labeler.js`：批次上限、选中文件大小提示、每批总大小预检、上传行 `size`、重试失败 UI、任务 API、结果加载与 DOM 分页。
- `naiba/http.py`：任务 JSON 请求体限制不能只按 500 条说明。对最多 9999 条 refs 评估路径/name 最大长度后的 JSON 上限，仍需设有限制并在上传前/任务创建前返回明确错误。
- `naiba/labeler/db.py`、`runner.py`、`jobs.py`：所有项查询、pending、处理、重试筛选、详情和恢复逻辑；runner 可分页拉 queued item，或以迭代器分块处理，不能一次只取 2000 后将任务结成 done。
- `naiba/labeler/engines/provider.py` / `engines/chat.py` / `naiba/skills/agent.py`：system prompt 通道与 Skill 组合。修改前读 `SkillAgent.run()` 参数契约和 provider role mapping；不要扩大 `CHAT_ALLOWED_TOOLS` 授权。
- 测试：`tests/test_labeler.py`（图片/数据库/runner/retry/upload）、`tests/test_labeler_custom_page.py`（提示词语义和 UI 契约）、`tests/test_labeler_skill_lifecycle.py`（真实前端函数 harness）；考虑新建压缩/大批量/结果分页专项测试。
