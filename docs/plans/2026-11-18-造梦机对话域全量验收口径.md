## 1. 证据分层（判「过」之前先认层）

| 层 | 含义 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| L0 | 静态/契约检查（AST、schema、分片清单） | 形状、登记、常量没被改坏 | 任何运行时行为 |
| L1 | 本地替身 + 真实引擎接线（`ToolExecutor`、handler、临时数据目录） | 权限链、幂等、归属、状态机逻辑 | 真实 ComfyUI 受理、真实出图、页面渲染 |
| L2 | 隔离实例 + 浏览器（桌面 / 375px） | DOM、弹窗、旧功能回归、可见性 | 付费节点、真实排队与产物 |
| L3 | 真实 ComfyUI 服务 + 用户指定工作流 | 单条 / 2 条批次真实受理与产物 | 全量异常注入（断网/重启要单独造） |
| L4 | 用户确认 | 预算/审批、文案与交互是否可接受 | — |

**红线**：L1 用例不得写「真实生成通过」；L2 截图不得当 L3 证据；没有跑过的项一律 `PENDING`，不许写 `PASS`。

## 2. 判定总则

1. 一个验收项判 `PASS-L1` 需要同时满足：有具名自动化用例、本轮实际执行、`exit=0`、用例断言的就是该项要求。
2. `GAP` = **功能根本没实现**，不是「没测」。GAP 项不能靠补测试变绿，必须先补实现或由本人明确裁掉该要求。
3. 任何一项出现「不重复生成被破坏」「未登记却承诺通知」「full 绕过白名单/归属/快照校验」，整批验收直接判不通过，不看其余项。
4. 验收后代码再有改动（含 KVMem 组改到共用 CSS/HTML），受影响的 L1/L2 项必须重跑，旧日志作废。
5. 发版门槛见 §6；`git add` ≠ 提交 ≠ 发版，`on: push master` 就是自动发版。

### 5.3 验收抓到的真 BUG（已修，附复验）

`test_concurrent_replay_creates_single_task` 第一次跑虽然 `OK`，但日志打出：

```
预检快照更新失败：...ds-9a4025b056ed.json（[Errno 13] Permission denied:
...ds-9a4025b056ed.tmp）
```

根因：`DreamSnapshotStore.update()` 用 `path.with_suffix(".tmp")` 固定临时名。两个并发重放同时写同一份提交回执 → Windows 下撞 `PermissionError`，且写失败被 `logger.warning` 吞掉后仍返回 receipt；更糟的是「读-改-写」无锁，`submitted` 与 `notify_*` 两次更新可能互相覆盖。回执是「同一快照不重复生成」的唯一凭据，不能只靠下游 `request_key` 幂等侥幸兜住。

修法：进程内 `threading.RLock` 包住读-改-写 + 临时名加 `uuid` 后缀 + `finally` 清理。守门同步加严：断言并发后**不出现该告警**、`submitted` 真的落盘、任务数仍为 1、两个回执 `task_id` 相同。修复后 16 例复跑绿，告警消失。
