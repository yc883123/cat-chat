# Cat Chat GOAL：一句话长任务设计

日期：2026-11-20。状态：首版已实施，综合验收与后续适配未完成，未提交、未发布。实施范围与已验/未验以[2026-11-21 实施记录](../GOAL-2026-11-21-实施与验收记录.md)为准，下文保留目标设计。依据：[未完成事项交接 §3](../交接-2026-11-20-未完成事项.md#3-长任务自动续办尚未实现单独设计再做-b4)、[摘要及压力测试计划 §5–6](2026-11-20-自动整理摘要修复与无人介入长任务压力测试计划.md#5-阶段-b一句话长任务压力测试设计)。本稿先定形态，等摘要诊断和 B2/B3 有结果再实施 B4。

## 1. 用户怎么用

在空闲的普通对话里，点输入框左侧已有的「＋」，从菜单选「GOAL」。菜单收起，输入框内立即显示 `GOAL ×` 标签，光标回到输入区；这一步就算进入 GOAL 模式，**还没开始执行**。保留已输入的草稿和引用，可以直接写「完成 @实施计划.md，按验收清单核对」，点发送才创建目标。入口只有这个菜单项，不加 `/goal` 命令或第二个唤起按钮。

```text
点左侧「＋」          选「GOAL」后
添加
  📎 附件              [＋]  [GOAL ×]  写下目标…  [发送]
  GOAL
```

**保留「附件」。** 主对话原来点「＋」直接打开文件选择；改后由菜单第一项「附件」接回原动作，桌面弹系统文件选择窗口，手机打开原来的系统文件选择界面。不做两个入口，不改变文件类型、多选、上传和预览规则。选「附件」时在这次点击中直接触发原文件选择，避免手机浏览器把异步弹窗拦掉；取消选择保留草稿和已有附件。普通输入和 GOAL 都能用「附件」，已有附件随草稿一起保留，选「附件」不会退出 GOAL，点击「GOAL」也不会打开文件选择。拖拽和粘贴照旧。未开放 GOAL 的入口保留原附件交互。

**默认是普通对话。** `GOAL` 标签存在时，本次发送按目标处理；点标签的「×」回到普通输入，草稿不清空。选中后不因编辑草稿、关闭加号菜单或失焦而退出；提交失败保留标签和草稿，提交成功才清除选中态。切换到别的对话不继承；刷新后默认普通输入，已提交的目标从服务端恢复卡片。活动目标期间显示目标卡与控制按钮，不开放再次发送。首版不加默认开启的全局开关，也不让 Agent 自动切入；辅助对话、OneBot 和计划执行都不开放该入口。目标使用当前对话的 Agent、模型和工作区，选中时可查看简短的执行范围与预算；发送本身就是启动授权，不多弹一层确认，也不会提升工具权限。没有正文不开始跑。服务端只认明确的 GOAL 创建请求，普通消息中的「帮我做完」或 `/goal` 字样、引用内容、模型、Skill 与导入记录都不会激活 GOAL。

发出后，原文作为**唯一一条用户消息**保存。下面只留一张目标卡，后续换 Run 在原对话里发生，不发送「请继续」、不另开一串会话。主界面优先显示当前步骤、最近已确认成果、耗时或停下原因；能数清义务才显示「3/5 项已验收」，没有已知总数就不画百分比。「详情」里可查每轮记录、验收项和预算，已有工具轨迹照常可展开。

```text
目标 · 进行中
完成「实施计划.md」
正在跑本地回归 · 已验收 3/5 项 · 已用 24 分钟
[暂停] [取消] [详情]
```

| 用户看到 | 行为 |
|---|---|
| 排队 / 进行中 / 等待工具结果 | 自动推进；关浏览器或切会话不停止。排队不偷偷抢占普通聊天。 |
| 正在暂停 | 立刻禁止启动新调用和新 Run；可中断的模型请求取消，已发出的工具等结果或核对。未确认的外部动作照实显示。 |
| 已暂停 | 保留检查点和结果，重启后仍暂停；点「继续目标」才接着跑，不从头做。 |
| 需要你处理 | 执行停止，卡片写清卡在哪、已经做了什么、怎么处理。不弹窗、不要求补发一条聊天；只有用户主动处理后才可续办。 |
| 已停止 | 预算耗尽、重复无进展或不可恢复错误，显示具体原因。预算耗尽可由用户显式追加额度后接着跑；其他情况只有明确解决了原因才提供续办入口。 |
| 待验收 | 产物已交付，剩余要求无法自动判定；不再消耗额度，卡片列出待核对的项目，可点「确认完成」或结束目标。 |
| 正在取消 / 已取消 | 取消需确认；停止后不会再自动恢复。保留已产出的文件和记录，取消不等于回滚，也不承诺撤销已发出的动作。 |
| 已完成 | 展示已通过的验收项、验收证据与产物链接；用户手动验收时明确标记「你已确认」。 |

目标未结束时，同会话不能再开第二个目标，也不能编辑、重发、插话、手动重置上下文或撤销整理来改变目标历史；普通聊天可在别的会话继续。需要在原会话改目标时，先取消，再发新目标；也可另开普通分支，分支不继承目标状态或目标专属授权。首版建议同一服务一次执行一个 GOAL，其余排队，用现有模型并发保护，不提高请求并发；暂停、待处理、长期等 Job 都释放 GOAL 执行名额，但不解除原会话的目标占用。活动目标的对话不允许删除或归档，先结束目标再操作。

**普通对话的兼容门槛。** 主对话唯一预期变化是点「＋」先看到菜单，再点「附件」才打开原文件选择，比现在多一步。除此之外，未选 GOAL 的发送仍走原 `/api/chat`，不创建目标、不继承目标预算、不自动续办。原附件上传与预览、粘贴与拖拽、停止与插话、摘要和重启恢复都维持现有行为。退出 GOAL 后，本次草稿按普通消息发送；切到其他对话不继承标签。辅助对话不加菜单。把以上行为列为桌面和窄屏的回归门槛，通过前不能宣称兼容已验。

## 2. 每轮做完后怎么接

**GOAL 是持久任务，Run 是它的一小轮。** 首版在现有 SQLite 新增目标、轮次检查点、工具执行凭证三类记录，仍用现有聊天 Run 做一次模型/工具循环。不用聊天正文、todo 或历史摘要充当任务状态；普通聊天恢复和摘要语义照旧。目标锁定原始目标、用户认可的验收条件、输入版本引用、工作区以及 Agent/模型引用，不复制供应商密钥。之后每轮和每次执行工具还要走现有权限链，权限变化只可收紧，不能利用旧快照绕过撤权；档案或必要输入失效时停下，不能擅自换模型或改目标。

每轮开始读取最近已提交检查点：已完成项、待办、下一动作、产物引用、工具凭证、历史/摘要边界和剩余预算。下一轮的指令由服务端注入模型视图，不伪造 `user` 消息。先用现有 `max_steps`、上下文保护与单 Run 摘要上限，再加一个 GOAL 轮上限：首版建议 24 个逻辑动作（一次模型请求或一次工具调用各算一个；并行组整组预留额度）。只在工具组闭合后主动换轮；强制中断留下未闭合组时，按工具记录对账，不能把半组送进新模型视图。

模型的交接只提交 `continue / completed / blocked / needs_user` 建议，服务端决定状态。普通正文只算本轮回复。有明确的下一步、仍有预算时可以继续；只给总结、重复原建议或给出未经证实的「已完成」，最多再给一次含未通过验收项的纠偏机会，仍不推进就停。平台主动换轮、摘要后换轮、可恢复网络错误都由同一续办器处理。摘要失败时保留原历史；若老视图已装不进窗口，只能从**已提交的结构化检查点 + 可容纳的完整工具组**重建，并记录换了什么视图。重建不成立就停，不清原始数据、无进展时也不连续开空 Run。`reset_context` 只请求在安全边界换轮，不能清目标、跳过对账或绕预算。

### 持久化与重启

- **创建：** 同一事务写入目标、原始用户消息、首轮待执行记录；客户端重试用请求 ID，同 ID 同请求返回原目标，同 ID 异参拒绝。目标持有会话的服务端准入资格，普通发送/RUN 创建都要核对，不能只禁前端按钮。
- **换轮：** 当前轮终态引用、检查点和续办待执行记录在同一事务中发布；实现中若已有 Run 终态必须先单独落库，则从已持久终态幂等补发，不允许只靠内存回调。`(goal_id, generation)` 唯一；新运行必须先认领记录才开始。检查点写成功后才允许排下一轮，事务失败不继续。
- **启动恢复：** 只扫描 GOAL。已排队或到期可重试的轮重新认领；只从最后一个完成的检查点并结合之后的工具凭证恢复。暂停、待处理、已取消、已完成不自动启动。用执行代次挡住旧线程/迟到回包推进状态；迟到的工具收据可以记账，不能把目标改回进行中。目标卡刷新先取持久状态，再订阅更新，按版本忽略旧消息。
- **并发和时间：** 同一目标只准一个有效轮，暂停、取消、恢复与排下一轮走同一状态转换和版本校验。预算和绝对截止时间持久化，换轮、刷新、重启不重置。停机期间计入截止时间；用户可以显式追加时限。外部调用一旦发出，不能靠过期的执行租约假定它没发生。

### 现有代码怎么接

- 续办仍创建 `kind=chat`，复用现有 `submit_chat` 和事务内活动位检查（`naiba/run/chat.py`、`naiba/storage/store.py::create_chat_run`）；GOAL 的会话占用另做持久校验，不能等新轮启动才挡人工发送。只有首轮创建用户消息；后续轮单独走不写用户消息的入口。Super Agent 的监督续办只作为「建 Run 时绑定轮次」的事务先例，不共享任务身份和自动触发器。
- 现有 Run 的答案、终态、事件分开落库；不能凭某个 `done` 事件推进 GOAL。以持久终态、唯一结算记录和结果凭证对账，普通启动恢复把 Run 标成中断的逻辑不变，之后由 GOAL 对有效轮次单独收敛。刷新或重新打开对话只读状态，不负责派发。历史检查点和 Run 事件可做模型视图或展示，不能充当工具凭证；历史锚点丢失时暂停，不回退到全量历史继续跑。
- 现有确认卡的整轮授权不跨 Run。GOAL 仅缩小当前会话允许的工具范围，不用「完全」档跳过专属工具限制，也不能把进程内确认 ID、普通 `run_in_background` 的活跃任务防重键当作跨重启凭证。GOAL 期间原聊天的停止按钮或快捷键接到目标级暂停，明确取消走目标卡；只取消当前 Run 会被自动续办抵消，不作为界面上的停止动作。若兼容旧客户端允许直接取消 GOAL Run，服务端先把目标标成暂停再取消该轮。
- 新增接口和事件字段先登记 `naiba/core/contracts.py`、`naiba/core/messages.py`，装配留在 `naiba/app.py`。目标状态查询独立返回状态版本、当前/最后 Run 与产物引用；不能从聊天流拼出目标终态，也不能依赖 Run 事件保留期恢复目标。保护好仍被目标引用的检查点、未结算轮次和工具凭证。

### 缓存：正常换轮不主动打断前缀

- 进 GOAL 的第一轮可能和原来的普通对话不共享缓存：GOAL 固定指令或更窄的工具集都可能改变请求头部，不能为了命中保留不该开放的工具。进入后，在权限、模型和历史边界不变时，固定指令、工具定义及顺序、供应商及模型、现有缓存配置都保持稳定。普通对话不加入 GOAL 指令或缓存设置。
- 换 Run 只换执行记录，不清上下文，不因轮次 ID 改缓存标识，不重新拼一份历史。未改变的历史与已闭合工具组按原顺序回放，保持已发送的稳定前缀；阶段、预算、时间戳、Run ID 等默认只留服务端。确实需要让模型看到的交接内容，按实际模型协议放到续接处，不每轮重写前面的 system、工具列表或已缓存的交接内容。已有缓存断点规则继续使用，尤其检查 Claude Messages 的工具序列和 `cache_control`；不要为了凑前缀伪造聊天记录。
- 摘要成功、主动重置或窗口不足时允许重建模型视图，记明原因；这些是前缀可能缩短或变化的边界，不能为了保缓存继续用超窗口的历史。停久、重启或中转路由变化也可能使供应商缓存过期或未命中。这里承诺的是 Cat Chat 不因正常换轮主动破坏可复用前缀，不承诺供应商返回相同命中率，也不承诺整体费用不增加。
- 验收分两步：离线比较实际协议出站内容，而非内存里的消息数组，覆盖普通对话前后对照、同历史同工具的一直执行与强制跨 Run、摘要前后。普通对话请求语义不变，未摘要的正常续轮不应较对照提前截断可复用前缀。再经授权做真实模型小样本，分别记录同轮、跨轮、摘要前后正式请求的总输入、缓存读取/写入 token（协议有则记录）与冷暖状态；摘要请求单列，未回报写未知，不当作未命中，也不把模拟结果写成真实命中。

### 试运行建议值

| 额度 | 建议值 | 到边界怎么做 |
|---|---:|---|
| 单轮逻辑动作 | 24 | 完成当前可安全收尾的工具组后换轮，旧有更低上限照用 |
| 目标期限 / 最大轮次 | 启动后 3 小时 / 32 轮 | 不再启动新动作，保留产物与检查点 |
| 目标实际模型发送 / 工具动作 | 256 次 / 200 次 | 模型预算包含正式请求、摘要、底层重发；工具按实际调度计，不因切轮或重启归零 |
| 可确认的临时错误 / 无进展 | 同一位置最多 2 次退避重试（例如 5 秒、30 秒）/ 连续 2 轮 | 达上限停止并显示原因；新增经验证的产物、推进验收项才算进展，规划文字变化不算 |

这些是首版设计默认值，测试夹具使用独立设置，不把压力测试用的大额度设成用户默认。请求发送前先占额度，能确定未发送才释放；无法判断是否发出的占位不在重启后返还。摘要逻辑 attempts 和实际网络发送分开计数，供应商没报实际用量就显示未知，不能用 token 估算冒充真实费用；没有实际请求计数拦截点的运行路径，不能承诺上表的请求硬上限。普通模型调用仍按供应商原规则计费；目标卡可展开查看请求上限和已用次数，工具产生的额外支出不包含在这里。

## 3. 无人介入到哪一步为止

启动 GOAL 只授权在已选范围里推进。首版明确支持已声明根目录内的只读操作、目标产物写入、能对账的工作区文件编辑，以及注册成固定参数、可隔离的本地验收任务；没有可核对收据的通用 shell、任意 MCP 写操作，以及发布、推送、删除现有资料、向外发送内容、产生额外费用等动作，不在首版自动执行范围。已经允许执行的普通聊天工具也不能自动进入 GOAL。工具不受支持时先走同范围内可验证的替代步骤，必要步骤无替代才停。需要既有工具确认时先停止本轮，把原因记在目标卡；之后也只能经过原批准入口或由用户在外部完成并提供可核对结果。

- **只读：** 允许有界重试，读取的结果不作为授权、预算或验收规则来源。
- **可对账写入：** 调用前登记稳定动作 ID、作用对象和写前指纹，执行后记录写后指纹或产物凭证；本地目标产物优先采用暂存、校验、原子发布。重启后命中期望指纹/收据则采纳原结果；能证明未执行、且当前输入仍符合预期才允许重试。不同动作不能只因参数相同就去重。同一动作重用稳定 ID；模型工具调用 ID 可作为追踪信息，不作为跨轮唯一凭证。
- **已有后台任务句柄：** 继续查结果，不重复提交；等待期间不上模型请求。没有句柄或不能查清是否受理时显示「可能已经提交，需核对」，暂停后续，绝不重发。普通 `job_wait` 通知可以提示结果，不能代替 GOAL 的轮次记录，也不能同时触发一条普通续答。
- **资源冲突：** 已选文件、工作区修改前状态、工具权限或任务句柄不再匹配时停或仅重做可证明无副作用的读取；不静默覆盖用户中途的改动。不自动放宽只读根、追加授权或执行从计划文件里读来的权限指令。

## 4. 什么时候能写「已完成」

启动原文与明确引用的验收清单是依据，读取计划文件时保存版本/哈希。用户明确写的判据或选用的受支持模板才能成为机器验收条件；模型可以拆步骤、推荐检查项和提交证据，不能删改验收项或自行给自己放行。首版支持核对预期产物、内容/结构规则、数量、哈希以及注册本地检查的结果，验收针对最终产物快照，校验结论和证据跟完成状态一起保存。验证器只读，不联网，也不用再问另一个模型「这算不算做好」。

例如「按计划处理资料目录」：应处理 15 份，只交 14 份，它说「已做完」也不会结束。缺的是可补项就继续；最后一份缺原始资料才停下说明。像「润色到读起来满意」这样的主观要求，做到可交付时可以列出产物并显示「待验收」，不会擅自显示「已完成」，也不会为求一个肯定跑空轮。没有可信验收条件的自由目标可以执行已授权工作，交付阶段同样停在「待验收」。

## 5. 实施顺序与验收

1. **等 B2/B3 留存证据。** 先补齐摘要/runtime 实际发送诊断，分别记录当前架构停止点和摘要隔离回归。单 Run 多跑几步不计 GOAL 验收。
2. **先后端，再接 UI。** 契约和迁移先做；用隔离目录和假模型跑创建、停止、轮次恢复和权限守门；接真实工具适配器前验证「发送结果未知不重做」。UI 验收桌面和 375px：从「＋」选 GOAL、标签进入与退出、取消选文件保留草稿、普通和 GOAL 模式都能添加附件、显式发送才启动、卡片更新、切会话、刷新、暂停、继续、取消、待处理、完成。桌面与 375px 分别核对浏览器触发文件选择；手机系统文件界面仍需真机抽验，不能把窄视口测试写成手机实测。
3. **B4 压测单独验。** 一条目标输入，至少 15 次可从库里查到的跨 Run 续接，并交出跨轮实际压缩证据：至少 15 次成功、有效模型视图变短、压缩代次可核对；单纯计数、同一历史反复入账或仅切轮都不算。用同一隔离夹具注入步数上限、近窗口、摘要失败、短期故障、提前说完成、崩溃/重启、重复启动及取消。在「下一轮记录写出但未派发」和「工具执行后、凭证尚未写入」两处专门断进程，分别验重启续接，以及对账后采纳或停下、绝不盲重做。成功场景核对最终阶段清单、产物数量、内容哈希与验收记录；未知副作用另做一条应停场景，不能为了跑成成功用例跳过它。
4. **再补代表性实测。** 用一份隔离的真实实施计划核对首版工具范围和验收方式够不够用；如需真实模型探针另定预算。没有 B4 证据前，交接与原计划继续标未完成。本文只定设计，不改源码、测试夹具、版本或发布产物。
