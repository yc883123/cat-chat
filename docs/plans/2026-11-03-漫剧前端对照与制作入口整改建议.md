# 漫剧前端对照与制作入口整改建议

日期：2026-11-03  
性质：只读调研与产品建议，不是已经批准的实施计划，也不是运行验收报告。

## 一、结论

当前最先要修的不是视觉，而是「第一次使用就能走通」的操作路径。用户进入任务总管后应当能够知道：要做什么、还缺什么、在哪里补、补完怎样继续。

需要区分三个层次：

- **制作任务**：这次要做哪些内容、用哪些素材、做到哪一步、哪些结果需要确认。
- **提词规则**：如何把剧本、图片或分镜写成模型需要的提示词。
- **生成配置**：用什么工作流、模型、输入位置与生成参数。

对外可以用一个「制作方案」组合后两者，但不能要求用户先理解内部组合关系才能开始，也不应把整张工作流参数表搬进总管。

## 二、当前最明确的断点

### 1. 总管能选方案，却不能就地发起新建或编辑

已确认的创建路径是：

```text
离开当前任务总管页面
  → 工作台 / 造梦机
  → 选择已导入的工作流
  → 点击「交给任务总管·制作方案」
  → 切回任务总管
  → 打开「保存为我的方案」
  → 保存后打开新的批量任务弹窗，并选中新方案
```

所以不能笼统说「完全没有实现创建功能」：它有创建实现，但唯一发起点放在另一个模块，用户从选方案的位置走不到那里。也不存在一个可以直接复用、完全独立的「造梦机方案编辑器」；造梦机负责发起交接，方案弹窗实际由总管处理。

保存后会自动选中新方案，这是已有能力；但没有把用户带回原批次并恢复原先素材和输入的完整往返约定。

### 2. 不是所有提示词都缺失，而是规则层的可用入口缺失

- 「直接使用提示词」已有逐项的完整视频提示词输入框。
- 「图片＋剧本」已有剧本输入，后续任务详情也有最终提示词编辑。
- 提词库已有正文非空的 H3 模板；两个内置制作方案也有完整的专用规则。
- 但是自定义方案只有模板名称下拉，没有推荐默认、正文预览以及就地创建／编辑入口。
- 两个内置方案专用模板与普通提词库不是同一组数据，专用模板没有出现在自定义方案的模板下拉中。

因此，不能用「再加一个提示词文本框」概括修复。需要补齐的是：规则来源、适用范围、选择默认、查看／调整、返回继续。

### 3. 两种使用模式仍被同一组依赖束缚

用户已经提供完整提示词时，仍被要求登记不实际执行提词的模型，后端还会校验图片能力。应按使用模式判断必需项：已有提示词只需检查生成能力；需要系统代写提示词时才检查提词规则和模型。纯文本代写也不应无条件要求视觉能力。

### 4. 有比入口隐藏更实质的保存断路

在造梦机改过模型名、LoRA、采样器等文本／枚举字段后，交接给总管会被拒绝，提示先把参数保存进工作流。但造梦机当前「编辑」里的保存只保存参数的显示项与排列顺序，不保存参数值。因此这条提示提供的应用内修复路线走不通；到外部 ComfyUI 修改后重新导入不是它所声称的直接保存操作。

应保留「编辑＝显示项／排序」的既有语义，不能偷偷改变它。需要独立提供「用当前配置另存方案／工作流」能力，并严格验证允许保存的模型枚举与参数，不应为绕过报错直接放开任意文本、路径或代码。

### 5. 其他影响首次使用和恢复的断点

- 自定义方案必须先点「添加一项」才显示剧本／完整提示词输入框，加重了「根本没有输入位置」的第一印象。宜默认给出第一项，或把空态操作做成明显主按钮。
- 自定义方案创建没有保存时长映射，但批量表单仍对所有方案展示 4–15 秒。后端只在存在映射时写入时长，因此该控件不能一律宣称生效；应按能力显示或明确说明沿用工作流。
- 失败项仍显示可编辑输入，已有生成记录时后端却拒绝保存；「复制为新任务」只有提示文案，没有对应动作。应让可编辑范围、重试和另开任务的行为一致。
- 当前自定义方案是内容哈希标识的不可变插入，没有现成完整的方案编辑／删除页。新增编辑宜按「另存新版本」设计，并保留已有任务快照。

### 6. H3 参考生视频被缩成图片子集，必须补正（用户追加反馈）

用户明确指出 H3 Reference to Video 支持最多 9 张图片、3 段视频、3 段音频，参考输入不必填满，不能要求固定图片组合。本节优先于前文仅用「图片＋剧本」举例的狭义表述。

**当前内置方案实际绑定：**

- `naiba/super_agent/recipe_assets/h3_i2v.api.json`：`105_104 / MiniMaxH3ImageToVideo`，一张首帧输入。这是首帧生视频，不是参考生视频。
- `naiba/super_agent/recipe_assets/h3_r2v.api.json`：`136 / MiniMaxH3ReferenceToVideo`，当前只连接六张参考图，没有参考视频／音频输入。
- 来源记录为 `comfyui_workflow_templates_json/templates/video_minimax_h3_i2v.json` 和 `video_minimax_h3_r2v.json`。`provenance.json:67–73` 明确记录参考图模板从官方两图扩为六图，且没有音视频。因此这是基于官方模板加工的内置副本，不能把界面名称里的「官方」当作完整原版或全部节点能力。
- 方案定义 `recipe_catalog.py:56–61` 将参考生视频的第一张图设为必填，其余五张可选；`:97–117` 将其限制在连续 1–6 张。这是本软件额外加的限制，不是 Reference to Video 节点要求。

**实时只读节点证据：**本机 ComfyUI `127.0.0.1:8188` 的 `MiniMaxH3ReferenceToVideo` schema（pack 为 `comfyui-h3-vbar-retry`）确认：

| 输入组 | 可选性 | 数量范围 |
|---|---|---|
| `ref_images` | optional | 0–9 |
| `ref_videos` | optional | 0–3 |
| `ref_audios` | optional | 0–3 |
| `ref_video_audios` | optional，视频配套音轨 | 0–3 |

这些是容量上限，不是待填满的表格。Schema 没有要求至少一张图；零参考媒体是否在具体模型／工作流下成功生成，本轮未执行验证，不能只凭 schema 当作成功实测。

**应补进整改范围：**

1. 参考生视频按「添加图片／添加视频／添加音频」逐项增加，展示容量上限，不默认铺满 15 个必填框，不强制首图、角色图或场景图。
2. 维持 `Picture / Video / Audio` 引用编号与实际已选素材的明确对应；未添加输入不应留下空加载节点、假文件或无效连接。
3. 限制不只在界面：自定义方案前端只枚举图片入口（`public/js/28-super-agent.js:1577–1580`），后端也只接受图片媒体槽并按图片扩展名及 PIL 解码验证（`naiba/super_agent/recipes.py:195–213,252–290`）。内置 `recipe_assets/h3_r2v.prompt.txt:3–5,19` 还写死 1–6 图、禁止音视频引用以及视频编辑／续接类任务。需一并补全媒体类型、素材映射、提词规则及输入、预览审核和执行传递；不能只加上传控件，否则新增媒体仍会被后端拒绝，或被旧规则忽略。
4. 造梦机执行器已有按实时 schema 移除未选可选媒体连接的逻辑：`naiba/comfyui/runner.py:621–666`；总管 `mode=recipe` 由 `:212–216` 转入 `_run_recipe_task`，在 `:437–444` 明确调用同一清理函数，再绑定媒体并校验执行图。内置六图方案仍被前面的业务校验限制。修复应先解除错误的方案层假设，再复用既有可选输入处理。
5. 「首帧生视频」与「参考生视频」保留不同输入要求。首帧方案需要首帧，不代表参考方案也需要至少一张图。

本次追加只读取工作流、来源记录和运行中的节点 schema，未提交生成、未更新 ComfyUI、未修改业务代码。

## 三、两套参考产品各学什么

| 对照项 | 辉映 | 启元 | Cat Chat 建议 |
|---|---|---|---|
| 用户从哪里开始 | 短剧创作／自由创作；短剧以项目、剧集、剧本开始 | 原文改编，或一句话原创；围绕一部作品展开 | 先让用户提供已有内容，不以内部配置名作为起点 |
| 提词规则 | 按阶段内置 Skill，生成模型／工作流与规则关联 | 按创作阶段内置规则；用户主要输入内容 | 默认提供适用规则，允许预览和修改，不把找模板变成前置作业 |
| 自定义生成能力 | 在正在使用的模型选择处可导入工作流，确认输入后立即选用 | 模板、参数、引擎各有用途，但不是通用工作流方案系统 | 在方案选择处提供新建／编辑，复用现有能力，保存后继续当前任务 |
| 内容如何承接 | 同一项目与剧集组织创作及资产 | 原文、人物、大纲、剧本和提示词有取源路径 | 下一步继承已有内容，并明确显示继承来源 |
| 不应照搬 | 命名约定和特定工作流映射要求；文字指路不等于可返回的导航 | 模板套用与重新生成语义易混，部分跨阶段代码存在承接疑点 | 借鉴交互原则，不复制私有代码，也不把静态功能列表当可靠闭环 |

这两套参考实现都不能被描述成「从任意输入全自动生成完整成片」：辉映观察到的短剧入口从已有剧本开始；启元的 H3 功能主要生成提示词，不能等同视频执行。

## 四、推荐整改顺序

### 第一轮：只打通自定义方案的完整往返

1. 在总管的方案选择旁提供 **「新建方案」和「编辑方案」**。空列表也要有明确的创建按钮，不能只提示去别处配置。
2. 新建时先选 **「基于已有方案」或「使用我的工作流」**；已有工作流直接选择，没有才转到导入。
3. 复用现有方案创建逻辑和造梦机工作流能力，不新增第二套工作流参数存储。
4. 提词方式明确为：
   - **让系统帮我写提示词**：选择适用的默认规则，可查看正文、复制后修改或新建；不静默选择与工作流不匹配的 H3 规则。
   - **我自己提供提示词**：不强制提词模板／提词模型，保留最终提示词编辑能力。
5. 跳转去导入工作流或调整规则时保留当前任务草稿，至少包括素材、剧本／提示词、批次、模式和已选项。
6. 主按钮写 **「保存并继续当前任务」**；保存成功后自动选中方案，恢复原草稿，而不是重新开一份空任务。
7. 缺项展示为可执行动作，例如「还没有选择工作流 — 选择／导入」「需要代写提示词 — 选择规则」「模型未配置 — 去设置」。
8. 规则与工作流的组合要校验所需输入和输出格式；普通 H3 模板不等于适用于任何 H3 工作流，不能仅按名称自动配对。编辑／另存是否已有后端支持需要实施前确认。
9. 保留已有任务的执行快照边界：修改方案默认只影响之后新建的任务，不暗中替换已经执行中的模型、规则或参数。模板来源、版本和本次最终提示词要可追溯。

### 第二轮：整理制作主线，不再堆独立入口

以下是目标结构，不代表这些交接现在已全部实现：

```text
原文／创意／已有剧本
  → 剧本与分镜
  → 角色、场景和参考素材
  → 本批提示词
  → 图片／视频生成
  → 审看、补做与整理产物
```

用户可以从已有成果对应的位置进入，不需要每次从头开始。角色／场景准备和分镜可以往返，不应为了流程图强行锁成单向步骤。

任务总管负责进度、缺项、确认、批量控制与产物关联；工作台保留专业编辑能力。每次进入工作台都应携带当前任务和素材上下文，并提供回到原任务的操作。

任务进度、提词规则和工作流配置是不同对象；不应混成同一个含糊的「方案」下拉，也不应拆成用户必须来回拼装的几座孤岛。

## 五、建议的验收标准

1. **首次使用、没有自定义方案**：从任务总管就能新建；不依赖用户提前知道造梦机的隐藏入口。
2. **已有工作流、没有合适规则**：能查看默认规则或新建规则；保存后返回当前方案，不丢工作流选择。
3. **已经有完整提示词**：不要求再登记不使用的提词模型；仍能查看并修改每项提示词。
4. **已经填了一批素材**：进入方案／规则／工作流设置后返回，素材、文本、排序与模式不丢失。
5. **保存方案后继续**：当前任务自动使用新方案，不意外另开空任务，不自动启动付费生成。
6. **复用内置方案**：能基于内置方案另存，规则来源清楚，不因模板不在另一个列表中而卡住。
7. **依赖不足**：逐项说明缺什么并给修复入口；修复后恢复任务上下文。
8. **专业参数**：仍由现有工作台承载；总管只让用户处理必要输入和阻断项。
