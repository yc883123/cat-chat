## 一、一句话目标

把《启元提示词助手》的「**原创小说模式**」（从零写一本自己的书）搬进 Cat Chat，**作为工作台第五个功能页**，与提词库 / 打标器 / 造梦机 / 拆书匠并列；同时把现有的第四个功能页「创作场」改名为「**拆书匠**」，让两条线的分工一眼看清：

| 板块 | 输入 | 干什么 |
|---|---|---|
| 拆书匠（原「创作场」） | 别人的一本 TXT | 拆章 → 要素 → 大纲 → 剧本 → 分镜（改编） |

## 四、产品形态（第五页）

### 4.1 定位

- **第五个功能页**，与提词库 / 打标器 / 造梦机 / 拆书匠并列进左侧竖向分页导航（不是拆书匠里的一个阶段）。
- 页面壳沿用拆书匠：`页面头（标题 + 当前作品与阶段 + 全局操作）` + `阶段条` + `三栏（作品与目录 / 当前阶段工作区 / 这次会做什么）`。视觉基准是物理预览稿 `_writer_mockup.html`，四档视口截图已过（含横 `844×390`、竖 `390×844`、浅色深色）。
- 阶段导航按创作顺序固定为：**设定 → 大纲 → 正文**（预览稿三档；是否加第四阶段见 §十四 待拍板）。

### 4.2 三阶段做什么

| 阶段 | 输入 | 输出 | AI |
|---|---|---|---|
| 设定 | 题材 / 基调 / 视角人称 / 章节数 / 一句话创意 / 参考作品 / 雷区 | **设定包 vN**：书名候选、人物卡、世界观、主线钩子、写作约束 | 有（一个 Studio 任务） |
| 大纲 | 选定的设定包 + 结构模板（三幕 / 四段 / 纯章节推进）+ 每章详略 | **章节梗概表**：每章 N 句，可逐条改，改完各自成版本 | 有 |
| 正文 | 本章梗概 + 设定包压缩稿 + 最近 3 章摘要 + 上一章结尾 | **正文 vN**，按章写、可重写、可续写下半章 | 有 |

### 4.3 与拆书匠的三条边界

| 维度 | 拆书匠 | 写书匠 |
|---|---|---|
| 有没有源文件 | 有（用户导入的 TXT） | **没有**，作品由 AI 逐章生成出来 |
| 章节从哪来 | 从原文拆出来、勾选保留 | 从大纲生成的「待写」条目，写完才有正文 |
| 抄写关系的方向 | 原文 → 改编稿（原文永不被覆盖） | 设定包 → 大纲 → 正文（上游改动不回溯改写下游，只提供「重新生成」） |

## 六、数据模型

新域独立目录，避免「无源文件的原创作品」混进「由 TXT 拆出来的作品」：

```
data_dir/studio/writer/<work-id>/
├── work.json         # {schema_version:1, revision, id, title, source:{type:"original", idea, ...},
│                     #  chapter_ids[], current:{setup_version, outline_version}, created_at, updated_at}
├── setup.json        # 当前设定包 {revision, versions:[{id, created_at, model_key, model_name, body}]}
├── outline.json      # 大纲 {revision, structure, versions:[{id, ..., acts:[], items:{章号: 梗概}}]}
├── summaries.json    # {章号: "本章首尾片段摘要"（零额外推理，照 prompts.summarize_chapter 口径）}
└── chapters/
    ├── 0001.json     # {schema_version:1, revision, i, title, outline, versions:[{id, created_at, model, body}], current_version}
    └── ...
```

沿用《总计划》§5.2 的持久化规则：单文件一章、原子写（同目录临时文件 + `os.replace`）、`_safe_path` 越界校验、`revision` 乐观并发、容量上限集中定义。
与 `studio/novel/` 只在 **tab 分区统计** 上并列，互不读写。

## 八、提示词与长文策略

1. **设定包常驻**：写每一章时都注入系统提示词（书名/人物卡/世界观/写作约束的压缩稿，的目标 ≤ 800 字），解决长篇最容易出现的「人名跑了、设定忘了」。
2. **滚动摘要链**：沿用 `prompts.summarize_chapter`（零额外推理：首 120 + 尾 220 字），每写成一章即写入 `summaries.json`，下一章只带最近 3 章摘要 + 上一章结尾原文。
3. **上一章结尾必带**：只靠摘要容易衔接不动，**上一章最后一段原样接上**（预览稿右栏写明「上一章结尾 220 字」）。
4. **分块生成**：单章目标字数超过模型可写长度时，复用已有能力的分块续写（《创作场阶段四》已落地，最多 20 块），最后一字不明确丢。
5. **阈值集中一处**：`naiba/writer/prompts.py`（新）或复用 `naiba/novel/prompts.py`——见 §十四 待拍板第 3 条。倾向**新建域**（理由见 §十四 第 3 条）。
6. **重复句式告警**：只是提示（把两段原文摆出来让人点开对照），**绝不自动改稿**。
