## 一、消息全文搜索 ✅ 2026-09-17

### 1.1 后端

新增只读接口，薄包装复用现成能力，不改存储层逻辑：

- 路由：`GET /api/search/messages?q=<关键词>&conversation_id=<可选>&limit=<可选>`
- 实现：`naiba/http.py` GET 分支新增一路，调 `storage.search_history`（`naiba/storage/store.py:1078`，`instr(lower())` 子串匹配，全库/限定会话两模式现成）。
- 返回（在 `search_history` 结果上裁剪为 UI 友好结构）：
  ```json
  {
    "query": "...", "total_hits": 12, "truncated": false,
    "hits": [
      { "conversation_id": "...", "conversation_title": "...",
        "message_id": "...", "role": "user", "ordinal": 8,
        "snippet": "...命中前后各约 60 字...", "created_at": 1726... }
    ]
  }
  ```
- 参数约束：`q` 空 → 400；`limit` 默认 30、上限 50；`conversation_id` 给了但不存在 → 404。
- `search_history` 现有返回带 `in_context` 标注（给模型用的），UI 接口保留该字段，前端可用「已划出上下文」弱化显示。

### 1.2 前端

- **入口**：侧栏现有搜索框（`index.html:43` `workspaceSearchInput`）升级为双模式：输入框左侧加小型切换「标题｜全文」，默认「标题」（现有行为零变化，`08-conversations.js:248/:271` 的本地过滤不动）。
- **全文模式**：输入防抖 300ms 调接口；结果列表**替换**会话树区域渲染（会话标题 + 片段 + 时间，命中词高亮 `<mark>`）；Esc 或清空关键词退回会话树。结果区头部显示「共 N 条命中（截断则明示）」。
- **跳转**：点命中项 → 打开该会话 → 按 `message_id` 定位：
  - 复用现有懒加载扩展：`index = state.messages.findIndex(m => m.id === hit.message_id)` → `ensureMessageRendered(index)` → `querySelector([data-message-id])` 取行（此模式在 `04-messages.js:403` 已有先例）→ 滚动到视口中心（沿用 `scrollToTurn` 的居中算法，不用 scrollIntoView 避免贴边）。
  - 定位后行级高亮 2 秒（CSS animation，只加 class 不改结构）。
- **手机端**：同一入口同一面板，不另做形态（侧栏在手机上本就是抽屉）。

### 1.3 边界

- 空结果显示「没有找到包含「X」的消息」。
- 大库性能：全表 `instr` 扫描在十万条消息级为毫秒~百毫秒，可接受；接口显式返回 `truncated`，不静默截断。FTS5 留作后续升级路径，本期不做。
- 搜索期间切换工作区/会话不取消已发出的请求，但渲染前校验当前仍处全文模式（防竞态错位）。

### 1.4 测试

- 单测（新 `tests/test_message_search_api.py`）：空 q 400、限定会话 404、命中片段与 total_hits 一致、limit 截断标记。
- 冒烟：隔离实例 + Playwright——造 3 会话含关键词 → 全文搜索 → 断言结果列表 → 点击跳转会话并定位高亮 → 截图。

## 二、分支导航 ✅ 2026-09-17

### 2.1 DB 迁移（v17 → v18）

- `naiba/storage/store.py`：`CURRENT_SCHEMA_VERSION` 17→18，迁移函数追加：
  ```sql
  ALTER TABLE conversations ADD COLUMN branched_from_id TEXT NOT NULL DEFAULT '';
  ALTER TABLE conversations ADD COLUMN branch_message_id TEXT NOT NULL DEFAULT '';
  ```
- **存量分支会话为空串 = 无来源记录，不回溯**（按标题 `(N)` 弱推断不可靠，明确不做）。迁移前后全量单测须无新增失败。

### 2.2 后端

1. `branch_conversation`（`store.py:1278`）：INSERT 时写入 `branched_from_id = source_id`、`branch_message_id = message_id`（INSERT 列清单同步加两列）。
2. 会话列表/详情返回补充字段：`branched_from_id`，以及 `branch_count`（`SELECT COUNT(*) FROM conversations WHERE branched_from_id = ?`，列表查询时一次性 GROUP BY 带出，避免 N+1）。
3. 新接口 `GET /api/conversations/{id}/branch_chain`：
   - 若该会话是分支：返回源会话 + 全部兄弟分支；若该会话是源：返回其全部分支；两者都没有：返回空链。
   - 每项 `{ id, title, created_at, updated_at, is_current, branch_message_id }`；源会话已删除时 `source_deleted: true`（`branched_from_id` 悬空不报错）。

### 2.3 侧栏渲染（决策已定：平铺 + 徽标，不做树形）

**不选树形的理由（决策记录）**：树形与 `updated_at` 排序根本冲突（分支一更新就脱离源会话位置）；多级分支会破坏虚拟化列表的行索引；用户诉求是「认得出、跳得过去」而非看层级。

- **分支徽标**：`branched_from_id` 非空的会话，标题行左侧加 `⑂` SVG 小图标，悬停 tooltip「分支自《源标题》」（源标题随列表数据带下，无需额外请求）。
- **源会话计数**：`branch_count > 0` 的会话，标题行右侧显示 `⑂N`（弱化小字）。
- **分支链面板**：点击徽标/计数 → 调 `branch_chain` → 弹小面板（fixed 挂 body，复用「⋯」菜单定位模式）：源会话（若有）+ 兄弟分支按创建时间正序，当前会话高亮，点任意项 `openConversation` 跳转；`source_deleted` 时源位置显示「源会话已删除」置灰项。
- **排序/分组/收藏逻辑零改动**；虚拟化行结构只多一个可选图标节点，行高不变。
- 源会话被删除：`branched_from_id` 悬空保留（不清空），徽标 tooltip 显示「源会话已删除」。

### 2.4 测试

- 单测（新 `tests/test_branch_chain.py`）：迁移幂等（v17 库直升 v18 两列存在且为空串）、branch 写入两列、branch_count 正确、branch_chain 三种角色（源/分支/无关联）、源删除后 `source_deleted`。
- 冒烟：分支一个会话 → 源出现 `⑂1` → 分支出现徽标 → 点徽标面板互跳 → 截图。

## 三、删除单条消息 ✅ 2026-09-17

### 3.1 语义与缓存结论（已定）

删除 = 从模型上下文剔除 + 界面移除。缓存结论：**不破坏前缀缓存机制**——删除点之前逐字节不变照常命中，之后的内容一次性重缓存（与「分割线换前缀」同模式，比「编辑」丢 tail 便宜），删尾部零成本；撤销按原字节插回后旧缓存可重新命中。确认框按此分级提示。

### 3.2 后端

- 路由：`POST /api/messages/delete`，body `{ conversation_id, message_id, mode: "single" | "turn" }`（与 `/api/messages/edit` 同风格，http.py:827 附近）。
- `storage.delete_message(conversation_id, message_id, mode)`：
  - `single`：删该 id 一行。`role='session'` 的遗留标记行拒绝（那是分割线的旧形态，走 `delete_session_start` 口径，防止误删）。
  - `turn`：仅当目标是 user 消息可用——删该 user 消息 + 其后**紧随的连续 assistant 消息**（直到下一条 user 或末尾；session 标记行也一并带走，它属于这一轮的痕迹）。
  - 返回被删消息**完整快照数组**（id/role/content/metadata/created_at，按序），供撤销插回；消息不存在 → 404。
  - 事务内删除 + 推进 `conversations.updated_at`（与 `truncate_from_message` 同口径，前端轮询自然感知）。
- **不级联删附件文件**：附件仍被「已删除」以外的消息引用时不受影响；不再被引用的附件交给现有缓存自动清理（其 15 分钟保护窗口 + 引用保护逻辑不变）。

### 3.3 前端

- **按钮**（`04-messages.js messageElement`）：
  - user 消息操作区：「编辑 · 分支 · **删除**」。
  - assistant 操作区：「复制 · 重新生成 · **删除** · 新会话」。
  - 运行中隐藏（与现有按钮同口径，`.conversation-running` CSS 已有）。
- **确认框**（复用「重新生成」的确认组件）按位置分级：
  - 目标是 user 消息：两个选项——「连同 AI 回复整轮删除」（默认推荐）/「仅删这一条」。
  - 之后无消息：直接提示「删除后可用撤销恢复（10 秒内）」。
  - 之后还有 N 条：追加「该消息之后还有 N 条消息，删除后下一轮对话会重建一次缓存（一次性成本）」；消息带图附件时再追加「图片会随后续消息重新发送」。
  - 消息 metadata 带 `session_start`（是分界线所在条）：追加醒目提示「此消息带有新会话分割线，删除后其之前的内容将重新进入上下文」。
- **撤销**：删除成功后 toast「已删除 · 撤销」挂 10 秒——快照（含 mode 删掉的全部行）暂存内存；点撤销调 `POST /api/messages/restore`（新接口，按快照原 id/content/metadata/created_at 逐行 INSERT 回去）。
  - 已知边界：rowid 重新分配，同毫秒邻居的次序可能交换（概率极低，仅影响同毫秒两条消息的相对显示序，模型侧字节序由 `(created_at, rowid)` 重排——接受并在维护说明记录）。
  - 快照只存内存：刷新页面后不可撤销（toast 文案写明）。
- 删除/撤销后按现有 `syncCurrentConversation` 重渲染即可（`updated_at` 已推进）；**正在编辑该会话其它消息时**沿用 2.6.3 的编辑现场复挂机制，无需特判。

### 3.4 边界（逐条对策）

| 边界 | 对策 |
|---|---|
| 删除带 `session_start` 的消息 | 确认框醒目提示；删除后上下文起点前移属用户显式选择 |
| 删除发起后台任务的消息 | 任务面板归属锚在 `background_tasks`，不依赖消息；产物挂回现有行为是写回失败记 warning 放弃（`job_media.py:89-91`，不崩）——MVP 接受，产物仍可在任务面板查看 |
| 附件引用计数 | 不级联删文件；撤销窗口 10s 远小于自动清理 15 分钟保护窗口，窗口内文件不会被清 |
| 被分支复制的消息 | 分支会话是独立副本，不受影响 |
| 会话只剩删除后 0 条消息 | 允许，回到开始页空态（与「清空会话」殊途同归） |

### 3.5 测试

- 单测（新 `tests/test_message_delete.py`）：single 删中间/尾部、turn 删 user+连续 assistant（遇下一条 user 停）、session 行拒绝/随轮带走、快照可完整 restore、restore 后 `build_model_history` 输出与删除前逐字节一致（缓存红利守门）、`updated_at` 推进。
- 冒烟：造 6 条消息 → 删中间一条（确认框文案断言含「之后还有 N 条」）→ 界面消失 → 撤销恢复 → 删整轮 → 截图。
