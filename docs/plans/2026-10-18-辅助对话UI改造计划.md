## 1. 目标（三条，按本人决策）

1. **UI 回到主对话同款**：消息复用主对话的 `.message-row / .message-card`，不再是自己一套左右气泡；
   只读约束照旧（后端锁死，不动）。
2. **工具可见**：辅助对话是**真的会调工具**的（只读白名单），但界面上完全看不见——必须让它看得见。
3. **独立供应商 + 独立模型**：面板底部自己选 API 供应商、自己选模型，不再受顶栏/左侧供应商牵制。
4. **跟随主对话**：辅助窗记住是从哪个主对话旁边开的，面板顶部显示「跟随：xxx」；切主对话时自动切到它的辅助窗。

## 6. 风险与开放项

1. **`messageElement()` 的头像**：它取 `currentAgentAvatarUrl()` = 当前主对话 Agent 的头像。辅助对话共用同一个 Agent，
   视觉上一致；若将来辅助要独立 Agent 再另说。
2. **拉真实消息的那一次请求**：`GET /api/conversations/<id>` 会带全部历史消息，长会话有体积成本。
   初版直接拉（简单、零后端改动）；若实测慢，再考虑后端给一个「只回最后一条」的端点。
3. **工具卡在 380 宽里展开很长**：`tool-run pre` 现 `max-height: 220px`。窄面板下可能要收到 140px。
   （＝之前问你的"展开到多细"，先按完整做，看完真机再收。）
4. **切主对话时自动切辅助窗**：若当前主对话没有辅助窗，面板会变空态——要不要在这里给一个
   「为这个对话开一个」的按钮？初版空态已经有「＋ 开一个辅助对话」，够用。
5. **`parent_id` 只用于"跟随显示"**，**不改变上下文隔离**：辅助对话仍然读不到主对话的历史（后端 `conv_kind='aux'` 隔离不变）。
   这条要在 UI 文案里说清楚，别让人误以为它能看到主任务。
