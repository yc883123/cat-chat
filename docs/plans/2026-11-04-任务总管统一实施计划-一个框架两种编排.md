## 二、目标架构

### 2.1 一个框架、两种编排

| 层 | A 类 · 本地批量（`executor_type=recipe_batch`，改） | B 类 · 写小说 / 拆书匠 / 自动对话 / 子助手（不动） |
|---|---|---|
| 入口 | 启动台类型卡 → 现有批量 dialog；详情按 `data-flow=batch` 渲染 | 现有 `domain` / `supervised` 路由与审批 |
| 编排 | **轻编排**：item 级快照 + 一次范围确认 + 静默预检 + 逐组独立 + 就地缺项提示 | **事务编排**：token 预算 / 轮次上限 / 逐阶段审批 / 工具审批 / `human_boundary` / 幂等 |
| 执行底座 | **共用、不动**：`naiba/comfyui/client.py`、`runner.py` 提交与 `_validate_recipe_graph`、素材上传、`params.py::scan_params` / `schema.py::enrich_slots`、工作流 store | 各自服务，不共用 |
| 正确性护栏 | 保留幂等、提交结果未知冻结、结果回收（理由＝时间 / 显存 / 结果正确性，非金钱） | 全部保留 |

**分流点已存在**：`RECIPE_EXECUTOR_TYPE = "recipe_batch"`（`naiba/core/contracts.py:615`），`naiba/super_agent/adapters.py:82-84` 按 `executor_type` 严格路由；前端 `public/js/28-super-agent.js` 已有 recipe 分支。实施是「在这一层换编排」，不是「再建一层」。

### 2.2 明确不做

- 不新建「本地批量框架」、不另造参数扫描 / 类型系统（母本 §5.1）、不另造生成通道（切片计划 §2.3）。
- 不把 A 类从总管里拆成独立页面；不改六类任务列表的入口层级之外的骨架。
- 不改 B 类任何行为；不为 A 类减负去动 `supervised.py` 预算、`domain.py` 审批、`super_agent/store.py` 通用幂等。
- 不迁移历史批次、不补授权、不自动复活旧任务。

### 3.1 交接带值口径（本人 23:30 拍板、23:33 澄清，已定）

> 本人原话：「造梦机调的参数有时候工作流自带素材路径，提示词文本，这种一定不要带过去」「真正定下来用什么素材一定是在任务总管」。

**角色分工**：造梦机定「工作流长什么样、参数怎么设、**哪个节点是素材入口 / 时长槽 / 提示词槽**」；任务总管逐组定「**选哪个文件、写哪段文字**」。**值与结构必须分开**：造梦机侧不留任何默认文件 / 默认文本的采用通道，但已识别好的槽位定义必须完整交接。本人 23:33「真正定下来用什么素材一定是在任务总管」指的是**选哪个文件**，不是让总管重新猜哪个节点是素材入口。

| 类别 | 交接是否带 | 落地规则 |
|---|---|---|
| 工作流结构 / 节点图 | **带** | 按冻结快照；但需剔除或显式标注图里自带的素材路径与文本默认值，不得静默生效 |
| **槽位定义 / 参数映射元数据**（造梦机 `enrich_slots` 后的 `params`：`node_id` / `field_name` / `field_type` / `role` / `label` / `control` / `media_optional` / 枚举 / 单位，及其确定的 `prompt_slot` / `duration_slot` / `media_slots`） | **必须原样带**（09:08 修订，原稿漏写） | 这是「**往哪填**」的结构信息，不是「填什么」的值。总管直接采用，**不再自己 `scan_params` 静态重扫、不再用正则猜时长**；仅当缺失才回退自动派生并在界面明示 |
| 纯参数（数值 / 布尔 / 枚举 / seed / 时长 / 分辨率档位） | **带** | 当前调整优先、未改则用已保存值；沿用 Q3 二选一，但**范围收窄为纯参数** |
| 纯参数（数值 / 布尔 / 枚举 / seed / 时长 / 分辨率档位） | **带** | 当前调整优先、未改则用已保存值；沿用 Q3 二选一，但**范围收窄为纯参数** |
| **素材文件路径**（工作流自带默认值、造梦机当前选的 `media_inputs`） | **一律不带** | 总管每组素材从**空**开始，由用户逐组上传 / 选择 |
| **提示词正文**（图里保存的、`recipeSlotValue` 取到的、表单当前写的、混进 `overrides` 的 text 值） | **一律不带** | 总管每组提示词从**空**开始；`overrides` 按字段类型白名单过滤，排除 `text` 与媒体类 |
| 每组条数 `shots` | **带** | 作为批次默认值，逐组可覆盖 |

**必须同时堵住三个隐性入口**：

1. `24-comfyui.js:294` 的 `media_inputs`（造梦机当前选的**素材文件值**）——交接 body 不传。**注意不要连带丢掉 `params` / `media_slots`（槽位定义）**，那是另一类信息（09:08 事故点）。
2. `24-comfyui.js:1884-1903` 的 `collectOverrides()` 会无条件收 `text` 字段——带参数时按 `field_type` 白名单过滤，只带纯参数。
3. 工作流 `prompt` 图里 LoadImage 节点的默认文件名 / 文本节点默认内容（阶段 0 盘点：W1 的 9 个图槽中 3 个带上次使用的默认文件名）——`24-comfyui.js:1907` 注释「其余按工作流原本的值执行」说明执行端会沿用；**交接建快照时必须清空或标「未采用」**，不能在总管出片时生效。

**交接弹窗文案同步改**：现在的「✓ 正文 ✓ 素材」是误导，改为明确写「参数已带入；素材与提示词请在任务总管逐组填写」。

**撤回**：裁决稿 §二 与本文旧版「原样带当前值 / 全带当前值 / 不做二选一」的推荐一律作废。Q3 二选一**保留**，但只针对纯参数，不再涉及素材与提示词。

## 四、视觉基线：两份预览稿怎么落

两份都是**单文件离线评审稿**（带场景工具条与真实 DOM 自检，非产品代码）。落地是把它们的**组件结构与样式规则**迁到 `public/index.html` / `public/styles.css` / `public/js/28-super-agent.js`，**不得整份搬入产品**，也不得把预览工具条、示意任务名、8 组假数据打进正式界面。缩略图保持 CSS 占位，不使用 `data/generated` 真实产物图。

### 4.1 直接采用

- **统一壳**：三栏骨架、标题 / 状态 pill、操作区、三个指标卡（口径随类型变）、时间线、右栏「下一步 / 最近产物 / 相关入口」、深浅主题与 375px 规则、状态色语义。
- **差异化只落 `#contentZone`**：不整页换皮、不给每类换主题色、不靠类型名猜视图；字段缺失或历史任务回退通用视图。
- **路由依据用现有字段**：`domain` / `mode=recipe` / `supervision` / `executor_type`，不新增猜类型逻辑。
- **批次芯骨架**：本批概览、组卡网格、素材计数、状态徽标、逐组主按钮，以及「哪组准备好就先确认哪组，不等整批」这句口径（正好对应逐组独立）。
- **B 类内容区原样采用**：writer 四阶段轨道 + 章节网格、novel 五阶段（import / review 标为关卡）、chat 轮次时间线 + 完成标准、job 只读镜像、subagent 指令 / 分工 / 待确认操作——因为 B 类编排零改动。
- **弹窗沿用 `.sa-dialog` 三段式**与 620–760px 尺寸阶梯、窄屏全屏与安全区规则。
- **验证基线**：稿一 19 项、稿二 21 项 headless 自检（含真 375px、深浅主题、无 pageerror）；落地后必须按同等口径复跑，不能只截图目测。

### 4.3 三芯 ↔ 两种编排的映射（避免概念打架）

- 稿一「一壳三芯」的 **chain / batch / loop 是展示结构**，稿二「六类」是内容区实例，两者不冲突。

### 5.1 任务删除：单个 + 批量（本人 23:41 新增范围）

**现状（已核源码）**：任务只增不减。`renderThreadList()`（`public/js/28-super-agent.js:146-162`）每条只有一个 `<button>`；`naiba/http.py` 的 GET / POST 路由清单里**没有任何 DELETE / archive 路由**；前端无删除按钮、无多选、无全选、无批量操作条。现有只有「取消」（`:852`，确认文案明写「已产出的内容不会删除」）。

**好消息：底层软删除能力已齐，不用新建数据模型**

| 已有 | 位置 |
|---|---|
| `archived` 状态；`THREAD_TRANSITIONS` 几乎所有状态可 → `archived` | `models.py:18, 66-76` |
| `list_threads(include_archived=False)` 默认过滤归档 | `store.py:349-355`、`service.py:43` |
| `update_thread(status="archived")` 自动写 `archived_at` | `store.py:392-394`、`models.py:111` |
| `app.api_super_agent_threads()` 默认不带归档 | `app.py:997-998` |

→ 只需接出 HTTP 动作 + UI，不新增表、不改 schema。

**定稿设计（安全口径；若本人要硬删除再说）**

1. 「删除」＝**软删除（归档）**。不动产物文件、批次、事件、审批、关联会话；保留执行事实。
2. **单个删除**：每张任务卡右侧一个删除按钮；二次确认写明「任务将从列表移除，已生成的文件仍保留在磁盘」。
3. **批量删除**：列表进多选态（勾选框 + 全选 + 「已选 N 项」操作条），确认一次；**逐项独立提交**，部分失败单独列出，成功项不回滚。
4. **运行中 / 停止中不可直接删**：`stopping` 在状态机里只能 → `cancelled` / `needs_recovery`（`models.py:71`），故须**先取消再删**；UI 给「先取消」入口，不静默跳过。
5. **「已归档」视图 + 恢复**：列表加第四个筛选（走 `include_archived=True`），可查看、可恢复。**注意**：`archived` 当前是终态（`models.py:76` 为空集），恢复需新增状态迁移 ⇒ 属改契约，按维护说明 §4 登记 + 补状态机守门测试，**不得绕过状态机直接改库**。
6. **权限与并发**：所有写操作带 `owner_id` 校验与 `expected_version`；批量不做整批原子，避免一项失败拖垮全部。
7. **前端实现坑（必须避开）**：现在列表项是单个 `<button data-super-thread>`（`:158-161`），**不能在其中嵌套删除按钮**（HTML 非法）。改为外层 `<div>` 容器 + 内部主按钮与删除按钮，事件委托里 `stopPropagation`，否则点删除会顺带切换选中任务。
8. **六套内容区共用**：删除入口挂在统一壳/列表层，六类任务一套实现，不给每类各做一个。

**涉及文件**：`naiba/http.py`、`naiba/app.py`（新增删除 / 归档 / 恢复路由）、`naiba/super_agent/service.py`（批量归档方法）、`naiba/super_agent/models.py`（恢复所需迁移，若做）、`naiba/core/contracts.py`（登记新契约）、`public/index.html`、`public/js/28-super-agent.js`、`public/styles.css`、`tests/`（状态机 / 权限 / 批量 / 恢复守门）。**B 类行为仍零改动**，删除只作用于任务列表层。

**验收**：单个删 → 列表消失、详情清空、产物文件仍在；批量删 N 项 → 全部消失、部分失败有明确清单；运行中删被拦并给「先取消」；已归档视图可查可恢复；刷新 / 重启后一致；375px 操作条不溢出；写小说 / 自动对话任务删除同样可用，预算 / 审批 / 轮次记录不丢。

## 附录 A · 上传素材入口（第 3 条，本人 23:41 拍板按推荐定案）

**它是什么**：在任务总管**某一组**里把图片 / 视频 / 音频放进去的操作界面——按钮长什么样、点开是什么、挂在组卡哪里、一组能放几种。不是独立功能，是「一组素材」这个动作的落点。

**为什么和第 6 条是一件事的两面**：第 6 条定了「造梦机不带素材、总管逐组定素材」，于是这个入口成了整条链路**唯一的素材来源**，它怎么设计直接决定好不好用。

### 定稿结论（A1–A6 全部定案，不再待拍板）

| # | 定案 | 说明 |
|---|---|---|
| A1 | **建完任务后在组卡里逐组放** | 建单时只定工作流 / 参数 / 条数；建完直接落在第 1 组，可继续逐组添加 |
| A2 | **按工作流真实槽位自动列** | W1 ＝ 9 图 + 3 音、无视频槽；不统一给三个固定入口，不要求填满。**槽位定义取自造梦机递过来的增强 `params`，总管不得自行静态重扫**（09:08 修订） |
| A3 | **造梦机自带的旧文件完全不显示** | 符合第 6 条「一定不要带过去」。交接摘要给一行「工作流自带 N 个默认值已忽略」，让用户知道是被有意忽略、不是丢了 |
| A4 | **组卡上「＋ 添加素材」按钮为入口，点开后支持拖拽 / 从素材库选 / 目录批量导入** | 三种方式并列，不各占一块常显区域 |
| A5 | **自动按槽位列出，取消手工「添加素材入口」** | 对应裁决 A2（删手工映射）；歧义用途才弹一次确认并按指纹记住。**取消的是「用户手工指认」，不是「交接槽位定义」**（09:08 修订） |
| A6 | **375px 组卡内折叠，点开走 `.sa-dialog` 全屏弹窗** | 沿用既有三段式与安全区规则，不另造手机布局 |
