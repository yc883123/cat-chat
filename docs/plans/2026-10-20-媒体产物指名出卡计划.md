# 媒体产物「指名出卡」实施计划

## 1. 目标与决定

用户明确要求展示某个已存在的图片、视频或音频时，将**唯一匹配的文件**作为当前助手回复的媒体卡片呈现；不明确、没有匹配或有多个匹配时先询问，不猜测、不随机出卡。

决定：新增专用 `show_media` 工具；不修改 `list_directory` 的范围过滤/意图门禁；不把 `show_media` 加入 `READONLY_TOOLS`，也不向辅助对话或 Plan 暴露。普通主对话中只接受当前工作区明确路径，或当前会话已记录媒体的精确引用。当前全部 6 个内置预设 Agent（`tutor / master / director / prompter / coder / skills`）都要显式启用它；升级时幂等补入用户配置里的内置 Agent 覆盖项，并补入这些 Agent 的既有主会话工具快照，保证老用户更新后马上可用。只追加 `show_media`，保留其余用户工具选择。此范围避免把辅助对话中读取宿主缓存后复制大文件的能力误称为只读。

工具调用必须同时通过两道独立门槛：

1. **用户意图门**：RunContext 基于本轮用户原文标记明确的正向展示请求；否定、假设、引用/转述和仅提及媒体不放行。匹配不确定时不调用工具。
2. **目标授权门**：工具路径必须与当前轮可验证的已知媒体候选一致，候选只能来自当前对话已记录的媒体附件/工具产物与当前工作区内明确给出的路径；不能靠扫描全工作区补候选。相对路径按本轮冻结工作区解析，解析后必须仍在工作区内，且文件存在、后缀属于受支持媒体类型。

模型的自然语言推理不是安全边界。即使模型误调工具，后端意图门和目标门仍须拒绝，不得产出媒体记录。唯一匹配是硬要求；模糊代词有且只有一个可验证候选才允许展示，零个或多个都拒绝并返回可供模型澄清的原因。

## 2. 现状与原因

- `list_directory`、`search_files`、`grep` 的媒体提取采用 `intent_gated`，只适合在用户明确要求浏览时列出范围内媒体；`scope_dirs` 是防止共享工作区旧媒体混入的保护，不得为了指名展示而放宽。
- `vision_analyze` 面向图片识别，不展示视频/音频；`probe_video` 和 `extract_frames` 也不能呈现原视频卡片。
- 让模型用 `pwsh` 回显路径会触发确认，不是可用的免确认展示入口；写文件、联网、Job 与子代理工具语义也不合适。
- `media_intent` 目前只判媒体词与查看动作词同时出现，不能充分处理否定和歧义，不能直接用作 `show_media` 的唯一闸门。
- `MediaCollector` 在采集本地未托管媒体时可能读取并复制完整文件到 `data/generated`。哈希去重可避免重复写入，但首次采集大视频仍有完整读写成本；此行为必须由明示的当前轮展示请求触发。
- 当前媒体卡按工具调用位置展示；消息末尾的 `metadata.files` 只列普通写入/编辑文件，媒体故意被排除。因此生成媒体没有统一的消息尾部产物清单。

## 3. 行为契约

### 3.1 意图判定

- 在 `naiba/core/attachments.py` 增加/拆分专用于展示请求的纯函数；保留 `_image_intent` 当前枚举工具语义，避免顺带改变既有目录枚举行为。
- 展示意图判定至少要求正向展示动作与媒体目标两者成立；明确覆盖否定句、疑问/条件假设、引用/转述和媒体仅作话题提及等反例。规则以测试表驱动，不用单一包含词正则作为承诺。
- 从本轮原始用户消息计算布尔意图，写入 RunContext；严禁取路由增强文本、Agent 提示或历史助手文本作为授权来源。
- 计划执行、子 Agent、后台 Job、无用户轮次的运行默认无展示授权；只有承载用户原始请求的普通主对话 Run 才可置位。
- 意图不足时工具不可执行或返回稳定的 `intent_required`；不能依赖系统提示劝模型不要误用。

### 3.2 目标解析与拒绝策略

- `show_media` 参数采用 `paths: string[]`，单次上限 1。一个调用只对应一个用户明确指定的文件，降低整批误出卡、超量读盘与模型多路径猜测风险。
- 每个路径必须通过两种受信来源之一：(a) 精确匹配当前会话已有 `metadata.attachments` / `tool_runs[].media` 中的媒体记录，允许复用该记录已经托管的上传/generated 文件；(b) 用户本轮消息明确给出的媒体路径，解析后必须仍在本轮冻结工作区内，拒绝符号链接/解析后越界路径。
- 候选索引只从当前会话记录和本轮用户原文构造，不查其他会话、不枚举工作区、不搜索宿主全局 generated，也不凭 basename 到磁盘猜路径。历史来源按规范化绝对路径精确匹配；新路径必须在用户原文中明确出现。路径不可访问时 fail closed。
- 若由自然语言代词（如“刚才那个视频”）解析，解析器必须从上述候选集合得到恰好一个候选；零个返回 `not_found`，多个返回 `ambiguous` 并列出安全的候选名供追问，不挑最新、不挑第一个。
- 用户消息出现明确路径/文件名时做规范化后的精确路径匹配；仅 basename 冲突时视为歧义。扩展名按 `core/media_types.py::media_kind_of` 唯一判型。
- 先完整校验所有参数，再调用采集器；任一条件失败时全调用不生成媒体记录（无半张卡）。结果用结构化 JSON 返回 `shown` 或 `skipped`，原因枚举：`intent_required`、`ambiguous`、`not_found`、`not_media`、`outside_root`、`over_limit`、`too_large`、`unreadable`。
- 工具结果及模型可见文本不得泄露未经允许的绝对路径；返回展示名、原因和必要的去歧义信息。

### 3.3 文件副作用与容量边界

- 本轮授权只代表用户要求展示文件，不自动授权读取工作区外任意路径。第一版严格限制为：工作区内由本轮明确给出的路径，或当前会话已记录的受管媒体引用；不因工具参数开放确认根、任意 uploads/generated 路径。
- `MediaCollector` 首次托管文件会完整读取/复制到 `data/generated`；因此实施时必须设置**单文件体积上限**，上限从现有运行配置/产品约束中选定并测试，超限返回 `too_large`，不读取全文、不复制、不创建缩略图。该上限仅用于此工具，不改其他生成工具的既有行为。
- 拒绝路径、缺失文件、非媒体、歧义和超限路径都不得调用 `_materialize`；确定失败路径不得产生任何 generated 写入。
- 托管成功后复用现有内容哈希去重和 generated 清理回调；消息记录只保存小型媒体元数据，不复制媒体字节进 SQLite 或模型上下文。
- 复用现有 `MEDIA_DECLARATIONS` inline/structured 采集和媒体卡渲染。消息附件与工具调用媒体可能同源，依赖既有去重，不在前端再造第二套媒体卡。

### 3.4 消息尾部「本轮媒体产物」

- 每条助手消息底部新增「本轮媒体产物」区，汇总本轮成功生成/经 `show_media` 明确挂入的图片、视频、音频。数据只来自该消息现有 `metadata.attachments` 与 `tool_runs[].media`，按规范化来源去重；不得扫描目录、重读文件或再复制到其他缓存。
- 原有消息正文/工具调用位置的媒体卡片继续显示，承担图片预览、视频/音频播放；底部区是并列的产物索引，提供文件名及统一的打开、另存为操作。桌面「打开文件夹」沿用已有 pywebview 条件；手机沿用现有更多操作菜单。不得把清单行做成媒体卡，也不得用清单替代媒体卡。
- 复用 `fileActionBarMarkup`、`saveLocalFile` 和既有 `/api/file`/原生桥接；不新增下载或打开实现，不把上传给模型的用户附件误列为本轮产物。
- `show_media` 的明确展示属于当前助手消息产物引用，但只复用已有 `attachments/tool_runs` 记录；如果该来源已经在本轮其他工具卡出现，尾部汇总仍只保留一个条目。
- 该区域是展示层派生内容，不添加新的 metadata 字段、不写 SQLite 媒体字节、不进入模型历史、不影响前缀缓存。历史消息也从已有 metadata 即时渲染，不做数据库迁移。

### 3.5 工具权限与可见范围

- 新工具注册到 core Provider 与 `MEDIA_DECLARATIONS`，描述只写用途、时机和参数，满足 ≤100 字/≤3 句。
- 权限策略接入读取策略的同一工作区快照解析，但 `show_media` 有自己的**禁止越工作区**规则；不能直接继承会放行宿主缓存和已确认外部根的通用只读语义。
- 不加入 `READONLY_TOOLS` 或 `SYSTEM_TOOLS_READONLY`。第一版仅普通主对话可见；辅助对话、Plan、子 Agent、后台 Job 默认不可用。将来若要开放，应另立权限决策并验证其文件副作用，不以“只读”名义自动扩权。
- 工具是否暴露按会话工具固化集 fail closed；新工具加入后不要隐式注入旧会话。确认 registry/schema、session 固化集、Provider 与测试中的工具名单保持同步。
- 内置 Agent 工具范围在 `_built_in_agent_defs()` 显式加入 `show_media`，六个 Agent 都必须含该工具。四个 preset-backed scope 等于各自 `TOOL_PRESETS` 展开结果再加 `show_media`；prompter/skills 也在各自原范围上加它。同步更新 scope 数量和守门；不必把工具加入用户可单独选择的通用 `TOOL_PRESETS`。
- 配置升级迁移：遍历已保存的当前内置 Agent 覆盖项，若为非空受限 `tool_scope` 且缺 `show_media` 则追加；若范围为空/未设置而语义为“不限制”，保持原样（新注册工具自然可用）。只改工具范围字段，不覆盖名称、提示词、Skill、头像、顺序和其他工具。迁移重复运行不重复追加；自定义 Agent 与已退役 Agent 原样保留。
- 会话升级迁移：对 `agent_id` 属于当前 6 个内置 Agent 且 `conv_kind=main` 的现有会话，将 `show_media` 幂等追加到 `enabled_tool_ids`；保留其他工具和顺序，不碰 aux、Plan/其他模式会话及自定义 Agent 会话。迁移在所有 Run 开始前完成并持久化，避免仅运行时临时注入造成 UI 快照与实际 allowed_tools 不一致。
- 新会话按 Agent scope 固化时自然包含 `show_media`；会话工具检查/展示 API 与运行期解析必须读到同一份固化集合。
- 系统提示说明：明确展示已有媒体时使用 `show_media`；发现目录内容仍用 `list_directory`；一个调用只传一个明确目标；目标有歧义先问；禁止为满足展示请求而目录扫描。

## 4. 实施范围

预计改动：

- `naiba/core/attachments.py`：展示意图规则与候选解析纯函数；保持旧枚举意图不变。
- `naiba/core/contracts.py`：新增 RunContext 授权键并登记默认值/类型；契约测试同步。
- `naiba/run/chat.py` / `naiba/run/session.py`：仅把本轮用户原文判定传入普通主对话 Run，并在工具决议中限制 `show_media` 的场景；任何恢复/回放路径均不得凭历史回复生成授权。
- `naiba/tools/providers/core.py`、`naiba/tools/registry.py`：实现 Schema、执行、def 级策略及媒体声明。
- `naiba/config.py`：六个内置 Agent 显式加入工具；配置升级时只为内置 Agent 覆盖项追加工具，保留用户自定义字段。当前预设 Agent 清单仍由 `built_in_agent_ids()` 单一权威来源决定。
- `naiba/storage/store.py`（或其唯一权威升级装配入口）：为已有内置 Agent 主会话的固化工具集合增加 `show_media`，幂等且不改其他快照。确定迁移版本/事务和启动顺序；不要用请求时静默改写代替持久迁移。
- `tests/test_builtin_agents.py`、`tests/test_config_migration.py` / 对应配置迁移测试、`tests/test_storage_migration.py` / 对应会话快照测试：锁住六个 Agent、新旧配置、会话升级、幂等、保留用户定制与 aux 排除。
- `naiba/storage/media_collect.py` 或专用校验助手：确保所有拒绝校验先于完整文件读取/落盘；若需单文件上限，提供可测试的预检而不影响其他工具。
- `public/js/03-media.js`、`public/js/04-messages.js` 与对应 CSS：从现有消息 metadata 汇总尾部产物行，去重并复用文件动作；媒体卡片原样保留。
- 系统提示权威入口：增加短编排规则；不改变 `/api/file` 和缓存布局。
- 相关测试：意图规则、目标唯一性、路径边界、大小预检、媒体采集、权限集合和描述长度。

不得重排或覆盖工作区现有无关改动；实施前先检查 Git 状态并只提交/修改本计划涉及文件。

## 5. 测试矩阵

### 意图与安全拒绝

- 正例：明确“显示/播放这个文件”并有一个可信目标；“把刚生成的唯一视频放出来”。
- 反例：仅提到视频；询问视频内容但未要求播放/展示；“不要播放视频”；“如果把视频放出来会怎样”；引用“他说‘播放视频’”；仅助手历史说过展示视频。
- 未授权 Run 形态：aux、Plan 准备、Plan 执行、子 Agent、Job 均拒绝。
- 误调保护：即使直接调用工具且构造了匹配路径，缺意图授权仍无 `run.media`。

### 目标与路径

- 唯一历史附件、唯一本轮路径可出一张卡；零候选、同 basename 多路径、多个历史视频均返回澄清原因。
- 绝对/相对工作区内路径通过；工作区外路径、越界符号链接、缺失文件、伪造扩展名、目录路径失败。
- `paths` 为空、错误类型、两项以上、重复项均拒绝或按明确契约规范化；拒绝结果不产生部分卡片。
- 工作区内大小超限文件只检查必要元数据，验证不发生全文件读取、generated 创建/写入和缩略图写入。
- 在限制内的成功文件出图；重复展示命中哈希缓存，不重复复制；媒体类型分别覆盖图片、视频、音频。
- 六个内置预设的 Agent 编辑页均显示 `show_media` 已勾选；`TOOL_PRESETS` 通用模板不因这次 Agent 专属要求被全局扩权。
- 六个内置 Agent 的出厂 `tool_scope` 均含 `show_media`；preset-backed scope 与各自原工具预设展开结果加 `show_media` 后逐项一致；对应工具数量和教程/设置页说明同步。
- 旧版 `config.json` 中未覆盖、已覆盖且定制过的内置 Agent 升级后均含 `show_media`；只追加该工具，其他工具、Skill、提示词、名称、头像逐字段不变。
- 旧版数据库中六个内置 Agent 的主会话（含已固化 `enabled_tool_ids`）升级后均含 `show_media`；自定义 Agent、aux、Plan 会话不被扩权；重复迁移结果字节/集合稳定。
- 升级后分别以六个内置 Agent 的新会话和已有会话实际发出明确展示请求，确认 `show_media` 进入模型工具定义并成功触发；仅检查配置/API 返回不算验收。

### 集成与回归

- `MEDIA_DECLARATIONS` 双向表、工具 schema 与执行器策略一致；只读白名单不含 `show_media`；aux 与 Plan 解析结果不含此工具。
- `list_directory` 的 intent_gated、`scope_dirs` 既有用例保持不变；`_image_intent` 旧行为 golden 不漂移。
- 采集的媒体只进既有消息 `attachments/tool_runs` 展示字段，不进入 `build_model_history` 的新增文本；消息卡去重、历史重放和缓存引用保护保持正确。
- 本轮媒体产物区从同一条消息的 `attachments/tool_runs[].media` 派生，去重后每个媒体只列一次；媒体卡仍在原位置出现。另存为/打开操作在桌面与手机均复用现有文件动作，用户上传附件不会混进产物清单。
- 历史消息重放能从已有 metadata 显示媒体产物清单；清单渲染不会写新 metadata、增加模型历史文本或复制媒体文件。
- 静态检查拒绝把本机盘符或真实数据目录写入计划、代码、测试。

## 6. 验证与验收

风险级别 C：涉及路径授权、工具权限、RunContext、媒体缓存与启动装配。按项目维护说明使用 `.venv` Python 执行：

```powershell
项目根\.venv\Scripts\python.exe -m unittest tests.test_media_collect tests.test_media_declarations tests.test_tool_description_slim tests.test_tool_registry_shape tests.test_contracts tests.test_aux_chat -q
项目根\.venv\Scripts\python.exe -m unittest discover -s tests -q
项目根\.venv\Scripts\python.exe verify\scan_undef_all.py
项目根\.venv\Scripts\python.exe verify\esm_graph_check.py
项目根\.venv\Scripts\python.exe verify\tdz_check.py
项目根\.venv\Scripts\python.exe verify\verify_doc_encoding.py
```

所有改动最后必须按维护说明 §6 启动源码服务并跑 Playwright `verify\browser_smoke.cjs`；功能相关另覆盖媒体卡与尾部媒体产物清单、打开/另存为入口及历史重放，覆盖桌面与 375px 手机视口。截图/日志只放 gitignore 目录。

验收必须全部满足：

1. 仅明确正向请求且目标唯一时出现恰好一张目标媒体卡；媒体卡仍是主要预览表现。
2. 否定、假设、引用、仅提及、歧义、多候选、aux/Plan/子运行及任何路径/大小拒绝均不出卡、不产生半成品。
3. 媒体卡片仍保留；消息尾部同时列出本轮媒体产物，提供打开/另存为且复用现有动作链路；不把用户上传附件误列为产物。
4. 展示区不增加模型历史文本、不向 SQLite 写入媒体字节、不重复托管同内容；超限文件不进行全量读写。
5. `list_directory` 原门禁不变，既有媒体采集与卡片前端无回归。
6. 新装与升级后的六个内置 Agent 主会话都能触发工具；Agent 设置页的勾选状态、持久化快照和运行期 `allowed_tools` 三者一致。仅追加工具，不丢其他 Agent/会话设置；C 级测试、静态检查和 Playwright 全绿。

## 7. 代价与明确限制

- 自然语言无法数学意义上保证永不误判；本方案的可靠性承诺是：误判不能绕过后端授权与唯一目标校验而出卡。模糊输入会追问，明确度优先于自动化。
- 新工具改变模型工具定义字节；按本计划明确迁移的六类内置 Agent 主会话会新增 `show_media`，其模型工具前缀缓存会断一次。这是用户要求的版本升级能力变更；迁移只追加此单一受限工具，并由大小/路径/意图闸门约束。
- 允许范围内、大小上限内、首次未命中的文件仍需一次完整托管读写；大小上限需在实施前根据典型媒体规模确定并写入常量/设置契约，不能在计划里留为实施者猜测。
- 系统提示只负责教模型何时调用；真正防止误触的是 RunContext 授权、唯一候选解析、工作区与大小校验。

## 8. 不在本计划范围

- 不改 `list_directory`、`search_files`、`grep` 的媒体声明、范围过滤与目录枚举行为。
- 不改“本轮修改文件”归类；媒体仍独立呈现为图片/视频/音频卡片。
- 不改变现有媒体卡的样式、播放/预览行为或图片复用行为；底部清单是额外索引。
- 不新增媒体格式、模型上下文附件规则、`/api/file` 路径白名单或缓存目录布局。
