# 修复报告：更新失败/放弃更新后「立即更新」按钮锁死

- 日期：2026-10-23
- 代码基线：3.6.3-beta（`589c5b7`）
- 触发：用户真机反馈两条
  1. 更新下载到一半断网失败，再点「检查更新」又能看到新版本，但「立即更新」按下去没反应；
  2. 更新包下载完成后选择「不要更新」，按钮同样点不动。
- 状态：已修复；单元测试与浏览器冒烟均通过（见 §4）

---

## 1. 结论速览

两条反馈是**同一个根因**：按钮的「可见」和「可点」走了两套口径。

- 点「立即更新」时先 `button.disabled = true` 防重复提交，只有**这个 POST 请求本身**抛错才复位；
- 而下载失败、用户取消、下载完放弃更新都发生在 POST 已经成功返回之后；
- `renderUpdateStatus` 每次都重算 `hidden`，却从不碰 `disabled`。

于是按钮重新出现了，但仍然停在置灰状态——除非重启应用，否则再也点不动。

| # | 现象 | 是否版本回归 | 性质 |
|---|---|---|---|
| 1 | 断网失败后按钮锁死 | 否（状态机自 3.5.x「下载/待重启」改造起就如此） | 前端状态缺陷 |
| 2 | 放弃更新后按钮锁死 | 同上 | 同一处缺陷的第二种触发路径 |

---

## 2. 链路与根因

```
点击「立即更新」
  → installUpdate(): button.disabled = true
  → POST /api/update/install 成功返回 phase=downloading
       （请求结束，只有 catch 分支会复位 disabled）
  → 后台线程下载
       断网失败 → phase=error
       用户取消 → phase=available
       下载完成 → phase=ready
  → 前端轮询/放弃更新拿到新状态 → renderUpdateStatus()
       hidden = !canInstall        ← 按钮重新出现
       （disabled 保持 true）      ← 永远点不动
```

`ready` 态同样受影响：此时 `canInstall=false` 藏起按钮，用户点「放弃更新」后 `ready` 清空、
按钮重新出现，仍旧是禁用状态。

---

## 3. 修复内容

### 3.1 前端：可见性即可点性

`public/js/07-models-agents.js`

- 抽出 `updateInstallAllowed(status, selected)`：`supported`、非源码模式、选中项不是当前版本、
  没有待重启包、不在 busy 阶段——可见与可点共用这一条判据。
- `renderUpdateStatus` 在写 `hidden` 的同一条语句里写
  `disabled = !canInstall || installRequestPending`。
- `installUpdate` 增加 `installRequestPending` 在途标记，并在 `finally` 里复位 + 按最新状态
  重算可点性（失败即可重试）。
- `checkUpdate` 视为放弃上一次悬挂的安装请求（断网时 POST 可能迟迟不返回），清掉在途标记。
- 顺带改准确认框文案：由「更新完成后程序将自动重启」改为「下载完成后可选择立即重启」
  ——3.5.x 起重启时机已交给用户。

### 3.2 断链上的其他问题（一并修掉）

| 位置 | 问题 | 处理 |
|---|---|---|
| `05-bootstrap.js` 30s 轮询 | 本地缓存 phase 为 `checking/downloading/restarting` 时直接 `return`，永不刷新；重开页面或另一客户端发起更新后，界面永远停在旧进度（检查中则永远显示「正在检查更新…」） | 启动时若 busy，接上 07 的 500ms 快速轮询；慢轮询发现 busy 时也接上 |
| `07-models-agents.js` 快速轮询 | 单次 `GET /api/update` 失败就退出，不再重试，进度条与「取消下载」随之停摆 | 仍处于 busy 时 1s 后续轮 |
| `updater.py::_download` | 只有用户取消才删半成品，断网/写盘失败会把几十上百 MB 的残缺 exe 留在数据目录 | 任何异常都先关闭句柄再删 `*.download` |
| `updater.py` PE 头校验 | `path.read_bytes()[:2]` 为了两个字节把整个 exe 读进内存（下载后与每次启动恢复「待重启」都会触发） | 新增 `_is_windows_executable()`，只读前 2 字节 |

### 3.3 验证脚本口径同步

`verify/update_panel_smoke.cjs` 有一处断言与现行产品口径相反：它在「稍后重启」后关窗时要求
弹出悬浮卡，而 `syncUpdateFloat` 自那次「点稍后还弹卡」事故起就明确不再弹卡、改走设置页常驻横幅。
已按现行为改写该段（悬浮卡不出现 + 横幅提供「立即重启/放弃更新」）。
