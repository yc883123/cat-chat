## 0. 目标

在「设置 → 软件更新」中，让用户能直接确认：

1. 更新包实际保存在哪里；
2. 下载正在占用多少空间，下载完成后保留的安装包有多大；
3. 下载失败、取消、放弃或应用更新后，临时文件和待重启文件是否仍存在。

当前页面已经显示下载进度、已下载/总大小、速度、卡住提示、取消入口和待重启入口。本计划只补齐“磁盘产物”信息，不重复制作进度展示。

## 1. 用户可见行为

在更新设置页现有进度/状态区域下方增加一行紧凑的产物信息：

- 常态：显示“更新文件夹”及实际路径；没有下载包时显示“当前没有保留的更新包”。
- 下载中：显示当前下载文件名、已写入大小；若服务端提供总大小，则同时显示总大小。
- 下载完成、等待重启：显示安装包文件名和完整文件大小，并说明“重启后生效”或当前待重启状态。
- 取消、网络失败、校验失败、用户放弃或更新应用后：状态刷新后显示文件是否已清理；若仍有文件，不能声称清理成功，应显示实际状态和大小。
- 路径过长时允许换行；路径可选择并复制，不提供点击打开目录的承诺。

所有文案以用户视角描述结果，不暴露内部 phase 名称、线程、标记文件等实现术语。

## 2. 数据与接口方案

### 2.1 后端状态字段

扩展 `/api/update` 的状态对象，增加只读的更新产物摘要。建议结构：

```json
{
  "artifacts": {
    "directory": "实际更新目录绝对路径",
    "file_name": "naiba-chat-<commit>.download",
    "size_bytes": 123456789,
    "state": "downloading | ready | absent | cleanup_failed"
  }
}
```

字段约束：

- `directory` 必须基于 `UpdateManager.data_dir / "update"` 计算，适配默认目录与自定义 `data_dir`，前端不得自行拼接路径。
- `file_name`、`size_bytes` 只针对当前活动或待重启的包；没有对应文件时返回空名与 `0`。
- 下载中可由已有下载进度提供已写入字节数；磁盘 `stat` 用于核对文件是否存在、报告实际大小。避免读取安装包内容来计算大小。
- `ready` 文件应从当前 `ready` 元数据映射并校验文件名只落在更新目录内；不能把任意路径返回给前端。
- `absent` 表示没有当前更新产物，不表示所有历史残留都已清理。
- 清理动作失败时不得伪报成功。按需记录清理错误，或至少通过文件仍存在反映 `cleanup_failed`。
- 不返回校验和、完整清单内容或安装包字节；路径仅供本机界面展示，不新增文件下载/读取接口。

如果逐状态计算产物字段会让 `status()` 变得难以维护，可提取私有的摘要函数；不新增独立存储系统，也不递归扫描整个数据目录。

### 2.2 清理语义

本次不改变更新包保留策略：

- 下载中断或取消：目标 `.download` 尝试清理；
- 校验失败：无效包尝试清理；
- 用户放弃待重启更新：清理对应安装包及待重启标记；
- 用户选择稍后重启：保留已校验安装包；
- 成功更新后的旧包清理由既有流程负责，本计划不新增额外清理规则。

只有在确实需要向用户区分“清理失败”时才补足异常状态；不要让清理异常覆盖原始下载/校验错误。若文件因杀毒软件占用或权限问题无法删除，界面显示残留文件大小和路径，供用户排查。

## 3. 前端呈现

- 复用更新设置页现有排版和状态区域，在进度条下加入一行产物信息，避免新增独立卡片或大面积占屏。
- 下载和状态轮询沿用现有 `/api/update`；不增加额外定时器或频繁磁盘扫描。
- 轮询成功后按最新 `artifacts` 状态更新信息；轮询失败保留最后一次有效状态，并避免误报已清理。
- 文件名/路径使用 `textContent` 写入，不拼接为 HTML。
- 长路径支持换行和文本选择；如提供复制按钮，使用图标按钮并提供可访问名称/提示，复制失败时给出普通文本路径作为后备。
- 同一信息在设置页和悬浮卡不重复展示；悬浮卡继续专注进度与立即重启/放弃动作。

## 4. 测试与验收

### 后端单元测试

覆盖：

- 默认及自定义 `data_dir` 下返回实际更新目录；
- 无活动包时字段为空且状态准确；
- 下载中报告当前文件与已写入大小；
- `ready` 状态报告安装包大小；
- 路径越界/畸形 ready 文件名不会泄露或读取更新目录之外文件；
- 取消、失败、放弃后的文件存在状态与实际磁盘一致；
- 删除失败时不谎报已清理，且不掩盖原始失败原因。

### 前端验证

- 更新页显示路径和包大小，长路径不溢出；
- downloading → ready → 稍后重启 → 放弃后信息正确更新；
- 下载失败、取消后显示实际清理结果；
- 状态接口短暂失败时不把最后有效信息清空成“已删除”；
- 无新增 JavaScript 控制台异常，桌面与窄窗口布局不遮挡现有按钮。

运行相关 updater 单元测试、全量 Python 单元测试、更新按钮与更新面板浏览器冒烟；若本地环境不具备完整浏览器依赖，明确记录未执行项。

## 5. 非目标与边界

- 不新增资源管理器按钮，不在应用内浏览/打开任意数据目录。
- 不新增“清理更新缓存”操作，不删除不属于当前更新的文件。
- 不做历史更新包列表、磁盘占用趋势、更新日志面板。
- 不更改断点续传、更新包下载、哈希校验、重启替换或待重启持久化协议。
- 不改变现有进度条、悬浮卡、稍后重启或放弃更新的用户决策语义。
- 不将机器绝对路径写入远端日志或模型上下文；只通过本机 `/api/update` 提供给应用界面。

## 6. 实施顺序

1. 为更新产物摘要确定稳定字段和状态定义，并添加后端测试。
2. 在 `UpdateManager.status()` 中以当前 `data_dir` 生成摘要，验证路径边界与异常处理。
3. 在更新页添加紧凑展示，使用实际后端字段，不在前端推导路径。
4. 补充浏览器冒烟，覆盖下载、待重启、失败/取消和放弃清理。
5. 跑目标测试及全量测试，核对现有更新状态行为未回归。

## 7. 实施结果（2026-10-23）

### 7.1 后端

`naiba/updater.py`

- `/api/update` 新增 `artifacts`：`directory`（`data_dir/update`）、`file_name`、`size_bytes`、`state`。
  体积只读 `stat`；目录与文件名都由后端给出，前端不拼路径。
- 新增 `_package_file` 跟踪正在写盘的 `.download`（`_download` 赋值、失败清理与 `_mark_ready` 时清空），
  所以 `downloading` 报的是**这次**下载的文件，选旧版本安装也不会串版本。
- `_remove_file()` 统一清理：删除失败（占用/权限）只记录，不抛、不盖掉原始下载/校验错误。
- `_artifacts_summary()` 优先级：正在写的包 → 待重启的包 → 删不掉的残留（`cleanup_failed`）→ `absent`。
- `_safe_update_path()` 把标记里的文件名限制在更新目录内；`_load_ready` 与 `apply_ready` 都改用它，
  顺手堵住「标记被改坏后读到目录外文件」。

### 7.2 前端

- `public/index.html`：进度块下方新增 `#updateArtifacts`（「更新文件夹」+ 可选中路径 + 复制图标按钮，
  下一行是包名/体积/状态）。
- `public/js/07-models-agents.js`：`renderUpdateArtifacts()` 按四个状态给用户视角文案
  （正在下载…／… · 重启后生效／未能清理…（体积）／当前没有保留的更新包）；
  `artifacts` 缺字段时保留上一次信息。
- `public/js/15-bind-events.js`：复制按钮用 `copyText`，剪贴板被拒时把路径原样打进提示。
- `public/styles.css`：把 `.update-artifacts` 从 `.update-status > div` 的 flex 压回块级，
  长路径 `overflow-wrap:anywhere` 换行、`user-select:text` 可选中。
