## 1. 要解决的问题与既有功能边界

各模型阶段生成原始结果时，通过受限工具分段写入任务 TXT；写入成功后才返回回执。展示、下载、阶段解析和版本保存统一读取已校验文件。模型最后的简短完成确认只表示执行结束，不能成为作品正文。

原调研记录过一条剧本输出因 `finish_reason=length` 提前停止，持久事件与任务结果一致。TXT 可保住已确认写入的段，不能单独突破模型输出限制，也不能据此断言所有短稿都是前端丢字；必须同时实现分段和接续。

4.4.6-beta 已包含以下功能，本任务应保留并回归检查：

- **分镜选择剧本版本**：剧本页与分镜页共享选择，预检和提交传 `script_version`，任务冻结指定剧本正文及 `sources.script_version`，重试沿用。单版可默认，多版可选择，来源版本可见。本任务不重做选版，也不能改回固定读取最新版。
- 拆书匠旧大纲接续兼容、已完成结果优先读取持久正文、查看历史任务后保存结果的作品归属检查。
- 织书台直接上传用户 TXT 作为续写输入、拆书匠原文/改编稿导入、来源冻结和旧章只读。本计划处理的是**模型输出文件**，不能拿导入接口替代结果实现。
- IndexedDB 正文草稿、保存期间继续输入、409 冲突保留、生成前先保存手改、取消与流水线重试规则。

不改贴签匠现有 TXT 功能，不新增任意路径写文件权限，不迁移全部历史任务，不在本任务内调整版本号或发布流程。

## 4. 文件协议与持久化

### 4.1 任务标记、归属与路径

- 建议常量 `STUDIO_RESULT_ARTIFACT_KEY = "result_artifact"` 表示公开文件摘要；另登记版本化的 `output_contract_version` 与 `logical_generation_id`。新任务在入队前由服务器设置协议和身份，并随冻结输入、任务及请求幂等记录一起持久化；不能等生成结束才加字段。
- 仅无新协议声明、且无产物标记的存量任务读取持久 `result/result_partial`。任一记录表明使用新协议时，摘要字段丢失、清单丢失、文件损坏或未完成都必须报错，不得退回旧正文、浏览器全文或模型完成确认。公开摘要字段缺失不能被解释成旧任务。
- 固定任务目录建议 `data_dir/studio/results/<task_id>/`。模型不能提交路径、作品 ID、流水线 ID或另一个任务 ID；工具上下文由服务器绑定。校验实际解析路径在受管目录内，拒绝目录穿越及越界链接。
- 冻结输入摘要覆盖 module、模型身份和提示词/Skill 快照、分块计划及来源版本。Novel 包含作品、阶段、章节和选定剧本版；Writer 包含作品、章节、pipeline、attempt、step_index、step、设定/大纲/正文基线。另存实际 task_id，不能仅凭文件名认归属。
- 明确序列化与摘要算法：稳定 JSON 编码后的输入指纹；正文按 UTF-8 字节计算 SHA-256，字数按服务端 Unicode 字符数计算并由界面直接显示。不要用 JS 字符串长度重新判定完整性。

### 4.2 分段、确认和完整发布

业务块 `block` 与传输段 `segment` 分开：chunked 每块可再写多个传输段；未分块任务视为一块。编号从 1 连续增长，片段不得被覆盖。

1. `write_result_txt(segment, text)` 只写当前绑定块。服务器校验段号、大小、取消状态、身份和内容摘要；相同段号相同内容重放返回原回执，不重复追加；同号不同内容、跳号、已完成块追加均拒绝。
2. 回执包含实际段号、已确认总段数、字符数、摘要、下一段号和不透明的 `receipt_id`。数字及摘要由服务器生成，模型在完成确认中原样回传，不能要求模型自行计算 SHA-256。
3. `complete_result_txt(receipt_id, segments, chars, sha256)` 确认当前块。服务器核对回执归属、完整连续段序、数量、原文摘要和本轮终止原因；所有预定块都完成后，才发布任务全文。JSON 的传输段按原样拼接，禁止每段补围栏、改空白或独立包装 JSON。
4. 原有业务块间的连接规则要显式冻结。当前 chunked 正文按 `\n\n` 连接；传输段之间原样连接，不隐式 `strip()`。测试覆盖空行、换行和中英文/emoji，避免字数及摘要不一致。
5. 持久化采用不可变片段和全文快照，最后原子更新 manifest。写入、必要 flush/fsync、manifest 发布完成后才发成功回执。现 `naiba/core/fsutil.py` 原子写入未调用 fsync，应补专用持久写入并说明 Windows 元数据持久性的实际保证，不把 `os.replace` 等同于断电持久保证。
6. 注入崩溃点验证“片段已写但清单未提交”“清单已提交但回执未送达”“全文发布但任务终态未写”。未获清单确认的孤立文件不能自动计入结果；已确认重放必须去重；发布完成后可核验恢复终态，无需重跑模型。

元数据建议至少包含 `schema_version/status/chars/segments/sha256`，内部另含归属摘要、块清单、各轮终止原因及恢复来源。公开 DTO 不暴露服务器绝对路径。

### 4.3 文件完整与业务成功分别判定

文件状态使用 `partial/final`；`invalid` 是读取发现缺失/损坏时的公开错误状态。`final` 只证明生成协议已确认并且原始文件可完整读回，不证明 JSON 或业务结构一定正确。

- 文本/JSON必须经过原阶段解析器；解析失败保留原始文件和错误，不创建作品版本、不继续需要该结果的步骤。
- Studio 现有任务 `done` 不是文件完整性的替代证据。`result` 只作为完整文件的兼容投影，`result_partial` 只表示已确认片段；工具参数 JSON、思考和“写好了”等确认不能混入正文。
- 完成工具成功后由 runner 校验并收尾，不额外请求一轮模型说“已完成”。已发布 final 后确认连接丢失，不应丢掉正式产物。取消与终态仍走 runner 的现有同锁裁决，文件 final 也不能把已确认取消的任务改成 done。
- 运行中普通 delta 可作临时预览，但要与“已落盘”区分。切回任务、终态、保存和下载以文件为准；流中未完整收到或未执行的工具参数不能谎称已保存。

## 5. 生成执行与模型兼容

当前 `runner._complete` 先分派 Skill，再分派 chunked，普通路径最后直调模型。只改普通路径会漏掉分镜 Skill 和分段正文，三条路径必须逐条接线。

- 普通/分块生成通过受限结果工具循环运行。Skill 保留已有 `SkillAgent` 循环，在该任务的 registry、allowed_tools 和 executor 同时装配工具；不注册到全局工具目录，不扩大其他 Studio 页签或对话权限。
- 使用已有原生工具与文本动作解析机制，核对来源规则、JSON 完整性和取消状态；不要在前端执行模型工具文本，也不要新增不受现有协议校验的正则执行器。
- 模型返回普通正文而未完成文件协议时，明确提示继续按协议写入，有限纠正后失败并保留可恢复内容。不能静默回退成“只存最后普通回复”的旧行为；底层对不支持原生 tools 的兼容重试也须经过此检查。
- 每轮模型调用的 usage 都归属当前任务并累加，保留每块/每轮 finish_reason；不得仅读取最后一轮来掩盖前面的 length 或中断。
- 按块数、字符预算和上下文预算设置有限调用上限与无进展上限，允许长任务完成所需的多轮写入；不能直接照搬贴签匠 8 轮/12 步，也不能无限循环。达到上限时保留 partial 和可读原因。
- 长剧本优先按已有章节/场次边界规划块，冻结顺序，附必要设定和前块末尾。结构 JSON 在同一逻辑结果内按字节顺序续写，完整后一次解析；不要把各块 JSON 直接用空行拼成非法文档。
- `length` 是待接续原因，网络异常是另一种原因。已确认段保留，未确认工具调用不执行；补齐并重新确认前不能发布 final。Writer 的 `parse_draft(..., finish_reason="length")` 拒收残稿语义必须保留。

## 6. 中断恢复、重新生成与换基

界面和接口分清三个动作，不能让一个“重试”按钮暗中改变来源或重复追加：

| 动作 | 来源与身份 | 已确认片段 |
|---|---|---|
| 继续未完成内容 | 原冻结输入、Writer 同一 pipeline/attempt/step，保留基线 | 逐段核验后只补缺段 |
| 重新生成（现有 retry） | Writer attempt+1，新任务；仍沿用原冻结来源 | 新建空产物，不接旧片段 |
| 基于当前版本重新生成（rebase） | attempt+1，刷新来源、提示词、基线、revision和指纹 | 新建空产物，不接旧片段 |

建议独立增加恢复入口。沿用现有 Studio “新建执行任务、保留源记录”的结构：恢复生成新的执行 task_id，记录源任务和源清单摘要，验证后复制已确认片段并重新绑定归属；`logical_generation_id`、生成来源和 Writer attempt/step 不变。逻辑 ID 初始可取首个任务 ID，恢复链继承；普通重试和 rebase 则产生新的逻辑 ID。复制不是共享可变目录，源任务文件保持不变。

**恢复换执行 task_id 后，业务写回幂等身份不能改变。**现有 `completed_task_ids` 和版本保存按 task_id 去重，须补稳定的逻辑生成 ID 或持久写回凭据（至少绑定 pipeline/attempt/step_index/logical_generation_id），让“版本已保存、完成标记未写”的恢复只补登记，不再次续写、追加章节或创建版本。Novel 也要防恢复链重复自动写回，同时保留用户明确“另存新版本”的既有操作语义。

恢复顺序与并发约束：

1. 确认源任务已停止，旧 worker/socket 不会继续写，running/stopping 不准克隆；只接受可恢复 partial 或“文件完整但终态未提交”的状态，缺失/损坏文件不能假定为空继续。完整文件业务解析失败应走重新生成，不能在错误 JSON 末尾盲目追加。
2. 先按稳定逻辑身份查询写回凭据或已生成版本，核对来源指纹与预期写回后的 revision。若能证明本次结果已提交，只补流水线完成登记，不再次调用模型；不能把自身保存引起的 revision 增长误判为外部冲突。尚未提交时再检查源清单、冻结输入、作品/章节版本和模型身份；无法由本次写回解释的来源变化或 revision 漂移返回冲突，由用户选择 rebase，不自动混接。
3. 用持久请求键保证恢复幂等；复核源任务仍是当前待恢复任务。不得让任意 Studio 通用接口直接恢复 Writer 任务，绕过其流水线。
4. 创建恢复子任务时先不调度，Writer 专属编排在作品锁内按 pipeline/attempt/step_index/step/源 task_id 比较更新 `current_task_id` 和提交占位，再在锁外提交模型任务；为“子任务已创建、指针未更新”“指针已更新、尚未入队”设计持久恢复登记和可重入收敛。比较失败收敛未认领子任务，不能放任它运行。
5. 取消先阻止推进，迟到回执与旧任务回调不能保存或提交下一步；同时检查恢复前后 `_submissions` 等占位，不能留下无法重试的 running 状态。
6. 刷新/重启先按现有规则收敛 interrupted。恢复需要明确动作，不在重启时自行重放收费请求；已取消任务也不自动继续。

不要直接调用当前 `jobs.retry` 来恢复 Writer：它会新建 Studio 任务，但不会替 Writer 更换 `current_task_id`。也不要直接复活终态 task_id 而沿用旧事件文件，否则旧 terminal 事件会使前端提前结束轮询。

## 7. 两工作台读取与保存

### 7.1 共享服务接口

建议提供 `jobs.result_text(task_id, require_final=True)`：读取真实任务、核对输出协议、文件身份和内容，按第 4.1 节判断旧任务兼容，新文件任务任何校验失败都抛明确领域错误。调用方仍须检查业务 owner，不能仅因给出了 task_id 就跨作品保存。

建议 `GET /api/studio/tasks/{id}/artifact` 返回 `{task_id, text, artifact}`；`?download=1` 返回 UTF-8 完整 TXT。接口沿用现有认证，文件缺失/损坏返回可辨认错误；partial 允许查看/下载但标注“未完成”。预览若限长必须显式回 `truncated` 与总字符数，完整下载不得走截断预览。

任务详情、列表、预览、导出、复制、Studio 交接、Writer 推进、Novel 保存、分镜发送造梦机统一使用产物投影。列表可以只读摘要，不应每次轮询整批全文；真正消费时重新校验。文件出错后旧 `result` 投影不得继续显示为可保存结果。

### 7.2 拆书匠

- `api_apply`：先核对任务所属作品、阶段、终态和 revision，再读取完整文件，调用原 `apply_elements/apply_outline/apply_script/save_manuscript`。新文件任务不能相信浏览器提交的 `text`。
- **同时修改 `api_save_manuscript`**：前端 `saveAiResult` 走章节 manuscripts 接口，并不只走 `api_apply`。AI 任务保存须核对作品、`adapt` 阶段、目标章节和来源稿件，从任务 TXT 读回；原稿来源优先使用冻结任务数据。
- 保留人工稿、导入稿和旧任务合法路径，不能把所有带 `kind=ai` 的存量稿都强制认作新 TXT 任务。用户对生成稿作人工编辑时，应另存本次编辑快照，不能读取旧生成文件覆盖手改。
- 分镜读取所选剧本版本生成结果，TXT 只承载其输出，不重新选择剧本；任务来源仍显示冻结 `script_version`。partial/invalid 分镜不允许作为已完成结果发送下游。

### 7.3 织书台流水线

- `_advance` 在原有 book/pipeline/attempt/step/chapter 归属检查后调用共享读取接口，再走 `_parse_step_output` 与 `_finish_step`；文件校验不能跳过锁内版本复核。
- `_finish_step` 保留当前任务、步骤、作品与章节 revision 检查、`completed_task_ids`，并接入第 6 节的稳定写回凭据。网络失败、重复轮询或恢复后执行 ID 改变均不能多建版本。
- `chapter_continue` 文件只含新增文字；`_apply_draft_step` 与完整冻结基线拼接一次。不可把基线也写进 TXT 后再次追加，且前一章上下文和基线版本必须保持冻结。
- `chapter_segs` 按原要点分块，恢复仅补当前缺段；`outline_all/outline_review/split/chapter_all/state_rebuild` 逐实际子任务验证文件。
- `state` 文件/解析失败沿用现有“记录派生状态失败、保留正文、按原策略继续”的语义；用户取消仍停链。其他关键阶段文件失败应停链并保留原产物。

### 7.4 人工“保存正文”

保留现有 PATCH 入口和前端本次全文/revision 请求。服务端可在同一请求内完成以下操作，无需新增两次浏览器往返：

1. 校验作品、章节、来源只读属性与 expected revision；为本次编辑分配独立 draft_id。若保留现有 revision 可省略的接口兼容，省略时须在锁内取得并绑定当前 revision。
2. 将本次编辑快照写入作品内的独立草稿 TXT 和元数据，绑定 book/chapter/revision/chars/sha256；不复用或覆盖 AI 生成产物。用 `read_bytes().decode("utf-8")` 读回，避免通用换行转换破坏 CRLF、首尾空白或摘要；路径解析后须仍在作品目录。
3. 从草稿文件读回并核验，再由原 `save_chapter_version(kind=manual)` 创建不可变版本。写盘期间若放开锁，保存前必须再次核对 revision；成功保存与版本指针更新沿用原锁边界。
4. 写盘、校验、版本提交或刷新失败都返回明确错误并保留编辑器/IndexedDB 副本。409 不刷新清空；保存期间新输入继续标为未保存；只清理确切成功的编辑代次。
5. 保留可恢复失败草稿并记录它与版本的关系，纳入生命周期；不能无界积累所有成功保存的临时副本。纯手写章节无需任何生成任务也能保存。

## 8. 前端状态与文件生命周期

- 两工作台显示已落盘字符数、partial/final/invalid 状态、查看与下载入口。partial 提供明确恢复动作，并禁用保存版本和依赖完整结果的下游操作。
- 保留来源版本、进度、终止原因和错误信息；详情请求、文件预览、下载准备、保存与恢复都核对当前作品/章节/任务及请求代次，迟到回包不能串稿。
- 桌面及 375px 手机可用，长错误/文件名可换行，控件不挤出屏幕；关键步骤后立刻检查 pageerror、console.error 与页面错误条。
- 删除前明确引用规则：活动任务/恢复中的任务不可删；被作品版本、派生任务或恢复链引用的文件受保护。建议首版对仍需文件的任务返回 `skipped: referenced`，界面说明原因；引用创建、恢复认领与删除须同步，防止检查后新引用建立却仍删掉文件。
- 已将完整内容和必要来源快照复制进不可变作品版本的路径，可在证明无文件依赖后回收任务文件。不得因删除历史任务使已保存作品或分镜来源失效，也不能仅凭作品被删就删除仍可查看的任务产物。
- 文件删除限定受管目录，跟任务/草稿元数据一致处理；启动后的孤立文件收敛须区分未确认临时文件与已确认产物，不用“最近访问时间”替代引用检查。

## 10. 验收矩阵

使用隔离 data_dir/config/SQLite、临时作品和本地模型替身。确定性测试不调用真实模型、不读正式用户配置；如补真实供应商兼容验证，单独记录模型与协议覆盖，不能由替身通过推断所有模型兼容。

| 范围 | 必须验证 |
|---|---|
| 文件与协议 | 中文、emoji、空行、JSON 原样读回；重复同段不追加；同号异文/缺段/乱序拒绝；hash/字数不符拒绝；路径越界和跨作品/任务拒绝 |
| 完成判定 | 只说“完成”未写文件失败；只存在文件不算 final；文件 final 但 JSON 错误不保存版本；工具参数不混正文；缺失/坏文件不能回退旧 result |
| 中断 | 工具已落盘后网络断开；回执丢失重放；完整块后第二块 length；取消与 final 竞态；重启后恢复；无进展/预算耗尽保留 partial |
| 恢复身份 | 重复恢复请求、两个标签页并发恢复、创建任务与更新指针间崩溃、版本已写但完成凭据未登记、旧回调迟到、恢复中取消；换执行 ID 不重复保存；普通 retry 新 attempt、rebase 新基线均不读取旧文件 |
| 全阶段 | 第 2 节每个实际阶段均经 TXT 原文到原解析器；普通/分块/Skill 均覆盖；各类批量每个子任务有独立产物 |
| Novel 保存 | api_apply 和 manuscripts 两入口均拒绝 partial/坏文件/错作品/错章；重复保存语义与来源版本保留；人工稿不被生成文件覆盖 |
| 分镜回归 | 单版默认、多版切旧版、预检/提交/结果来源一致；重试不改版；选旧版后有新版产生仍使用冻结旧版；模板及 Skill 结果均可下载 |

| 下载与删除 | 大于 512 KiB 文件下载与服务端 SHA-256 一致；预览限长有标志；partial 下载注明未完成；任务/作品删除和恢复链引用互不破坏 |
| 浏览器 | 两工作台 1280px 与 375px：生成→文件可见→查看/下载→保存→刷新；中断→恢复→无重复；故障下草稿不丢；无页面脚本错误 |
