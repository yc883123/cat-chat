## 1. 入口与模式切换

### 1.1 `nv.mode` 的全部取值

`nv.mode` 实际是 `state.novel.mode`，只有 **两个**取值：

| 值 | 含义 | 证据 |
|---|---|---|
| `"adapt"` | 改编模式（默认值） | `nv_main.js:1759` `state.novel={mode:"adapt", ...}` |
| `"create"` | **原创模式** | `nv_main.js:2195` `(nv.mode==="create") ? "原创模式" : "改编模式"` |

> 注意：全文件只有 **1 处** 判断 `nv.mode`（`nv_main.js:2195`），即决定落盘目录名。模式切换的其它分支（UI 显示、按钮绑定）靠的是 `#main.nv-on` 这个 class（`nv_main.js:1778`、`novel-editor.html:390`）。

### 1.3 切换时做了什么 —— `setMode()`（`nv_main.js:1773-1795`）

```js
function setMode(m){
  ensure().mode=m;                                    // ① 写回 state.novel.mode
  document.querySelectorAll("[data-nvmode]").forEach(function(b){
    b.classList.toggle("on", b.getAttribute("data-nvmode")===m);   // ② 两处 seg 同步高亮
  });
  $("main").classList.toggle("nv-on", m==="create");  // ③ 盖上来/盖下去 #nvWrap
  if(m==="create"){
    nvHwClone(); refreshAll(); log("已进入原创模式");   // ④ 克隆硬件监视器 + 全量刷新 UI
    if(window.requestAnimationFrame){
      requestAnimationFrame(function(){ if(NV.foldApplyDefault) NV.foldApplyDefault(); });  // ⑤ 折叠校正
    }
    var done=null; try{ done=localStorage.getItem("nv_guide_done"); }catch(e){}
    var g=$("nvGuide");
    if(g) g.style.display = (done || window.innerHeight<=719) ? "none" : "flex";   // ⑥ 首次引导条
  } else {
    save(); log("已返回改编模式");                       // ⑦ 切走时自动存盘
  }
}
```

逐项说明：

1. **`nvHwClone()`（`nv_main.js:1797-1800`）**：`hwMon`（显存/内存监视器）是 `#center` 的固定件，但原创模式的中栏是 `.nv-center`，没有 `.mcol.mid`，所以手动把 `#hwMon.innerHTML` 克隆进 `#hwMonNv` 占位（HTML:2628）。只克隆一次（`!host.querySelector(".hwi")` 守卫）。
2. **`refreshAll()`（`nv_main.js:2115-2139`）**：把 `state.novel` 的全部字段回填到所有 DOM 控件。
3. **折叠校正（`nv_main.js:1781-1785`）**：注释明确写了原因——*「页面初始是 `display:none`，列高为 0，`foldInit` 里那次测量不可信」*。所以要在 `requestAnimationFrame` 里按**实际渲染高度**重算一次 `foldApplyDefault()`。
4. **首次引导条（`nv_main.js:1786-1791`）**：读 `localStorage.nv_guide_done`；未看过 **且** 窗口高 `>719` 时显示 `#nvGuide`。用户点「知道了」（`nv_main.js:3288-3290`）写入 `nv_guide_done="1"` 永久关闭。

## 3. 完整创作流程（核心）

### 3.0 总览：两条流水线，共 8 个可触发阶段

原创模式**没有一键跑到底**。设计哲学写在 `nv_main.js:2564-2567` 的注释里：

> 一句话 → 题材推断 → 书名 → 简介 → 世界观 → 角色 → 章节大纲，**跑完停下待用户检查**；正文**保持按需**（到 ⑥ 卡点【生成本章正文】才生成），不做自动长跑。

```
【开始创作】NV.start() ──▶ 6 阶段自动流水线（设定）
  ① genre  题材推断    → genreApply：写回 流派/关键词（用户可改）
  ② title  书名        → 取 JSON 数组[0] 填入 #nvMetaTitle
  ③ blurb  简介        → 取 JSON 数组[0] 填入 #nvMetaBlurb
  ④ world  世界观      → 填入 #nvWorld
  ⑤ chars  角色设定    → 解析 JSON 数组 → nv.chars[]，渲染到 #nvChars
  ⑥ outline 章节大纲   → 解析 JSON → nv.outlineMeta[]，渲染到 #nvOutline
                          └─ 自动调 NV.syncChapters() → 重建 state.chapters
  ▼ 停机待检（toast「设定已就绪：检查后可生成正文」）
【生成本章正文】NV.genDraft() ──▶ 按需，两种模式
  ⑦a seg   段落要点(segs) → N × 正文(draft) 逐段续接
  ⑦b whole 整章正文(draft) 一次生成
  ▼
【合并全文】NV.mergeNovel() ──▶ ⑧ 落盘 文件缓存\原创小说\<书名>\全书_<书名>.txt
```

**另有旁路**：若已套用模板且骨架已填满，`NV.start()` 会**改道** `NV.tplRewrite()`（`2660-2662`），走 5 阶段随机改写流水线。

### 3.1 统一生成核心 `NV.gen()`（`nv_main.js:2189-2228`）

所有 8 个任务共用一个入口：

```js
NV.gen=function(task, userText, onDone, opt){
  opt=opt||{};
  if(genBusy){ toast("正在生成中：可点右侧「■ 停止」中断，或等它跑完"); return false; }
  var nv=NV.ensure();
  var nvModule = (nv.mode==="create") ? "原创模式" : "改编模式";        // 2195
  var sys=NV.SYS[task]||NV.SYS.draft;
  var jsonMode=(task==="chars"||task==="outline"||task==="title"||task==="blurb"||task==="segs");  // 2197
  var payload={id:"nv"+Date.now()+"_"+Math.random().toString(36).slice(2,6),
    messages:[{role:"system",content:sys},{role:"user",content:userText}],
    settings:Object.assign({}, state.settings, {maxTokens:opt.maxTok||NV_MAXTOK[task]||1024}),
    module:nvModule, tag:"原创小说", act:task,
    jsonMode: jsonMode ? {enabled:true, schema:"custom", custom:""} : {enabled:false}};   // 2201
  ...
};
```

关键结论：
- **API**：只有 `POST /api/generate`（`2219`），与改编模式共用；靠 `module` + `tag` + `act` 三个字段区分归属。
- **`module`**：`"原创模式"` / `"改编模式"`（决定 `文件缓存\<module>\<日期>\` 的生成日志目录）
- **`tag`**：恒为 `"原创小说"`
- **`act`**：`genre`/`world`/`chars`/`outline`/`title`/`blurb`/`segs`/`draft` 之一
- **JSON 模式**（`2197`）：**只有 `chars`/`outline`/`title`/`blurb`/`segs` 五个任务开 JSON**；`world`（世界观）、`draft`（正文）、`genre`（题材推断）是纯文本。
  - ⚠️ 注意：`genre` 的系统提示词里写了「只输出 JSON」，但 `jsonMode` 判断里**没有 `genre`**，所以**题材推断实际没有 JSON 约束**，只靠提示词约束（且失败时被 `parseJsonLoose` 静默跳过，见 §10 坑 #13）。
  - JSON 模式传的是 `{enabled:true, schema:"custom", custom:""}` —— **custom 为空串**！后端 `resolve_json_schema`（`llm.txt:231-238`）在 `custom` 为空时会走「提示词约束」降级路径（`llm.txt:483-494`：`JSON 输出已开启，但 自定义 Schema 为空或不是合法 JSON …本次按纯提示词运行`）。**所以启元的"JSON 模式"实际是软约束，靠 `parseJsonLoose` 兜底。**

### 3.2 逐阶段详解

#### 阶段 ① 题材推断（`task="genre"`，maxTok 512，❌无 JSON 约束）

### 3.3 流水线的调度与竞态守卫（`nv_main.js:2693-2714`）

```js
var next=function(){
  if(i>=steps.length){ /* 收尾 */ }
  var s=steps[i++];
  NV.progLine("正在生成："+s.n+"（"+i+"/"+steps.length+"）", Math.round((i-1)/steps.length*100));
  NV.gen(s.k, NV.userText(s.k), function(txt){
    var mySeq=NV.S.genSeq;                                   // 捕获完成时刻的 seq
    try{ s.f(txt); }catch(e){ NV.log(s.n+" 处理异常："+e,"err"); }
    setTimeout(function(){ if(NV.S.genSeq!==mySeq) return; next(); }, 400);   // 延迟调度前校验
  }, {target:s.t?NV.S.getEl(s.t):null});
};
```

注释（`2694-2697`）说得很直白：*「『生成完成 → 400ms 延迟调度下一步』窗口内点【停止】，旧版 `next()` 照跑、剩余步骤继续开新任务」*。⚠️ **不能在 `next()` 里比较流水线起步时的 seq——`NV.gen` 每步都会 `++genSeq`。**

**每步间隔 400ms**，`NV.start` / `NV.tplRewrite` / `NV.genTitleBlurb` / `NV.genAll` / `NV.draftNextSeg` 五处流水线全部同构。

### 3.4 结果写回与渲染

`NV.poll()` 的 `d.done` 分支（`2375-2388`）：

```js
if(d.done){
  var cb2=NV.S.onDone; NV.S.onDone=null;    // v1.91.34 致命修复：必须先取回调再 genEnd
  NV.genEnd();
  NV.log("✓ 完成（"+txt.length+" 字）","ok");
  NV.histPush(NV.S.task, txt);              // 完成即入册
  if(NV.S.task==="draft" && NV.S.curCh){    // ← 恒 false，死代码，见 §5
    NV.summarySave(NV.S.curCh, txt);
    NV.progLine("第 "+NV.S.curCh+" 章已完成 · "+txt.length+" 字", 100);
  }
  if(cb2) cb2(txt);
}
```

渲染路径两条并行：
1. `target.value = txt`（`2373`）→ 目标 textarea（卡片内）
2. `NV.streamPut(txt)`（`2374`）→ 右栏 `#nvStreamBody`

注释 `2376-2377` 记录了一个致命 bug：*「必须先取回调再 `genEnd` —— `genEnd` 会把 `NV.S.onDone` 置 null，旧顺序导致 `onDone` 永不触发，自动流水线跑完第一步就停在 1/6（用户看到的「卡住」）」*。
