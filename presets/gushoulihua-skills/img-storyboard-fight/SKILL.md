# 图片分镜 · 动漫战斗

把漫画、已有分镜、人物四视图或文字战斗需求整理成一条可直接交给生图模型的“多格战斗分镜图提示词”。本 Skill 是 `h3-storyboard-fight` 的上游，只负责设计分镜图，不负责生成图片，也不负责撰写 MiniMax H3 视频提示词。

## 绝对边界

- 负责生图／修图提示词及必要的参考映射、成图检查与交接信息；不自动调用生图工具。
- 不输出 H3 的 `subject_definitions`、`summary`、Shot 时间码或其他视频字段。
- 不把人物参考图当作首帧、尾帧或分镜；人物四视图只绑定身份、脸、发型、服装、身体结构、武器与稳定颜色。
- 不擅自改变原素材的胜负、能力、攻击结果、伤势、武器、变身阶段、对白含义或破坏规模。
- 默认直接交付一条完整提示词，不设置方案确认轮；能保守决定的构图细节直接处理。涉及剧情事实、身份／参考职责冲突、能力、胜负、对白归属或无法兼容的时长／画布限制时，才询问缺失的关键事实。

## 三种工作模式

### A. 漫画／已有分镜重构

用户提供漫画图或分镜图时，先通读全部素材、确认阅读顺序和不可改变的剧情事实，再按 [storyboard-design.md](references/storyboard-design.md) 检查它是否具备可拍摄的攻防因果、人物交互、受力反馈、空间路线、镜头接力和结果落地。

- 已经适合打戏：忠实转写为分镜图生图提示词，只补足构图、资产绑定和防错约束。
- 不适合打戏：保留原事件顺序和结果，只补与既定结果相容的连接姿态、接触关系、位移过渡与环境反馈；不得为了完整套用攻防模板而新增格挡、反击或碰撞。
- 原素材明确是单方面压制、攻击落空或强者静止承受时，保留该关系；通过衣物、尘土、接触面、攻击者回弹和环境反馈表现力量，不虚构伤势或反击。

### B. 文字需求原创

用户没有漫画或分镜时，根据人物参考、场景、能力、战斗目标、目标时长和结局要求，设计完整的战斗因果链。若用户未指定胜负，默认采用“阶段性交锋尚未分出胜负”，不得自行击杀、重伤或改变人物能力。

人物四视图、武器设定图和场景图仍只承担各自资产职责。没有专门参考的内容才根据用户文字做保守、稳定的可见设计。

### C. 返回成图检查／返修

用户返回生成图时，先按 [handoff.md](references/handoff.md) 对照原需求逐格验收。只对实际可见问题给出定位与一条修图提示词；通过则交付简短检查结论和必要交接信息。不把提示词自检当成成图合格，也不自动生成 H3 正式词。

## 工作流程

1. 按用户提供顺序建立 `Picture 1...N` 映射，并区分：剧情／原分镜、人物、武器、场景参考。
2. 锁定战斗结果、能力边界、场景地理和本段主要视觉峰值。有碰撞时才选主碰撞；无碰撞时可用擦身、脱离或位置反转作为峰值。按 [storyboard-design.md](references/storyboard-design.md) 检查目标时长容量；未指定时不强套 10 秒或固定格数。
3. 内部建立“必要前提 → 攻击路径 → 命中／格挡／偏转／闪避／无效接触 → 可见结果”的事实链；对手反应与后续动作按素材选用，不是必填事件。
4. 先按 [动作拆解规则](references/storyboard-design.md#3-事件镜头关键姿态与分镜格) 展开足够指导衔接的关键姿态，补齐运动、接触、重心与支撑变化，再合并无独立信息的格。不得先定格数再删必要连接，也不把某次任务的格数或时长固定为默认模板。
5. 区分连续事件、镜头、关键姿态与分镜格；相邻格可属于同一镜头，不因多格而强制切镜。逐格确定当前状态、相对前格新增的可见事实，以及必须入画的部位；再选择景别、机位与格子比例。每格只画一个时间点，不把内部动作链抄进单格。
6. 按 [visual-direction.md](references/visual-direction.md) 把画面空间、动作关键帧、冲击瞬间、镜头语言、构图引导、光影特效和节奏剪辑转译成静态分镜可见信息；不把时间码、连续运镜或声音指令塞给生图模型。
7. 按 [output-contract.md](references/output-contract.md) 写出确切格数、行列／跨列位置、阅读顺序、逐格瞬间、参考绑定与少量相关防错约束。指定 GPT Image 2.5 时，再读 [gpt-image-2.5.md](references/gpt-image-2.5.md)；调用设置与画面提示词分开。
8. 按 [handoff.md](references/handoff.md) 做提示词验收，分别检查剧情可读性、动作衔接与燃向表现；交付必要的镜头关系／事实说明，不输出内部状态表或推理过程。成图返回后核对动作意图是否真正画出，不能仅凭格数正确和画面精致判定通过。

## 分镜设计底线

- 每次主要攻击都必须有可辨认的目标、路径、结果及相容的反馈。直接命中可以没有主动防御；纯闪避可以没有接触或受力改线；无效接触可以保持强者静止。
- 不把“互动”限定为反击、双方受伤或攻击者改线；人物动作必须在同一空间关系中产生明确结果。上述结果分支优先于参考文件中的通用接触、反馈和节奏手法。
- 关键接触格必须看清攻击端与受击／防御面、肢体归属和作用方向；速度线、闪光、粒子与爆炸不能遮住接触点。
- 高速残影只表示原角色轨迹，不额外制造人物、共用肢体或重复命中；原设定明确具有分身能力时按事实区分真实分身与残影。
- 特效遵循“触发源 → 附着对象 → 运动方向 → 接触变化 → 跨格余波 → 消散／破坏结果”。
- 每格以一个核心攻防事件为中心，只附加能共同说明这次动作的姿态、惯性、特效和环境反馈；不能靠“炸裂、史诗、华丽”等形容词制造假密度。
- 景别、机位、透视、前中后景、运动线、光源和粒子必须共同指向本格的主要动作或接触点，不能各自炫技。
- 每个短交锋单元突出一个主要视觉峰值；纯追逐／闪避不新增碰撞。长素材按完整事件组织多个单元，不为整页只有一个峰值而删除原作高潮。
- 最后一格必须显示人物位置、姿态、环境状态与阶段结果；有受力时呈现其结果，纯闪避则呈现脱离或收势。不能用尚无结果的发射或挥拳替代完整交锋。

## 与 H3 打戏 Skill 的交接

成图通过检查后，才交给 `h3-storyboard-fight`：新图负责获准的动作与构图，专门资产图负责外观，原素材／用户事实与对白交接信息负责剧情。映射与缺失处理见 [handoff.md](references/handoff.md)。不得提前生成 H3 正式词。

维护或验证本技能时，以 [output-contract.md](references/output-contract.md)、[storyboard-design.md](references/storyboard-design.md) 和 [handoff.md](references/handoff.md) 的可观察约束为准。设计推演、成图观察与视频实测分开记录，不把个别结果概括为模型成功率。
