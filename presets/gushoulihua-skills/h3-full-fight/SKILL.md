# H3 完整动漫打戏

以「剧本 → 每段视频的关键画面参考图 → H3 视频提示词」制作打戏，默认日系手绘 2D 燃番。统一用**视频段 P01、P02…**表示独立的视频生成请求，用**镜头 Shot**表示段内的观看单位；每段可以有经剧本确认的运镜或切镜，最终提示词中的 `[Shot 1]、[Shot 2]…` 在每段内重新编号。每段至少选择一张能确立构图、动作或人物关系的画面，必要时增加。参考图可以对应段首、段中或段末，**不默认是 0.00 秒首帧**，也不是多格分镜。

默认交付范围是打戏方案设计、参考图准备和逐段 H3 提示词。剧本及待用关键图已确认、逐段提示词与生成设置及上传清单交付后，标记**制作资料已交付，视频效果待验证**；用户返回实际视频后再进入验收与返修。视频生成、剪辑拼接和成片导出按用户具体任务决定，不因“完整”名称而默认执行。

## 开工前确认

每次开始一项新的完整打戏任务，先完成以下八项确认，再进入阶段 1。把用户已明确提供的信息直接记下，不在后续分段重复提问；仅对缺失或互相矛盾的项一次性提问，用户明确授权自行决定时采用下述默认值。收到必要答复前不正式制作剧本、图片或视频提示词。

1. **画风**：本次是否严格锁定日本手绘 2D 动画画风？默认是。用户明确取消 2D 后，图片与视频表现以用户的要求及指定画风参考为准；文字要求与画风参考互相矛盾时确认采用哪一项。停用本 skill 的图片画风标准及图片／视频画风专项验收，手法库保持不变，人物、装备、空间、动作因果和跨段连续性检查继续执行。
2. **出图方式**：用户要求在对话内直接生成图片，还是只交付可复制的图片提示词？先记录用户选择，再按下方“出图模式与能力判定”核对当前环境及可调用能力，确定直出模式或提示词模式。只要用户要求仅交付提示词，就不调用生图工具；不把提示词冒充成已生成的图片。
3. **角色与场景资产**：用户是否提供可用的人物设定图和场景图？缺失时询问已有文字设定，协助设计并确认角色、装备和场景资产；直出模式制作资产图，提示词模式提供对应资产生图提示词，然后再制作关键画面。
4. **生成配置**：用户本地配置可支持的最大单段时长是多少（本 skill 单段仍不超过 15 秒）？上限为 N 秒表示 1–N 秒均可自选，不询问固定时长档位。按剧情需要在有效上限内分段，不假设用户一定能生成 15 秒。
5. **已有内容**：是否有现成剧本、剧情想法、锁定台词或必需动作？没有剧本和构思时，默认设计**全片总长约 15 秒**的剧情，并按第 4 项配置拆段；不是默认单段 15 秒。
6. **成片规格**：目标全片时长和画幅比例是什么？若用户未指定全片时长且第 5 项也无内容，使用约 15 秒默认；画幅未定时先询问，避免后续构图返工。
7. **参考图职责**：逐张标明已有图片是锁人物、场景、画风，还是仅参考动作或构图；一张图可承担多个已确认职责。新参考图加入时补记其职责，不把构图参考里的环境、颜色或人物擅自带入正片。
8. **正式产物保存位置**：确认用户希望保存到哪个目录，或仅在对话内交付；用户已有文件存放规则时沿用并在开工摘要中记录，不重复询问已明确的信息。需要保存时，资产图、关键图、剧本、提示词、版本记录及上传清单统一放在确认的项目目录中；不固定盘符，也不默认建立桌面副本。

可把八项合为一条简短问卷；若已知信息足够，直接用一段开工摘要记录配置并进入阶段 1。后续只有配置、保存位置或参考用途改变时才重新确认受影响项。

## 出图模式与能力判定

**用户要求优先，实际能力决定能否执行。** 从当前环境已知信息判断是否处于 Codex，不把所有用户都视为 Codex 用户。以下规则同时适用于角色／场景资产、关键画面及图片返修；调用生成仍须遵守所在阶段的剧本、资产与图片确认条件。

1. **Codex 环境，用户要求直接出图**：内置图像生成工具可用时，依照可用的 `imagegen` skill 在对话内直接生成并展示图片，执行直出模式。
2. **Codex 环境，用户要求只出提示词**：执行提示词模式，只交付图片提示词，不调用图像生成工具，也不因工具可用而改为直出。
3. **非 Codex 环境，用户要求对话内生成**：询问是否有当前可调用的外置图片生成 skill 或 API，例如 ComfyUI 本地 skill；用户已提供该信息时直接沿用。具备可调用能力时，按其使用规范联动生成并提供可查看的成图，执行直出模式。调用前提醒用户一次：**不同图片模型对提示词的要求不同，本 skill 无法内置所有模型的提示词预设，对 GPT 生图的适配度最高，不保证其他模型的生图效果。** 有对应模型的提示词 skill 或指南时，按其要求适配，同时保留已确认内容、画风、参考职责和连续性约束。
4. **非 Codex 环境，没有可调用的图片生成 skill 或 API**：说明无法在当前环境直接生成，执行提示词模式，交付图片提示词，等待用户提供成图。

非 Codex 用户若本来只要提示词，直接执行提示词模式，无需询问外置生图能力。任何环境下，用户要求直出但实际工具不可用、调用失败或无法取得可查看的成图时，如实说明当前限制并回退交付图片提示词；用户提供成图后再检查，不将失败的调用或未查看的结果记为已验收。开工摘要及进度记录注明当前出图模式；直出时同时注明所用生成工具／模型（已知时），回退时更新记录。

## 输入与目标

- 使用用户给的人物、场景、剧本、想法和已确认修订；未给想法时，默认设计总长约 15 秒的短打戏。用户指定的总时长、招式、攻击次数、命中与结局优先。
- 默认日系手绘 2D 燃番。普通攻击、位移、闪避和受力实时高速完成；只有剧情或演出确实需要的瞬间才作主观时间变化，并说明恢复高速的触发。动作、镜头、特效应有主次峰值，避免匀速摆拍和双方轮流归位出招。
- 保持人物位置与朝向、距离、身体支点、攻击源与路径、接触或避让间隙、受力方向、装备和能力状态在镜内及相邻镜之间可推导。不得把特效写成无来源的额外攻击。
- 设计剧本和最终动作时读取 [2D 打戏手法库](references/techniques.md)，按事件选择相容的作画、摄影与特效；选中的手法要有触发、可见作用和退出或承接，不堆名称。取消 2D 后仍使用原手法库，按用户画风适配手法的具体表现，不借手法重新施加手绘线条、赛璐璐上色等 2D 画风要求。

贯穿三阶段维护简短的**连续性记录**：固定场景地标与天桥、墙、栏杆等相对位置，人物在世界中的站位、距离、朝向和镜头轴线，以及武器数量、左右手、刀与刀鞘、能力、投射物的当前状态。新图和新视频须与已确认版本核对；构图参考只借构图，不能擅自替换已定的环境、人物或事件。发现冲突先修正，不靠后续提示词掩盖。

同时维护轻量的**进度与版本记录**；需要保存时写入确认的项目目录，仅对话交付时随阶段交付更新。每个视频段记录：剧本版本、关键图编号与文件／对话引用、图片检查结果、用户确认状态、提示词版本及当前是否有效、待办问题。共同使用的角色／场景资产另记当前版本；只有用户明确确认才记录为已确认。

修改时按实际依赖标记受影响的产物为待修订或待确认，不把旧版继续当作当前版。末态变化可能影响下一段开场，共用资产变化可能影响多个段，均应检查实际影响；仅修改音效措辞等不影响画面的内容时，不让已确认关键图失效。修改确认过的剧本时重新确认受影响的剧本，只有关键图表达的内容也变化时才重新制作并确认该图；只改图时重新验收并确认该图，只改提示词时不重复前两阶段确认。

## 阶段 1：逐段剧本

按 [剧本格式](references/script.md) 产出完整时间轴，写明每段的情节动作、景别与构图、运镜、特效与作画、声音和台词、段初段末状态。已有剧本时沿用事件与用户修改，必要的分段调整先体现在可审阅的剧本中。H3 单段最长 15 秒：优先把连续、可清楚表达的动作编入同一段，允许段内运镜或切镜；只有动作密度、复杂空间转换、生成难度或必要的剪辑衔接使其难以在一段内清晰完成时才拆段，不为每个招式或画面变化单独拆视频。每段时长和剪辑边界应能在用户当前生成方式中执行。

设计跨段接口时，上一段优先停在**动作已有结果、位置和装备明确、可短暂稳定保持**的画面；下一段优先以能独立确立观看关系的镜头开场，再承接该结果。不要默认要求两段首尾逐像素接合；确需同一连续动作跨段、用户明确指定精确首尾帧，或独立镜头无法交代因果时，再使用共用衔接图与首尾帧控制。每段至少从手法库指定一项可见的作画或摄影手法及其作用，具体表现适配已确认画风；整场打斗须有随动作变化的景别、观看方向或摄影运动，不能成为固定双人全景里无意义轮流出招。**交付剧本后等待用户确认；此时不制作画面图，也不输出最终视频提示词。** 用户对某版剧本的明确确认可沿用，不重复索取。

## 阶段 2：逐段关键画面参考图

仅据已确认剧本，为每段视频选至少一张关键画面，逐张标明它对应本段的哪一刻、画面中谁在何处、动作与装备处于什么状态，以及图前图后的运动。若同段有多处视频模型容易误解、单张图难以约束的高难动作或空间关系，可为不同关键时刻分别配图；若跨段衔接需要锁定人物、场景、装备、朝向和位置，可增加段末／下段段初的衔接图，并明确两段共用的状态。按实际难点决定数量，不机械地一处动作配一张。每张图只呈现一个瞬间，不能排成漫画格、时间线或把几个动作叠进一图；不得把角色设定图的多视图当作多名角色。

若开工确认缺少人物或场景资产，先按已确认设定制作并验收相应资产图，或在提示词模式提供资产生图提示词；关键画面随后使用这些已确认资产。**2D 模式下，关键画面必须是日本手绘 2D 电视动画正片或高质量关键帧质感。** 出图和返修时按 [2D 关键画面标准](references/keyframe-2d.md) 约束人物、背景、材质、光影和特效：清晰手绘轮廓、平整固有色、硬边赛璐璐阴影、有限高光、概括的动画背景与手绘特效。已有参考图即使是写实图、游戏 CG 或精细二次元插画，也只借用其已标明职责的内容；锁人物、动作、构图或场景时，不擅自借入其他部分。2D 模式将视觉表现重新动画化，不沿袭 PBR、摄影光影或厚涂插画质感；雨夜、霓虹、湿地不得成为提高写实渲染程度的理由。**用户取消 2D 后，停止上述图片画风标准、动画化转换及相关负面限制，图片提示词改用用户要求或指定画风参考；内容与连续性约束继续生效。**

按已确认的出图模式执行：直出模式通过上方判定的内置工具或外置 skill／API 使用人物和场景参考生成图片；提示词模式只交付图片提示词，不调用生图工具。**每生成、返修或收到用户提供的成图，就立即实际打开并检查；2D 模式同时执行画风专项检查，用户取消 2D 时跳过画风验收，其余检查继续执行。未通过不能交付为已验收图或继续当作基准图。** 核对身份、人数、场景、装备、招式数量、接触或近失；对照连续性记录和相邻已确认图，核对地标与人物的前后左右、距离、朝向、透视、身体支点、左右手持物、刀与刀鞘的数量及位置，排除错位、穿模、畸形和穿帮。2D 模式还须逐项检查人物、背景、反射和特效是否真正遵循 2D 番剧作画逻辑，尤其检查皮肤、头发、布料、金属、石地与湿面有无 PBR 反光和摄影质感；画面若仍像游戏 CG、写实概念图或精细宣传插画，即使内容正确也不算合格。针对失误在直出模式编辑或从干净的已确认版本重生成，在提示词模式交付针对性的返修提示词，待取得修订图后实际查看，不能只凭提示词判断。

**用户自行出图后的查验与返修**：在提示词模式交付角色／场景资产或关键画面的图片提示词时，简短提醒用户：“如果生成结果不满意，可以把成图发回来，并说明不满意的地方，我会检查图片并给出针对性的返修提示词。”用户反馈不满意但尚未提供成图时，请其返回对应图片；收到后实际查看，按当前启用的内容、画风与连续性标准定位问题，并交付可复制的返修提示词，取得修订图后再检查。若当前环境无法查看返回的图片，如实说明并请用户重新提供可查看的图片；在能够实际查看前，只能根据用户描述给出排查建议，不记为已验收。

按同一具体问题记录返修轮次，首次生成不计入返修；**同一动作、构图或场景关系连续三轮返修没有改善时，暂停该问题的继续生成，指出具体困难，主动建议用户提供对应的动作／构图／场景参考图，不自主搜索参考。** 用户提供参考或明确选择其他处理方案后再继续；拿到参考后标明只借用哪些部分，再按当前出图模式生成或交付图片提示词。不要把错误图作为下一轮底图反复涂改。若仍有关键错误，说明具体问题并停在阶段 2，不把有误图片当作已验收成图。提示词模式或直出能力不可用时，交付各段所需、可复制且符合当前画风要求的图片提示词并停在阶段 2，等待用户提供成图；收到图后执行同样的自主检查，返修继续遵循当前出图模式。**所有待用关键画面通过自主检查并经用户确认后，才进入阶段 3。** 用户明确复用已确认的图时不重新生成。

需要保存文件时，按开工确认的目录整理正式产物；关键图较多或经过多轮改版时，在项目内建立 `upload/` 当前版上传目录及编号与用途清单，不另建桌面文件夹。视频段用 `P01、P02…`，关键图可用 `P01-K01、P01-K02…`，共用图在清单中注明适用段；文件编号与实际上传的 `<Picture N>` 分开管理。旧版移出当前上传目录或明确标为旧版，避免用户上传错图；阶段 3 的 `<Picture N>` 必须按每段实际上传顺序重新编号。生成工具使用默认保存位置时，生成后将正式产物整理到确认的目录；仅对话交付时提供清单，不创建项目或上传目录。

**最终图片交付预览**：适用于直出模式的角色／场景资产、关键画面及其返修结果。对话中供用户审阅、确认和最终交付的预览，必须对应已检查通过的当前版本及其最终保存位置。

- 需要保存时，先将通过检查的图片复制到确认的目录（已处于最终保存位置时直接使用），再从最终路径实际打开，核对文件可读取、画面及版本正确，并更新进度记录、上传清单和交付引用。生成工具默认目录中的初次预览不能代替归档后的交付预览。
- 每次交付或请求确认时，在对话中逐张呈现本次待审阅的最终图片预览，并标明图编号与版本；不能只列文件路径或下载链接。环境支持本地图片内嵌时，使用最终文件的绝对路径展示；否则使用当前工具支持的、可持久访问的媒体预览。仅对话交付时使用稳定媒体引用，不新增项目目录。
- 返修或更换版本后，重新展示通过检查的最新图，说明它替代哪个旧版，并同步更新上传清单。历史生成图可保留为过程记录，但不得让用户将错误图或旧版误认为当前交付结果。
- 移动图片或清理旧副本前，先保证最终文件已存在、可实际打开且新的交付预览已呈现；不能继续把即将失效的原路径作为唯一预览来源。只按用户授权和生成工具的保存要求处理旧副本，不因本规则自行删除其他文件。若无法提供可查看的最终预览，如实说明并修复展示方式，在恢复前不要求用户确认一张不可查看的图。

## 阶段 3：逐段 H3 视频提示词

按 [视频提示词格式](references/video-prompt.md) 为每个视频段独立输出六字段正文和规定尾部，并在正文前列出**视频段编号、单段时长、画幅、实际输入模式**及该段上传清单与编号；设置说明置于可复制正文外，与已确认剧本和用户配置一致。视频提示词的画风开头按当前用户要求编写：2D 模式使用手绘 2D 表现，取消 2D 后替换为用户要求或指定画风参考，不保留固定 2D 开头。参考职责是：人物图锁外观，场景图锁环境，该段已确认的关键画面图提供构图、姿态和动作关系的视觉锚点；文字描述前因、运动、节奏和后果。默认使用 `[reference generation]`，不得把关键画面误写成强制首帧。只有用户明确要求某图精确充当第一帧或其他确定关键帧时，才依实际任务切换到 `keyframe completion` 关系。

每段只上传该段实际用到的图片；相邻段共用的衔接图可分别用于两段，但不混入无关段的关键画面。每个独立请求的 `<Picture N>` 从实际上传顺序编号，并在清单与六字段里一致；多张关键画面须分别注明对应时刻及作用，不让模型误以为是同时发生或必须逐帧复现。音频参考另用 `<Audio N>` 独立编号，写清它是直接复用还是只参考音色、节奏或音效质感；无文件不虚构音频标签。

用户返回实际视频时，按剧本逐段检查速度、空间与受力、招式次数、所选手法是否真正出现、镜头是否随动作提供新的观看信息，以及音画和跨段衔接；2D 模式额外检查 2D 画风与动态，用户取消 2D 时跳过画风专项验收，其余检查继续执行。若打斗沦为一个固定机位下两人无意义对打，视为未通过，重写动作与摄影设计；有明确用意的短暂定机位冲击停顿、角色反差或结果镜头可以保留。只根据看见的问题返修剧本、关键画面或提示词，按进度与版本记录更新实际受影响的段与产物。文字检查不等于视频效果已通过。
