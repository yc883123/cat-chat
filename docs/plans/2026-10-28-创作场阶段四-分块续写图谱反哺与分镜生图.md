## 二、4A 分块续写（单任务多轮）

### 触发与策略

- 只作用于 `stage="adapt"`（单章 AI 改编）：`len(正文) > body_chars` 时不再截断，
  改为按段落贪心打包成 ≤ body_chars 的块，**一个 Studio 任务内多轮调用、逐块拼接**。
- 单段超长（整段无换行）按句子硬切（。！？；……换行符），保证每块不超上限。
- 块数上限 `ADAPT_CHUNK_LIMIT = 20`：超出时只取前 20 块，剩余字数**明说**
  （「内容过长，已按 20 块生成，最后 X 字未纳入本次生成」），绝不静默。
- 每轮输入 = 固定头（作品 + 改编指令 + 稿件说明 + 总块数）+（第 2 块起：上一轮
  已生成改编稿的结尾 `CONTINUITY_TAIL_CHARS = 500` 字，要求紧接续写不要重复）+ 本块原文。
- 预算预检按「头 + 全部块」估算；分块信息进任务快照，重试原样重放。

### 改动

| 文件 | 改动 |
|---|---|
| `naiba/novel/prompts.py` | `split_body_chunks` / `build_adapt_chunks`（块切分 + 轮次组装 + 超块明示） |
| `naiba/studio/runner.py` | `input_data["chunked"]` 分支：循环 complete()、每轮发 status 事件「正在生成第 i/N 块」、轮间补 `\n\n` delta（partial 与最终结果同构）、取消/失败保留已完成块、用量跨轮累加 |
| `naiba/novel/service.py` | `_build_adapt` 超限走分块；`api_stage` 挂 `input_data["chunked"]` |
| `public/js/25-novel.js` | 事件轮询处理 status 事件，AI 润色面板显示「第 i/N 块」进度 |

### runner 契约（通用，不认识小说域）

```json
"chunked": {
  "blocks": ["…", "…"],
  "prefix": "固定头",
  "continuity_chars": 500,
  "continuity_label": "【已生成改编稿的结尾（…）】"
}
```

runner 只认这个形状：内容 = prefix +（continuity 段）+ block[i]；`result = "\n\n".join(各轮输出)`。

## 三、4B-1 图谱反哺（系统提示词）

- `prompts.build_kg_context(elements)`：从要素三类取**最多 20 条**（人物优先，其次场景、道具），
  每条裁到 80 字、总量裁到 `KG_SLOT_CHARS = 1200`；空要素返回空串。
- 服务端为 elements / outline / script / adapt / storyboard 组装 `system` 文本：
  「全书设定参考（来自已保存要素，仅供保持人物与设定一致，不是本次素材）」。
- `runner._complete` 支持 `input_data["system"]`：非空时消息列表前置 system 消息
  （带图任务同样前置）；为空时行为与现在完全一致。
- 用量：`budget_report` 增加 system 的字符数与 token 估算。
- 来源说明：`sources.kg_entities` 记条数，右栏「这次会做什么」如实显示。
- 重试：system 随 input 落盘，原样重放。

## 四、4C 分镜生图（复用造梦机）

### 后端

- 新阶段 `stage="storyboard"`（分镜生图），输入是**已保存剧本的最新场次**（不选历史版本），
  不吃章节素材：请求带 `scene_ids`（缺省 = 全部场次）。
- `build_storyboard_content`：每场一块（场景行 + 正文，单场裁 4000 字），指令要求
  每场输出一条出图提示词（场景、人物外观与动作、景别、光线氛围；不写台词），格式
  `【第 N 场】<场景行>` + 提示词正文。
- `parse_storyboard(text)`：按「【第 N 场】」标记拆分；识别不到结构时 `parsed=False`
  整段原样显示（与剧本 `parse_scenes` 同口径，绝不臆造切分）。
- 任务契约与其它阶段一致：`module="novel"`、`origin_label="创作场"`、`novel.scene_ids`
  + 场次快照；**不写回作品**（`api_apply` 对 storyboard 明确拒绝），结果只在任务里。
- KG 反哺同样注入（人物外观描述帮助跨场人物一致）。

### 前端

- 阶段栏加「分镜」；阶段面板克隆机制照旧（`prepareStagePanels` 加 storyboard）。
- 分镜面板：显示场次数量，不显示逐章稿件 / 正文上限滑条 / 上下文版本选择。
- 任务完成且解析成功：逐场行（勾选 + 场景行 + 提示词），「发送到造梦机」把勾选的
  提示词批量带过去；解析失败只显示原文。
- 交接：`document` 自定义事件 `naiba:storyboard-handoff`（`{items:[{no,head,prompt}]}`）
  + `setStudioPage("comfyui")`；不做剪贴板复制。
- 造梦机页（24-comfyui.js）：监听事件存入 `comfyui.storyboardQueue`，参数区上方渲染
  「分镜队列」条：每条带「填入」按钮 → 填进当前工作流的正向提示词框并标记已填；
  「清空」清队。未选工作流时提示先选。队列只存内存（本页刷新即清）。
