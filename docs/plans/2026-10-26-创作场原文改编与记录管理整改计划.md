# 创作场原文、改编稿与记录管理整改计划

> 日期：2026-10-26。现状基线：3.8.2-beta，提交 `ad536b81212057af46cd38e83b2d9ce1042644ea`。
> 状态：仅完成需求整理与只读代码核对，尚未实施本计划。本文不代表源码已修改、功能已测试或新版已发布。
> 本轮交付只新增这份 Markdown 计划；不覆盖根目录现有 `plan.md`，不自动提交、推送或发版。
> 用户本轮确认的产品口径优先于旧阶段计划：原文与改编稿并存；生成记录参照提词库；正文与章数限制可调；统一管理全部记录。

## 一、这次要解决的问题

本次不是把现有保存结果逐一变成“历史版本卡”，也不是先解决下拉框位置。核心是让章节原文、人工改编稿和 AI 改编稿成为能辨认、能选择、能管理的独立内容，后续要素、大纲、剧本可以明确选择使用哪份稿件。

应用中“保存状态”目前只是被动展示状态文字与提示，并没有点击事件；本计划保留这个事实反馈用途，并新增明确的作品路径与导出位置说明，不把状态文字伪装成按钮。作品保存在应用实际数据目录的 `studio/novel/<book-id>/` 下；冻结版默认数据目录在 `%LOCALAPPDATA%\NaibaChat`，但用户可配置数据目录。当前导出由浏览器触发下载，文件名为作品名加 `.txt` 或 `.md`，通常进入浏览器默认下载目录；操作系统或浏览器也可能弹出保存位置选择框。

### 1.1 用户确认的九项要求

| 项目 | 本轮确定的行为 |
|---|---|
| 1. 原文与改编稿 | 选中第一章，先显示原文卡片；点击编辑并保存，新增改编卡片，原文仍保留。提供手动编辑与按要求 AI 润色／改编两种方式。后续要素、大纲、剧本均允许选择章节稿件。 |
| 2. 生成记录 | 参照提词库：紧凑最近任务列表，完整历史通过独立入口查看；一次查看一条生成结果，不把所有任务堆成正文卡片。 |
| 3. 手机与桌面 | 修复手机布局、控件溢出和内容滚动；三个手机分栏按钮（章节／编辑／预览）要有清楚的可点击轮廓、悬停／按下／键盘焦点反馈和明确的当前态；桌面同样要能直接发现编辑、选择稿件、折叠与管理入口。 |
| 4. 右侧说明与路径 | 随阶段和本次选择说明生成条件、实际引用内容、尚未保存结果的处理方式、输入限制和省略情况；说明作品数据实际保存目录，以及导出文件保存到浏览器下载目录并显示文件名。 |
| 5. 输入限制 | 每章正文上限使用滑条，在 3000–15000 字之间调整；一次生成的章数上限也可调整，突破现有 6 章。 |
| 6. 卡片折叠 | 卡片可反复展开、收起；不能第一次打开后就关不回去，也不能被轮询重新撑开。 |
| 7. 拆章正文排版 | 去掉“正文”标签下不必要的大块留白，正文从内容区顶部开始呈现，阅读和编辑各有清楚状态。 |
| 8. 内容管理 | 阶段栏最右侧提供“管理记录”，集中管理原文、改编稿、要素、大纲、剧本及生成记录，支持多选、全选、批量删除。 |
| 9. 路径反馈 | 清楚显示作品保存在应用的哪个数据目录，以及导出文件名和导出方式；保存状态保留为状态信息，不误导成可点击按钮。 |

### 1.2 本轮不做

- 不以新增版本下拉框替代原文与改编卡片；下拉框的进一步调整暂缓。
- 不加入续写、知识图谱、分镜生图等阶段四功能。
- 不改聊天、打标器、造梦机的业务流程，不把创作场记录混入提词库历史。
- 不把全部界面问题归因于缓存或自动重启；冻结版资源一致性作为验收项目单独验证。
- 不把保存状态做成没有动作的假按钮；它负责报告最近的保存／读取／导出结果，稳定显示当前作品位置与可操作的导出说明。
- 只写计划；实现、提交和下一版发布由后续明确执行任务承担。

## 二、已核对的现状与根因边界

| 现状 | 代码依据 | 对整改的影响 |
|---|---|---|
| “保存本章”覆盖章节文件里的 `content`，没有独立的原文、改编稿实体。 | `naiba/novel/service.py`：`update_chapter()` | 必须先补稿件数据关系，不能只增加前端卡片。 |
| 后续生成从当前章节文件读取正文，不接受逐章稿件选择。 | `naiba/novel/service.py`：`stage_material()`、`api_stage()` | 请求、来源显示、摘要与导出都要知道选中的是哪份稿件。 |
| 当前历史卡按生成任务建卡，任务数与已保存内容数不是一回事。 | `public/js/25-novel.js`：`renderStageTaskHistory()` | 任务记录与内容卡片分开呈现、分开删除。 |
| 要素、大纲、剧本已有成果版本字段，但章节稿件没有同样能力。 | `naiba/novel/service.py`：`apply_elements()`、`apply_outline()`、`apply_script()` | 复用已有成果存储与 Studio 任务，不重建整套任务系统。 |
| 右栏“下一步”仍是固定的阶段二文案，没有本次输入说明。 | `public/index.html`：创作场 `.novel-preview` | 改为动态的阶段说明与本次素材清单。 |
| 正文限制为每章 3000 字，章数硬上限为 6；截断说明随提交结果返回。 | `naiba/novel/prompts.py`：`BODY_SLOT_CHARS`、`MAX_CHAPTERS_PER_CALL`、`_chapter_blocks()` | 参数要贯通预检、正式提交、任务重试，超限在调用模型前展示。 |
| 无要素、无大纲时仍可生成剧本；有保存内容才加入参考。 | `build_stage_content()`、`api_stage()`；已有无大纲测试 | 右栏如实说明可选关系，不能新增强制前置条件。 |

卡片折叠及正文留白需要结合具体交互路径确认，不能仅凭截图判定最终根因。当前只读检查已发现“章节点击直接打开，缺少同项再次点击收起的分支”；其他卡片及样式覆盖在实施时逐项复现。截图图像内容在本轮模型输入中不可见，不把未观察到的画面写成已验证事实。

## 三、章节原文与改编稿：最终交互

### 3.1 选章后先看到原文卡片

以第一章为例：

1. 左栏选中“第一章”。
2. 中栏显示“原文”卡片，标题包含章节名、字数；正文只读，默认从顶部展开。
3. 卡片操作提供“编辑”“AI 润色”“用于后续生成”及明确的展开／收起。
4. 尚未改编时只显示原文，不渲染空的改编占位卡，也不把空编辑表单当成第二份内容。

### 3.2 手动编辑后新增改编卡片

- 点击某张原文／改编卡片的“编辑”，以该卡片正文建立临时编辑区，标清“基于哪份稿件”。
- “保存改编稿”新建一张改编卡片，不覆盖原文；“取消”不创建记录。
- 第一份为“改编稿 1”，后续保存为独立的新稿件，编号只增不重排。
- 编辑已有改编稿后保存，默认另存新稿，原稿保留，避免悄悄改掉被后续成果引用的素材。
- 内容未改变不新增重复卡片；重复点击保存由前后端共同防重。
- 新卡片显示：原文／改编稿名称、来源稿件、人工编辑／AI 改编、保存时间、字数；支持展开阅读与收起。
- 新保存的改编稿不静默替换后续生成的素材选择；提供明确的“用于后续生成”操作。

### 3.3 AI 润色与改编

- 在选定原文或改编稿上点击“AI 润色”，填写自己的改编要求，选择供应商与模型。
- 提示文案说明：“AI 会根据这份稿件和你的要求生成新稿，原文会保留。”不把“润色”限定为只能改病句。
- AI 使用与要素、大纲、剧本同一套 Studio 后台任务、流式状态、取消与重试机制；单章改编作为小说域新增任务阶段，标清来源稿件和用户要求。
- 非 AI 的导入、拆章和手动编辑继续是普通文件操作，不进入模型队列。
- 生成中、失败、取消仅产生任务记录；生成成功先显示待确认结果，点击“保存改编稿”后才新增内容卡片。
- 同一个任务只能保存一次；刷新、重试读取和重复按钮点击都不能创建重复稿件。
- 用户切章或切阶段不让迟到结果写入当前正在看的另一章。
- 改编请求的来源和参数提交时固定；任务排队期间另存稿件，不改变已排队任务的输入。

### 3.4 后续阶段选择哪份章节稿件

- 在要素、大纲、剧本的素材章节列表中，为每个被勾选章节提供“使用稿件”选择，默认原文。
- 允许混合：第一章用“改编稿 2”，第二章用“原文”；每章一次只选一份，不把同章多稿拼成重复素材。
- 三个后续阶段都能使用原文或改编稿，不要求先生成要素／大纲。
- 剧本阶段另行选择已保存的要素和大纲；两者没有内容时允许直接生成。
- 选择对当前作品保持，切换阶段或手机分档不丢失；切换作品按作品恢复，不串用另一作品的稿件 ID。
- 明确区分“选择素材稿件”与“展开查看卡片”，点开阅读不会悄悄更改本次生成素材。
- 右栏列出本次逐章稿件及选中的要素／大纲。仅生成但未保存的结果不能自动被引用。
- 前文摘要按具体稿件关联，不能在使用改编稿时误用旧原文的摘要。
- 导出沿用明确的稿件选择；现有原文导出保持可用，选择性导出改编稿时在导出前显示范围。

## 四、保存与迁移设计

### 4.1 数据职责

- `naiba/novel/` 继续负责作品、章节、稿件、成果与来源关系。
- 数据继续保存在 `data_dir/studio/novel/`，每章正文按需读取，列表接口不返回整本正文。
- 为每章建立稳定的原文标识与改编稿标识；持久化保存稿件类型、来源稿件 ID、正文、创建时间、任务 ID（如有）和用户要求（如有）。
- 稿件正文独立存储，清单保留索引；避免每次读作品列表就反复传输全部稿件正文。
- 已有要素／大纲／剧本版本继续保留，补稳定记录 ID 与明确来源，不按可变数组位置识别。
- 显示编号不代替记录 ID；删掉第 2 稿后，后面的稿件不能重编号或复用其 ID。
- 继续使用原子写、清单权威与乐观并发校验，失败不得写出半份新稿或半次删除。

### 4.2 请求与来源

- 生成输入从单纯 `chapter_ids` 扩展为明确的章节与稿件对应关系，服务端校验稿件确实属于该作品、该章。
- 旧调用未带稿件选择时读取原文，保持原有工具／接口兼容；有显式无效稿件 ID 时返回错误，不静默换成原文。
- 每次任务保留来源稿件、字数／章数设置、要素／大纲选择，以及提交时使用的内容快照或等效不可变输入。
- 重试复用提交时的实际输入与预算，不因当前页面选择变化而换素材。
- 后续成果保留来源说明，删除某条任务记录不删除已保存稿件，也不抹掉成果的来源摘要。

### 4.3 老作品迁移必须诚实

- 显式升级作品与章节的数据结构，保留 3.8.2 已有的要素、大纲、剧本历史，不丢弃旧成果。
- 老作品若只剩一份已编辑正文，不能伪称其为“未经修改的原文”。应标记“升级前保存的正文”，缺失的原文来源说明清楚。
- 只有能从可靠源文件和原有拆章参数确定重建、且核对章节对应关系后，才可恢复真正原文；无法证明时不猜、不覆盖。
- 原文文件缺失或损坏必须报数据异常，不能补空正文。
- 升级失败不破坏旧作品；迁移流程可重试且幂等。

## 五、生成记录参照提词库

### 5.1 日常生成区域

- 只显示当前打开的一条任务结果；最近任务使用提词库同类紧凑行，建议沿用最多 3 条。
- 紧凑行显示任务名称、阶段、状态、时间和“查看”，不直接展开多篇长正文。
- AI 改编、要素、大纲、剧本任务都可查，但始终限于创作场，不混入提词库记录。
- 内容卡片只来源于作品中已保存内容；未保存任务不冒充稿件版本。

### 5.2 完整历史与统一入口

- 完整生成记录进入“管理记录”内的“生成记录”页签；最近任务区域可以提供直达该页签的“全部记录”。
- 这与“完整记录独立查看”的要求一致，不另造一套分散的历史管理弹窗。
- 点一条记录进入单条详情，返回后保留筛选、滚动与多选状态。
- 成功、失败、取消和中断状态有文字区分；重试创建或恢复任务时沿用现有任务机制。
- 保存成功的任务标出“已保存为某改编稿／某阶段版本”，避免再次引导用户重复保存。

## 六、阶段栏最右侧：管理记录

### 6.1 位置与范围

阶段栏布局定为：“拆章 / 要素 / 大纲 / 剧本”在左侧，“管理记录”固定在同一栏最右侧。

- 桌面、手机横屏、手机竖屏都有该入口，不埋进卡片的省略号菜单。
- 窄屏阶段按钮可在自己的区域内滚动，“管理记录”不能随阶段按钮一起被挤到看不见的位置。
- 打开统一管理面板；桌面采用宽面板／弹窗，手机采用全屏管理视图，关闭返回原阶段原位置。
- 默认只管理当前作品；未选作品时提示先打开作品，不能默认对全部作品执行批量删除。

### 6.2 管理内容

| 分类 | 管理对象 | 行内信息 |
|---|---|---|
| 章节稿件 | 原文、升级前正文、人工改编稿、AI 改编稿 | 章节、稿件名、类型、字数、时间、是否被本次选择引用 |
| 要素 | 各次已保存要素 | 名称／版本、来源章节及稿件、时间 |
| 大纲 | 各次已保存大纲 | 名称／版本、来源章节及稿件、时间 |
| 剧本 | 各次已保存剧本；所选剧本下的场次 | 来源、版本、场次数、时间；场次可在详情中多选管理 |
| 生成记录 | AI 改编、要素、大纲、剧本的任务 | 阶段、状态、时间、是否已经保存成果 |

- 支持按分类、阶段、章节和关键字筛选；内容按需加载，长列表分页。
- 提供“多选”“全选当前筛选范围”“取消选择”“删除选中”。全选涉及哪些记录必须显示明确数量，不暗选其它作品或未纳入范围的记录。
- 只选可删除项；进行中的任务先取消，确认为终态后才能删除，不能直接清掉仍在执行的记录。

### 6.3 删除语义

- 删除改编稿只删除该稿，不删除原文、同章其他稿件或已保存的下游成果。
- 删除原文明确等同于删除该章的原文记录；确认框列明是否仍有改编稿，并提示可能影响素材选择。原文不会因删除改编稿而被顺带删除。
- 有改编稿的章节可只保留改编稿；若删掉该章全部稿件，按“移除章节”处理，确认时明确说明。沿用作品至少保留一章的规则，整本删除走已有作品删除入口。
- 删除要素／大纲／剧本版本不级联删除已经生成的其他内容。历史来源显示“源记录已删除”，保留提交时的来源说明。
- 删除剧本场次仅作用于明确选中的可编辑剧本稿；历史稿需另存可编辑稿，不在浏览历史时静默篡改。
- 删除生成记录只清任务记录，不删除从它保存的原文、改编稿、要素、大纲或剧本；确认框明确写出此差别。
- 已被当前待提交表单选中的稿件／成果被删除时，清除对应选择并提示重新选择；不能悄悄切到“最新版本”。
- 任务执行期间，正在被其使用的来源记录先锁定删除，用户可等任务结束或取消后再管理；已完成任务使用固定输入，不因后续删除来源而改变内容。
- 批量请求执行前统一校验权限、作品归属、引用保护和 `revision`，无效选项不导致悄悄删掉一半内容。
- 多文件删除先原子提交清单变更，再清理已解除引用的文件，避免进程中断后留下“清单仍指向已删文件”的坏记录。清理失败明确反馈并可重试。
- 确认框列出分类、数量、作用范围与不可撤销说明；取消不写盘。删除后的列表、正文、选择器和右栏同步更新。

## 七、右侧栏：说明本次到底会做什么

替换固定的“下一步 · 阶段二”说明，随阶段、选章、选稿及任务保存状态变化。作品与导出路径也必须在此区域或对应操作反馈中说清，不能让用户猜文件保存到了哪里。

### 7.1 所有生成阶段都要显示

- 是否已保存为作品、选了几章、使用的供应商和模型。
- 每章使用“原文”还是哪份“改编稿”，实际字数以及是否将超过每章上限。
- 当前每章字数上限、一次允许的章数，以及本次实际发送的正文总量。
- 当前输出是临时生成结果还是已保存内容，保存后会新增哪类卡片。
- 生成前就展示省略章节及省略字数；不能等任务排队／计费后才通知用户。
- 所有阶段信息卡均提供清楚的阅读／保存／操作提示，但没有对应动作的“保存状态”维持为状态文本，不套用按钮样式。
- 保存状态附近明确说明作品存放目录：使用实际运行数据目录的 `studio/novel/<book-id>/`；冻结版通常是 `%LOCALAPPDATA%\NaibaChat\data\studio\novel\<book-id>`，若用户配置了自定义数据目录则显示实际配置位置。
- “打开保存位置”只有在桌面环境和宿主允许时才显示为可操作按钮；手机网页不可直接打开本机文件夹，显示完整路径并提供复制路径按钮，不承诺手机能浏览电脑磁盘。
- 导出开始前显示格式、导出文件名及包含范围；完成后状态显示文件名与路径行为：由浏览器发起下载、通常保存到浏览器默认下载目录，或遵从系统／浏览器弹出的保存位置选择。绝不声称服务器已将 Blob 导出写入作品目录。
- 导出菜单可提示默认下载位置并链接“查看作品保存位置”；每次导出完成告知格式和文件名，失败保留明确错误。
- 显示数据目录时使用后端实际解析路径，不在前端猜 `%LOCALAPPDATA%`、源码目录或 EXE 相邻目录。完整本机路径只在当前客户端展示，不写入任务记录或模型提示词。
- 手机“预览”分档能看到完整说明，不仅桌面右栏可见。

### 7.2 各阶段专属说明

- 拆章：原文只读；手动编辑和 AI 润色会生成改编稿；原文与改编稿可以分别作为后续素材。
- 要素：根据本次选择的章节稿件整理人物、场景和道具，不要求事先有大纲。
- 大纲：可直接根据章节稿件生成，不强制先生成要素。
- 剧本：未保存要素／大纲也能直接生成；有保存内容时按明确选中的版本加入人物设定和改编大纲。
- 剧本的引用详情：当前选择的要素、大纲名称与来源，是否引用前文摘要；没有时显示“未使用，直接根据章节改编”。
- 所有阶段提示：“仅生成、尚未保存到作品的内容，不会自动被后续步骤引用。”
- 手机“预览”分档能看到完整说明，不仅桌面右栏可见。

## 八、字数与章数滑条

### 8.1 本计划确定的参数

| 控件 | 默认 | 可调范围 | 含义 |
|---|---|---|---|
| 每章正文上限 | 3000 字 | 3000–15000 字，步长 500 | 每个选定章节稿件本次最多引用多少字符；不是模型输出长度。 |
| 一次最多选择章节 | 6 章 | 1–20 章，步长 1 | 用户可提高超过 6 章；超过当前设定的选章不允许提交。 |

20 章是本轮产品交互的最大值，由本计划确定，不代表任意模型都能接收 20×15000 字。最大组合的章节正文为 300000 字，必须根据实际模型容量预检，不能机械放行。

- 两个滑条配文字值和键盘可操作的数值输入；手机能触控，值变化立即反馈。
- 参数按用户保存为后续默认值，作品切换不无故重置；已提交任务另外保存自己的参数快照。
- 导入的拆章块长与“本次生成每章字数上限”是两个不同设置，文案不能混为一谈。
- AI 润色也使用正文限额规则，固定单章来源，不暗中转成一次全书改编。
- 人物 800 字、大纲 1200 字等现有额外槽位限额本次不擅自放大；仍需在预检中说明实际引用和省略范围。

### 8.2 提交前预检与正式组装共用规则

1. 服务端读取被选定的稿件，核对归属、版本和实际字符数。
2. 按滑条值计算每章引用范围和逐章省略量；右栏显示实际输入，而非仅显示“最多 6 章”。
3. 连同指令、人物、大纲、前文摘要、补充要求，估算完整输入的 token；复用项目现有估算方式并标为“估算”，不把字符数当成精确 token。
4. 将估算输入与模型配置／探测得到的上下文容量、输出预留对照；已知不足时阻止提交并给出减章、调低字数或换模型的具体建议。
5. 容量未知时明确提示“无法确认模型能否容纳本次素材”，不伪造模型上限；大输入需用户确认后才提交。
6. 有正文省略时必须提交前确认；用户可以调高滑条或减少章节，也可按明确片段另行处理，不自动换成摘要。
7. 预检和正式提交复用同一个预算／组装函数；正式提交重新校验稿件版本，避免预览与实际发送内容不一致。
8. 重试复用任务内保存的字数／章数设置和实际输入，不能回落固定 3000／6。

## 九、卡片展开、收起与正文排版

### 9.1 可反复折叠

- 区分“选中用于生成”“选中批量管理”“展开阅读”“进入编辑”四种状态，不能共用一个点击状态。
- 每张内容卡片以稳定 ID 记录展开状态，标题栏有箭头与“展开／收起”，同步 `aria-expanded`。
- 同一标题再次点击确实关闭正文；点编辑、保存、复选框等操作不冒泡触发意外折叠。
- 轮询任务状态、更新保存提示、切阶段返回时，不得无条件重新展开用户收起的卡片。
- 有未保存编辑时收起或切稿需要保护草稿；不能折叠就丢稿，也不能为了保护草稿完全禁用收起。
- 当前章节若通过左栏选中，选中高亮与卡片展开分别管理；重复点击同章按界面约定收起或展开，不重新打开覆盖状态。
- 原文、改编稿、要素、大纲、剧本及任务详情都纳入检查，避免只修一处展开逻辑。

### 9.2 消除“正文”下空白

- 阅读态用只读正文区域；只有点击“编辑”才出现输入框，不把大空白编辑表单当常驻阅读器。
- “正文”标签与正文首行保持普通字段间距，不使用剩余高度把标签行单独撑大。
- 检查网格行分配、`flex: 1`、`min-height`、textarea 全局样式、行间距及 `[hidden]` 覆盖，按复现证据修根因。
- 短章也从顶部显示，不为填满面板留出一大块中间空白；长章在正文区滚动。
- 要素／大纲／剧本面板克隆与活动 ID 交换保持唯一性；隐藏阶段的表单、正文和监听器不能挤占当前面板。
- 纸面与浏览器验收都关注“正文首行出现在哪里”，不能只断言 textarea 有内容。

## 十一、验收标准

### 11.1 必须跑通的真实用户路径

1. 导入并保存作品，选第一章，只出现一张原文卡；正文首行紧跟卡片标题／正文标签，没有大块空白。
2. 编辑第一章并保存，出现原文＋改编稿 1；刷新后两者完整保留，原文逐字不变。
3. 基于改编稿 1 再编辑生成改编稿 2，来源清楚，改编稿 1 保留；无改动保存不重复建卡。
4. 按用户要求提交 AI 润色；生成成功但未保存时只在任务结果中，保存后新增一张稿件卡；重复保存被拒绝。
5. 要素、大纲、剧本分别使用不同章节稿件；核对实际模型输入与右栏逐章对应，刷新／重试后不串稿。
6. 跳过要素和大纲直接生成剧本可用；保存的参考按选择引用；未保存的结果不混入。
7. 每类卡片连续展开／收起三次；轮询、保存状态变化和切阶段返回都不把已收起卡片强制打开。
8. 最近任务只占紧凑列表；完整任务进入“管理记录”的生成记录页签；正文区域一次只展开一条任务结果。
9. 字数滑条分别验证 3000、6000、15000；章数上限验证 6、7、20，21 章拒绝；预检提示与实际发送内容一致。
10. 上下文不足在调用模型前拦截；上下文未知如实提示；不存在“滑条 15000 实际仍按 3000 截断”。
11. 从阶段栏最右侧打开“管理记录”，筛选并多选删除改编稿、要素、大纲、剧本和终态任务；原文、其他稿件和已保存下游成果不被误删。
12. 验证删除原文、删除全部稿件、移除章节、删除已选来源、删除当前版本、取消确认、并发修改和文件清理失败；范围与结果都明确。
13. 老作品升级后已保存内容不丢；无法恢复的原文不被伪造；旧任务与成果可继续查看。
14. 保存作品、稿件与来源后重启应用，稿件选择、历史、字数设置与引用关系仍一致。
15. 原文卡片、改编稿、要素、大纲和剧本详情可查看保存状态与作品位置；状态文字不呈现成无动作的假按钮。
16. 冻结版且未设置自定义目录时，路径提示指向真实 `%LOCALAPPDATA%\NaibaChat\data\studio\novel\<book-id>`；源码版和自定义数据目录显示各自实际解析路径，不因运行方式写错目录。
17. 浏览器导出反馈明确显示格式、导出文件名和“已交给浏览器下载”，提示在浏览器下载列表查看；若宿主弹出另存对话框，只在能够确认保存成功及实际路径后显示完成和目标位置。
18. 作品位置可复制；桌面“打开保存位置”与手机提示按 §7.1 验收，手机不能出现无法执行的电脑文件夹打开动作。
19. 手机三个分栏按钮在未选中时仍看得出可以点击，选中、按下和键盘焦点反馈明确；验证三个按钮可反复切换，隐藏面板不占位或拦截操作。

### 11.2 自动化与界面验收

- 服务端使用临时目录与本地假模型，覆盖迁移、原文保留、跨章归属、AI 结果保存幂等、输入快照、预算和批量删除一致性；不调用真实付费供应商。
- 前端覆盖单稿／多稿、没有参考／有参考、零任务／4 条以上任务、多阶段反复切换及长标题、长正文。
- 扩展现有小说冒烟，断言卡片数量与已保存稿件一致，任务数量不会增加稿件卡数量。
- 桌面：1440×900、1280×900；手机横屏：844×390、812×375；手机竖屏：390×844、375×812；浅色／深色均检查。
- 视觉检查：管理入口可见、按钮可触达、滑条值可读、正文从顶部显示、折叠后空间回收、面板能独立滚动、隐藏区不可聚焦、全页无横向溢出。
- 修改后跑相关测试与全量 `python -m unittest discover -s tests`，以及前端语法／模块图和文档编码守门。
- 浏览器 smoke 的脚本断言通过不能代替实际视觉检查，特别检查手机短高度和正文留白。

### 11.3 冻结版专门验收

- 对新构建的隔离冻结包验证，不仅在源码版假数据页面检查。
- 核对冻结包携带的 `index.html`、`styles.css`、`25-novel.js` 与目标提交一致；遇到 CRLF／LF 差异先归一换行，不能误判为漏打包。
- 在独立配置、独立端口用合成作品跑上述原文／改编稿、记录管理、滑条与折叠路径，不操作用户正式数据。
- 同时用桌面内置页面和手机视口访问同一个冻结版服务，核对后端版本、页面资源标记和实际显示一致。
- 更新后新桌面窗口正常加载；已打开手机标签页刷新后加载新资源。若自动刷新要另立需求，不用它遮盖本次布局与内容逻辑问题。
