# 造梦机对话预设 Agent 与专用工具集设计

日期：2026-11-17
状态：设计稿，已完成关键源码静态核对；参数指认作为推荐方案，待用户审阅，尚未实施。

## 1. 目标与范围

新增一个可在对话顶栏选择的内置 Agent「造梦机助手」，配一套明确的专用工具白名单。Agent 能读取用户在造梦机导入的工作流，指导用户确定提示词、画幅、分辨率及其他工作流支持的常用参数，再提交造梦机原生单次任务或原生批次。任务在造梦机现有页面出现，完成或失败后回到发起对话通知用户。

沿用现有 Agent 的 system_prompt、skill_ids、tool_scope 和会话首轮固化机制。Agent 不使用 HTTP、Shell、通用代码执行、任意文件写入、旧 ComfyUI 直提工具或子 Agent，也不自行制作或修改工作流。

造梦机现有导入、编辑、单次、批量、历史和重试操作保持原有语义。新对话入口复用服务层，不修改现有页面的操作流程，也不接管页面草稿。

## 2. 初步交互

用户：我要生成一只猫。

助手：可以，用造梦机生成。提示词直接用「一只猫」吗？你也可以补充外观、场景和风格。图片要横图、竖图还是方图，分辨率要多少？当前可用工作流如下，选一个编号即可。

工作流列表必须来自实时工具结果；编号只在本轮列表有效，实际提交使用工作流 ID 和指纹。

用户：提示词：一只猫，9:16，1.0MP，工作流选4。

助手：按工作流实际尺寸控件确认可执行的宽高。如果不能从工作流公开参数安全得到宽高，说明原因并要求用户补充配置，不猜节点、不把比例塞进未知字段。准备完成后，按现有授权规则提交，不重复索要用户已经明确给出的参数。

任务成功受理后：已在造梦机创建任务，你可以在造梦机看到任务卡片。只有后台通知登记成功，才承诺完成或失败后通知。

## 3. 工具集设计

以下均为待新增的专用工具；统一使用这里的名称，模型只传用途 ID 和用户值，宿主解释为真实参数地址。

- `dream_workflows`：分页列出实时工作流，返回稳定 ID、名称、指纹、可用状态；分类与用途仅使用有依据的资料。
- `dream_workflow_details`：查看指定工作流已指认的参数、常用参数、媒体槽、默认值和校验约束；未指认参数仅作为候选说明，不把整张工作流图交给模型，也不开放按裸地址写入。
- `dream_prepare`：无生成副作用的预检，解析明确的参数绑定，计算实际宽高和实际生成次数，返回可提交快照或缺失项。
- `dream_submit`：按预检快照创建造梦机原生单次任务或批次；幂等提交，返回实际任务/批次 ID。
- `dream_task_status`：读取当前执行归属已关联任务的进度、产物和错误；主对话按会话校验，总管受管Run按节点/attempt校验。
- `dream_task_cancel`：取消当前执行归属已关联且允许取消的任务；不扩大到造梦机全库。
- `dream_task_wait`：有界等待；主对话可登记后续通知，总管来源向原节点交还执行关联并由宿主跟踪；复用或扩展现有基础设施，不让模型空轮询。

工具输入契约以准备快照和用途绑定为边界，不把总管的通用控制面交给模型。真实待补接口和衔接见第 7 节。

## 4. 单次与批量

同一提示词生成多张，优先复用造梦机现有 shots。多个不同提示词、不同逐条素材等任务，使用造梦机原生批次，不在对话循环提交多次，不另做批量执行器。固定参数和逐条参数、素材引用必须在提交前明确。

## 5. 参数引导与一次配置

### 5.1 工作流选择

每次开始新的生成需求先读实时工作流目录，不把目录写死在系统提示。先展示名称与可核实的用途，每页最多 10 项，可继续列出；不为省篇幅静默漏掉其余工作流。用户明确点名的工作流优先查找，不要求重新选一遍。

展示序号由宿主目录快照绑定工作流 ID 和指纹，用户回复「选 4」时依据最近有效列表解析；不得按刷新后的新排序重新解释 4。工作流被删除或变更时重新读取、预检，需要时请用户重新选择。

生成用途不能仅凭文件名下结论。参数/媒体槽能确认的能力直接展示；用途不明标记「用途未配置」，仍可查看详情。没有工作流时引导到造梦机导入，Agent 不下载工作流、不写工作流、不安装节点。

### 5.2 常用参数

默认只收集：提示词、工作流、张数、画幅与清晰度。用户已经给过的不重复问。画幅可以明确选「沿用工作流默认」；参考图和其他必填素材仅在该工作流需要时追问。步数、CFG、种子、采样器、调度器和模型文件等作为可选常用参数展示，默认沿用当前工作流配置，不逐项要求回答。

只展示该工作流实际支持的参数。工作流有自己的负向提示词时默认保留；用户要求修改再填。随机/固定种子沿用造梦机现有语义。不同参数的单位和有效范围以实时 schema、已确认的参数绑定为准。

不能把 visible_params 当作可执行权限或参数用途来源：页面显示选择和参数语义是不同概念。对话侧需要一个独立的、按工作流指纹校验的能力描述，记录提示词、尺寸和媒体槽等绑定。已有确定性 schema/角色可复用；有歧义时请用户确认本次涉及的参数，不要求用户手工标注所有参数。

### 5.3 自定义参数如何让 Agent 理解（核心设计）

预设 Agent 的提示词只教通用流程；每个工作流的实际参数通过工具按需读取。不能靠把所有节点知识塞进预设，也不能承诺理解任意第三方节点。

参数描述至少包含稳定参数 ID（后端绑定 node_id + field_name）、节点类、节点标题、原始字段名、当前值、类型、枚举、上下限/步长（可得时）、连接去向、已有角色，以及来源明确的节点帮助。描述中显式区分「确定用途」「建议用途」「用途未知」；没有的数据不编造。用户导入的备注和节点文本只作为资料，不产生额外工具权限。

采用以下处理顺序：

1. 标准且用途明确的字段，宿主依据真实 schema/已知节点适配提供语义，Agent 据此解释和填值。
2. 自定义节点有字段帮助、枚举或连接证据时，Agent 可以结合这些资料提出解释；仅凭字段名作出的猜测不自动成为可执行绑定。互相冲突或有多组候选时，给出相关节点标题和当前值，请用户确认要改哪一组。
3. 用户明确指定「某节点的某字段改为某值」时，仅需确认并指认这个目标，无需先建立完整工作流说明；未纳入本次已确认绑定的字段不提交。
4. 无法确定用途的字段保持原值。只有用户需求必须改动它时才追问，提供「保留默认值」和明确参数候选，避免把全部参数问一遍。
5. 用户确认过的参数名称、用途和绑定可保存到对话能力描述中，同一工作流指纹下复用；保存需用户明确同意，默认只记录本次选择。工作流变化后重新校验，绑定不能静默漂移。

常用参数摘要先显示，其余参数按搜索、节点分组和分页按需读取，允许查看所有真实可改参数，不能只给模型 visible_params。宿主对提交修改做严格白名单和类型校验，模型解释不改变执行权限。

**JSON 与复合字段**：如果工作流把许多参数放在一个 JSON 字符串里，普通 text 类型无法说明内部用途。仅对现有专用编辑器/适配能解析的结构或有可靠 schema 的结构提供子字段（例如「配置 → 输出 → 分辨率」），由宿主按已解析路径局部修改并校验，保留未知字段；没有解析规则的作为不透明参数，不让 Agent 重写整串 JSON。动态枚举和模型文件候选以实时节点能力为准，无法刷新时标记未校验，不自行下载或安装。

这套设计不要求 Agent 理解所有参数才能工作；它需要可靠识别本次要改的少量字段，其余参数沿用用户已经调好的工作流。

### 5.4 参数指认方案（推荐定稿方向）

采用与造梦机批量生成相同的指认方式，新增可选的「对话参数配置」。**不增加造梦机分页**：入口放在现有「工作流」页选中工作流后的操作菜单，点「对话参数」打开弹窗；对话缺少配置时由宿主提供按钮打开同一个弹窗，确认后回到原对话，保留已经给出的提示词和参数。此按钮是确定性界面操作，不让模型生成任意可执行 HTML 或 URL。

弹窗默认展示提示词、尺寸、参考素材三组配置，以及已配置的常用参数摘要；高级参数按需展开或搜索，不一次铺满全部节点。每组复用现有批量指认选择器的标签和消歧方式。自定义参数通过「添加参数」逐项加入，允许设置显示名、用途和询问策略，不引入独立参数管理页。配置作用于所选工作流，标题明确显示工作流名称。

复用现有参数扫描、节点/端口标签和参数选择控件，配置保存在服务端，按工作流 ID + 指纹绑定。现有批量映射和页面草稿保持不变；可显式复制已有映射作为候选，复核后保存到对话配置，不暗中导入浏览器状态。

用户只需指认希望 Agent 修改的参数，无需逐项解释整张工作流。模型不能从指认界面扩权，允许写入的地址及转换规则由宿主配置决定。指认表建议如下：

| 对话用途 | 实际绑定 | 填写规则 |
|---|---|---|
| 正向提示词 | 单个或多个经确认的文本槽 | 多个文本槽可分别命名为主体、场景、风格；不默认把整段提示词复制到所有槽 |
| 负向提示词 | 指定文本槽 | 默认保留，只在用户要求时修改 |
| 输出尺寸 | 一组 width + height，或节点原生比例/MP槽 | 宿主负责单位、步长和取整转换；多组尺寸分别命名为输出、参考图处理、二次放大等，不自动全部改 |
| 随机种子 | 指定 seed 槽或已有 seed 策略 | 用户选择随机或固定，沿用造梦机种子语义；不同阶段的 seed 不自动联动 |
| 步数、CFG、采样器、调度器 | 各自指定数值/枚举槽 | 默认不追问，用户要求再改；保留真实范围、枚举 |
| 参考图/视频/音频 | 指定媒体槽 | 按用途命名；显式标记必填、可选、沿用固定素材的策略 |
| 自定义参数 | 任意已扫描、允许编辑的参数，或已适配的复合子字段 | 用户给名称、简短用途、可选单位及选项解释；类型与范围来自 schema，不能随意自报 |

每条绑定还可设「每次询问」「用户提到再改」「保持默认」及是否在批量中允许逐条变化。未配置的参数默认保持原值；不向 Agent 提供写入目标。预设默认只把提示词、工作流、数量、尺寸和缺失的必填素材视为本次收集项，其余按配置决定。

工作流首次用于对话且关键用途未指认时：宿主显示必要字段的指认表，已有确定性候选可预填但必须标明依据；请用户确认关键绑定，不要求确认所有高级字段。若用户选择原尺寸，只需指认提示词即可开始文生图。聊天工具返回「缺少哪些绑定」及可打开的配置入口，不要求用户输入 node_id 或代码。配置面板是新增可选入口，不改变原有单次/批量表单和操作顺序。

同一份配置供该工作流的对话单次和对话批量使用；批量中「固定参数」与「逐条参数」复用其稳定用途 ID。不同工作流各有配置，不能因同名字段就跨工作流沿用。工作流指纹变化时重新校验绑定，失效项单独提示；不能只按名称自动迁移。用户可随时重置对话配置，重置不改原始工作流。

JSON、动态控件等只有宿主已支持解析时才能指认其子字段，不能将「指认了 JSON 槽」等同于允许 Agent 重写整个配置。无法解析时可以保留原值并继续生成，不影响已有造梦机原生编辑能力。

相比直接让 Agent 猜所有自定义参数，这个方案把准确性放在用户可见的一次确认上；Agent 负责理解需求与引导，程序负责地址绑定、尺寸换算和校验。应先实现这套指认，再考虑模型辅助推荐绑定。

### 5.5 比例与 MP

`1.0MP` 定义为目标总像素约 1,000,000，和长边像素、文件大小是不同单位。若工作流使用宽高控件，可用 `W≈sqrt(P×r)`、`H≈sqrt(P/r)` 得到初值，再按节点真实步长、上下限及允许尺寸约束选取实际宽高。比例/MP是否严格、取整允许误差及候选排序由确定性程序实现，不能让模型自由计算后随意填写。

预检返回用户请求、实际宽高、实际比例、实际 MP 和取整说明。小幅合理取整在提交回执里说清；无法同时满足或差异明显时先让用户选尺寸。工作流原生使用比例/MP控件的，直接按对应 schema 绑定，不再强行写宽高。没有可信尺寸绑定时拒绝修改尺寸，提供「用工作流默认尺寸」或「在造梦机配置尺寸参数」两条可行路径。

9:16 + 1.0MP 的最终宽高必须在选定工作流后才能确定，不在预设提示里固定写成某个尺寸。

## 6. 请求确认与生成回执

参数齐全且用户已经明确要求生成时，先无副作用预检，再按当前会话既有授权模式提交。预检不需要模型再问一次同样的问题。若宿主仍要求动作确认、工作流发生变化、数量扩大或尺寸不能满足，则走对应确认；Agent 不能替用户批准。

提交中立即返回稳定请求标识，不让超时引发第二次生成。只有取得原生任务/批次 ID 才能说「已创建任务」。失败回报需区分未提交、已受理但生成失败、受理结果尚待核对；最后一种只查原执行，不盲目重提。

成功回执至少包含：工作流、实际尺寸、预计生成次数、造梦机任务/批次链接、通知是否成功登记。任务卡片和状态以造梦机原生记录为准。生成数量和产物文件数分开记录，一个工作流执行可能产生多个文件。

## 7. 源码核对结果与实现安排

### 7.1 已有能力与缺口

- Agent 已有明确 tool_scope、首轮会话固化和执行前拦截。工具模板是复制名单，不是绑定 preset_id。新增预设沿用这些机制，不改已有 Agent 或会话。
- 工作流参数已经包含 field_type/default/role/node_title/class_type/label/connections，以及 control/candidates/media_optional 等增强信息；还缺通用的数值上下限/步长、description、单位与 JSON 子字段 schema。现有尺寸角色仅 width/height，没有完整比例/MP语义；需要补描述、确定性适配和绑定。
- 当前批量映射部分来自浏览器 localStorage，后台工具不能直接复用这份浏览器状态。对话用的映射独立保存且明确来源，不覆盖页面现有映射和草稿。
- 原生单次 submit 已有 owner_id/request_key；原生批次 create 没有外层 owner/request_key。须补批次请求幂等及总管关联，不能把超时后再 POST 当作重试。
- 当前总管没有造梦机原生任务/批次 Adapter；现有 job 关联对应 app.jobs，不能冒充原生造梦机任务。
- 普通后台等待目前直接读 app.jobs，不能把造梦机原生 ID 原样传给 job_wait。需要类型化目标解析及专用通知工具。

### 7.2 统一调用路径

`对话预设 Agent → dream_* 专用 Provider → 总管原生造梦机 Adapter → 现有造梦机单次/批次服务`。

目录和参数读取走工作流服务的只读快照；提交、关联与授权通过总管适配；实际上传、队列、执行、重试和产物仍由造梦机完成。目录读取不需要创建任务总管线程，只有提交时建立一个生成节点并记录发起对话。不得恢复 recipe_batch/配方执行器，不额外调用执行模型。

原生任务关联至少记录 conversation_id、origin_run_id、准备快照 ID、request_key、总管节点/attempt、native task/batch ID。owner 和请求标识由宿主生成，工具参数不能自报 owner、权限或任意执行 domain/kind。

`dream_prepare` 生成有期限的不可变快照，绑定当前执行归属（主对话或总管节点/attempt）、工作流指纹、参数修改、素材引用、单次/批量模式与实际次数；返回人类可读摘要及缺失项。`dream_submit` 只接受有效快照 ID，不接受任意工作流图或原始执行器参数。工作流变化、素材失效时重新准备。过期但已提交的快照仍能查到原任务，不重复创建。

读取详情现有入口可能联网重扫并保存元数据，新的只读工具需抽取真正的读取/能力描述路径；更新扫描结果与用户确认的参数说明需作为显式独立操作，不能暗中修改工作流。

### 7.3 权限与工具集

内置 Agent 建议 `id=dreamer`，名称「造梦机助手」，skill_ids 默认空；有效工具名单严格为本方案七个dream_*工具。为避免「未限制」Agent自动纳入新增生成能力，建议七个工具走既有单独授权通道，出厂预设tool_opt_ins明确包含本组，tool_scope保持非空且限定同组；具体序列化遵守现有opt-in规则并以最终固化名单验收。无需授予通用读文件、写文件、HTTP、Shell、旧 comfyui_prepare_workflow/comfyui_batch、run_in_background、子代理、MCP 或能力安装工具。参考素材由宿主从本会话真实附件解析并经造梦机受管上传，不让模型传任意本机路径或远程 URL。

执行归属由宿主解析为当前会话，或总管明确派发的thread/node/attempt；所有工具共用该归属，不信任模型自报标识。参数说明需保存时由宿主呈现确认动作，复用现有明确确认通道；无人值守执行遇到需保存或补指认时返回待用户处理，不为此开放通用文件写入或任意配置修改工具。

新工具不要加入现有 Job 创建器的依赖闭包，以免自动带入其他控制工具；单独登记确有需要的依赖。system=True 的 Provider 不能仅靠 permission 字段就假定会弹确认，submit/cancel 必须接入真实执行权限与确认检查。允许的执行来源包括普通主对话和任务总管明确派发的受管助手Run；辅助对话、未适配的普通子代理和结果通知续答不开放创建生成。总管来源的具体授权、输入与返回契约见第7.7节，不能只因“来自总管”就放行。

既有会话工具集不自动追加新工具。用户选新预设创建新对话即可使用。新增预设与工具模板及教程从同一来源登记，并遵守维护说明 §9.138/9.141/9.145 的同源测试要求。

### 7.4 被其他 Agent 使用时的行为

七个专用工具是可复用能力，不以 agent_id=dreamer 作为授权判据。具有明确工具白名单的其他Agent，需经用户配置并在新会话固化后才能使用；不自动追加到现有出厂预设、默认选中工具集、历史已固化会话或其他工具模板。提供同源的「造梦机对话」工具集模板，套用仍遵守现有工具集复制名单及覆盖确认机制。

当前代码中，空tool_scope表示「未限制（全部工具）」，新会话会通过all_tool_names纳入新注册的普通工具；旧有消息却未固化的兼容路径也存在全工具回退。因此，若要求专用生成能力必须明确勾选，新dream工具须接入现有单独授权（opt-in）通道，不能仅注册为普通工具后声称「只有勾选才可用」。建议整组dream工具明确授权，专用出厂预设携带该授权，其他Agent由用户主动启用；配置/固化/计划模式/辅助对话/子代理/通知续答等全部路径按组验证。此时tool_opt_ins需登记为本组工具，调整前文空opt-in初稿；普通未限制Agent不能隐式获得生成提交能力。只读目录是否同样单独授权可在实施时按一致性收口，默认推荐整组一致。

**工具自身始终执行相同限制**：只能读取已导入工作流，按用户确认的用途绑定准备参数，提交有效快照，操作本会话关联任务；不接受原始图、任意地址/代码、伪造owner或任意总管执行参数。普通主对话/辅助对话/子代理/通知续答的边界不因Agent名称变化。提交前冻结来源会话的实际权限与配置，不能改用造梦机助手或任务总管的更宽权限。参数配置和用户明确生成意图由宿主核验，不能依赖专用预设提示词才成立。

**只走造梦机是专用预设完整工具范围的保证**：其他Agent如果同时有HTTP、Shell、旧ComfyUI工具、子代理等能力，新工具不能撤销这些既有授权，也不能保证其所有生成都经过造梦机。给全能Agent增加这组工具，只能表示它多了一个受限的造梦机入口。需要同样的专用限制时，应使用完整窄白名单创建新对话；不能靠额外勾选本工具集获得该保证。

工具的基本用法与必要编排提示按本会话实际工具集条件注入，不能只写在dreamer.system_prompt里。核心规则包括先读工作流/参数配置、prepare后submit、继承默认、禁止猜绑定、登记通知后才能承诺。只有submit具备且prepare/details等必要依赖也具备时才能提交；用户配置缺项应明确提示缺少哪些工具，不隐式补HTTP、Job或其他执行能力。可用依赖限定在同组窄工具内，最终固化工具名单必须可见并可验收。

完成通知继承发起Run的授权，并进一步收窄为本次目标的只读工具；即使来源Agent是全能Agent，续答也不能获得其Shell、HTTP或再次生成权限。普通主对话是否允许生成依然取决于当前执行模式与权限确认，预设名称不替代授权。

新增跨Agent验收：窄预设、只读Agent、全能Agent自定义增加此工具集、缺少prepare等依赖的配置、辅助对话、子代理、通知续答分别验证。原有Agent的工具列表与行为保持原样，未配置工具时不存在目录访问或提交入口；工具被授权时执行同一套归属、快照、参数与确认校验。

### 7.5 完成通知

扩展现有等待机制的目标引用，明确区分普通 Job、原生造梦机任务和批次；只读 resolver 向各自服务查询真实状态，不创建 app.jobs 假镜像。沿用既有持久等待、一次续答事务、人工输入竞争和重启 needs_attention 机制，保留旧 Job 等待行为。

提交工具成功后由宿主立即登记通知，再一起返回回执，避免完全依赖模型记得再调用 wait。dream_task_wait 用于显式等候、查询等待及恢复用户明确要求继续查看的目标；登记和终态核对要处理「刚生成完才开始等」的竞态。

续答只开放本次目标的只读状态/产物读取，不提供提交、取消或配置修改，也不自动重试失败任务。成功回报图片/视频；失败回报实际错误、已有产物和可行下一步；批次等待全部条目终态后汇报成功/失败/取消数量及产物，不把部分失败说成全成或全败。

通知登记失败时如实说「任务已创建，但自动通知未登记，请在造梦机查看」，并可重试登记但不能重提生成。服务重启后按现有等待规则提示需要继续查看，不承诺关机期间仍会自动通知。人工后续输入优先，不插入失去上下文的重复续答。产物 URL 遵守现有媒体口令与路径校验契约。

### 7.6 批量处理

同提示词多张走 shots；不同提示词/逐条素材走原生 batch schemes/items。参数描述中尺寸对应多字段时，宿主转换为 overrides 或逐条 extra_points 等真实批次契约，不让模型误认为 resolution_slot 天生支持宽高或 MP 派生。预检显示条目数、每条 shots、实际总执行次数，不能把条目数当最终图片数。

长批次不逐条弹确认，同一已确认批次统一授权；新增条目、扩大次数或更换工作流需重新准备和依现有规则确认。取消与失败重试由原生任务契约决定；本工具集不开放自动失败重试，用户可在造梦机原有页面操作，后续若增加对话重试工具需单独设计防重和权限。

### 7.7 未来任务总管调用造梦机助手

这是需要预留的正式执行入口。复用同一个造梦机助手Agent预设与专用工具集，总管可把需要语义整理的生成任务交给它；不另建第二份Agent定义或复制参数解释逻辑。当前版本未实现这一派发闭环，设计接口应兼容，不声称现有子代理直接可用。

总管有两种使用方式，由任务输入决定：

- 已确定工作流、参数用途和值、素材与授权时，确定性Adapter直接提交造梦机原生任务；无需额外模型调用。
- 仍需理解创作需求、组织提示词、选择已指认工作流或整理逐条参数时，总管派发造梦机助手执行该节点；助手继续只用专用工具完成生成，产物及状态交还原节点。是否允许改写提示词由派发输入明确，不让助手擅自扩大创作范围。

执行链为 `任务总管的生成节点 → 造梦机助手受管Run → dream_*工具 → 当前节点的原生造梦机执行关联 → 造梦机`。工具通过执行上下文识别已有父节点，把原生任务挂在这个节点下；不再创建顶层总管任务，不递归委托给同一个助手，不重建已存在生成。多人、多任务并发时也按原节点/attempt隔离。

宿主派发上下文至少包含：父thread/node/attempt、派发身份与授权快照、工作区和可访问素材引用、可选工作流范围及指纹、已确认参数绑定/值、允许的生成模式与执行次数边界、需确认事项、结果返回位置及稳定请求身份。上下文由总管生产并在执行前复核，模型不能伪造这些字段。权限来自该任务的明确授权，同时受选定Agent工具范围、执行模式和运行期guard限制；总管身份不增加权限，委托也不能把助手变成总管管理员。

交互方式：

- 普通对话来源：缺参数就在原对话追问，缺指认就打开同一配置弹窗。
- 总管受管执行：缺参数/绑定或遇到必须确认的动作，返回结构化needs_input/needs_approval和候选项，节点暂停并在总管显示待处理；若有关联对话，可把同一问题投递到该对话，由宿主关联回答。不能空等没有UI的确认、假定默认授权或失败后擅自扩大范围。

任务状态按阶段表达：助手完成参数整理或已提交，不等于生成成功；原节点保持执行中，直到原生单次/批次进入终态。返回至少包含原生任务/批次引用、所用工作流指纹、实际参数摘要、素材引用、状态、产物、错误及用量来源。总管保存持久关联；助手Run退出后，确定性同步继续跟踪原生执行，无需让模型轮询等候。用户明确取消时，按归属沿原生取消路径执行。

通知路由由宿主决定：主对话发起走原对话的等待/续答；总管委托走父节点状态和产物回收，仅在节点配置要求时通知关联对话。不额外注册一份重复主对话等待，不重复报完成。重启和未知提交只按持久关联对账，恢复助手也必须先找已提交原生任务，不能从头再生成。

工具描述应使用「当前执行归属」概念，在会话中落实为会话归属，在总管受管Run中落实为节点/attempt；工具名称与主要业务参数保持一致，区别由宿主上下文处理。首版可以只交付主对话入口，但准备快照、归属解析、结果协议和幂等身份须预留总管来源，不能在七个handler里写死conversation-only。普通子代理在完成上述上下文、确认、恢复与回传适配前继续拒绝生成提交。

增加未来验收：总管派发同一预设，缺参数进入待处理；两节点并发不串素材；助手退出后仍追踪生成；恢复不重复提交；取消/失败/部分产物正确回父节点；总管不被助手递归创建；关联对话只收一次通知。该扩展不改变造梦机现有页面、批次执行器和原生任务存储职责。

### 7.8 询问 / 自动 / 完全三档权限

沿用现有permission_mode=confirm/auto/full，不新增造梦机专属权限档。工具白名单决定哪些能力存在，权限档决定已授权能力执行时是否需要动作确认；full也不能启用未勾选工具、越过工作流/参数指认/执行归属/快照校验。

源码依据：`naiba/tools/executor.py::_evaluate_confirmation_reason`：full免工具动作确认；自定义policy优先；无副作用免确认；普通副作用在auto免确认、confirm需确认。`naiba/skills/agent.py::_execute_with_retry`中的整段围栏来源仍遵守现有强制确认规则，不能因新增Provider绕开。

| 操作 | 询问 confirm | 自动 auto | 完全 full |
|---|---|---|---|
| 工作流目录、参数说明、只读预检、状态/产物查询 | 直接读取 | 直接读取 | 直接读取 |
| 原生单次生成/同提示词多张 | 提交前一张动作确认卡 | 参数齐全且任务范围明确后直接提交 | 参数齐全后直接提交，不弹普通动作确认 |
| 原生不同提示词/素材批量 | 整批一张确认卡，展示工作流、条目/次数与参数摘要 | 在该次请求明确范围内直接提交 | 在该次请求范围内直接提交 |
| 取消已关联生成 | 按现有副作用规则确认一次 | 直接执行 | 直接执行 |
| 同一生成登记通知、等候与完成续答 | 不追加生成确认 | 不追加生成确认 | 不追加生成确认 |

准备快照产生临时持久记录属于宿主预检设施，不能启动生成、改原工作流或保存用户参数配置；三档均不为纯预检弹动作确认。批量批准应绑定不可变快照及实际次数，一次整批批准后由原生runner逐条执行，不能每条再弹；未批准不创建可执行生成。若确认摘要过长，展示完整数量和可展开条目，不静默隐藏范围。

“缺信息追问”和“执行动作确认”分开：缺少提示词、尺寸选择、工作流选择、关键指认或必填素材时，三档都返回具体缺项；用户已给值或选择默认时不重复追问。auto/full不会让模型猜未知参数。保存或修改参数指认是独立界面配置操作，由用户在弹窗里明确保存；不因full而允许Agent擅自更改绑定。

full不替代输入校验、归属验证、幂等、防重复、取消竞态或执行边界。付费节点有已配置的预算/审批要求时按原要求执行，不借full绕过；auto不为一切ComfyUI生成新增统一的第二次付费确认，也不能仅凭ComfyUI地址为本机就声称执行免费。当前工作流无法确定计费时不编造价格，按真实可得信息呈现。

总管委托使用该节点派发时冻结的permission_mode，并按原节点批准范围执行，不读取别的会话或临时全局full作为替代。confirm下若无可用确认UI，返回needs_approval暂停总管节点，交给既有审批通道；已有批准只有在明确覆盖同一生成快照/次数时才可消费一次，不能无限续用。auto/full沿相同语义执行，缺参数仍needs_input。运行期收紧权限/用户取消继续由已有guard复核，不能因快照允许忽略取消。

三档测试需覆盖单次、多张、批量一次确认、取消、拒绝/超时、确认期间快照失效、围栏来源、通知无重复生成、full调用未启用工具被拒绝、总管无UI待审批。新工具必须接统一判定与确认后复核；禁止system=True直接绕过这套规则。

## 8. 验收要求

- 新对话能列出真实导入工作流，参数来源可追溯，用户选编号不会误提交到另一工作流。
- 只提交造梦机已有工作流，模型伪造 HTTP、Shell、旧 ComfyUI、子 Agent 调用均被既有权限系统拒绝。
- 提交后在造梦机对应列表出现原生任务或批次，页面仍能正常操作。
- 单次与批量完成、失败、取消、断网和重启均有明确状态，不重复生成，不虚假承诺通知。
- 原有造梦机功能、已有 Agent、历史固化工具集不被自动改写。
- 不新增造梦机分页；工作流菜单和对话缺配置入口打开同一参数指认弹窗，桌面与 375px 手机均能确认、取消并保留对话输入。
- 自定义节点、多组宽高、动态枚举、JSON 子字段、失效映射都按已确认用途绑定处理；不理解的参数不擅自改。9:16/1.0MP由程序计算并显示实际结果。
- 新工具无通用依赖工具漏入；伪造快照、越会话查询、重复提交、批次受理未知、原生结果晚到、通知登记竞态和重启均有对应守门。

## 9. 预设系统提示词草案

> 你是 Cat Chat 的造梦机助手，使用用户已经导入造梦机的工作流完成图片、视频等生成需求。
>
> 开始新生成需求时先读取当前工作流目录；用户选过且没有更换意图时继续使用该工作流。只列真实工作流，按最近目录快照解释选择编号。读取所选工作流的对话参数配置、默认值与素材要求。
>
> 收集本次需要修改的提示词、数量、画幅/清晰度与必要素材。用户已经明确给出的内容不重复问；用户可选择沿用默认参数。步数、CFG、种子、采样器等除非用户提出或配置要求询问，否则保留默认值。提示词需要润色时先让用户选择保留原文或使用改写内容，不擅自扩展用户已确认的提示词。
>
> 只能填写已经指认的用途参数。参数用途不明、存在多组候选或缺少绑定时，说明具体缺项，并使用宿主提供的参数指认入口；不要猜节点地址或重写工作流。比例和MP交给准备工具计算，按工具结果报告实际尺寸。
>
> 相同提示词多张使用单次多张；不同提示词或逐条素材使用原生批量。提交前用准备工具核对工作流、实际参数和总执行次数；参数完整且用户已要求生成时按会话既有授权规则提交。不得自行批准确认、扩大数量或自动重试生成。
>
> 只使用专用工具，不自行请求生成 API，不写脚本，不导入或修改工作流。模型输出不代表任务已经执行，只有工具返回受理成功才说已创建任务。通知已登记才承诺完成或失败后告知；登记失败如实说明并给出查看入口。
>
> 生成结束按真实状态报告产物、成功/失败/取消数量和错误。将图片或视频附回对话，由宿主提供造梦机查看入口。收到取消要求时只操作本会话关联目标。
