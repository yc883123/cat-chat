# 织书台自由文本出口与断链接通修复计划

> 状态：已实施并随 4.7.1-beta 发布（2026-11-21）。用户 2026-11-21 拍板两项：①freeform 产物要有出口；②断链要接。
>
> 日期：2026-11-21

## 1. 背景与目标

远端用户关闭 JSON（自由文本模式）后反馈四个问题：设定生成完不填充到设定集、内容生成了但看不到、章节无法拆分（不进章节目录）、正文无法使用。

排查结论（见 2026-11-21 讨论记录）：四个现象同一条根因链——自由文本模式下所有结构化阶段的产物只追加进 `setup["freeform_outputs"]` 原始文本列表，后端不回填结构化字段（这是 2026-11-20 计划 §3.3 拍板保住的语义，本身不动），但：

1. **前端没有任何界面展示 `freeform_outputs`**（数据已随 `get_book` 到前端，`27-writer.js` 从未渲染）——「只存不看」；
2. **拆章后没有把文本确认为章节的路径**，正文链硬校验只认章节目录（`pipeline.py:302-303`），目录永远为空 → 正文链对每一章都起不来——「断链无路」。

目标：

1. 自由文本产物有查看、复制、采用的出口；
2. 自由文本拆章生成后停下来等用户确认成章节，确认后落章节目录，正文链随之可用；
3. 不改变「程序不替用户猜字段」的语义：一切回填都经用户明确确认。

## 2. 已核实的现状（代码事实）

- `naiba/writer/pipeline.py:1397-1399`（设定五步）、`:1334-1336`（大纲）、`:1388-1391`（拆章）、`:1319-1320`（章末状态）：freeform 下全部提前 return 走 `_save_freeform_output`，只写 `freeform_outputs`（上限 30 条，`store.py::normalize_freeform_outputs`）。
- `freeform_outputs` 已在 `store.py:452-453` 随 `normalize_setup` 持久化并随 `get_book`（`store.py:943` 返回 `setup`）到前端；`27-writer.js` 无任何渲染（grep 仅 4 处输出模式开关相关）。
- `_decision_editor`（`pipeline.py:888-893`）：freeform 下**恒返回 `"text"`**——即使拆章进入待处理，编辑器也不会是章节行编辑器。这是接通断链要改的第一处。
- 决策链机制完备可复用：`decide_pipeline`（幂等 request_key、四动作、决策历史）、`_supplement_output` 的 `editor == "chapters" and step == "split"` 分支（`parse_split(raw, from_no=本批起点, require_count 默认 False)` 允许数量不足）、`_apply_step_output(kind="manual")` → `append_chapters` 落目录。
- 前端决策面板已有：章节行编辑器（`27-writer.js:1902-1915`，标题/情节简述/章末钩子行编辑，提交 `{chapters: rows}`）、「查看模型原文」折叠区（`:2025-2028`）、跳过确认流程。
- 设定人工保存通道已存在：`saveSetupManual`（`27-writer.js:3127`）用表单 `collectSetup()` 走 `PATCH /api/writer/books/<id>` 的 `setup` 分支（`api_patch_book`）。「采用」只需把文本填进表单字段，保存仍由用户点按钮，不需要新端点。
- 分部大纲（outline_text/outline_review）两种模式共用写回路径（`pipeline.py:1346-1387`），所以远端用户看到「大纲能填、设定不能填」——本次不动这条路径。
- 拆章按 `SPLIT_STEP_CHAPTERS` 多批连拆（`pipeline.py:332`），每批是独立步骤，批间衔接依赖上一批已落库。

## 3. 修复原则

1. **程序不猜，用户确认**：自由文本回填任何结构化字段（章节目录、设定表单）都必须经用户明确操作；预填的候选行不给「直接接受」，必须走「补充并继续」确认。
2. **正文等下游不动**：正文链、段落要点、章末状态在自由文本下的现状不改；章节目录一旦经用户确认落库，正文链自然可用。
3. **不新增语义层**：出口复用现有决策链与人工保存通道，不发明第二套回填机制；自由文本输出列表只放设定页一处，不做多页重复展示。
4. **跳过要留痕**：拆章批被用户跳过时沿用现有决策记录（本批章号缺失的后果在确认弹窗里说清楚）。

## 4. 实施方案（大白话）

### 4.1 设定页加「自由文本输出」区块（出口，前端为主）

在设定页底部（设定表单之后）加一个常驻折叠区「自由文本输出」，数据源 `writer.setup.freeform_outputs`：

- 每行显示：阶段中文名（复用现有阶段标签映射）+ 时间 + 可展开的全文 + 「复制」按钮；
- 列表超过 30 条时后端只留最近 30 条（现状已如此），区块内说明「仅保留最近 30 条」；
- 「采用」按钮按阶段给：
  - `world` → 把文本填进设定表单的世界观字段；
  - `title` → 填进书名字段；
  - `blurb` → 填进简介字段；
  - `genre` / `chars` → **不给采用**，只有复制（题材大类/角色卡是短字段和结构化表单，从散文里自动映射就是替用户猜）；
- 「采用」只填表单，不自动保存；表单脏状态提示照旧，用户自己点「保存设定」。填入前若表单字段已有内容，先弹确认，避免静默覆盖用户手写内容。

### 4.2 自由文本拆章停下来等确认（接通，后端为主）

freeform 模式下 `split` 步模型输出完成后不再直接完成，转为待用户处理：

- `_decision_editor`：freeform 分支改为——`split` 返回 `"chapters"`，其余步骤维持 `"text"`；
- `_parse_step_output_inner` 的 freeform split 分支改为抛 `ContentIssue`：
  - `category="freeform_confirm"`，文案「自由文本拆章结果待确认：请把原文整理成章节行并登记，或跳过本批」；
  - `raw` = 模型原文（决策面板「查看模型原文」自动展示）；
  - `partial` = 按**严格模式**从原文预填的候选章节行：只识别以「第N章」（N 为阿拉伯数字或中文数字）开头的行，标题取该行剩余文字，情节简述/钩子一律留空；识别不到任何行则 `partial=None`。候选行没有「接受」动作，必须经用户在编辑器里确认（补充并继续）才落库——与拆章抢救「打捞行不给 accept」同一原则；
  - `counts = {"actual": 候选行数, "target": 本批 want_count}`，`available_actions = ["retry", "supplement", "skip"]`（无 accept）；
- 用户「补充并继续」：走现有 `_supplement_output` chapters+split 分支 → `parse_split`（本批 from_no 起点连续编号、允许数量不足）→ `_apply_step_output(kind="manual")` → `append_chapters` 落目录 → 流水线前进到下一批/收尾；
- 用户「跳过」：本批章号缺失，沿用现有跳过确认（填原因）与决策历史记录；
- 用户「重试」：本批重新生成；
- **行为变化（要向用户说清）**：自由文本拆章从「跑完只存原文」变成「每批跑完停下等你确认，确认完才拆下一批」。批间衔接依赖上一批落定，这是有意的；
- 正文链零改动：章节落目录后 `chapter_ids` 校验自然通过。

### 4.3 拆章提示词补一行分章格式（提高候选命中率）

freeform 拆章步的用户提示附加一句「请分章输出，每章以『第N章 标题』单独起行」。仍是自然文本，不要求 JSON；目的是让 4.2 的严格模式预填能命中，减少用户手打。

其余阶段（题材/书名/简介/世界观/角色/段落/正文/状态）的提示词一律不动。

### 4.4 输出模式说明更新

前端输出模式开关旁的说明（`27-writer.js:1611-1621` 的 modeText/protocolText）补充自由文本模式的实际行为：

```text
自由文本模式：产物保存为原文，可在设定页「自由文本输出」查看、复制或填入表单；
拆章每批生成后会停下来，等你确认成章节后才进目录，确认前正文无法使用该批章节。
```

## 5. 测试计划

### 5.1 解析器单测（`tests/test_writer_prompts.py`）

- 严格模式候选预填：「第N章」行（阿拉伯/中文数字）识别为标题行；非「第N章」开头的行不猜；`beat`/`hook` 恒为空；无任何命中返回空/None；
- freeform 拆章 `ContentIssue` 的 category/raw/partial/counts 字段正确；`available_actions` 不含 accept。

### 5.2 流水线单测（`tests/test_writer_pipeline.py`）

- freeform split 生成成功后进入 `needs_user`（不再直接完成），`pending.editor == "chapters"`，raw 保留原文，partial 为候选行或 None；
- 「补充并继续」提交章节行后：`append_chapters` 落目录（章节号从本批 from_no 连续）、流水线前进、下一批正常启动且衔接上下文含上一批；
- 数量不足的补充（少于 want_count）允许通过（`require_count=False` 契约）；
- 「跳过」记录决策历史，本批章号缺失，前序批次不受影响；
- 「重试」走 attempt+1 重新生成本批；
- 章节落目录后，正文链 `start_pipeline` 的 `chapter_ids` 校验通过（接通验证）；
- JSON 模式拆章行为不变（回归）。

### 5.3 前端与冒烟

- 设定页「自由文本输出」区块：有数据显示行（阶段名/时间/展开/复制），无数据显示空态说明；采用填表单且不自动保存；字段已有内容时先确认；
- 自由文本拆章暂停：决策面板显示待确认原因 + 章节行编辑器（预填候选）+ 原文折叠区；补充/跳过/重试三动作可用；
- 输出模式说明文案更新；桌面与 375px 无横向溢出、无 pageerror；
- 浏览器验证沿用 `verify/_serve_writer_draft_ui.py` 隔离入口模式（本地模拟数据，不联网）。

### 5.4 全量

`.venv/Scripts/python.exe -m unittest discover` 全量（预存失败基线以当次记录为准，不与 bump 并发跑）。

## 6. 实施顺序

1. 后端：`_decision_editor` freeform split 分支 + freeform split 转 `needs_user` + 候选预填严格模式（prompts.py），补 5.1/5.2 单测；
2. 前端：自由文本输出区块 + 采用填表单 + 输出模式说明；
3. 提示词补分章格式一行；
4. 定向测试 → 全量 → 静态检查（node --check / git diff --check / 文档编码）→ 浏览器冒烟；
5. 验证结果回填本文第 7 节，没跑的不写成已跑。

## 8. 范围外

- `genre` / `chars` 的自动采用（防猜，只复制）；
- 章末状态、段落要点在自由文本下落结构化字段；
- 自由文本解析回设定字段的后端自动通道（一切回填经用户确认，后端不加解析）；
- 大纲、正文步的自由文本改造（正文链本身能用，大纲两种模式都能填）；
- JSON 模式的任何行为变化；
- 提示词除拆章分章格式一行外的重写；
- 发版（按项目维护说明另行走流程）。
