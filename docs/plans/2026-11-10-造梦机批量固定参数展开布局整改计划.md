# 造梦机 JSON 数组参数可视化编辑器实施计划

日期：2026-11-10
状态：已实施，随 4.2.1-beta 发布
关联交接：[2026-11-09-造梦机固定参数展开排版交接.md](2026-11-09-造梦机固定参数展开排版交接.md)

## 背景与目标

4.2.0 已发布固定参数 Grid 布局和固定值回写修复，但用户期望的 JSON 数组参数可视化编辑仍停留在独立 HTML 预览。此前交接把“未接入生产”写成“本次不处理”，错误缩小了实施范围，导致 4.2.0 发布后 JSON 参数仍只能看到长字符串。

本次将已验证的预览方案做成生产功能：单次生成、批量固定参数和批量逐条参数共用一个 JSON 编辑弹窗。列表编辑后写回原参数字段，原始 JSON 保持可检查和校验。完成代码、测试和桌面/375px 浏览器验收后，按项目流程发布 4.2.1-beta。

## 实施范围，不得省略

以下三条路径全部要接入同一个可视化编辑弹窗：

- **单次生成**：JSON 参数行显示“`N 项启用` + 编辑列表/编辑预设”；编辑并应用后写回该工作流的单次任务草稿，提交 JSON 字符串。
- **批量固定参数**：固定参数区显示相同摘要和编辑入口；弹窗应用后更新当前方案的 `scheme.fixed[slotKey]`，该方案内每条共用这份值，提交 JSON 字符串。
- **批量逐条参数**：任何映射到合法 JSON text 参数的条目单元格都显示摘要和编辑入口，不限于 `spare` 映射；如果现有 prompt/duration/resolution 专用控件与该字段语义冲突，不能静默跳过，必须保持对应映射并从同一条目打开共用弹窗。弹窗应用后只更新当前条目的 `item.extras[key]` 或该映射当前使用的值源，其他条目和方案不变，提交 JSON 字符串。空值继续代表按工作流值执行。

不得以“逐条控件在表格里难放”为由排除逐条路径；可以在单元格中用紧凑摘要按钮打开共用弹窗。不得把批量固定功能降级成只能复用单次草稿。

共用弹窗必须有可视列表与原始 JSON 编辑区，支持对象数组逐项改字段、启用/停用、删除、添加；应用后按来源回写。可视控件不认识的字段、嵌套对象和数组必须保留，用户可以在原始 JSON 区修改。对象类型不支持安全增删时可以限制对应的可视操作，但不能丢弃数据。JSON 无效或根结构不匹配时禁止应用，取消不回写。

JSON 行摘要只显示启用数量，例如“2 项启用”，后接编辑入口；不要显示文件名、提示词或一长串简述。媒体槽不属于 JSON 参数范围，维持现有单次媒体样式，批量复用。

## 数据契约与当前代码基线

- 当前 `master` / `origin/master` 包含 `1052f767 chore(release): 发布 4.2.0 Beta`。
- 固定参数展开区已使用响应式 Grid；`batchSetFixedValue()` 和 `input/change` 委托已将值写回 `scheme.fixed`，4.2.0 前端测试已覆盖。此处只接入 JSON 弹窗，不重做 Grid。
- `renderSlot()` 与 `collectOverrides()` 当前把 JSON 参数当 text 字符串处理；弹窗应用后必须 stringify，后端仍接收 text，不增新 API 字段。
- `batchFixedMarkup()`、`batchSetFixedValue()` 和 `submitBatch()` 是固定参数路径；提交只发送变化的 fixed override。
- 批量逐条参数当前 `batchExtraCellMarkup()` 为 prompt/duration/resolution/spare 生成不同控件。实施前逐一检查四类映射的数据落点，所有 JSON text 槽都必须可打开共用弹窗；优先在对应单元格显示摘要按钮，应用后写回该条目该槽当前的存储位置，不串到别的条目。


## 交互与数据契约

### 参数识别

- 只对 text 字段中可解析为 JSON 数组或 JSON 对象的值展示结构化编辑入口；普通文本维持原输入控件。
- 本期主要编辑对象数组，覆盖 LoRA 配置、提示词预设等常见形态。简单顶层对象也可显示通用键值编辑；未知嵌套字段必须保留在对象中，不因 UI 不认识而丢弃。
- 初始化解析失败时保留普通文本控件，不破坏旧工作流。

### 共用弹窗

- 同一弹窗根据参数 schema 和当前 JSON 值绘制可视列表，支持逐项字段编辑、启用/停用、删除、添加项目。
- 右侧或下方保留原始 JSON 编辑区。可视列表改动同步更新原文；原文修改后先解析并校验结构，成功后刷新可视列表。
- JSON 非法、根类型不匹配或当前数据无法安全应用时显示错误，禁用应用；取消不写回任何来源。
- 摘要只显示启用数，如「2 项启用」，不要拼接文件名、提示词或长摘要。
- 启用字段按现有对象中 `enabled` 布尔属性识别；没有该字段的对象不擅自添加开关。添加项目时按该数组已有对象的字段形状和类型建立默认值，并保留扩展字段。

### 三种写回源

- 单次生成：弹窗应用后将序列化 JSON 字符串写入 `comfyui.drafts` 对应工作流/槽位键，刷新参数摘要；`collectOverrides()` 最终仍提交字符串。
- 批量固定：弹窗应用后写入 `scheme.fixed[slotKey]`，更新摘要栏并保留 `fixedOpen`；提交时 fixed override 仍为字符串。
- 批量逐条：所有 JSON text 映射都显示简短摘要按钮；打开时携带方案 id、条目 index、参数槽地址和实际值源；应用后仅写回该条目对应位置。普通 extras 仍使用 `item.extras[key]`；其他映射若由专用字段承载，沿用其现有数据契约并加测试。空值仍按现有提交语义不覆盖工作流值。
- 不把弹窗临时状态写入 workflow 本体或别的条目；每次打开从对应数据源重新解析。

## 实施步骤

1. 更新旧交接和本计划的基线事实。不要继续引用 flex 布局和缺少 fixed 回写的旧判断。
2. 定义纯函数：JSON 候选识别、格式化/校验、保留未知字段的数组条目更新、摘要启用数计算。通过现有前端测试 harness 覆盖正常/无效/未知字段。
3. 在 `public/index.html` 增加单一原生 `<dialog>`，提供可视条目区、原始 JSON 编辑区、状态提示和取消/应用操作。
4. 在 `public/js/24-comfyui.js` 实现弹窗状态与委托事件；接入单次参数、批量 fixed 和逐条 extras 三种来源。所有打开动作都携带明确来源标识和地址，不依赖 DOM 顺序推断。
5. 给三种来源的 JSON 字符串控件渲染紧凑摘要行，保留节点号、节点标题、字段名及现有下游端口说明。桌面适配并保证 375px 下弹窗可滚动、底部操作可达。
6. 扩展 `tests/test_comfyui_frontend_assets.py` 覆盖三来源入口、读写隔离、取消不写回、应用 stringify、摘要、无效 JSON 禁用应用、逐条不串值和 fixed 状态保留。若纯函数拆分，增加测试导出。
7. 执行相关 ComfyUI 单测与浏览器验收；跑完后更新版本/README/CHANGELOG/清单及 release workflow 所需版本字段至 4.2.1-beta，按维护说明核对发版内容和资产。

## 验收标准

1. 工作流原始 JSON 字符串未更改时，单次参数行显示启用数量和编辑入口，不再露出整段 JSON。
2. 编辑列表字段、enabled、增删条目后，原始 JSON 合法且可视列表与原文双向同步；应用后字段值是 JSON 字符串。
3. 取消或非法内容不改变来源值；未知字段和嵌套值在可视编辑后仍保留。
4. 单次应用只影响当前工作流草稿；批量固定只影响当前方案 fixed；逐条只影响当前条目的对应 extras。
5. 逐条空值仍按工作流原值；fixed 未修改值不进入 overrides；JSON 字符串按现有 text 契约提交。
6. 原值不是合法 JSON 数组/对象的文本参数继续显示原输入控件。
7. 桌面验收弹窗双栏、列表和原文编辑可用；375px 下改为单列或等效布局，关闭/应用按钮可见可点，页面无横向溢出。
8. `.venv\Scripts\python.exe -m unittest tests.test_comfyui_frontend_assets tests.test_comfyui_batches tests.test_comfyui_module` 通过；按维护说明跑 ComfyUI 浏览器冒烟与桌面/375px 截图验收。
9. 4.2.1-beta 发版后 Actions 成功，Release 五资产齐全；下载的 `naiba-chat.exe` SHA-256 与更新清单一致，清单 commit 与推送到 master 的提交一致。

## 保持现状，不纳入本次改造

- 媒体槽不是 JSON 参数，不进入 JSON 弹窗；单次媒体分组/槽位控件保持现状，批量继续复用其媒体语义与视觉。
- 4.2.0 已完成并发布的固定参数 Grid 不重做；只有弹窗接入造成回归时才修复对应布局。
- 原值不是合法 JSON 对象/数组的普通文本仍用原输入控件；不得强行 parse、自动格式化或改写用户文本。
- 不改 ComfyUI 后端协议、API 参数字段类型或工作流原始 prompt；JSON 作为 text 字符串走现有提交链路。
- 不缩减单次、批量固定、批量逐条三种来源中的任何一种 JSON 编辑能力。
