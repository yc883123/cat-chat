# 造梦机工作流控件与媒体输入输出补齐计划

## 1. 目标

在保留造梦机现有任务、产物管理和安全边界的基础上，借鉴绘影已验证的媒体输入流程：明确识别图片/视频/音频加载节点，提交前上传媒体并把返回文件名写入本次工作流副本。同时补足绘影方案未能确认覆盖的 ComfyUI 节点 schema 控件识别和 Chat 媒体卡复用。

本计划仅覆盖造梦机，不改动聊天域 ComfyUI worker 的执行实现。实施时保留工作区已有未提交改动，不重置、不覆盖用户改动。

## 2. 当前问题与设计判断

1. 参数槽位主要根据 API 工作流 `inputs` 的标量值及少量字段名规则推断。扫描器没有系统使用 ComfyUI `/object_info/<class_type>` 的节点输入声明，因此自定义多行文本、`UNETLoader.unet_name`、CLIP/VAE 模型选择，以及连接式 sampler 等没有可靠映射。
2. `LoadImage.filename` 虽标记为 image 类型，但当前仍按普通字符串覆盖，没有资产选择、上传到 ComfyUI 或任务引用保护；视频/音频输入也没有对应闭环。
3. 后端能从 ComfyUI 历史收集图片、视频、GIF、音频并保存到任务目录；造梦机前端独立渲染图片和视频，音频退化为下载链接，和 Chat 媒体卡能力不一致。
4. 绘影静态代码显示它按明确的 `LoadImage`、`LoadAudio`、`LoadVideo` 节点类型识别媒体输入，执行前调用 `POST /upload/image`，再将 ComfyUI 返回文件名写回提交参数；对已有 ComfyUI `type=input` 引用会尝试复用。它的参数识别主要是显式类型/字段规则，未确认有覆盖所有自定义节点的通用 schema 控件生成。因此本计划采用混合方案：媒体输入借鉴其明确映射与执行前上传；参数控件采用节点声明增强、规则可降级；任务和产物仍沿用造梦机现有后端管理。

## 3. 节点声明增强的参数扫描

### 3.1 输入 schema 与显式规则

- 以导入的 API prompt 为基础，只为工作流中真实存在的节点与标量/可编辑输入生成参数槽位。
- 查询当前 ComfyUI `/object_info/<class_type>` 中对应节点的 required/optional 输入声明，提取输入类型、枚举候选和多行属性。保留显式节点/字段规则作为稳定基线；schema 用于补充候选与控件语义，不要求所有节点必须在线才能识别。
- 查询结果按节点类缓存；仅在导入或参数 schema 刷新时访问，不进入任务轮询和生成步骤。
- ComfyUI 离线、插件节点未安装、字段声明缺失或响应格式变化时，不能阻断工作流读取。退回显式规则及现有 API prompt 类型判断；枚举不可用时使用保留当前值的自由编辑控件。
- 对声明不明确的自定义节点不凭字段名推断媒体上传协议，不把连接端口伪装成可编辑槽位。

### 3.2 提示词识别

- STRING/multiline 声明作为多行文本控件依据；节点标题和类名用于识别提示词语义。
- 主正向/负向提示词优先沿 sampler 的 `positive`/`negative` 连线回溯；节点声明和标题作为补充识别信号。
- 不将任意普通字符串自动归类为主提示词。无法判断语义时仍显示普通字符串输入；必要时可在参数设置中覆写多行显示属性，但不增加每次提交时的额外选择步骤。

### 3.3 模型与采样选择

- 支持 Checkpoint、LoRA、UNET、CLIP、VAE 等模型加载字段，并以 ComfyUI 对应节点声明的候选为下拉选项；字段映射优先使用节点 schema 的枚举，显式已知字段作离线识别回退。
- sampler 与 scheduler 按输入 schema 的枚举候选显示下拉；自定义节点存在相同声明时同样适用。
- 候选列表不可用或不包含工作流当前值时，保留当前值并允许自由输入，避免升级后已有工作流无法提交。
- `SamplerCustom` 等节点的 sampler 若是连线输入，则追查来源节点；只有来源字段确属可编辑枚举值时才生成对应槽位，不推造 override。

### 3.4 参数数据兼容

- 参数槽位增加控件类型、候选、媒体类型等元数据，已有 `node_id`、`field_name`、`field_type`、`default`、`role` 字段保持兼容。
- 递增 `PARAMS_SCHEMA_VERSION`，沿用工作流详情读取时对旧条目懒重扫的机制。
- override 仍按原始值类型转换；schema 只决定前端控件与输入校验，不改变工作流中字段的原生值类型。

## 4. 自动生成参数表单

- multiline/prompt 类字符串使用多行输入框，普通短文本仍为单行。
- enum 和模型加载字段使用下拉框；当前值不在候选中时仍可保留并提交，不静默替换成第一项。
- 参数扫描失败或无候选时继续提供可用的自由编辑回退，不增加每次提交前的额外操作。
- 媒体输入槽显示文件选择和对应媒体预览，并提供替换/清除入口；媒体参数置于用户容易找到的位置，不藏在纯文本字段中。

## 5. 图片、视频、音频输入闭环

### 5.1 明确的加载节点映射

- 采用类似绘影的显式节点映射识别媒体槽：ComfyUI 核心 `LoadImage`，以及经目标环境确认的 `LoadAudio`、`LoadVideo` 和常见节点包加载节点。记录每种节点的媒体类型、文件字段和 ComfyUI 上传协议。
- 节点类由显式映射或可验证的节点声明确认；不把任意名为 `filename`、`image`、`audio` 或 `video` 的自定义字段自动当成可上传输入。
- 对无法确认协议的自定义节点，保留原自由输入方式并明确说明该槽位尚未接入资产上传，不展示误导性的已上传状态。

### 5.2 执行前上传与 prompt 回填

- 前端选择输入媒体后保留受控资产引用，提交任务时由服务端校验引用；不得接受任意客户端本机路径。
- 每段任务执行前，把引用资产上传到配置的 ComfyUI；图片使用 `POST /upload/image` 的 multipart `image` 字段。视频和音频仅在目标 ComfyUI/节点包确认支持同一上传端点与格式时复用该协议，否则按已确认的节点协议实现并测试。
- 解析上传响应的 `name` 和 `subfolder`，按对应节点字段要求回填路径/文件名；只修改提交用 prompt 副本，不污染工作流库快照或后续任务。
- 若任务/工作流引用的是已有 ComfyUI `/view?...&type=input` 文件，先按绘影的方式验证输入文件仍存在，存在则复用文件名，避免不必要的上传；无效引用才从本应用受管资产重新上传。
- 同一个任务执行周期内，同一受管资产只上传一次并复用 ComfyUI 返回文件名；任务重试/续跑从受管引用重新读取，必要时重新上传。
- 上传失败必须停止对应段提交，并报告媒体类型、节点/字段和 ComfyUI 返回原因；禁止回退到旧文件名继续提交。

### 5.3 资产校验与生命周期

- 文件选择后由应用现有上传/资产存储机制生成受管引用，任务快照保存该引用，不保存临时浏览器对象 URL，也不依赖永久有效的用户本机路径。
- 服务端提交时校验资产引用、文件存在、媒体类型与文件大小；限定可接受格式和体积，错误应定位到具体参数槽。
- 扩展 `referenced_upload_paths()`，保护仍被排队、运行或可重试任务引用的上传文件，避免缓存清理使任务失去输入。
- 任务终态和任务删除后的资产回收沿用现有上传缓存清理策略，不另造一套生命周期。

### 5.4 输入预览

- 图片显示缩略预览；视频和音频使用带 controls 的播放器。
- 替换和清除操作只更新该工作流参数表单状态，提交时才把所选资产引用写入任务快照。
- 刷新参数表单、切换工作流或恢复任务时，不将临时浏览器对象 URL 当作持久资产引用。

## 6. 生成结果复用 Chat 媒体卡

- 将造梦机产物转换成 Chat 公共 `mediaKind`/`mediaMarkup` 接受的附件记录，复用图片、视频、音频和普通文件的展示语义。
- 图片保留缩略图和灯箱；视频/音频可直接播放；其他类型提供文件操作/下载入口。
- 媒体 URL 继续经带访问口令的 `/api/file` 地址和真实路径参数生成，保障手机/局域网访问与桌面端另存为。
- 保留造梦机现有多任务聚合、最多展示 24 项、任务/文件去重、顺序稳定、下载入口，以及轮询中产物集合不变时不重建媒体 DOM 的行为。
- 复用公共媒体卡内部 renderer 时，外层由造梦机继续管理稳定节点；公共 renderer 不得导致轮询中媒体重载或打断音视频播放。


## 7. 测试与验收

### 7.1 参数与 schema

- 用用户提供的 H3 工作流验证 `NaibaTextbox.text` 可成为多行提示词输入，正负提示词识别符合连线/标题规则。
- 用 MOSS-Image 工作流验证 CLIP/UNET/LoRA、提示词、sampler、scheduler、分辨率控件。
- 用 Qwen Image 2.1 工作流验证图像编辑输入、模型/LoRA、提示词及采样参数。
- 覆盖自定义节点 schema 缺失、节点未安装、ComfyUI 不可达、当前模型不在候选列表等降级路径。

### 7.2 输入媒体与任务生命周期

- 覆盖图片、视频、音频上传请求及 ComfyUI 文件名回填。
- 覆盖路径遍历/任意本机路径拒绝、类型和大小校验、资产不存在、上传失败不提交。
- 覆盖同一输入复用、任务 prompt 隔离、失败任务重试/续跑和上传引用清理保护。

### 7.3 结果卡与整体验证

- 覆盖图片、视频、音频和普通文件媒体卡，带 token 的 URL、下载、桌面端另存、灯箱及播放器行为。
- 验证轮询无变化时媒体 DOM 不重建，播放状态不被中断；验证多任务顺序、去重与 24 项上限。
- 运行 `tests/test_comfyui_module.py`、相关前端 verify 检查和必要的 JavaScript 语法检查。
- 使用三份示例工作流检查控件分类；不自动提交付费或真实生成任务。

## 8. 性能、错误与范围约束

- `/object_info` 查询仅在导入/schema 刷新阶段执行并缓存，不在轮询、采样步骤或每个任务事件中反复访问。
- 实际媒体上传是输入到达 ComfyUI 必须承担的时间，耗时随文件大小和连接速度变化；同任务复用避免重复传输。
- schema 候选不可用时降级而不阻断工作流；媒体资产上传失败时明确失败而不使用错误旧文件继续运行。
- 不自动发起真实生成，也不触发任何付费服务。
- 修改时保留仓库当前未提交的相关文件和差异，不使用 reset、checkout 或 stash 清理工作区。
