## 三、后端改动（比预想的小）

### 3.1 必须：`state()` 回显配置

`MCPServerConnection` 已有 `self.command / self.args / self.env`。`state()` 增加三个字段：

```python
"command": self.command,
"args": list(self.args),
"env_keys": sorted(self.env.keys()),   # 只给 KEY，不给值
```

> **安全口径**：env 里常见 `GITHUB_TOKEN` 一类令牌，列表只读展示 **KEY 列表**；要改就去「编辑」，那时才回填完整 JSON（本机应用，但仍按这个口径做）。

连带检查：`states()`（`mcp.py:452`）被 `/api/mcp` 与 `/health` 共用，`lightweight_status()`（`mcp.py:457`）不含这些字段——轮询时 `pollMcpStatus` 只覆盖状态字段，回显值不会被擦掉，**无需改前端轮询逻辑**。

### 3.2 必做：`start_timeout_ms`（每个服务可配的启动超时）

**为什么**：现在三处写死 20 秒（`mcp.py:58` 的 `start` 默认、`mcp.py:427` retry 循环、`mcp.py:158` `reconnect_once`）。
首次要拉包的 npx 服务、`rmg_navserver` 这类重服务常常 20 秒建不上连接，用户只能眼看着它红，却没法调。
参考稿也带这个字段，所以做了。

**默认值口径（重要）**：新建表单预填 **30000**（与参考稿一致，对新服务更宽松）；**后端缺省仍按 20000**，
保证所有已存在的配置行为零变化。

#### 改动清单（`naiba/mcp.py`）

| # | 位置 | 改法 |
|---|---|---|
| 1 | `__init__`（`:22`） | 新增参数 `start_timeout_ms: int = 20000`；存 `self.start_timeout_seconds = clamp(start_timeout_ms, 5000, 600000) / 1000` |
| 2 | `start()`（`:58`） | 签名改 `timeout: float \| None = None`；为 `None` 时取 `self.start_timeout_seconds`。现有显式传值的地方行为不变 |
| 3 | `start()` 报错文案 | `超过 {timeout} 秒` 改成格式化整数，避免出现「超过 30.0 秒」 |
| 4 | `reconnect_once()`（`:158`） | 默认改 `None`，透传给 `start()` |
| 5 | `call()` 内的 lazy start（`:181`） | 由 `start(timeout=max(15, min(call_timeout_seconds, 45)))` 改为 `start()`——统一走 per-server 口径 |
| 6 | `retry_unconnected_until_stopped()`（`:427`） | `connection.start(timeout=20)` → `connection.start()` |
| 7 | `_connection()`（`:328`） | 从 config 读 `start_timeout_ms` 传给连接对象 |
| 8 | `upsert()`（`:341`） | 归一化 payload 里带上 `start_timeout_ms` |
| 9 | `state()` | 回显 `start_timeout_ms`，编辑表单才有值可回填 |

#### 改动清单（`naiba/config.py`）

- `upsert_mcp_server()`（`:2541`）：接受 `start_timeout_ms`，**必须是整数且在 5000–600000 之间**，
  非法即 `ValueError`（与其它字段同一报错口径）；缺省写 20000；整体替换 payload 的语义不变。
- 旧配置缺这个字段时走缺省 20000，**不做数据迁移**（没有强需求，且 `_connection` 缺省值已经兜住）。

> ⚠️ 别混两个超时：`env["MCP_TOOL_TIMEOUT"]` / `call_timeout_seconds` 管的是**单次工具调用**（默认 620 秒），
> `start_timeout_ms` 管的是**连接建立**。两者独立，不要合并。

### 3.3 明确不做

- 不做「启用/停用」端点。原先把 `enabled: false` 的服务不可见当成缺陷要修——现在 UI 不产生这个状态了，就**不碰**：`MCPRegistry.__init__` 跳过 disabled 的行为保持原样，`upsert_mcp_server` 的「command 必填」约束也不动。省掉一处改动和风险。

## 七、风险与开放项

1. **`args` 空格分隔**（抄参考稿）对带空格路径天然不友好 → 已用 `splitArgs()` 引号感知兜住，但若你更想要「每行一个」，现在改代价最小。
2. **env 回填策略**：编辑时回填完整 JSON（含明文令牌）。本机应用可接受；若你要求掩码，我改成编辑时保留原值、只显示 `KEY=••••`，改动不大。
3. **「类型」下拉只有一个选项**：为将来 SSE/HTTP MCP 留位。觉得多余可以直接写成静态文字。
4. **硬默认 vs 智能默认**：`start_timeout_ms` 只在新建表单预填 30000，**首次连接失败不会自动放宽**。
   要不要做「连接超时就建议把超时调到 60s」的提示？属于额外的一步，暂不做。
5. 旧的 `.connection-item / .mcp-add-form / .mcp-actions / .mcp-env-row` CSS 在删除 card 后成为死代码，是否一并清理由你定（建议留到下一版，避免本次 diff 变大）。
