# 文案写作

把一段素材变成能直接发出去的成稿。核心不是辞藻，是**先把「给谁看、看多久、看完要干什么」问清楚**。

## 什么时候用

- 用户给了素材（截图、要点、一段说明）要变成成稿；
- 要写口播稿 / 视频脚本旁白、公众号文章、小红书笔记、产品介绍、软件教程文案；
- 已有初稿，要按平台口味改写或压缩。

## 动笔前必问（一次问全，别挤牙膏）

1. **载体**：口播（抖音 / 视频号 / B站）、公众号、小红书、软件教程、产品页？
2. **长度**：字数或时长。口播按 **220 字 ≈ 1 分钟**折算。
3. **读者**：完全小白 / 同行 / 决策者？决定了要不要解释术语。
4. **目的**：看懂、行动（下载/关注/下单）、还是留存备查？
5. **硬约束**：必须出现的词/链接/数据，绝对不能出现的词。
6. **语气**：口语 / 专业 / 轻快。

> 用户没给全时：**按最可能的假设先写一版，并在开头用一行标注假设**（例：「按 1 分钟口播、面向完全没用过的人写」），让用户在此基础上改。不要空转等答案，也不要把假设藏起来。

## 通用写作规则

- **口语优先**：能顺口念出来的句子才算通顺；一句话太长就拆成两句。
- **先结论后细节**：前 3 句必须让读者知道「这跟我有什么关系」。
- **一段一件事**：段首用短句当小标题，方便扫读。
- **数字具体化**：不说「很快」，说「3 分钟」；不说「很多」，说「1872 个用例」。
- **少用空词**：赋能、闭环、抓手、生态位、降本增效——要么删掉，要么换成具体动作。
- **每篇给 3 个备选标题**：分别偏「利益点 / 好奇缺口 / 数字对比」。
- **结尾给一个明确动作**：下载、点链接、试用、留言，只给一个。

## 三种高频文体模板

### A. 口播稿（1–3 分钟）

```
【钩子｜15 字内，制造「这跟我有关」】
【痛点｜1 句，说出观众现在的麻烦】
【方案｜2–3 句，我有什么，怎么解决】
【演示｜3–5 句，具体到「你点哪里、看到什么」】
【价值｜1 句，用数字或对比收口】
【行动｜1 句，下一步做什么】
```

写法要点：短句、动词开头、不用书面连接词（「然而」「此外」换成停顿）；每句不超过 20 字。

### B. 公众号 / 图文

- 开头 100 字内交代「读这篇你能得到什么」；
- 正文用 `##` 小标题切成 3–5 段，每段一个观点；
- 关键句单独成行，方便截图传播；
- 结尾给摘要式回扣 + 一个动作。

### C. 软件教程文案

- 第 0 步写清前置条件（装什么、配什么），后续步骤不重复；
- 步骤必须**照着点就能做**：精确到按钮名与页面名（如「⚙ 设置 → API 供应商 → 添加 API」）；
- 每步后面用 `>` 补一句「为什么会这样 / 出错了怎么办」；
- 术语第一次出现时用括号给一句白话解释。

## 发布前自检

- [ ] 前 3 句抓人吗？把最狠的一句挪到第一句。
- [ ] 有没有把用户的书面语原样搬进来？
- [ ] 每个步骤都能「照着点」吗（按钮名/页面名齐全）？
- [ ] 有没有没解释的缩写、内部黑话、代号？
- [ ] 字数/时长达标吗？
- [ ] 三个备选标题都给了吗？
