# Cat Chat 缓存诊断包

适用于 Windows 10 / 11，无需安装 Python，也不需要关闭 Cat Chat。

## 发给测试用户的步骤

1. 把压缩包完整解压到一个新文件夹，双击 `START.cmd`。
2. 选择出现缓存问题的 API，确认模型名。要换模型，可以直接输入完整名称；输入 `?` 可查询该 API 的模型列表。
3. 建议选择 **2：对照 Claude 和 Chat**。如果只想检查当前格式，选择 1。
4. 填写 Cat Chat 版本号，核对请求数量和计费提示后输入 `Y` 开始。
5. 测试结束会打开结果文件夹，把里面的 **`report.zip`** 发回来即可。

不要发送 `config.json`、API Key 或聊天记录。报告里会保留 API 名称、服务地址和模型名，便于定位线路；请只发给协助排查的人。

如果默认位置找不到配置，窗口会让你把配置文件拖进去。冻结版默认配置位置为 `%LOCALAPPDATA%\NaibaChat\config.json`。脚本只读取配置，不保存或修改配置，也不会复制密钥到报告。

如果窗口没有自动打开，可以在诊断包旁边的 `reports` 文件夹中找到结果。若运行中断，已经完成的请求会保存为 `report.json` 和 `report.txt`，这两个文件也可以发回。

## 请求数量与费用

- 仅测当前格式：最多 **2 次生成请求**。
- 对照两种格式：最多 **4 次生成请求**。
- 每次人工测试文本约 **6,000 输入 token**，输出上限 **256 token**，提示模型只回答 `OK`。
- 每种格式第一次失败就停止该组，不自动重试，不自动换模型。
- 查询模型列表是额外的 GET 请求，仅在输入 `?` 时发生。
- 所有请求使用你选择的供应商，按供应商规则计费。脚本不能查询或承诺实际费用。
- 每次请求最多等待 60 秒。客户端超时关闭连接后，上游是否停止生成取决于供应商。

## 报告能说明什么

报告保留流式响应开头和末尾的用量字段，区分普通输入、缓存写入和缓存读取，并与 **2026-11-13 Cat Chat 用量解析逻辑快照**对照。这个对照不代表已读取你正在运行的 exe 或界面数值，报告中的版本号由你填写。

第二次请求保持长 system 前缀完全一致，只更改末条 user 文本，降低中转整份复用响应的干扰。报告记录响应 ID 的哈希，若两次仍相同会提示。不同格式使用独立诊断标记，避免两组完全相同的前缀互相预热。

- 服务端报告缓存读取大于 0，但解析快照为 0：可定位到解析差异。
- 服务端返回缓存读取 0：仅说明这次没有报告命中，还需查前缀长度、缓存有效期、断点或上游路由。
- 服务端没有缓存字段：记为未知，不当作零命中。
- HTTP 503、401、超时等：保留脱敏错误，不将请求失败当作缓存失败。

这是一组最小的普通文本探针，不测试并行工具、Agent 多步任务、图片、长思考或真实对话历史。不同中转可能有额外协议参数；若被拒绝，报告会保留原因，不自动剥掉参数重发。

## 兼容与隐私

- Windows 自带 PowerShell 5.1，或者通过终端使用 PowerShell 7；无需下载依赖。
- `START.cmd` 的 `ExecutionPolicy Bypass` 仅对这次 PowerShell 进程生效，不修改系统执行策略。
- API 密钥只在内存中使用，并发给你选择的 API 地址；拒绝跟随 HTTP 重定向。
- 不保存完整响应正文、生成文本、鉴权头、Cookie、真实会话或配置文件。
- 报告只允许指定的计数字段和脱敏错误摘要；已读取的 API Key、访问口令和配置路径会过滤。
- 尽量沿用 Cat Chat 的代理设置；系统代理的解析在 PowerShell 和应用之间可能存在差异。

## 开发者使用

自动化调用示例（不会绕过调用者对付费测试的授权要求）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\cache-diagnostic.ps1 `
  -ConfigPath "C:\path\config.json" `
  -ProviderName "供应商名称" -Model "claude-sonnet-4-6" `
  -Mode both -OutputDirectory ".\reports" -Yes -NoPause
```

`Mode` 支持 `configured`、`both`、`claude`、`chat`。`-Yes` 明确跳过交互确认，必须同时指定配置和供应商；用于离线假服务验收或已经授权的诊断。请求超时可通过 `-TimeoutSeconds` 调整，范围 5–180 秒。

诊断包不会修改 Cat Chat 安装目录和配置。报告生成在独立的带时间与随机编号的文件夹中。
