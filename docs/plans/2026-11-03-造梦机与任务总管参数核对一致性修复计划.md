# 造梦机与任务总管参数核对一致性修复计划

日期：2026-11-03  
状态：待实施；本文只记录方案，不代表代码已修改或当前运行任务已修复。

## 一、背景与目标

用户反馈：新建／另存工作流时能核对的参数太少；交给任务总管后，创建执行方案所展示的高级参数与实际运行配置对不上。目标不是让任务总管重新验证 ComfyUI 工作流能否运行，而是让用户看清**当前工作流原值、另存副本值、方案默认值、本批次改动值和最终提交值**之间的关系，避免遗漏、误导和跨方案串值。

本次反馈附图在当前模型输入中未能读取，以下定位来自代码链路；实施前须用实际工作流和用户所指界面再次对照，不把推断当作截图事实。

## 二、现状链路与根因

1. `naiba/comfyui/params.py::scan_params` 扫描 API 图中节点的标量 `inputs`，跳过连线数组；`enrich_slots` 根据 `object_info` 补候选、控件语义，不会凭空补出图中没有的输入。造梦机主表单还通过 `visible_params` 只显示常用项，“编辑参数”才列全部扫描结果。**扫描到的参数、主表单显示的参数和可另存参数是三种不同集合**。
2. `public/js/24-comfyui.js::saveCurrentWorkflowAs` 从 `collectOverrides()` 收集当前主表单已渲染控件的值；隐藏参数没有控件，也就不在另存时的核对范围内。`naiba/comfyui/service.py::api_workflow_save_as` 对提交值再用实时 `object_info` 校验枚举、布尔与有界数值，拒绝任意自由文本／路径／代码等。这道安全边界保留，但界面必须说明哪些值没有另存。
3. 造梦机交接传入工作流详情和可见控件覆盖；`public/js/28-super-agent.js::recipeCustomFixedOverrides` 只保留可支持的数值、seed、布尔固定覆盖。方案保存时 `naiba/super_agent/recipes.py::save_recipe` 以工作流指纹冻结原图，覆盖另存，不改原图。
4. 任务总管创建批次时 `recipeNumericSlots` 仅从冻结原图枚举数值；高级控件的占位值是**原图值**，不体现 `recipe.overrides` 的**方案值**，也不列布尔或同名节点的身份。提交却以 `recipe.overrides` 为默认，再叠加批次控件填写值。因此用户看到的“留空沿用方案值”与旁边显示的原图占位值可能互相矛盾。
5. 高级草稿按 `override:节点|字段` 存在公共 `recipeState.options`，切换方案仍可把旧值套到新方案的同地址字段。服务端又会依次合并方案、批次、单项覆盖，并在最后绑定提示词／时长；只展示原图的 `effective_workflow.prompt` 不是已应用全部覆盖的执行图。

## 三、实施边界与方案

### 3.1 造梦机：完整核对，不扩大不可信写入

- 复用 `scan_params`／`enrich_slots` 返回的槽位、节点名、字段名、原值和 `object_info` 声明，提供**全部已扫描参数**的核对视图；明确区分“主表单已显示／隐藏”“当前草稿是否改变”“本次可另存／不可另存”。隐藏槽位可从核对视图显式编辑或引导加入主表单；不能把未编辑的隐藏槽位误说成已改变。不要伪造连线端口或 API 导出里不存在的字段。
- 另存确认展示每项实际要固化的 `节点／字段：原值 → 新值`，并在提交前阻止不支持的改动被静默丢弃；提示具体节点、字段和原因。枚举、严格布尔、带权威上下界的数值沿用 `api_workflow_save_as` 的服务端校验和源指纹检查；自由文本提示词、媒体路径、代码、URL、凭据及无权威声明的变更不悄悄写入副本。
- 另存成功后以**返回的副本工作流**重新读取参数、选中副本，再交给任务总管；保留原件及草稿，但明确哪些草稿没有进入副本。旧工作流扫描版本与实时声明拿不到时明确降级说明，而非声称全部核对完成。

### 3.2 任务总管：展示和提交使用同一套有效值

- 从冻结 `recipe.workflow` 与 `recipe.overrides` 计算参数行：节点号／标题、字段、原图值、方案值、可选批次改动值；数字、布尔、seed 一并纳入，排除提示词／媒体／由方案单独管理的时长。对于多个同名字段，不能只显示字段名。
- 空白控件表示沿用**方案值**；不要把原图值放在占位符里冒充最终值。明确 seed 未固定时执行器可能随机化；布尔值不得用空字符串、`false` 或“未改”混淆。
- 创建批次的提交覆盖由上述同一份参数模型生成，前端先检查整数精度、范围语义及固定 seed 不得为负；服务端 `_overrides` 和合并顺序保持最终权威。为批次预览标出“原始工作流图 + 待应用覆盖”，并按服务端返回的 `overrides`／`effective_params` 核对，不把未打补丁的 `effective_workflow.prompt` 称为最终图。
- 按方案 ID／版本或工作流指纹隔离高级参数草稿；切换方案保留素材与正文，但旧方案参数不套入新方案。方案重新读取或另存副本后重建参数行，过期地址不复用。

### 3.3 不在本次范围

- 不修改已运行或已冻结的批次，不自动重试／重提生成任务，不重启现有实例。
- 不把任意文本、路径、代码加入“固定参数”白名单；不改变原生 ComfyUI 执行器的 seed 随机化与上传协议。
- 不调用付费模型，不提交、推送或发布。

## 四、关键文件

- `public/js/24-comfyui.js`、`public/index.html`、必要的 `public/styles.css`：另存核对清单、提示与交接。
- `naiba/comfyui/params.py`、`naiba/comfyui/schema.py`、`naiba/comfyui/service.py`：复用扫描与权威声明，只有核实缺口后才做最小修正。
- `public/js/28-super-agent.js`：高级参数统一展示、提交、草稿隔离。
- `naiba/super_agent/recipes.py`：保持指纹与覆盖合并的权威规则；仅在预览契约确有缺口时补足，不复制执行器另造一套逻辑。
- `tests/test_comfyui_module.py`、`tests/test_comfyui_safe_save.py`、`tests/test_super_agent_recipes.py`、`tests/test_recipe_frontend_assets.py`、相关 `verify/*recipe*_smoke.cjs`：回归与界面验收。

## 五、验收判据

1. 用包含**已显示／隐藏数值、布尔、seed、枚举、自由文本及同名不同节点字段**的本地假工作流：核对视图覆盖所有已扫描标量输入；未改值不提交，不能另存的改值被指名解释，成功副本的实际图与确认清单一致，原图不变。
2. 方案默认覆盖不同于原图值时，新建批次的高级参数显示方案值；留空创建后的批次覆盖与方案一致，填写新值才覆盖；切换到另一个同地址方案不会串入旧草稿。
3. 比较前端显示、`POST /api/super-agent/recipe-batches` 请求、返回的批次 `overrides/effective_params` 及原生任务构图前参数；明确提示词、时长和随机 seed 由后续阶段处理，不虚称完全相同。
4. 使用项目 `.venv` 跑上述相关单测、前端语法／静态检查及文档检查；用隔离本地服务和假模型跑桌面与 375px 手机 Playwright 冒烟，检查页面错误和可见文案。若当前运行实例仍加载旧后端，不能拿其页面结果冒充新代码验收；不打断用户任务。
5. 修改前重新检查工作树的未提交改动，只做增量小改；测试失败、未运行项和环境限制如实汇报。
