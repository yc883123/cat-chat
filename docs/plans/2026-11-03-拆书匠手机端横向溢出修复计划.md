# 拆书匠手机端横向溢出修复计划（2026-11-03）

状态：**已实施（2026-11-03）**。P0（`.studio-view` min-width: 0）、P1（`.novel-page-state` 可收缩 + `25-novel.js` 书名号去重）、§六守门（`novel_visual_check.cjs` 改逐元素几何判据 + 长书名 + 320/360 视口；`test_mobile_parity.py` 新增网格视图 min-width 守门）全部落地；9 视口 × 2 主题 × 4 分档 = 72 组扫描 0 溢出。

## 一、结论先说

**根因只有一条**：`.studio-view`（工作台外壳，`public/styles.css:3569`）缺 `min-width: 0`。

它是 `.chat-main` 网格里唯一的隐式列项。CSS 网格的列项默认 `min-width: auto`，会取内容的 min-content 宽度；工作台里任何一页把 min-content 撑大，整条主区列就被固定住，`html, body { overflow-x: hidden }`（`public/styles.css:2321`）再把超出部分裁掉——用户看到的就是「页面没有正确缩放、右边内容被切掉」。

对照证据：同一网格里的兄弟视图 `.super-agent-view` 已经写了 `min-width: 0`（`public/styles.css:6015`），只有工作台这一个漏了。

## 二、复现与实测数据（真实实例 8765 + 真实作品）

在 8765 上用 Playwright 手机模拟（Android UA、`isMobile`、DPR 2.625/2.75/3），打开真实作品《恐怖副本：大BOSS是恋爱脑》（157 章）：

| 视口 | 修复前 `.chat-main` 列 | 修复后 |
|---|---|---|
| 320×720 | 402px（超 82） | 320px |
| 360×800 | 402px（超 42） | 360px |
| 393×852 | 402px（超 9） | 393px |
| 412×915 | 402px | 412px |

关键现象：**402.047px 是一个与视口无关的定值**——它就是 `.novel-page-head` 的 min-content（标题行 378px + 左右内边距 24px）。视口越窄，露在外面的被裁得越多，所以看起来「越窄越离谱」，像是缩放坏了。

另外，基线对照组在 320/360 下有时「通过」、393/412 稳定失败；修复后 4 个视口 × 3 分档 × 5 阶段 = **60 组全部 0 溢出**，且重复运行结果稳定。

## 三、谁把 min-content 撑到 402px

`.novel-page-head` 在竖屏（`max-width:760px`）下是纵向 flex，两行：

- 第一行 `.novel-page-title-row`：`min-content = 378px`
  - `h2 「拆书匠」` 约 61px
  - `#novelPageState` 状态文字 `min-content = 317px`
- 第二行 `.novel-page-actions`：`min-content = 297px`（四个按钮，可横向滚动）

状态文字是罪魁：内容是 `《${book.title}》已保存 · ${stageLabel}`（`public/js/25-novel.js:1185`），而真实书标题本身就是 `《恐怖副本：大BOSS是恋爱脑》作者：姜乐你`，拼出来成了 `《《恐怖副本：大BOSS是恋爱脑》作者：姜乐你》已保存 · 改编大纲`。

它写了 `overflow: hidden` / `text-overflow: ellipsis` / `white-space: nowrap`，**但没写 `width: 0` 或 `flex-basis`**——在 flex 行里，`flex: 0 1 auto` + `min-width: 0` 只是允许它收缩，浏览器算父级 min-content 时仍按「不可断开的一整行文字」计 351px。所以省略号从来没真正生效过（实测 `stateW=317` / `stateSW=351`，一直在溢出状态下被裁）。

**这不是「几乎所有抽屉页面都坏」的普适缺陷**：横向扫了工作台 5 个分页，在同一 360px 视口下，作品库 / 打标器 / 造梦机 / 织书台全部 `列=360/360` 正常，只有拆书匠撑破。用户看到「几乎所有抽屉页面都没正确缩放」，是因为拆书匠**每个阶段**（拆章/要素/大纲/剧本/分镜）都共用这一个页头，切来切去都是同一处被裁。两个弹窗（作品列表、管理记录）实测也正常，没有独立缺陷。

## 四、修复方案

### P0（唯一必须改的一行）

`public/styles.css` 的 `.studio-view` 加 `min-width: 0`（放在 `min-height: 0` 旁）：

```css
.studio-view {
  grid-area: 1 / 1 / -1 / 2;
  display: none;
  min-width: 0;   /* 新增 */
  min-height: 0;
  ...
}
```

**已实测验证**：仅此一条，360/393 的列宽即回落到视口宽度，60 组扫描全绿；桌面 1440/1280 与手机横屏 844/812 的三栏数值**逐项不变**（248/568/280、248/408/280、170/183/198、170/160/198），零回归。

顺带修好的还有横屏：基线时 844 视口下 `.chat-main` 列被撑到 626px、中栏 217.81px（异常小数）；修复后回落到 591px、中栏 182px——即横屏中栏此前也被同一个 min-content 顶着，只是没超视口所以没人发现。

### P1（页头仍要能优雅截断）

P0 只保证「不再撑破」。`.novel-page-state` 的省略号目前其实从未生效，建议补上真正可收缩的写法，让长书名在窄屏显示为「《恐怖副本：大BOSS…」而不是被硬切：

```css
.novel-page-state { flex: 1 1 auto; width: 0; }  /* 或在 760 块内单独加 */
```

同时建议顺手处理标题重复书名号：`public/js/25-novel.js` 里 `《${book.title}》` 共 5 处（431、958、2671、2778、2987 及 1185 行的状态文字）。书名是用户文件名带进来的，本身就常含 `《》`，再包一层就成了 `《《…》》`。建议加一个小工具函数：标题已以 `《` 开头且以 `》` 结尾就不再套。这一条不影响缩放，属观感修复。

### 不改的

- 不动 `html, body { overflow-x: hidden }`：它是既有的兜底，去掉会让任何一处溢出变成整页可横拖，反而更糟。
- 不动 `.chat-main { min-width: 0 }`：它已经写了，问题在下游列项。
- 不动 `#novelPageState` 的 `nowrap`：多行折返会让页头高度随书名跳动。

## 五、为什么现有自动化没拦住

`verify/novel_visual_check.cjs` 确实在 390/375 竖屏跑，也读了 `document.documentElement.scrollWidth - clientWidth` 判溢出。它漏掉的原因有两条：

1. **只测 `documentElement`**：手机端 `html { overflow-x: hidden }` 会把溢出吃掉，`scrollWidth` 永远等于 `clientWidth`，该断言恒真。
2. **用的是短 mock 标题**（`长夜灯`、`第1章 雨夜来客`）：状态文字很短，min-content 远小于 390px，根本触不到 402px 这个阈值。真实书标题带 `作者：`，长度差了一倍以上。

所以这个检查在用户报障前是「56 张截图、全部无横向溢出」的绿灯，实际什么都没测到。

## 六、验证与守门

### 本次已完成的验证

- 真实实例 8765 + 真实作品，4 视口 × 3 分档 × 5 阶段 = 60 组：修复前失败 15/30/36/36（320/360/393/412），修复后 0。
- 桌面 1440/1280、横屏 844/812 回归：三栏宽度与修复前逐项一致（横屏中栏从被错误撑开的 217.81px 回落为 182px，属修正）。
- 工作台 5 个分页横向扫描：仅拆书匠受影响，其余正常。
- 两个弹窗（作品列表 / 管理记录）360px 下实测 `右溢出 = -19 / 0`，无独立缺陷。

### 建议补的守门

1. **让 `novel_visual_check.cjs` 真正有效**：把「溢出」判据从 `documentElement.scrollWidth` 改为逐元素 `getBoundingClientRect().right > clientWidth`（`html` 的 `overflow-x: hidden` 挡不住元素几何），并改用**带 `作者：` 的长书名**、至少在 360 与 320 两个宽度跑。
2. **加一条静态守门**（`tests/test_mobile_parity.py` 或新增）：`.studio-view` 与 `.super-agent-view` 这类 `.chat-main` 直属视图必须带 `min-width: 0`。这类「漏一条就整页错位」的规则靠浏览器冒烟兜底太晚，静态能零成本拦住。
3. **页头文字长度回归**：`#novelPageState` 在 360px 下必须满足 `scrollWidth <= clientWidth`（即省略号真的生效），否则长书名会再次把页头撑开。

## 七、影响面与风险

- 改动面：`public/styles.css` 一行（P0）；P1 另加一行 CSS + 一个 JS 标题工具函数。
- 风险：极低。`min-width: 0` 只影响「列项允许收缩」，不改变任何已适配布局的宽度（桌面/横屏实测逐项不变）。
- 不需要数据迁移、不需要后端改动、不影响 8765 上的既有作品。
- 用户当前 4.0.1-beta 实例（8765）用的 `styles.css` 与仓库**逐字节一致**（md5 相同），所以这是仓库现存缺陷，不是发版漂移；修复后需随下一次版本发布才到 8765。

## 八、执行顺序

1. P0 补 `.studio-view { min-width: 0 }` —— 单独一行，先跑 60 组手机扫描确认 0 溢出。
2. 补齐 `novel_visual_check.cjs` 的溢出判据与长标题数据（否则以后还会漏）。
3. P1 补 `.novel-page-state` 可收缩 + 标题去重书名号。
4. 跑桌面/横屏回归 + `tests/test_mobile_parity.py` + `node --check public/js/25-novel.js`。
