## 1. 背景

用户反馈 Cat Chat 打标器的「通用描述」模板过于简单，模型容易忽略或不稳定输出以下内容：

- 面部、五官、肤色、妆容和表情；
- 发型、发色和年龄特征；
- 体型、姿态、手势和动作过程；
- 服装、配饰、面料、图案和颜色；
- 画面中的主体物件及其材质、结构、纹理和颜色；
- 场景、背景、时间、天气和空间层次；
- 构图、镜头、视角、画风、色调、光影和氛围。

当前「通用描述」的产品语义是“完整描述画面里有什么，不刻意忽略任何内容”，但实际提示词没有把这些视觉维度列成明确的观察清单。因此模型可能只输出主体、场景或风格，不能稳定完成完整盘点。

用户同时提出增加一个“自定义”档位。本次确定的方向是：

> **自定义忽略内容**：用户填写要从标签和描述中忽略的内容，用于自定义 LoRA 训练描述。

## 2. 当前实现现状

### 2.1 预设唯一真源

预设定义位于：

- `naiba/labeler/presets.py`

当前预设通过 `PRESETS` 维护，并由以下函数提供给服务端和前端：

- `preset_list()`：返回前端可展示的预设清单；
- `get_preset()`：按 id 获取完整预设；
- `canonical_preset_id()`：处理历史别名；
- `filter_tags()`：执行模型输出后的标签过滤。

当前已有九档：

- `general`：通用描述；
- `character_lora`：忽略人物；
- `face_lora`：忽略面部；
- `body_lora`：忽略人体；
- `outfit_lora`：忽略服装；
- `style_lora`：忽略画风；
- `scene_lora`：忽略场景；
- `object_lora`：忽略主体物件；
- `action_lora`：忽略动作。

旧的 `concept_lora` 只作为历史兼容别名映射到 `action_lora`，不能破坏该兼容关系。

### 2.2 提示词与结果处理链路

主要调用链：

```text
PRESETS
  -> LabelerService.api_presets()
  -> public/js/23-labeler.js
  -> build_prompt()
  -> ProviderLabelerEngine
  -> LabelerRunner._finalize_tags/_finalize_description
  -> LabelerDB
```

关键文件：

- `naiba/labeler/presets.py`：预设、忽略词和结果过滤；
- `naiba/labeler/engines/provider.py`：组装多模态提示词、解析模型响应；
- `naiba/labeler/runner.py`：置信度过滤、预设过滤、去重、截断和触发词处理；
- `naiba/labeler/jobs.py`：配置白名单、预设校验、任务指纹和任务快照；
- `naiba/labeler/service.py`：预设 API 和任务门面；
- `public/js/23-labeler.js`：预设动态加载、配置收集和任务提交；
- `public/index.html`：打标器配置区和帮助说明；
- `tests/test_labeler.py`：打标器单元测试和源码契约测试。

## 3. 已确定的后续改造方向

### 3.1 增强 `general` 通用描述

保持 `general` 的核心语义不变：

- 不主动忽略任何视觉领域；
- 继续只清理无信息的通用噪声词；
- 不因为图片没有某个维度而强行编造内容。

后续应将用户可见说明改成更明确的完整范围，例如覆盖：

1. 主体、人物身份和可见关系；
2. 面部、五官、肤色、妆容和表情；
3. 发型、发色和年龄；
4. 体型、身体比例、姿态、手势和动作；
5. 服装、配饰、面料、图案、颜色和结构；
6. 物体的品类、材质、颜色、结构、纹理和磨损；
7. 场景、地点、背景、时间、天气和空间层次；
8. 构图、镜头、视角、景别和主体位置；
9. 画风、媒介、线条、纹理、色调、光影和后期质感；
10. 可见的情绪、氛围和叙事关系。

同时在 `build_prompt()` 中增加通用档专属的观察指导：

- 要求模型逐项检查上述维度；
- 只描述图片中实际可见或能够直接确认的内容；
- 没有该元素时跳过；
- 不凭空推断身份、故事、材质或画外信息；
- 不要只用“一个人”“一个场景”等过泛词替代可见细节；
- 该指导必须兼容标签、词组短语、自然语言和标签+描述四种输出形式。

通用指导应位于基础 JSON/语言/输出形式规则之后、用户补充要求之前，不改变现有 `custom_prompt` 的优先级。

### 3.2 增加 `custom_lora` 自定义忽略档位

建议新增稳定 id：

```text
custom_lora
```

产品语义：

- 用户自己指定需要忽略的内容；
- 指定内容必须从标签和 description 中省略；
- 未被指定的内容正常描述；
- 不从自然语言中自动猜测硬过滤关键词。

建议复用现有 `custom_prompt` 字段，不新增任务 API 字段，避免配置迁移：

- 非自定义档：`custom_prompt` 继续作为可选补充要求；
- `custom_lora`：`custom_prompt` 改为必填，并解释为“自定义忽略内容”；
- 输入继续沿用现有长度上限、白名单、任务快照和配置指纹；
- 提示词使用明确的“以下内容必须从标签和描述里省略”语义。

示例：

```text
忽略面部和动作
忽略红色手提包的材质与结构
忽略背景环境，只保留人物、服装和动作
```

与 `subject_filter` 的边界：

- `custom_prompt` 负责告诉模型哪些内容不要写，适合自然语言范围；
- `subject_filter` 负责对模型已经输出的标签做确定性关键词过滤；
- 后续实现不应把“忽略红色手提包”未经确认地解析成一组可能误伤的硬过滤词。

## 4. 配置、指纹与兼容性要求

### 4.1 预设 API

`/api/labeler/presets` 继续从 `preset_list()` 返回预设，不在前端另维护第二份预设清单。

新增档位后需要同步检查：

- `PRESET_IDS`；
- `preset_list()` 返回数量和字段；
- `normalize_config()` 的预设白名单；
- 历史 `concept_lora` 到 `action_lora` 的兼容映射；
- 前端动态选项和说明。

### 4.2 提示词版本

由于通用档提示词会发生实际变化，并且新增自定义档位，实施时建议将新任务默认 `prompt_version` 从 `2` 提升到 `3`：

- `naiba/labeler/jobs.py` 的默认值；
- `public/js/23-labeler.js` 的提交值；
- 相关测试辅助配置。

`prompt_version` 已参与 `config_fingerprint`，因此：

- 新任务不会错误复用旧的简略通用结果；
- 历史任务仍保留原配置和原版本；
- 不改写已有任务、不迁移历史标注、不重新生成历史结果。

### 4.3 自定义档必填

服务端必须是最终校验方：

- 选择 `custom_lora` 且 `custom_prompt` 为空时拒绝任务；
- 有效内容经过现有长度归一化后进入任务快照和指纹；
- 前端可以提前提示，但不能只依赖前端校验。

## 5. 前端交互要求

前端已有预设动态加载和说明渲染能力：

- `ensurePresets()` 从 `/api/labeler/presets` 加载；
- `renderPresetDescription()` 显示 `ignored` 和 `description`；
- `collectConfig()` 收集 `custom_prompt`；
- 预设切换事件位于 `public/js/23-labeler.js`。

后续实现时：

1. 选中 `custom_lora` 时，把现有“补充要求”文案改为“自定义忽略内容”；
2. 更新 placeholder，给出忽略面部、动作、物件等例子；
3. 标记为必填或在开始任务前给出明确错误；
4. 切回其他档位时恢复“补充要求”文案；
5. `collectConfig()` 仍只提交 `custom_prompt`，不改变任务接口；
6. 帮助文案补充通用档“尽量盘点可见维度、没有就跳过、不猜测”的说明。

## 7. 实施边界

本交接方案明确不包含以下内容：

- 不把自定义自然语言自动拆成硬过滤词；
- 不改变现有专项档的“选什么就忽略什么”语义；
- 不修改历史任务和历史标注；
- 不新增客户端密钥、供应商配置或任意 URL 字段；
- 不把“完整描述”理解成对图片中不存在的内容强行输出；
- 不在本次方案阶段运行真实供应商付费探针。
