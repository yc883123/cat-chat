# 造梦机结果交互与媒体槽跳过计划

> 状态：**已实施（2026-11-09，用户明确要求执行）**。原文先要求只写计划文档；实施时未查看或使用冻结版作为证据，验证以源码版实例与自动化测试为准。

## 一、目标与已确认口径

本计划合并两组造梦机问题：批量结果页的导航、产物按钮和耗时显示；以及单次/批量生成中媒体槽的跳过行为。

媒体槽范围已确认：

- 单次生成和批量生成都支持明确选择“跳过这个输入”。
- 未上传/未替换不能自动视为跳过：工作流槽位已有默认音频、图片或视频时，默认仍沿用原文件，支持固定素材工作流。
- 媒体槽提供三种清晰状态：沿用工作流原文件、使用用户选择的新文件、手动跳过这个输入。手动跳过必须是用户明确操作，且可取消恢复原本状态；空值且确认 optional 的槽仍保留自动跳过行为。
- 跳过控件使用用户指定的 `⊘` 符号，并提供可访问名称/悬停提示“跳过这个输入”；图形仅作为状态/操作标记，不用文字按钮替代。
- 保留 optional 对空媒体槽自动跳过的判断，不全局删除这层规则。工作流已有原文件时，“沿用原文件”优先，不能因为它是 optional 就自动删掉固定音频、图片或视频。
- `⊘` 是独立的手动强制跳过操作：只有此路径不受 optional 限制。用户点击后，执行端从本次提交工作流副本移除对应的下游输入连接；如果 ComfyUI 因此无法执行，就显示其正常错误。
- 未选新文件且工作流原值为空时：确认 optional 的槽继续自动跳过；必填或无法确认的槽保持现有选择文件提示，用户也可手动点 `⊘` 强制跳过。
- 仅处理媒体槽，不增加任意节点的删除开关。被跳过的媒体加载节点只在本次工作流副本中、且确认没有其它连接引用时清理。
- 已确认的按钮文案“设置高级参数”保留，不纳入本计划的代码变更范围。

批量结果反馈：

- 从结果页「批量」列表打开某批次后，批次详情应留在结果区域，不应切回「批量生成」填单入口。
- 条目产物操作应打开对应产物所在文件夹，不应展开产物列表或打开原地灯箱/播放器。
- 历史批次耗时应反映该批次真实耗时，切换页面或重新打开详情时不能从零开始，也不能对已完成批次继续累计。

## 二、已查明现状

- `public/js/24-comfyui.js::openBatchHistory()` 将历史批次切到 `data-comfyui-pane="batch"`；批次填单视图和跑批详情共用该档，因此结果列表打开批次后会离开结果档。
- 跑批条目上的 `data-batch-action="toggle-item-outputs"` 只展开条目产物卡。媒体卡按类型调用共享灯箱/播放器；结果页另有单独的打开产物根目录入口，条目卡没有定位文件夹动作。
- `startBatchRunElapsed()` 用 `Date.now() - batch.runStartedAt` 更新耗时。`openBatchHistory()` 每次打开历史批次都会重置 `runStartedAt`，离开批量档会停止计时器，再次进入后又继续基于新起点累计。
- 普通媒体槽目前按 `media_optional` 和工作流默认文件区分“未选即跳过”“请选择文件”“沿用原文件”。`collectMediaInputs()` 只提交用户选中的媒体；runner 仅在 ComfyUI schema 确认目标 optional 时移除下游连接。当前缺少对任意媒体槽显式执行“跳过”的状态。
- 批量媒体口空值的缺项检查也使用 optional 语义，可能阻止必需声明或未知 schema 的条目提交；需区分“沿用工作流原文件”和“明确跳过”。
- 普通标量槽的覆盖与默认值规则不属于本次媒体槽跳过范围，不改变其现有行为。

## 三、实施方案

### A. 批量结果页

1. 分离「批量生成填单/当前跑批」与「结果页历史批次详情」的视图状态。由结果页批次行打开详情时保留结果分档和「批量」结果来源；提供明确返回批次列表的操作。填单区「查看以前的批次」仍可进入结果页批次列表。
2. 在批量条目产物操作处改为“打开文件夹”语义，使用已有文件定位能力或增加窄范围的 ComfyUI 产物 reveal 接口。操作目标为该条目的产物目录，不能用打开产物根目录替代具体批次/条目目录；浏览器模式不支持本机 Explorer 时需按项目现有桌面能力降级并给出明确反馈。
3. 为批次耗时使用稳定的任务时间数据。新批次从服务端批次/任务实际开始时间计算；完成后以终态时间固定耗时。历史批次根据已有任务 `started_at`/`finished_at` 等持久时间计算，不在打开详情时初始化新的起点。若老记录缺少必要时间，显示“耗时未知”，不伪造计时。
4. 离开详情只停止 UI 刷新定时器，不修改持久起止时间；重新进入时根据持久时间立即重算显示。

### B. 单次与批量媒体槽跳过

1. 在 `public/js/24-comfyui.js` 为单次媒体槽增加独立的 `⊘` 手动跳过控件，提供可访问名称和悬停说明。再次点击取消手动跳过，恢复此前的原文件/已选文件状态。默认行为按明确优先级处理：已选文件则替换；没有新文件但原文件非空则沿用；原值为空且确认 optional 则自动跳过；其余提示选择文件，可手动点 `⊘` 强制跳过。
2. 批量映射/条目素材采用同一优先级，区分沿用原文件、上传替换、optional 空槽自动跳过和手动强制跳过。取消映射只控制条目列的显示，不能替代手动跳过；隐藏的媒体槽也要保留方案原文件。手动跳过的条目不因必填声明而在前端被拦住。
3. 手动跳过状态独立于 `media_inputs`/`overrides`，通过明确的槽位地址列表随单次和批量任务提交。执行端验证地址属于工作流扫描出的媒体槽后，在任务 prompt 深拷贝上移除对应下游连接，此路径不以 optional 为门槛。保留原有 schema 查询用于空槽自动跳过判断，并让“沿用原文件”优先于 optional 自动清理。选中的媒体仍走既有受管上传与回填流程。
4. 删除下游连接后，重新统计工作流剩余连接。只清理由这些媒体输入失去所有引用的加载节点；加载节点仍被其它分支使用时必须保留。`GetVideoComponents` 等中间节点要按现有安全清理模式处理，禁止留下悬空引用。
5. 修改只作用于执行用深拷贝，不改工作流库母本、任务输入快照或批次快照。ComfyUI 对跳过后的图返回必填输入等校验错误时，保留并展示正常失败信息，不在客户端猜测或静默恢复默认。

## 四、关键文件

- `public/js/24-comfyui.js`：批量历史详情导航、条目产物按钮、耗时显示；单次媒体状态、批量条目媒体留空与提交校验。
- `naiba/comfyui/runner.py`：区分沿用原文件、optional 空槽自动跳过与显式强制跳过，复用现有媒体应用和无引用节点清理边界。
- `naiba/comfyui/batches.py`、`naiba/comfyui/jobs.py`、`naiba/comfyui/store.py`：显式媒体跳过地址的校验、任务/批次快照与编辑回填、重试继承；批次与任务时间字段的可用性、生成/汇总和持久化。
- `naiba/http.py`：若现有路径无法定位具体批次条目目录，再增设受限的本机文件夹定位接口；需复用现有路径校验与桌面调用模式。
- `tests/test_comfyui_module.py`：固定素材默认沿用、optional 空槽自动跳过、手动强制跳过必填/未知声明、共享加载节点保留及母本不变。
- `tests/test_comfyui_native_submission.py`：runner 实际提交图的媒体连接裁剪、原文件保留、已选媒体回填、清理引用安全。
- `tests/test_comfyui_batches.py`、`tests/test_comfyui_frontend_assets.py`：批量媒体三态意图、optional 自动判断与手动跳过不冲突、结果页导航、耗时稳定性及条目打开文件夹行为。

## 五、验证与完成定义

- 定向运行 ComfyUI 模块、批量、runner/native submission 和前端资产测试。
- 后端测试区分两条跳过路径：空槽自动跳过仍需 optional 判断；手动 `⊘` 可强制跳过必填或未知声明的槽。验证即使槽声明 optional，只要默认原文件非空且未手动跳过，也必须保留固定素材；母本不变；共享 loader 仍被引用时不删除；ComfyUI 返回错误时任务错误正常展示。
- 前端测试验证单次和批量均区分沿用原文件、上传替换、手动跳过，不能把未上传统一序列化为跳过；取消 `⊘` 恢复此前状态；空值 optional 槽保留自动跳过提示。普通标量与 seed 行为未变。
- 前端交互验收：结果页点批次后仍在结果区域；条目“打开文件夹”定位该条产物目录；批次离开/重进和再次打开历史详情时耗时不归零，完成批次不继续增长。
- 源码版 Cat Chat 实例验收，不打开冻结版；跳过验证使用离线/mock 工作流，不发起真实生成或付费请求。记录若 ComfyUI 拒绝移除后工作流时返回的实际错误。
- 已按计划实施并运行定向与全量测试；记录保留过程文档的「先写计划」约束是为了说明约束来源，不是当前实施状态。
