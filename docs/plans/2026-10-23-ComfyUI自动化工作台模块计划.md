# ComfyUI 自动化工作台模块计划

> - 日期：2026-10-23
> - 状态：**已实施并真实环境验收通过（2026-10-24，实施记录见 §13；真实端到端验收记录见 §11 勾选项）**
> - 核查基线：commit `7aae51e`（3.6.5-beta），打标器相关文件当时另有未提交改动，本计划不触碰
> - 参考材料：`D:\huiying.rea`（绘影 huiying.exe 0.9.31 静态拆包工作区，Tauri v2 + React）
> - 上游惯例：`docs/plans/2026-10-23-打标器接入工作台计划.md`（工作台新功能页样板）
> - 本文档回答三个已确认的产品口径：
>   1. **工作流库不是定死的**——用户随时导入自己的任意工作流，参数模板由后端自动扫描派生，不是每个工作流手写模板；
>   2. **只收 API 格式工作流，不做 UI→API 自动转换**——但导入界面必须内嵌「如何导出 API 格式」的操作引导，并提醒用户「先在自己的 ComfyUI 里完整跑通再导入」；
>   3. **显示名定为「造梦机」**（用户授权按创意取的三字名，内部代号不变：页面 key `comfyui`、路由 `/api/comfyui/*`、文件名 `24-comfyui.js`、后端 `naiba/comfyui/`）；**验收必须用一份真实跑通的 API 工作流在造梦机页端到端跑通**，不能只靠假模型/假端点测试闭环。

## §1 目标与依据

在工作台（模块库）新增「造梦机」功能页（内部代号 comfyui）：用户把自己在 ComfyUI 里跑通的工作流导入成库，填几个参数就能反复出图/出片，任务排队执行、产物落库可查看，重启后能恢复。

### §1.1 参考程序（绘影）的 ComfyUI 自动化设计

以下全部来自 `D:\huiying.rea\frontend\assets\comfyui-workflow.adapter-BTwYGdoB.js`（美化副本 `_pretty_comfyui-workflow.adapter.js`，下文行号指美化副本）与 `comfy-user-workflow.store-D_NeE6tN.js` 的静态证据：

| 能力 | 绘影的做法 | 证据位置 |
|------|-----------|---------|
| 连接配置 | providers 里 `comfyui` / `comfyui-video` 条目，兜底 `http://127.0.0.1:8188`，无需 API Key | ai.store + RhWorkflowImportModal |
| HTTP 通道 | 直连强制 `Origin: ''` 绕过 ComfyUI origin 校验；浏览器态降级同源代理 | safeFetch（:262-301） |

| 参数应用 | 按原值类型做字符串→number/bool 的保真转换（`x()`），`confirmedParams` 持久化在工作流条目上 | applyParamsToPrompt（:371-379） |
| 种子处理 | `seed`/`noise_seed` 数值槽：默认随机（<2^53），可固定，可只统计不改动 | randomizeSeeds（:381-397） |
| 动态剔除 | `excludeNodeIds`：删节点并清掉其他节点里指向它的连线输入 | runWorkflow（:422-437） |
| 输入上传 | `/upload/image`（multipart，overwrite:true）；`/view?type=input` 的 HEAD 探测复用已传文件，避免重传 | uploadFile（:520）/ resolveExistingInputRef（:612） |
| 取消 | `POST /interrupt` + `POST /queue {delete:[promptId]}` 两步 | cancelTask（:773-813） |
| 节点级进度 | WS 事件流（executing/executed/execution_cached/progress）+ 拓扑序预填已完成节点 | monitorProgress + buildExecutionOrder（:40-70） |
| 任务恢复 | 节点数据存 `taskId` + `comfyClientId`，重开应用后从 `/history` 的 status.messages 回放进度 | replayFromHistory（:1195-1216） |
| 输出回收 | `/history` outputs 拼 `/view` URL，6 次 × 4s 重试 | getTaskResults（:1228-1267） |

| 工作流库 | 用户导入任意工作流，三个桶（image/video/sidebar）存放，localStorage + AppData JSON 原子写（tmp+rename），FNV 内容哈希去重 | comfy-user-workflow.store |

**关键结论：绘影的工作流库同样不是定死的。** 库条目由用户随时导入（`addWorkflow`），参数模板是导入时扫描生成的，`confirmedParams`（用户确认过的参数绑定）和 `capabilities`（能力标注）作为可选元数据挂在条目上。

## §3 范围边界

### 本期做

1. 工作台「造梦机」功能页：连接测试、工作流库（导入/列表/详情/删除）、参数表单、任务提交与排队执行、事件轮询、取消/重试、产物查看与删除、重启恢复。
2. 后端独立域 `naiba/comfyui/`（labeler 式分层），只依赖 config 的 `comfyui_url`，不产生聊天 Run、不写回聊天消息。
3. 取消语义对齐绘影：`/interrupt` + `/queue` 删除两步。
4. 导入体验三件套（用户拍板）：**只收 API 格式**、检测到 UI 格式时报错并**内嵌导出 API 的操作步骤**、导入界面常驻提醒「**请先在自己的 ComfyUI 里完整跑通这份工作流，再导出导入**」。

### 本期不做（留后路）

| 不做 | 理由 | 后路 |
|------|------|------|
| UI→API 自动转换 | 转换有损（widget 序列化、primitive、reroute、组嵌套），社区转换器不可靠；绘影与 Cat Chat 现有工具都不做 | 报错信息里给手动导出步骤；未来可加独立转换工具 |
| WebSocket 节点级进度 | 轮询口径与现有 jobs.py 一致，段级进度（完成 x/y）够用；WS 要引入长连接生命周期管理 | runner 预留进度事件结构（`node_progress` 事件类型），升级只改采集端 |
| 图片输入上传 | 工作流多数纯文生图；上传链路（/api/uploads → /upload/image → 注入 LoadImage.filename）独立可后补 | 参数扫描已把 `LoadImage.filename` 识别为图片槽位，P5 接 |
| 与聊天域 comfyui 工具共用执行代码 | jobs.py 是聊天域稳定路径（2026-09-20 事故修复沉淀），动它有回归风险 | 两边共用「口径约定」（seed 2^50、提交错误要带原因、丢失判定），代码后置合并 |
| 内容哈希去重（绘影有） | 按 id 管理已够；重复导入靠名称+时间可辨 | store 层加 content_hash 字段即可后补 |
| LLM 辅助填参（模型帮写参数） | 与「用户输入一级位」口径一致：先做纯表单 | 后续可挂 handoff |

## §4 关键决策

| # | 决策 | 理由 |
|---|------|------|
| D1 | **独立域任务，不复用 JobRegistry** | Job 的 owner/conversation 语义挂在会话上，产物写回聊天消息；工作台任务要对齐 labeler 形态（任务 JSON + 事件游标 + 60 条历史上限 + 批量删除 + recover_interrupted）。执行逻辑借鉴 jobs.py 的 checkpoint 设计而非直接调用 |
| D2 | **执行引擎自建于 runner，轮询监控** | 同口径于 jobs.py（提交期 1s、轮询期 1-3s、30 分钟单段超时、队列+历史双查才判丢失）；进度=段级。WS 留事件类型后路 |
| D3 | **工作流库不定死：用户导入，JSON 文件存储** | `data/comfyui/workflows/<id>.json`，原子写；字段含扫描出的 `params`。不进 SQLite（无标注库那种查询需求） |
| D4 | **参数模板 = 导入时后端自动扫描派生** | 遍历节点 inputs，跳过数组（连线）值，产出槽位 `{nodeId, fieldName, fieldType, default}`；`seed`/`noise_seed` 数值槽标为 seed 类默认每次随机（上限 2^50，沿用既有教训）；提交时按槽位原类型保真转换。用户的填值可存成命名参数集（paramSets），类似 confirmedParams |
| D5 | **API 格式硬门槛 + 导出引导** | 判别复用 `_normalize_comfyui_workflow` 的规则（nodes/links 数组即 UI 格式）；报错文案内嵌导出步骤（见 §7 导入契约）；界面常驻「先跑通再导入」提醒。不做自动转换 |
| D6 | **取消两步走** | `POST /interrupt`（停止正在执行的）+ `POST /queue {delete}`（移除排队的），与绘影一致；现有 jobs.py 只置 Event 不够 |
| D7 | **产物落盘存字节，不存 URL** | 完成后拉 `/view` 字节存 `data/comfyui/outputs/<task_id>/`；ComfyUI 清历史后 URL 失效，本地文件才是资产。服务走 `_serve_local_file`（`http.py:1480`）同款机制 |
| D8 | **连接配置沿用 `comfyui_url` 键** | 已是既定口径（jobs.py 读取处）；工作台页提供「测试连接」（GET /system_stats 透传，展示版本与设备），修改地址引导到现有设置入口 |
| D9 | **任务串行（并发=1）** | 与打标器 `VALIDATED_CONCURRENCY=(1,)` 同口径；ComfyUI 本身按队列执行，客户端并发提交只会把排队关系弄乱 |

## §5 分期实施

### P0 域骨架 + 连接（后端为主）

- 新建 `naiba/comfyui/`：`__init__.py`（状态机常量）、`service.py`（门面）、`client.py`（ComfyUI HTTP：reachable/submit/queue_ids/history_once/output_urls/interrupt/delete_queue/download_output）、`store.py`（工作流+任务存储）、`jobs.py`（submit/cancel/retry/recover）、`runner.py`（串行线程）
- `naiba/app.py` 装配：`self.comfyui = ComfyUIService(self)` + try/except `recover()` + `stop()` 收尾 + 两处 `referenced_upload_paths()` 并入
- 路由：`GET /api/comfyui/health`（连接测试）
- 功能页四点同步（config.py STUDIO_PAGE_VIEWS、22-studio.js STUDIO_PAGES、index.html nav + page-view）+ 空白页 + `public/js/24-comfyui.js` 骨架（含轮询经 `onStudioPageChange` 暂停/恢复）

验收：起隔离实例，工作台出现造梦机页；ComfyUI 开着时「测试连接」绿、关着时红且文案说明去哪开。

### P1 工作流库（含导入三件套）

- `POST /api/comfyui/workflows`（导入：校验 API 格式 + 扫描 params + 存库）、`GET .../workflows`（列表）、`GET .../workflows/<id>`（详情含 params）、`DELETE .../workflows/<id>`
- 请求体上限表加条目（工作流 JSON，20 MiB，对齐 `_load_comfyui_workflow` 的文件上限）
- 导入界面：文件选择 + 粘贴 JSON 两种入口；UI 格式报错内嵌导出步骤；常驻跑通提醒（文案见 §7）
- 参数扫描（D4）：全量槽位 + seed 类标记 + `LoadImage.filename` 标记为图片槽位（只标记，不上传）

验收：导入一份真实跑通的 `workflow_api.json`，详情页列出参数槽位；导入 UI 格式被拒并显示导出步骤；删除后列表消失、磁盘文件删除。

### P2 任务执行

- `POST /api/comfyui/tasks`（{workflow_id, overrides, shots≤200}）：runner 串行提交（applyParams 类型保真 + seed 随机化 2^50 + `POST /prompt`），轮询 `/history`+`/queue`，checkpoint（submitted/completed/errors/resubmits），事件 JSONL（task_started / shot_submitted / shot_done / shot_failed / task_done / log）
- `GET /api/comfyui/tasks`、`GET .../tasks/<id>`、`GET .../tasks/<id>/events?after=`（游标轮询，POLL_MS 对齐打标器 1200）
- `POST .../tasks/<id>/cancel`（两步取消 D6）、`POST .../tasks/<id>/retry`
- 前端：参数表单（按槽位类型渲染 text/number/bool）、任务卡（状态 + 段进度 + 取消/重试）

验收：提交 2 段任务，事件流逐段推进；执行中取消，ComfyUI 侧当前段被 interrupt；提交错误信息包含 ComfyUI 返回原因（对齐 jobs.py `_summarize_comfyui_reject`）。

### P3 产物采集与查看

- 完成段拉 `/view` 字节存 `data/comfyui/outputs/<task_id>/`；task JSON 存相对文件名
- `GET /api/comfyui/tasks/<id>/files/<name>`（`_serve_local_file` 服务，图片/视频按后缀给 Content-Type）
- 前端产物网格：点击放大（FullscreenImage 同款体验）、单删；`DELETE /api/comfyui/tasks` 批量删历史（进行中跳过）

验收：任务完成后产物页出图；重启 ComfyUI 并清空其历史后，产物仍可看；**并用一份自己 ComfyUI 里跑通的真实 API 工作流，在造梦机页完整走一遍 导入 → 填参 → 提交 → 产物查看（真实端到端，本期验收硬条件）**。

### P4 恢复与诊断

- `recover_interrupted()`：启动时遗留 running/queued → interrupted；task JSON 里的 prompt_ids 逐个查 `/history`，已完成的段直接收产物（借鉴绘影 replayFromHistory 的语义、jobs.py 的 checkpoint 实现）
- 失败诊断：`/history` status.messages 的 error 摘要（异常类型 + 节点名）写入事件与任务错误字段；提交 4xx 时透传 `_summarize_comfyui_reject` 同款摘要

验收：执行中杀进程重启，任务收敛为 interrupted 且已完成段产物在；「重试」从未完成段继续（不重复提交已完成段）。

### P5 增强（可独立砍）

- 图片输入上传链路（/api/uploads 选图 → runner `POST /upload/image` overwrite → 注入 filename 槽位）
- 命名参数集（paramSets：保存/套用一组填值）
- 能力识别增强（主提示词/比例/分辨率槽位置顶，绘影函数 `h` 的规则子集）
- 内容哈希去重、shots 与 200 上限的进一步口径说明

## §7 接口契约

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/api/comfyui/health` | 测试连接（system_stats 透传：版本/设备/空闲判断） |

| POST | `/api/comfyui/workflows` | 导入 {name, workflow}：API 格式校验 + 参数扫描 |

| DELETE | `/api/comfyui/workflows/<id>` | 删除（被进行中任务引用时拒绝） |

| POST | `/api/comfyui/tasks` | 提交 {workflow_id, overrides, shots} |

### 13.2 关键实现口径

- **执行代码独立**：`client.py` 的提交/轮询/丢失判定与 `naiba/jobs.py` 同口径（提交失败带 node_errors 摘要、历史+队列双查才判丢失、重提交预算 1、单段 30 分钟超时），未改动聊天域任何代码。
- **seed 语义**：未填 = 每次随机（上限 2^50）；填了 ≥0 = 固定；负数 = 随机哨兵（jobs 层过滤 + `apply_overrides` 双兜底）。
- **任务快照**：任务 JSON 保存 prompt 副本与名称，删除工作流不破坏历史任务；删除工作流前检查活跃任务引用。
- **取消两步走**：`/interrupt`（停当前段）+ `/queue {delete}`（移排队段），取消运行中任务保留已下载产物。
- **恢复收养（P4）**：启动恢复 queued/running → interrupted；重试时对上次已提交未确认的段先查 `/history`——已完成的直接收产物，不重复提交。
- **产物落盘（D7）**：段完成后 `/view` 字节写入 `data/comfyui/outputs/<task_id>/`，任务只存相对文件名；服务走 `_serve_local_file`（含视频 Range seek）。
