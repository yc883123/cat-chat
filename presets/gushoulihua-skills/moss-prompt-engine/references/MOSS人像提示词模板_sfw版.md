# MOSS 人像摄影提示词模板（SFW 完整版 v3.0）
作者：B站-是古手梨花sama

主要面向 MOSS-Image-SFT 真人摄影的提示词设计；MOSS-Image-Base 可参考格式与组织方式，不据此承诺相同美学。适用内容，包括日常随拍、自然光写真、棚拍、商业时装、精致性感写真、古典人像、双人互动、环境叙事、海报与摄影拼贴。

将整份文件交给负责写词的 AI，再输入画面需求。AI 根据本文件直接交付可用的正向提示词，不复述模板、不展示规划或自检表。模板中的人物、服装、地点、例句均为素材，不是用户已经要求的内容。

默认使用中文自然语言，用户明确要求英文或双语时切换。摄影表现方式单独组成第一句。保留 Caption、Tag、Layout 三种格式，普通人像优先 Caption。默认从用户需求自由设计，运用关系判断完成画面；案例和词库只是辅助，不作为预设路线。只写用户需要的画面，不自动加入质量评分、画师、负向、模型与采样参数。每次修改返回完整成稿。

## 1. 输出协议：写什么，交付什么

### 1.1 语言与可见文字

- 默认中文。用户指定英文则写一份完整英文；指定双语则交付两份语义相同、各自独立可用的完整版本，不能把两种语言重复贴进同一个正向框。
- 英文应是自然摄影描述，保留人物归属、接触、光源方向和空间关系，不压缩成另一套模型的标签语法。
- Layout 字段与枚举保持英文，`caption` 等描述值按用户选择的语言写；可选媒介标签也可翻译或省略。
- 画面里真正需要印出的文字原样保留，包括大小写、标点和换行。引号里的情绪、标题灵感、比喻不自动变成印字任务。
- 常用摄影器材与焦距可以按原名写，但不要为显示专业而在每句中英重复。

### 1.2 正向结果不自动包含的内容

不自动添加质量 tag、评分 tag、画师、`@artist`、负向词、模型路径、LoRA 文件名和强度、步数、CFG、种子、自检成绩、测试编号、统计、解释与生成指令。不能通过 JSON 的 `meta`、`tags` 等字段绕过。

`masterpiece`、`best quality`、`score_9`、`32K杰作`不是具体画面设计。把「细节拉满」落实为可见的服装结构、面部焦点、发束交叠和材质差异，不用一串夸赞代替。

可以写真正改变摄影观感的内容：胶片颗粒、手机高感噪点、闪光投影、长焦压缩、自然肤色、选择性对焦、低饱和暖棕配色。分辨率文字不是皮肤细节的替代品；用户明确需要时可保留，但不当固定开头。

### 1.3 Caption、Tag、Layout 的交付

| 格式 | 正向框接收的内容 | 交付边界 |
|---|---|---|
| Caption | 有主语、关系和因果的连贯摄影描述 | 默认一至数个自然段，不强制一行，不附自检与说明 |
| Tag | 摄影首句＋紧凑内容标签，复杂关系用短句补足 | 用户明确要求才优先使用，不添加其他模型权重 |
| Layout | 已编译的一行紧凑 JSON | 实际画布尺寸在正向外说明，不能把像素草稿直接当成稿 |

用户只要一条词时只给一条，不擅自扩成方案合集；只要多个不同方案时，每条都完整，不用「同上」省略。文件包装成 JSON 不等于模型使用了 Layout。

### 1.4 独立摄影首句

选择优先级：用户指定表现与参考图 → 当前题材与用途 → 合理默认。第一句只确定整体摄影方式、成像特征或风格，不分析人物和灯位，不自动指定摄影师。

可用开头：

| 方向 | 独立首句示意 |
|---|---|
| 生活街拍 | 真实生活人像摄影，日常手机随拍的自然成像。 |
| 精致写真 | 自然光时尚人像写真，细腻肤质与克制的胶片色彩。 |
| 棚拍 | 黑灰背景的低调棚拍人像，具有明确的面部明暗结构。 |
| 古典 | 真人东方古典人像摄影，暖色暗调与细腻的织物层次。 |
| 夜景 | 低照度城市人像摄影，真实高感颗粒与清晰的人物焦点。 |
| 直闪 | 千禧年数码直闪人像，直接闪光与轻微颗粒形成随性快照感。 |

Caption 第一完整句即摄影句；Layout 放在 `summary.caption` 首句，不另加 `style`，不在每个人物项重复；Tag 放在标签前。只改风格时只改这一句并完整返回正文；若用户要求同时改变光照或成像，才调整相关内容。

### 1.5 丰满度与篇幅

默认交付一份设计充分的摄影描述，不因用户只写一句话就只扩一句形容词。通常可用约400～800中文字展开人物、衣装、姿态、空间和光影；精简要求可缩短，复杂礼服、双人、古装或环境叙事可以更长。这是写作参考，不是模型最佳长度结论，也不是必须凑满的字数配额。

不照搬固定十段的字数硬上限。信息密度由取景决定：胸像把精力放在五官神态、肩颈、可见衣领与近景；全身才展开下装、鞋履、重心和地面。无关细节越多，越需要删掉，而不是继续加长。

## 2. 格式选择决策树

```text
用户明确指定格式 → 按指定格式。
否则，是否需要固定区域、多个独立文字块、图文排版或摄影拼贴？
    是 → 先定画布，再使用 Layout。
    否 → 单人、双人、自然场景、复杂姿势均优先 Caption。
只需大致左右关系 → 用自然语言；不因细节丰富自动升级 Layout。
用户只要标签 → Tag；需要接触、镜面与多人关系时补完整关系句。
```

### 2.1 常见任务

| 需求 | 默认格式 | 重点 |
|---|---|---|
| 一个美女在咖啡馆窗边 | Caption | 人物、衣装、姿态、窗光与日常道具 |
| 16:9性感半身写真 | Caption | 脸与肩颈为主体，服装剪裁、手部与横向环境关系 |
| 低机位坐姿、侧躺、露背回眸 | Caption | 支撑、身体与头部朝向、机位相容 |
| 两人并肩或相互整理头发 | Caption | 精确人数、独立属性、共享接触与目光 |
| 人物占左半，右侧三段指定文案 | Layout | 人物与文字独立占位，真实可见文案 |
| 两套服装并排、三格写真拼贴 | Layout | 每格一个瞬间，同一身份重复出场明确 |
| 只想保存一个prompt.json文件 | Caption文件包装 | 模型实际接收描述字符串，不伪称布局模式 |
| 只修脸、手或油亮问题 | 先修Caption | 坐标框不能控制五官、关节和皮肤材质 |

### 2.2 不自动启用的功能

不因「高级」「电影感」「精致」「姿势新颖」就改 JSON，不自动加海报标题、边框或水印，不把多张参考图理解为必须生成拼贴。没有真实排版要求时，空白是空间与情绪，不是默认广告位。

### 2.3 草稿与最终结果

普通描述可以用 `{"caption":"..."}` 存档，但正向内容是字符串值。Layout 则需按§12编译字段与坐标，不能只把普通描述套一层 JSON 就声称拥有区域控制。

## 3. 需求解析与默认补全

### 3.1 内部需求表

| 维度 | 需要确定 | 未指定时的补全 |
|---|---|---|
| 主体 | 人数、年龄语境、身份、不可改特征 | 单人明确成年，结合任务设计外貌；不自动加路人 |
| 审美主目标 | 漂亮脸、服装、性感、环境、故事中的主次 | 按用户目的确定，不把看脸优先强加给完整造型、环境或概念任务 |
| 摄影体裁 | 街拍、自然写真、棚拍、商业、古典等 | 选择一种主体裁，允许有目的的融合 |
| 外貌 | 脸部特征、肤色、发型、体型、神态 | 补有用特征，不统一成夸张尖下巴或同一妆容 |
| 服装 | 主件、廓形、材质、颜色、穿着状态、露肤方向 | 依据场景与景别主动设计，精致不等于随意堆珠宝 |
| 动作 | 一个瞬间、支撑、双手任务、目光 | 选择自然可拍动作，不让人物只站在背景前 |
| 镜头 | 裁切、机位、观看方向、透视与主体大小 | 看脸则近一些，看全身则让脚与接触面入镜 |
| 环境 | 地点、时间、前中后景、关键道具 | 一个具体地点，细节随取景分配 |
| 光影 | 主光位置、性质、面部作用、暗部、填充 | 根据空间与时间建立一套可解释照明 |
| 色调 | 主色、暗部色、点缀、肤色关系 | 一套有主次的配色，避免全脸无差别染色 |
| 成像 | 对焦、颗粒、噪点、运动模糊、眩光 | 随体裁选用，不同时强求超清和全图模糊 |
| 输出 | 语言、格式、条数、画幅、可见文案 | 中文Caption；画幅服务任务，不把所有图固定16:9 |

普通缺项自行补全，不要求用户先填十几个字段。用户指定的衣装、身份、关系、动作、尺寸与排除项优先。只有缺失信息会改变任务本身时才澄清，如单张还是拼贴、提供的图片是人物参考还是需复刻的整体构图。

原创性感、魅力写真使用明确成年人物。保留用户明确指定的族裔、肤色与体型，不把漂亮一律改成冷白、苗条或某一种脸。参考图只提取可见信息，不根据模糊细节杜撰身份。

### 3.2 从用户需求推导画面，而不是检索相近案例

写词的入口永远是这一次用户的需求。例图不是先验场景菜单，漂亮、性感、冷艳、氛围感等形容词不自动等于咖啡馆、窗边、黑底或某种机位。内部先分清以下五类信息：

| 信息类型 | 如何处理 | 不应混淆的内容 |
|---|---|---|
| 用户硬约束 | 保留指定人数、身份、衣服、动作、机位、地点、画幅、文案和排除项 | 不能为了更像优秀例图而替换 |
| 用户效果目标 | 将漂亮、性感、朦胧、压迫、精致等转成可见选择，按用户表达确定主次 | 不是套一个情绪标签，也不自动改场景 |
| 未指定的开放项 | 自行设计相容的发型、工艺、道具、背景与光照，允许新组合 | 补全决定不是用户已锁定的要求 |
| 必要关联 | 从当前方案推导机位、可见面、支撑、光源、投影、材质与尺度关系 | 关联关系必须成立，但没有唯一固定搭配 |
| 偏好与不确定性 | 把肤质、妆色等偏好用作可调整的选择倾向，保留例外 | 不能把一次差评提升成模型硬禁令 |

随后完成下面的设计推导，不要求用户填写表格，也不把过程写进最终提示词：

1. **明确要保留什么、突出什么。** 从用户这次的目的安排主体、服装、动作与环境的主次；明确要看全身时，不为放大脸擅自裁成胸像。只说“美女”时可合理补全，但不固定返回同一场景和姿势。
2. **确定观看条件。** 根据主次决定画幅、景别、相机位置、观察方向和必要留边。考虑近远物体、遮挡和空间线条怎样组织画面；不先指定一个“最稳焦距”再让题材迁就。
3. **使动作在这个镜头里成立。** 确认身体、头部、目光、支撑面、重心与可见手部。用户要新颖动作时保留意图，通过受力、构图与遮挡解决，而不是退回标准坐姿。
4. **设计衣装与场所。** 根据身份、尺度、用户想要的精致程度完成剪裁、面料、工艺、穿法和配饰；环境提供地点、时间、接触与叙事，不把背景当无关装饰。
5. **让光真正作用于该人物和空间。** 决定光源位置、性质、颜色与强弱，说明哪些可见面受光、哪些保留暗部、环境如何反射；脸、衣服、金属和玻璃各自响应，不共用一种光泽。
6. **检查是否实现了目标。** 漂亮靠面容、神态与合适观察条件；性感靠用户选择的露肤、体态、服装和距离；氛围靠时间、光比、色彩、空间与行为；精致靠具体工艺和可见细节。不把它们都翻译成“皮肤更白、更亮”。
7. **分配细节并写成完整提示词。** 在真正需要的区域加细节，删除互相抵消与画外无关信息。丰富度来自设计充分，不能以避免风险为由把所有图写成普通衣服、简洁背景和柔光半身。

允许同时创新地点、服装、姿态和灯光，只要整体有清楚主次与可解释关系。没有“每次只能改一项”的创作限制；控制单变量仅在用户要求复现、定位问题或实验时使用。

### 3.3 仲裁与风格反差

优先级：用户明确约束与内容边界 → 主体身份和动作可读性 → 摄影与光照自洽 → 丰富度与装饰。不能为了补漂亮细节，擅自改变用户的体型、服装、肤色或事件。

物理冲突必须修正；有意反差允许存在。「冷脸配温暖灯光」「古装配现代场景」「清新容貌配性感服装」可成立，不机械视为错误。必须有同一画面里的设计理由，而不是彼此无关的词库碰撞。

### 3.4 参考图、图像反推与复刻

有参考时区分人物、衣服、姿势、光影和整体构图的约束范围。复刻整体画面优先保留景别、站位、脸朝向、主色块、光源和关键遮挡；人物参考不意味着沿用原图服装与环境。只换衣服时保留已经认可的脸、姿势、镜头与灯位，除非新衣装确实需要关联调整。

看不清的花纹降低描述粒度，画外身体不要求模型同时展示，文字只在用户需要时逐字转写。多图融合先绑定来源，避免发型来自A、衣服来自B的要求被写成两个人。

### 3.5 可迁移的判断顺序

在任意新题材中依次问：**用户要什么 → 哪些可见关系能表达它 → 哪些条件会互相影响 → 当前信息是否足够 → 是否有不必要的默认偏好覆盖了用户意图**。

例如用户要“巨大落地窗前、全身、强烈侧逆光、华丽露背、低角度”，应设计能展示背部和脸的身体/头部关系、全身留边、相机位置与可信补光；不能换成窗边侧坐胸像。用户要强烈彩色硬光，应明确染色区域、五官体积与服装反光；不能把彩灯降成背景小灯点来回避要求。

### 3.6 自由创作、定向复用与问题定位

| 用户任务 | 工作方式 | 应保护的东西 |
|---|---|---|
| 新创作或开放想法 | 默认方式。根据本次需求完整设计，可调用词库或自由创造 | 用户硬约束与效果目标，不保护某张例图的布景 |
| 参考某图的部分属性 | 只提取用户指定的脸、衣服、姿势、构图或光影，其他按新需求设计 | 约定的参考范围，不把整张图强行带入 |
| 延续已认可成图 | 用户明确要求“保持这张感觉”“只换衣服”等时，保留已认可关系 | 实际被认可的身份、镜头、动作、光影或其他约定项 |
| 对照实验/定位问题 | 按用户目标控制变量，记录哪些变哪些不变 | 可比条件，不把这套实验方法变成日常创作限制 |

缺少非关键细节时自主补全。如果用户给的是充分而一致的画面，不需要先寻找对应案例，也不需要先把它翻译成内部分类名称。

### 3.7 指令、创作偏好与物理关系分层

用户明确要求优先于模板的默认审美。默认偏好只填补空缺，不擅自改变用户的肤色、体型、露肤程度、妆容、场景、画幅与镜头。需要特定湿发、水光妆、红色彩灯、白衣白背景、极端广角或夸张摆姿时，按要求组织关系，不先“纠正”为自然柔光。

先区分真实矛盾与有意反差。同一只手不能在同一刻既远举又握住胸前杯柄，需要协调；冷脸配暖光、华丽衣服出现在日常街头、古装与现代灯光并不天然冲突。复杂设计是需要说明关系，不是应该删除的错误。

通用摄影/空间关系可以帮助检查可见面、支撑与明暗；个人偏好只决定当前取舍；样本观察只能说明某张结果被喜欢或不喜欢。不要把三者都写成模型保证或永久禁令。

## 4. 创作任务与可迁移的画面判断

先按用户需求确定任务，下面的类型只提示应考虑哪些关系，不预先决定衣服、光源、场景或机位。用户可以跨类型创作，不需要匹配一张旧图。

| 类型 | 人物与服装重点 | 镜头与动作 | 光影与环境重点 |
|---|---|---|---|
| 近脸情绪肖像 | 眼神、唇形、发际与可见领口 | 胸上、头肩、侧脸；轻微转头或停顿 | 光落在脸的具体面上，背景支持情绪 |
| 都市生活街拍 | 自然妆发、衣料层次、生活携物 | 平视、轻仰或微俯，中近景或全身 | 天空、店门、街墙与路面反射有方向 |
| 窗边写真 | 头发、肩颈、领口与面料 | 坐椅、倚窗、翻书，手部有任务 | 窗光、远脸阴影、桌面或墙面回填 |
| 精致性感写真 | 剪裁、露肤位置、腰线、材质与配饰 | 半身亲近、侧背回眸或有支撑坐姿 | 照脸同时保留肩颈体积，饰物不抢焦 |
| 度假海边 | 风向、轻盈面料、肩带与手部 | 倚栏、坐石阶、转身、走动停顿 | 日照、天空与海面各有作用，不把肤质写成缎面 |
| 夜间街景 | 深浅衣装衬脸，妆容简洁 | 店门、车窗、灯下的一个动作 | 实际店光/路灯照脸，远处灯点作辅助 |
| 暗调棚拍 | 清楚五官、发束与深色衣装 | 适度低机位、正面或三分之四近景 | 伦勃朗或分割光择一，暗部保留层次 |
| 白底商业 | 廓形、领口、结构、深色边界 | 胸像、半身或完整服装展示 | 白底与肤色分离，面颊不被补成平板 |
| 彩灯时装 | 发型轮廓、皮革/织物反差 | 脸为焦点，姿态简洁有力 | 指定染色区域、交界和暗部，不只说霓虹 |
| 直闪快照 | 松散发丝、轻松表情、实际穿搭 | 平视、微倾斜或短暂抓拍 | 闪光投影、背景曝光、有限皮肤高光 |
| 古典与旗袍 | 发簪、盘扣、织金、垂饰与气质 | 近景、侧坐、执扇或触簪 | 窗光、灯笼、烛火或棚灯有实际依据 |
| 双人亲密互动 | 独立妆发衣装，年龄明确 | 同时容纳两张脸，接触有方向 | 两张脸受光关系一致，肤色不混成一片 |
| 环境叙事 | 人物身份与一件叙事道具 | 中景、留白、动作与空间有关 | 光影支撑事件，不为故事感强加灾难 |
| 海报/多格摄影 | 身份重复与图文主次 | Layout规划占位与读序 | 全局风格统一，各格事件可分别描述 |

### 4.1 体裁不是统一滤镜

日常感由放松动作、真实空间、自然裁切与合理成像共同形成，不靠反复喊「随手拍」。商业写真可以精致但不必全身油亮；冷艳不必是僵硬无眼神；性感可以来自肩颈、衣装、目光与距离，不要求所有动作都夸张。

### 4.2 带故事的人像五要素

身份是「谁处在什么状态」，动作是一个当下瞬间，环境有可见时间线索，道具有作用，观众与人物有明确关系。可用「读到一半被叫住」「离开餐厅前轻扶耳坠」「落日海风中按住帽沿」；不把「忧郁」「故事感」当作事件本身。人物在看书、望海、与同伴对视时，不强制直视镜头。

### 4.3 将画面目标转成判断关系

下表用于推导用户的新需求，不输出固定地点、衣装或镜头。它不要求先选择某个“人像方案”，也不把某种摄影风格和某个姿势绑定。

| 用户目标或画面现象 | 应判断的关系 | 可采用的设计手段 | 不应自动做什么 |
|---|---|---|---|
| 想突出漂亮面容 | 面部大小、朝向、可见五官、神态与光照是否共同支持阅读 | 选择合适取景、转头和光区；必要时减少前景遮挡与背景竞争 | 不强制大脸、平视、微笑、白皮或柔光 |
| 想看完整造型 | 服装整体、脚下支撑、手部与脸的尺度怎样兼顾 | 保留全身，使用廓形、颜色、肩颈方向和局部光比建立主次 | 不为了保脸把用户全身需求裁掉 |
| 想要精致服装 | 当前取景能看到哪些结构，材质和装饰如何承重与受光 | 设计领口、裁片、腰线、拼缝、刺绣、镶边、连接扣和配饰 | 不自动全部堆满，也不认为细节越少越稳 |
| 想性感而自然 | 用户期望的露肤、身体线条、观看距离、目光与服装状态是否协调 | 按要求设计肩背、领口、腰侧或腿部；支持自然也支持有目的的摆拍 | 不默认取消露肤、不统一夸张胸腰或挑逗表情 |
| 想要新颖镜头 | 观察位置如何改变尺度、遮挡、身体缩短与情绪 | 新机位、新裁切、前景、反射或动作停顿，明确必要几何关系 | 不把低机位或广角本身当答案，也不一律禁止 |
| 皮肤显油或塑料 | 哪些部位高光连续、面积过大，是否混入衣料材质描述或过度提亮 | 区分皮肤、唇部、发丝与织物的反射，重新分配亮区和暗面 | 不建立“所有高光都是坏的”规则 |
| 脸部颜色奇怪 | 是妆色、局部红斑、环境反射还是彩光？它与体积和身体色彩一致吗 | 明确颜色来源与范围，按目标调整妆面、灯位和强弱 | 不把红唇、红灯、自然红润全部删除 |
| 画面过亮或过平 | 人物与背景的曝光、面颊阴影、材质边界如何区分 | 明度、色彩、反差、遮挡、景深或边缘光择需组合 | 不规定背景必须暗、衣服必须黑 |
| 氛围弱 | 时间、地点、光源、色彩、距离与行为是否共同表达情绪 | 给光和物体实际作用，安排空间层次和人物当下动作 | 不只追加雾、全局模糊或“电影感” |
| 元素很多却不协调 | 主视觉与注意力如何分配，各元素是否在同一空间 | 保留用户元素，通过尺度、位置、亮度和细节密度重新组织 | 不先删用户明确要的内容，也不把“多”本身视为错误 |
| 同词观感不同 | 景别、种子、上下文、模型执行和局部外观都可能变化 | 核对实际图与运行记录，区分未执行和审美不喜欢 | 不把一张差评归罪于一个未经隔离的词 |

### 4.4 从观察中保留判断能力，而不是固定配对

1. **成功方向可能相反。** 柔光与硬光、白底与黑底、平视与低角度都可能得到被认可的人像。因此规则应解释如何在当下条件下组织主次，不能选择其中一种当所有题材的答案。
2. **相同词不保证相同面部。** 光线描述、人物动作、构图上下文和随机结果相互作用；不把局部短句当稳定触发词。写清关系能明确意图，但不提供锁脸或精准相机标定。
3. **油亮与合适光泽不是一个阈值词。** 需要检查反光位置、范围、强弱和属于哪种材质。接受自然小高光与否不等于接受全脸漆面；减少反光时也不能把皮肤改成无体积的死哑光。
4. **颜色要有来源。** 彩色照明、妆面与自然肤色可以并存，关键是它们在表面上的范围和明暗是否被描述清楚。不能用“不准红色”代替这个判断。
5. **服装复杂度不能替脸或姿态背锅。** 不喜欢一张华服全身图，不足以证明复杂衣服或露肤有问题。应分别检查面容、支撑、观察尺度、照明与材质；修脸不必改成普通衣服。
6. **近景与全身各有代价。** 近景可展开眼神与领边，全身可展示廓形和动作。根据用户的主目标安排，而不是为复用某个成功取景牺牲用户需求。
7. **氛围不是所有参数都加大。** 高反差、强彩光、颗粒、装饰和夸张姿势可以共同使用，也需要明确哪一项是主视觉、其余怎样支持。没有固定的创新维度数量上限。
8. **喜欢实例不等于验证规则。** 已认可样图可以用来理解偏好；由此提出的写词调整仍是创作策略，不能被描述成单词因果、跨种子稳定率或模型能力上限。

### 4.5 需求宽泛时怎样补全

用户只有“美女、人像、漂亮”时，可主动给出一个完整的新设计：选成年人物的气质、适合的衣装与场所，安排动作、镜头和光线，并形成主次。不要反复输出同一咖啡馆、纱帘、花店、35mm低机位或三分之四侧脸。

用户连续索要不同方案时，有意识改变题材、观看关系、衣装结构、空间和色彩中的有用维度，同时保证每张自洽；不机械只改衣服颜色，也不为多样性故意制造无意义冲突。用户明确要重复同一效果时，才保护既有组合。

## 5. 人数、身份、外貌与表情绑定

### 5.1 人物不是一串赞美标签

按「成年身份/年龄语境 → 族裔与肤色 → 气质与体态 → 可辨面部特征 → 眼神和神态」设计。近脸可以细化眉眼、脸颊与唇形；远景只保留能辨认的特征，不把每个角落都写成微距。

漂亮要有可见表现：眉眼比例协调、五官清楚、唇部自然、面部有体积、表情与目光有对象。避免同时堆极小脸、极尖下巴、极大眼睛、浓腮红、极白皮和夸张修容。不同气质可以使用不同面部特征，不默认同一张网红脸。

用户声明人脸LoRA或身份参考时，外貌只补其未锁定部分；不能因为使用一枚通用风格LoRA就删除全部面部描述，也不能声称提示词可稳定锁脸。

### 5.2 发型、妆容、表情各司其职

发型用长度、发色、卷直、扎法、刘海与少量碎发确定轮廓。发丝的运动、重力与人物姿势一致，不能坐姿静止却让全部发丝向多个方向飞。

妆容选择一种主要方向，再写一两处眼妆和唇色。腮红可选，不默认鼻尖红、眼下大面积红或颧骨高光全开。用户要浓妆时明确其范围，仍区分粉妆与灯光染色。

表情按「眼睛在看谁/何物 → 眼睑与眉部状态 → 嘴角或唇部动作」写。微笑不必露齿，冷艳不必皱眉，慵懒不等于双眼失焦。只选择一个主情绪，允许微妙反差，不同时让同一张嘴大笑、紧闭和微张。

### 5.3 体型与性感表达

保留用户需要的身高感、肩胯、腰线、腿部与身形。全身服装可描述重心和线条，近脸不必量化所有身体部位。默认成年、自然比例；不把性感自动改成夸张胸腰或统一修长体型。

露肩、低领、露背、侧腰、短裙、开衩、泳装与精致内搭可作为成年人物的非露骨服装设计。根据姿势检查实际可见范围与衣料覆盖，需要时写内衬、打底短裤或裙摆落点，不给每个胸像强加画外内衣细节。明确裸露隐私部位或性行为不属于本SFW模板的延伸任务。

### 5.4 多人独立绑定

先写精确人数，再分别绑定外貌、衣服主色、站位、动作与目光。例如「左侧黑长直女性穿白色针织上衣；右侧短发女性穿浅蓝衬衫。右侧女性的近手轻搭对方肩头，两人向中间靠近并互相看着对方」。不要把两套属性混成共用词串。

共享道具只一件：递同一束花、共同看同一本书、两手接触同一只杯。人物与镜中倒影、照片、屏幕中的脸分别说明实例性质；精确两人不等于背景绝不能有模糊路人，按需求区分。

### 5.5 左右与目光

画面左右按观众方向，解剖左右按人物自身。优先用近侧手、远侧手、靠窗脸颊、背光面等可检查关系。明确身体朝向、脸朝向和目光，不把「身体背向镜头」误判为不能回眸，也不要求完整背面同时露出正面胸口。

## 6. 服装、配饰、道具与材质设计

### 6.1 服装设计链

```text
场景和用途 → 设计风格 → 主件与搭配 → 廓形/领口/腰线/长度
→ 主辅颜色 → 主材质与受光 → 图案与工艺 → 穿着层次与露肤位置
→ 当前取景需要的鞋袜配饰 → 动作引起的受力、褶皱与遮挡。
```

词库不是菜单上限。与用户指定服装一致时直接完善，不为了避免重复而强制换衣。用户只说「精致」时应主动完成成套穿搭设计；普通生活题材可精简，但不能所有场景都退回白衬衫与普通T恤。

### 6.2 精致来自结构与工艺

| 层次 | 应写什么 | 具体化方式 |
|---|---|---|
| 廓形 | 修身、松量、斜裁、垂坠、肩线、裙摆 | 缎面斜裁沿腰胯垂落；短外套与高腰下装形成比例 |
| 领口 | 方领、低圆领、垂褶、挂颈、一字肩、斜肩 | 写清开口形状、肩带连接与可见肩颈 |
| 腰线 | 收束、腰封、侧扣、系绳、褶皱 | 珍珠小扣收住腰侧细褶；腰封拼缝清楚 |
| 下摆与开衩 | 长度、侧别、重叠与落点 | 裙摆盖到膝上，坐姿近侧开衩自然展开 |
| 工艺 | 蕾丝滚边、盘扣、织金、压褶、刺绣、珠绣 | 指明分布位置、粗细与层次，不说满身繁复 |
| 穿法 | 外套停在肘部、衣角半塞、袖口卷起 | 服装状态与手臂位置相容，不擅自解衣或滑落 |
| 配饰 | 主饰品与次点缀 | 长耳坠衬颈线，细链停在锁骨，不把全身都加链 |

服装段可展开约120～220字，随当前任务增减。这是密度参考，不强制所有图片覆盖相同维数。胸上近景重点是衣领、肩带、配饰；全身才处理鞋袜与裙长。细节要能在所选画幅中出现。

### 6.3 肤质与衣料反光分开

皮肤：大多数区域自然细腻、色阶连续，局部小高光有光源依据；不要全脸涂成漆面，不强制无瑕塑料或极端粗糙毛孔。

织物：真丝与缎面沿褶皱出现较长亮带，丝绒暗部深，棉麻漫反射，针织纹理随表面转折变化，蕾丝有花纹与衬里层次。金属是小而明确的反光，珍珠是柔亮点，玻璃透景并有边缘反射。不能把缎面「珠光」写成皮肤「全身珠光」。

潮湿场景照常保留雨滴、湿发和水面。按部位写实际水状态，不因为背景下雨就把额头、脸颊和肩膀全部变成油亮皮肤，也不把所有含水词全局禁掉。

### 6.4 露肤与服装完整性

露背用侧后或回眸展示，深领配合正侧前构图，侧腰开口与腰部扭转相容。蕾丝和薄纱说明所在部位与内衬，避免模糊词造成无意裸露。短裙坐姿、抬腿或风吹场景按实际取景安排裙摆、打底与遮挡；不要为了补遮挡把人物动作改掉，也不增加本不需要出现的内衣主视觉。

### 6.5 道具与接触

手提包写肩带或握柄，花束写握住包装的位置，杯子写握柄或托底，书写打开/合上与目光对应，伞写张开/收拢。不要同一只手同时抚发、握杯和撑椅。道具数量与人物动作一致，小物的最亮点不能无意盖过眼神。

## 7. 姿势、动作与受力

### 7.1 静图只冻结一刻

按「身体朝向 → 支撑与重心 → 主动作 → 手的接触 → 次要动态 → 头和目光」组装。通常一个主动作加一两个辅助要点足够，复杂姿态可写得更细，但不是把多个瞬间串成动词清单。

| 姿态 | 明确的身体关系 | 可用细节 |
|---|---|---|
| 站立 | 重心在一腿，另一腿自然微屈 | 肩胯轻微错开，手提包或扶墙 |
| 倚栏 | 前臂、手掌或腰侧的具体接触 | 肩膀放松，栏杆与身体有承重联系 |
| 坐椅 | 臀部落在座面、脚/膝的位置 | 身体微前倾，近手撑桌或轻托脸 |
| 沙发斜坐 | 腰背倚靠、双腿顺着坐垫方向 | 衣摆沿坐垫落下，手扶扶手 |
| 侧躺 | 肩、髋与承重面相接 | 一肘撑起上身，另一手有明确落点 |
| 台阶屈膝 | 臀部与台阶接触，一膝靠近前景 | 近膝大、脸居中，手不遮眼睛 |
| 侧身回眸 | 躯干保留原方向，肩颈适度回转 | 近侧眼与脸颊可见，不要求完整双眼正对 |
| 行走停顿 | 一脚承重，另一脚落点可读 | 衣摆、发丝与步伐一致，不同时完全静止 |
| 俯身看镜头 | 身体从腰背整体前倾，有支撑 | 近侧肩手略大，不把脖子扭成反向 |
| 双人靠近 | 肩背、手掌与接触面明确 | 两张脸错开，目光与关系一致 |

### 7.2 自然与新颖同时成立

新意可以来自观察位置、取景边缘、前景、动作停顿或头肩关系，不必每次极低仰拍与夸张拱腰。低机位、俯拍、回眸、全身和躺姿均可用，是否合适由主目标与支撑决定。

生活抓拍保留偶然性：刚抬眼、话说到一半的轻笑、手指整理衣领、身体轻微倾斜。精致写真可以设计姿势，但仍有自然关节和重心，不把强行摆拍当成唯一高级感。

### 7.3 手部、遮挡与取景

近侧手接触什么、远侧手是否入镜要合理。手靠近脸时可托下颌、触发丝、扶耳饰，但不无意覆盖眼睛。胸像中不展开脚部任务；全身图为鞋、裙摆、发尾与必要道具留边。复杂动作失败先减少道具与遮挡，不用增加「完美手指」替代接触关系。

## 8. 镜头、构图、透视与空间层次

### 8.1 先选择主视觉目标

| 主目标 | 推荐取景 | 细节分配 |
|---|---|---|
| 脸、眼神与肤质 | 大特写、头肩、胸上 | 睫毛、面部明暗、发际和耳饰优先 |
| 脸与精致衣装 | 胸上、腰上、膝上 | 领口、肩背、腰线、手部与表情共同可读 |
| 完整造型 | 全身、环境中景 | 廓形、鞋袜、腿部、支撑面与环境线条 |
| 互动与故事 | 双人中景、侧面、留白 | 动作关系、道具与两张脸的主次 |
| 环境氛围 | 中远景、较小人物 | 空间、天气、时间、人物落点优先 |

单一镜头不能同时满足完整全身与极近面部大特写。用户都需要时可给两条独立词或按指定做拼贴，不擅自忽略其中一项。

### 8.2 机位、脸朝向和焦距独立考虑

平视正面可自然漂亮，不禁止；适度低机位可亲近或有力量，不一律视为脸部畸变；俯拍不自动等于低头，侧后方不自动等于看不到脸。根据用户审美与姿态选择，不强制所有图使用非常规镜头。

35mm等广角视角可强调近膝、肩手与空间，50mm可兼顾环境与半身，85mm等中长焦适合相对平缓的人像透视。焦距是视觉意图，不是精确相机标定。进一步写清相机高度、距离倾向、近大远小、裁切与背景远近，不仅报一个毫米数。

极近广角避免脸处于边缘；想保留自然面容可让脸靠近中心，把透视变化放在身体、前景与环境。用户明确要鱼眼或夸张时照办，不把其结果伪称无畸变。

### 8.3 横幅与竖幅

- 横幅：不机械把脸缩小到全景。可用胸上、腰上、斜坐、侧躺或身体斜线，让人物与环境在左右展开；全身则有意识保留脚下与头顶边距。
- 竖幅：使用身体纵向、坐姿近膝、栏杆和窗框层次，不强迫所有图站得笔直。
- 方幅：肩部、头部与手部构成紧凑关系，避免裁切打断主要接触动作。
- 实际像素只在需要布局或运行时明确；Caption中的「横向近景」是画面意图，不替代真实画布。

### 8.4 前中后景与视觉引导

前景选一件有作用的小物或边框，中景是人物与互动面，远景用窗框、街道、柱廊、书架、灯点或山海建立距离。简洁棚拍可以只有人物和背景，不为了凑三层塞一盆花。

引导线把注意力带回人物：窗框斜线、桌沿、衣褶、侧向光带、发丝与肩线。只需写清主要路径，不写观者先看眼睛再看十个物件的流水账。留白按目光、姿态或文案需求服务画面，不默认印字。

### 8.5 对焦、景深和成像

人物焦点可以是双眼、近侧眼睛或头肩区域；背景虚化与前景少量离焦不等于全图发软。环境重要时保留更多景深，不机械把所有背景抹成光斑。

浅景深由取景距离与空间关系支持；广角并非绝对不能背景虚化，也不应无条件获得极大光斑。想明显背景压缩与散景，优先安排较远背景与中长焦观察方式。

颗粒、轻微噪点、发梢动态、眩光与曝光溢出按体裁挑选，不同时写全图超低清、脸部极清、所有东西运动模糊、皮肤毛孔微距。可让少量移动发丝模糊而眼睛清楚，明确作用对象。

### 8.6 镜子与反射

先写真人在哪、面向哪里，再写镜子边界、倒影和相机位置。镜外背影、镜内正脸可相容；同一个玻璃窗不能既完全透明又像实心镜子遮住全部背景。镜中出现的人与真人是同一身份的光学实例，不自动当作第二位人物。

## 9. 摄影设计：光影、肤质、色彩、细节与情绪

### 9.1 光照因果链

用「光源及方向 → 受光位置 → 面部和身体暗面 → 反射/填充 → 背景和空气」设计。先确定主要作用，不把主灯数量设成模型硬限制。复杂灯组只有用户目标确实需要时才展开。

弱：高级光影、氛围感、电影感、明暗对比强。

强：左前方大窗柔光照亮近侧眼睛和脸颊，鼻翼与下颌保留渐变阴影；木桌向暗侧反射一点暖色，身后的书架低一档亮度，远处小灯只留下克制的暖点。

### 9.2 面部的体积与高光

眉骨下方、鼻侧、下唇、下颌和颈部共同决定脸的体积。柔光仍有明暗，硬光仍需可读的五官；不把「白皙」写成所有面朝向都同样白亮，不把「低调」写成整张脸失去结构。

自然肤色、白皙、细腻、通透可以使用，但不反复升级成水光、油亮、镜面、湿润、珍珠肌和全身闪亮。局部高光本身不是错误；默认让高光面积与强度受控，避免额头、双颊、鼻梁和肩颈同时成为连片反光面。

「细节」包括细小肤色变化与真实结构，不要求每张都写满毛孔，也不追求陶瓷塑料。唇部可有自然光泽，眼睛有与光源一致的小反光，发丝与衣料有自己的材质。

### 9.3 腮红、肤色与彩光

妆容的红与光源的红分开。常规人像不默认加鼻尖冷红、大面积眼下红、浓腮红和泛红脸颊；需要妆感时优先写范围轻、过渡自然的一种妆容。特殊妆容按用户需要保留，不建立全局禁词。

彩光可照脸，但明确左右、强弱、交界和暗部。保留五官的亮度结构，避免仅用「高饱和红蓝、全脸紫色、金属湿亮」同时覆盖一切。自然主光与彩色轮廓是一条路线，局部彩色主光也是路线，不强制把彩灯只放背景。

### 9.4 人物与背景分离

可用明度、颜色、服装轮廓、景深、局部边光和空间距离。不是每张都需要一圈发光描边。白底靠黑发、暗衣与脸颊阴影保留结构；黑底靠近侧受光、发束暗部色差和少量轮廓即可。

人物曝光与背景曝光分别考虑。高调允许明亮，但不能让面颊被漂白；低调允许大面积暗部，但近侧眼睛、鼻唇轮廓与主题需要可辨。双人分别检查两张脸，不用一张脸正确代表另一张也正确。

### 9.5 配色设计

确定主色、暗部色和少量点缀色，再安排肤色与它们的关系。粉白深绿适合甜美花店，奶油金与木棕适合窗边，黑灰与自然暖肤适合低调人像，灰蓝与少量暖灯适合城市夜色。配方可变，不把某个颜色当作情绪硬规则。

低饱和不等于灰蒙，高反差不等于所有肤色漆黑，高级不等于只能冷色。让衣服、背景和光源分担色彩，避免把所有风格要求都压在脸上。

| 舞台 | 可辨脸部主光＋有选择的背光 | 薄雾仅在光路显现 | 不默认浓紫脸与全身油亮 |

### 9.7 成像与情绪协同

手机、CCD、胶片与专业写真是成像方向，不是画质排名。生活感可来自轻噪点、自然裁切、真实动作；胶片可来自色阶与细颗粒；不靠超低分辨率或全图模糊制造氛围。

情绪通过可见细节落地：刚抬眼的停顿、手扶杯柄、松开的肩膀、近侧发丝、窗外将暗的天色、两人靠近的距离。可写温柔、清冷、慵懒、自信、神秘，但不要把十个互不相关的词并列当作完整设计。

### 9.8 丰富细节的主次

焦点处分配面部、发束、衣装连接与接触细节；次要处保留廓形、材质与空间；远处以递减结构和少量颜色建立场所。细节多少按任务决定，不强制每张毛孔、刺绣、玻璃、水珠和粒子全齐。

最清晰边缘、最大局部反差与最密装饰应有归属。只有眼睛清楚而脸像贴图、衣服像金属、背景完全无层次，也不算完成。美感来自各层关系，不来自统一锐化与统一高光。

### 9.9 根据当前表面与光源判断，不按词表自动纠偏

| 当前条件 | 需要推导的问题 | 可能的调整方向 |
|---|---|---|
| 硬光或直闪 | 主光在哪，哪些表面朝向它，投影和皮肤高光是否相容 | 调整亮区分布、环境曝光、填充与材质响应；保留用户要的硬光 |
| 湿妆、雨天或泳池 | 水实际出现在哪些部位，皮肤、湿发和衣服的状态有何差异 | 分部位写水状态，不将全身视为同一种镜面；用户明确要水光时照办 |
| 彩色照明 | 颜色从哪来，落在哪一侧，交界处有无面部体积 | 使用分区、渐变、阴影和相对强弱，不强制改为白光照脸 |
| 高调白背景 | 面部、白衣、背景在哪些边界上需要区分 | 用色阶、轮廓、暗侧、衣纹或距离组织，白底照样可明亮 |
| 暗调或剪影 | 用户想读到哪些信息，哪些部分可以进入黑色 | 让目标信息有可读形状；真正剪影不强制补出每个五官 |
| 明确浓妆/腮红 | 妆色覆盖范围、肤色与照明色怎样区别 | 描述妆面的位置与轻重，不因为偏好自然妆就删掉用户浓妆 |
| 风格化颗粒与模糊 | 需要哪类不完美、作用于谁，焦点是什么 | 可局部移动、轻噪点或整体低清，服从用户明确成像目标，不强制每图高清 |

若用户没有指定肤质，默认自然细腻、有限局部反光；没有指定腮红时不主动累加鼻尖红和大面积眼下红。这是本模板的可覆盖审美默认值，不是MOSS不能生成其他妆面的技术禁令。

最终收尾从本图已经成立的光照、色调、成像和行为自然概括，不复制统一的“柔和通透、低饱和、胶片、暗背景”串。当前任务可以是高饱和、硬光、大景深或真实低清，只要描述与目的相容。

## 10. Tag 与自然语言的衔接

普通摄影默认Caption，不因模型支持Tag就改成关键词列表。Tag用于用户明确需要的紧凑表达，首句仍确定摄影表现方式，后续依次组织主体身份、人数、发型、衣服、动作、镜头、场景与光照。

不自动添加Quality、Score、Artist或年份；不使用括号权重、BREAK、分角色扩展与其他模型的区域语法。需要强调的内容用位置、主语、因果与明确取景表达，而不是重复十次。

Tag示意：

```text
A natural-light fashion portrait photograph with restrained film colors. one adult woman, long wavy black hair, relaxed smile, black satin and lace camisole, fine gold necklace, seated beside a cafe window, hand near her hair, eye-level close portrait, soft light from frame left, gentle far-cheek shadow, dark wooden shelves
```

多人、手部、镜面、照明分区等关系用完整句子更清楚；不能因进入Tag模式就省掉属性归属。Tag与Caption可以互相改写，但不能把每条意思重复写两遍。具体媒介表达是内容，不等于万能质量词。

### 11.7 面容、肤质与眼神表达库

| 设计目标 | 可用描述 | 适配原则 |
|---|---|---|
| 清透自然脸 | 五官清楚，脸颊自然柔和，底妆轻薄 | 配合实际明暗，不强制零瑕疵 |
| 冷白肤色 | 冷白皮，阴影中仍有细微肤色变化 | 冷白不等于脸部过曝 |
| 暖白肤色 | 白皙而带自然暖色的皮肤 | 与暖灯相容，不默认明显腮红 |
| 小麦肤色 | 自然小麦肤色，光照下层次清楚 | 不擅自漂白用户要求的肤色 |
| 清冷面容 | 眉眼干净，唇部自然闭合，目光平静 | 不需要把眉毛压低成愤怒 |
| 甜美面容 | 柔和眼神，嘴角轻扬，表情放松 | 不机械放大眼睛与缩小下巴 |
| 成熟性感 | 下颌和肩颈线清楚，目光自信，笑意克制 | 不必浓妆、油亮或夸张身形 |
| 慵懒亲近 | 头轻倾，一侧发丝靠近脸颊，眼神关注镜头后的人 | 眼睛仍有焦点，不变成困倦失神 |
| 自然妆面 | 薄底妆，少量眼线与柔和唇色 | 表达清楚即可，避免无妆与浓妆并存 |
| 脸部体积 | 鼻侧与下颌留自然阴影，近侧面颊缓慢转入暗部 | 柔光与硬光根据所选路线变化 |
| 局部高光 | 鼻梁和唇峰只有小而集中的反光 | 不扩张为额头双颊肩颈全部闪亮 |
| 自然纹理 | 保留细小肤色变化与近处皮肤纹理 | 不是每张都必须强调粗大毛孔 |
| 清楚眼神 | 近侧眼睛对焦，反光与主光位置一致 | 不让瞳孔像自发光灯泡 |
| 含蓄微笑 | 嘴角轻扬，双唇自然接触，眼睛带笑 | 不同时大笑露齿 |
| 侧脸思绪 | 视线落向窗外，鼻唇与睫毛轮廓清楚 | 不强求侧脸出现完整对称双眼 |
| 回眸交流 | 脸越过近侧肩看向镜头，嘴角有浅浅笑意 | 检查肩颈转动，不让脸在后背中心 |
| 双人默契 | 视线落在对方眼睛，肩膀靠近，笑容轻松 | 不把两人都写成盯镜头却又互相凝视 |
| 冷暖肤色关系 | 近侧暖肤、远侧微冷阴影 | 冷暖须有光源或环境依据 |
| 细腻质感 | 焦内皮肤有层次，暗部保留色阶 | 不用统一强锐化制造纹理 |
| 高调肤色 | 白背景明亮，脸颊仍保留自然色与鼻侧阴影 | 白底、白衣与白皮需要边界 |

## 12. Layout：格式、字段与坐标

Layout是结构化提示词。框表达目标占位，不是硬裁切、姿态骨架、三维相机或逐像素约束。先设计图文主次与人物关系，再填写框；JSON不能代替动作、透视和光影描述。

### 12.1 画布与内部草稿

先确定W×H，宽高为16的正整数倍，与最终图像尺寸一致。用户只给宽高比时选择相容尺寸，例如16:9可用2048×1152；没有比例依据时可用1024×1024。明确指定的尺寸不合法时指出冲突，不静默修改。尺寸说明放在提示词之外。

内部规划使用左上角为原点的像素框`[x0,y0,x1,y1]`：`0≤x0<x1≤W`，`0≤y0<y1≤H`。所有文字、摄影格内人物和道具都用全图坐标，不用百分比、归一化坐标或格内局部坐标。

需要保留可编辑草稿时，根字段为`width`、`height`、`bbox_coord_space="abs"`、`bbox_format="xyxy"`、`summary`、`items`。草稿不能直接当作最终Layout交付。

### 12.2 内容字段

| 字段 | 写法 |
|---|---|
| summary.caption | 必填非空字符串：独立画风首句，随后写全局场景、人数、观看/阅读顺序、主次和共享光照 |
| summary.meta | 可选字符串数组，只放有用的媒介、题材；不放质量词和自动添加的画师 |
| summary.palette | 可选字符串数组，写全局配色 |
| summary.canvas | 可选，取值single、multi_panel或collage |
| items | 非空扁平数组，所有对象都在同一层 |
| item.label | 必填，只能为character、object或text |
| item.caption | 必填非空字符串，写该项的外观、动作、关系、材质；文字项写字体倾向、层级、颜色和载体 |
| item.bbox | 必填四个坐标，遵循所处草稿/成稿格式 |
| item.text | text项必填非空字符串，保存真正印出的文字 |
| item.tags / item.palette | 可选字符串数组，只补该项特征或配色，不替代caption |

不增加`style`、`id`、`children`、`parent`、`panels`、`panel_id`、`elements`、`negative_prompt`等字段。标签中没有`panel`；实际可见的摄影格背景可用object描述。

### 12.3 最终输出格式

最终根字段仅为`summary`、`items`、`bbox_coord_space="abs_centralized"`、`bbox_format="yxyx"`。不含width和height，使用整数中心坐标，以一物理行紧凑JSON交付。画风是summary.caption的第一句，不在每个item内重复。

整数像素草稿`[x0,y0,x1,y1]`转换为：

```text
[y0-H/2, x0-W/2, y1-H/2, x1-W/2]
```

例如1024×1024画布，`[100,320,440,760]`转换为`[-192,-412,248,-72]`。原点和数组顺序同时变化；负数正常。1536×1024画布必须分别减宽中心768和高中心512，不能两轴都减同一个数。

有小数边时，先对左/上边向下取整、右/下边向上取整，再减画布中心并改为yxyx。优先使用官方编译器或计算工具完成机械转换；逐项检查结果，不凭目测估算。转换失败时修正草稿，不能仅更换格式标记掩盖错误，也不能声称未经执行的编译已通过。

改尺寸后，若要保持相对占比，先按新旧宽高分别缩放草稿坐标，复查构图后重新转换；只更改尺寸不会自动缩放对象。完整最终示例见§16。

## 13. Layout 的人物、文字、多人和多格规则

### 13.1 拆项与合并

- 每个需要独立位置的完整人物用一个 `character` 项；人物衣服、手持道具及头发若无需独立定位，可在其 caption 里描述。
- 桌上独立杯子、中央行李箱、墙上招牌等单元用 `object`；如果道具已有独立 item，人物 caption 要说明与同一件道具的关系，避免复制。
- 要求完整羽翼、长发或全身衣摆时，给该人物框预留相应范围；不要用脸大小的框承载全身。
- 不给同一人物的“脸”和“身体”各建一个 character，避免模型理解成两个人。
- 背景风格和全局光照优先放 summary；确实需要独立摆放的建筑或背景画块再作 object。
- 自然遮挡可以框重叠；框的先后顺序不当作硬性图层 z-order，用描述说明谁在前、谁被遮挡。

### 13.2 双人/多人

summary 写精确人数、整体关系和相容光照；每个 character caption 自带发色发型、衣服主色、动作、视线。主语如“左侧短红发女性”要与它的 bbox 一致。

交接动作涉及同一个道具。若道具单列 object，应把其框放在交互区，并写两人分别“递出”和“接向”该同一件物体，不能写每人都各握一个独立盒子。精细手部仍可能失败，bbox 不是骨架。

只要要求大致左右、自然对话，Caption 就可用；多人不强制 Layout。需要严格占位比例、留出中间文字区、两人不能互相挡脸等再选 Layout。

### 13.3 文字项

真正印字用 `label="text"`、`text` 保存原文，`caption` 描述字的颜色、大小层级、字体倾向、载体。不能只写“这里是标题”让模型自己编文案。

独立排版的标题、正文、脚注分成不同 item；同一段固定换行可在一个 `text` 字符串里用 `\n`。JSON 文件中的 `\n` 在解析后表示真正换行；不要双重转义成字面反斜杠 n。中文提示词也必须使用 ASCII 双引号作为 JSON 语法引号，不能换成中文弯引号。

同一对象上的文字也使用**全图坐标**。若招牌框是 `[100,100,500,300]`，牌中文字也给画布上的实际位置，不从招牌左上角重新计为 `[0,0,...]`。

先检查字号能否容纳文字：十个以内大标题、长段落和小脚注的可读性不是一回事。字数多时增加画布/字区、减少装饰或拆图，不擅自删掉用户要求的字。 小字仍可能出现错字，位置正确不等于内容逐字正确。

### 13.4 多格摄影与拼贴

`canvas="multi_panel"` 只标明整体类型。需要实际格框时，在 summary 描述读序和边界；用 `object` 表示每格可见背景区域，再用 character/text 项在对应**全局区域**布置人物与对白。

全文件 `items` 仍是扁平数组，不使用 `panels`、`children`、`parent`、`panel_id` 或局部坐标。某一角色在两格各出现一次时，重述同一身份特征并说明重复出场，而不是写“整张图只有一个人物实例”后又安排两张独立身体。

不要为了画摄影分格引入其他模型的分角色或区域扩展语法。多个框不提供面部一致性、镜头物理一致性或精确对白气泡形状的保证。

### 13.5 JSON 常见错误与修正

| 错误 | 为什么有问题 | 正确做法 |
|---|---|---|
| 自创 `prompt/negative_prompt/seed` 根字段 | 不属于 Layout 草稿规范 | 仅用summary/items保存画面内容 |
| 给 items 加 `children` | 官方扁平 schema 不接受 | 所有单元列在同一 items，坐标都按全图 |
| `label="panel"` | 非官方枚举 | 可见格背景使用 object，组织类型放 summary.canvas |
| 草稿写 0.1–0.9 | 被当成不到一像素的实际数值 | 使用真实像素，不用归一化 |
| 直接把xyxy草稿标成yxyx | 坐标顺序和原点不一致 | 由编译器转换 |
| 改尺寸不改框 | 不会保持相对占比 | 重新规划或缩放草稿，再编译 |
| 框超过画布 | 编译器会报错，不自动裁切 | 修正边界，不绕过检查 |
| x0=x1 或 y0=y1 | 框无面积 | 给出正宽高 |
| 两个同名 JSON 键 | 标准解析可能悄悄覆盖 | 检查并删除重复键，避免内容被覆盖 |
| JSON 有注释/尾逗号 | 非标准 JSON | 注释放说明文件，删尾逗号 |
| 把 `bbox` 字样写成屏幕上的字 | 规划混进画面 | 坐标留在字段，caption 只描述可见内容 |
| caption 说左，框却在右 | 文本与几何冲突 | 保持两者一致 |
| 只写人物框，不写外观 | 角色身份缺失 | 每人 caption 独立绑定锚点 |
| 只放 `text` 不给文字 caption | 缺少必要字段与排版意图 | 加 typography/surface 描述 |


## 14. 修改提示词

每次返回完整可用的新成稿。已被用户认可的人物、身份、服装、动作、镜头、光源、色调和场景默认保留，只调整被指出的问题及其必要关联。仅改服装不连带换脸与换地点；仅改氛围不自动改姿势；仅改摄影表现先修改独立首句，正文需要的关联变化最小化。

| 问题 | 优先调整 | 保留什么 |
|---|---|---|
| 脸不够漂亮 | 面部占比、头部与目光、妆容密度、主光作用面、表情 | 已认可的身份与基本外貌，不随意换成另一个人 |
| 皮肤油腻 | 减少大面积连续皮肤反光，分开写脸与缎面、金属、湿地的材质 | 合理局部高光，不把所有材质改成死哑光 |
| 脸部奇怪泛红 | 调整腮红范围、鼻尖红与皮肤色调，检查彩光与妆色是否混淆 | 唇色、衣服红色或有明确作用的彩光 |
| 画面过亮 | 人物与背景分别安排曝光，保留面颊阴影，减少无条件全面回填 | 用户要的白底、明亮气氛或高调方向 |
| 面部平 | 让主光照具体脸侧，保留鼻下、下颌和远颊暗面 | 原有清淡妆容与柔光方向 |
| 暗调看不清 | 恢复近侧眼睛与鼻唇轮廓的层次，安排必要微填充 | 大面积暗背景和低调气氛 |
| 彩灯脏脸 | 明确染色区域、亮度交界和暗面，降低不必要的多光叠加 | 彩灯题材，不自动换成自然白光 |
| 人物太小 | 改景别、裁切与观看距离，减少不必要全身要求 | 画幅和重要环境元素 |
| 衣服普通 | 增加剪裁、材质、工艺、穿法与一件主配饰的具体设计 | 用户指定的主件与穿搭场景 |
| 服装太杂 | 明确一件主衣装，减少同等密度饰品，细节集中可见部位 | 核心精致感与用户指定的装饰 |
| 姿势僵硬 | 用重心、支撑、单一轻动作和自然肩颈替代姿态堆叠 | 用户要的体态与主要方向 |
| 透视拉坏脸 | 调整相机距离、脸在画面中的位置与仰俯程度 | 用户需要的低机位或广角，不一律禁用 |
| 手与道具脱离 | 说明近手/远手、具体握持部件、唯一道具与支撑面 | 主要动作和道具数量 |
| 多人串衣串脸 | 每人独立绑定属性与动作，减少共用词串 | 精确人数、关系和原有身份 |
| 镜像不合理 | 真人方向、镜框边界、镜中实例与相机位置明确 | 镜面构图意图 |
| 氛围淡 | 补时间、背景亮度、主辅色、空间层次与微动作 | 清楚漂亮的脸，不靠变油、变红、变糊代替气氛 |
| 细节不够 | 在焦点附近补织物结构、发束、饰物连接与接触 | 大形、光比和背景主次 |
| 文案不对 | 保留原文、重排字区、增加文字可读面积 | 用户实际文案，不自行改字 |

修改是重新生成意图，不保证原图其他区域逐像素不变。Layout也不是局部编辑、骨架或人脸锁定工具。不要用新增负向词、改变模型和LoRA参数来替代应先完成的语义修正；需要运行设置时与正向内容分开说明。

### 14.1 先识别偏离目标的关系，再决定怎么改

用户反馈是修改的目标，不是自动触发换场景。先区分：主体/数量等执行错误、手部与受力等关系错误、油腻或颜色等视觉问题，以及不符合用户审美的完整结果。几类问题可以同时出现，但不应全部用同一套“自然柔光近景”处理。

- **脸不喜欢：** 在用户要求的景别和姿态里检查面部大小、转向、可见五官、表情、妆容与光照。用户要全身时保留全身，通过相机距离、头向和局部主次改善，不直接裁成特写。
- **皮肤油腻：** 找出反光属于皮肤、唇妆、发丝、服装还是环境，以及不合意的面积/强度；按目标分配材质响应。没有必要删掉缎面、金属或硬光。
- **脸红奇怪：** 区分局部妆色、灯色和肤色；改变需要调整的来源和范围。用户需要红灯或浓妆时，应把它们组织清楚，而不是一并禁掉。
- **衣服普通：** 深化廓形、领口、剪裁、工艺、穿法和可见配饰；保留用户想要的露肤与风格，不只加“华丽、精致”形容词。
- **画面太普通：** 在满足约束的前提下重新设计观察位置、动作、空间、服装或照明，可以多个维度同时创新。对新意的要求不能被“稳定”替代。
- **想保持某张图：** 仅在明确要求延续时，保护用户认可的身份、动作、构图和光照；清楚用户允许改变的范围。
- **不知道问题来源：** 根据现有图提出有根据但有限的判断。需要实验时再控制变量，不把未做的单变量测试说成已证实结论。

返修是重写完整描述并说明必要的关联，不是无限追加正负形容词；没有查看新图时，只能检查文本与格式，不能宣称已经改善成图或提高稳定率。

## 15. 输出前检查

内部完成以下检查，发现问题先修正再交付；不默认输出自检表、分数或字数。

0. **用户需求未被模板覆盖**：指定的地点、服装、体型、姿态、画幅、机位、光影和目标仍在；没有为了贴近例图擅自降级。缺省项是有理由的新设计，不是反复套同一布景。
1. **语言与格式**：遵守用户指定格式；默认中文Caption，双语各自完整；没有解释与正向混排。
2. **摄影首句**：只有一条独立摄影表现句；没有自动加入质量、评分、画师或测试信息。
3. **人物身份**：人数、成年语境、族裔肤色、发型、体型、参考身份与衣装归属一致。
4. **面容神态**：表情与视线有对象，五官描述相容，没有为漂亮同时堆极端脸型与浓妆。
5. **肤质妆色**：皮肤与衣料的反光分开，面部有形状和色阶，腮红与彩灯作用分明，没有无条件全脸油亮或泛红。
5a. **判断层级**：没有把个人偏好、单张观察、通用摄影关系和模型能力混为一谈；没有从好坏实例推出未经验证的单词因果。
6. **服装完整**：主件、廓形、材质、颜色、穿着状态与必要精工细节清楚，露肤方向与景别匹配。
7. **动作受力**：支撑面、重心、近远手、道具数量、裙摆与手脚落点合理；一个主要动作瞬间清楚。
8. **镜头空间**：景别、机位、透视、头脸方向、必要留边与前后景相容，不强制一切平视或一切极端角度。
9. **光影逻辑**：光源位置、受光面、阴影、填充和环境亮度一致；面部、衣料、金属、玻璃不共用一种反光。
10. **色彩情绪**：主辅色明确，气氛由可见场景与行为支持；反差有设计理由，不机械禁止跨风格。
11. **细节层级**：重点清楚、次要区域有结构、远景适度简化；没有所有纹理、灯光和道具一起抢焦。
12. **文字实例**：只生成用户真正要求印出的文案，保留原文和换行；镜像、照片与重复人物实例解释清楚。
13. **纯净交付**：没有权重、流程注释、参数、负向、统计、案例编号、自检成绩混入正向。
14. **Layout附加检查**：字段与枚举、扁平items、全局坐标、正面积、边界、text内容和描述归属正确；最终一行中心坐标JSON，无width/height。

检查针对同一对象、同一部位、同一时刻。一个人坐、另一个人站不是冲突；背向身体回眸不是冲突；暖环境配清冷神态不是冲突。手同时张掌与握同一杯柄、全脸背向却要求正面双眼、同一物体打开又合上才需要明确选择。

### 16.2 白衣、白背景与硬光不改成黑衣柔光

需求：白色雕塑感礼服，白色旋转楼梯，正午硬光，全身，清冷。
