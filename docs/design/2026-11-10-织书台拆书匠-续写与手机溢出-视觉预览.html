min-width:0 必须从外壳贯穿到条目
1 · 收缩链不能断.studio-view → .columns → .panel → .list → .row { min-width:0 }现状根因：外层缺一条 min-width:0，整条网格列被 min-content 顶到固定宽度，越窄裁得越多。
2 · 标题单行省略overflow:hidden; text-overflow:ellipsis; white-space:nowrap配合 width:0 或 flex:1 1 auto，省略号才真的生效；长书名不再套第二层《》。

一 · 先修的三项（续写的前置条件）

问题现状要求
导出坏章静默漏章章节读不出来就跳过，仍返回导出结果；稿件卡片已有 broken 标记但导出链没用上。导出前预检；一旦有缺失章，返回明确章号与原因并停止导出，不产生残本。导入共用同一套预检。
删版本后指针不同步大纲 / 剧本版本删除后，当前指针、页面显示、后续生成、导出可能各读各的。删除与指针重算在同一事务内；落到剩余最新版本或空；四处统一读同一个裁决点。
批量删除中途失败可能删掉前几项才失败，界面看起来像全成或全败。二选一：整体事务可回滚；或逐项返回 succeeded / failed 明细，界面按行反馈，并明确「部分成功 N / M」。

二 · 续写边界（第一轮）

  • 入口：织书台「从已有小说续写」，从拆书匠选作品 → 章节 → 稿件版本。
  • 导入为织书台新作品；原作品与全部改编稿保留，不覆盖、不回写。
  • 稿件来源必须明确选：原文 / 指定改编稿，二选一，不自动挑默认；选改编稿时显示分叉章数与坏章。
  • 用户确认人物、关系、剧情现状、后续大纲后再动手，不自动重构设定与伏笔。
  • 在末章之后新建章节，走织书台现有写作流程；生成失败保留摘要与骨架，可原样重试。
  • 旧章节为只读导入正文，保留各自版本；每章写 source_book_id / source_manuscript_id / source_chapter_no / imported_at / source_kind。

  • 右侧 280px 常驻栏取消：它现在是「说明与状态」静态信息，不是导航。改为按需抽屉 + 44px 图标条，把宽度还给工作区。
  • 顶部三行压两行：页头（标题 + 可收缩状态 + 主操作 + 更多）、阶段条（带序号可横滑）；桌面不再单独放「分档」条。

  • 条目契约：min-width:0 贯穿、标题单行省略、元数据第二行、操作收进 …、路径与报错可断行、长书名不重复套《》。
