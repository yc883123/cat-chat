## 一、范围与定位

### 1.1 本计划管什么

只管「弹出来的表单」这一层：遮罩、弹窗尺寸与圆角、标题栏、滚动区、底部操作条、错误提示、移动端全屏、深浅主题下的输入框/内容框可读性，以及弹窗内**信息呈现方式**（不再露技术标识）。

覆盖 5 个 `<dialog>`（读取时位置）：

| 弹窗 | 用途 | 位置 |
|---|---|---|
| `superAgentRecipeDialog` | 用图片批量制作视频（新建配方，大表单） | `public/index.html` 1728–1752 |
| `superAgentRecipeCustomDialog` | 保存为方案（含精确槽位、JSON 字段名、固定参数快照） | 1753–1765 |
| `recipeReviewDialog` | 生成前确认 | 1766 |
| `superAgentResultDialog` | 本次执行结果 | 1767–1769 |
| `superAgentCreateDialog` | 新建任务（大表单，`method="dialog"`） | 1770 起 |

### 1.2 本计划不管什么

- 不改三栏页面（那是 V2 页面计划的事）。
- 不做 A01–A08 的功能/信任整改。
- 不新增授权、不新开模型调用、不改任务状态机与数据契约。
- 不换色板：沿用现有 `:root` 令牌与紫色主色。
- 不把预览里的播放按钮、双模式切换当成已实现能力（见 §七）。

### 1.3 与 V2 页面计划的关系

两份计划共用同一套设计语言（圆角 16px、字号下限 11px、`--surface-inset` 输入面、状态 pill、通俗文案表）与同一套验收纪律（全量单测、隔离实例冒烟、重编 exe + 打包标记探针、提交/发版规则）。V2 页面计划 §六 的整体验收标准同样适用于本文，不重复抄写。

## 三、改版方案（与弹窗预览一一对应）

### 3.1 统一尺寸阶梯与容器

| 档位 | 宽度 | 用于 |
|---|---|---|
| 小 | 480px | 单条确认、轻量提示 |
| 中 | 720px | 保存方案、执行结果 |
| 中偏大 | 760px | 生成前确认 |
| 大 | 880px | 新建配方、新建任务 |

统一 `border-radius:16px`、1px `var(--line)` 描边、`--surface` 底、`--shadow-3`；`max-height: min(88dvh, 900px)`。

### 3.2 三段式骨架（核心修复 D-02）

```
dlg-head   固定：图标 + 主标题 + 副标题 + 关闭
dlg-body   唯一滚动区：flex:1; min-height:0; overflow:auto
dlg-foot   固定（sticky 语义）：左侧说明 + 右侧「次按钮 / 实心主按钮」
```

**只有 body 滚**。标题栏和主按钮在任何滚动位置都可见；5 个弹窗行为一致，不再有三套滚动逻辑。

### 3.3 遮罩与标题栏

- 遮罩：浅色 `rgba(14,17,30,.55)` + `backdrop-filter: blur(3px)`；深色 `rgba(4,6,14,.72)`。
- 标题栏：统一线性 SVG 图标 + 16px/700 主标题 + 12px `--muted` 副标题 + 独立图标关闭按钮 + 1px 下边框。不再复用 `super-agent-section-title`。

### 3.4 操作条与错误提示

- 底栏左侧一句「这一步会发生什么」说明，右侧主次分明；完成态只给一个主按钮。
- 错误提示从底部 11px 红字改为 body 顶部的 inline alert 条（图标 + 文案 + 成功/阻断两态），就近可见、不再藏在滚动区外。

### 3.5 移动端全屏

- `width:100vw; height:100dvh; border:0; border-radius:0`；head 顶 `env(safe-area-inset-top)`、foot 底 `env(safe-area-inset-bottom)`。
- head/foot 仍固定，只有 body 滚；双列表单、卡片网格转单/双列；底栏按钮等宽铺满。
- 用**一处**统一规则替换 6157 与 6277 两套分散写法。

### 3.6 主题与可读性

- 所有 `input` / `textarea` / `select` / 内容块走 `--surface-inset` + `--text`；聚焦态 `--accent` 描边 + `--accent-soft` 外圈。
- 验收覆盖：编辑态、禁用态、占位提示、聚焦态；配方 textarea、子助手工具审批、拒绝结果、自动续办最终正文（A07 全补测点）；深浅主题各走一遍。

### 3.7 弹窗内去技术化

| 弹窗 | 预览里的呈现 |
|---|---|
| 保存方案 | 「素材用在哪 / 提示词写到哪 / 结果怎么读」三张用途卡；节点与字段映射收进「高级：仅专业配置」折叠区；固定参数快照不进普通界面 |
| 生成前确认 | 缩略图占位 + 可编辑提示词 + 每组数量/时长 + 就绪检查 + 「确认后会发生什么」；不露节点标识、文件路径、执行指纹 |
| 执行结果 | 结果摘要 + 产物卡（缩略图 + 播放/下载）+ 相关入口；不露 `<pre>` 正文块与路径 |
| 新建配方 | 两种互斥输入方式卡片、方案优先、高级设置默认收起（与工作树已有实现方向一致） |
| 新建任务 | 目标 + 分组字段 + 步骤预览 + 执行方式，分组折叠，主操作「创建任务」 |

### 3.8 文案

沿用 V2 页面计划 §3.5 的 A15 通俗文案表，不另立一套；改文案前先查 golden / 守门测试是否钉住旧串，文案变更与守门更新同一提交。

- 深浅两套主题：所有输入框、内容框、审批/结果区域可读；编辑/禁用/占位/聚焦四态齐全（A07 不回潮）。

- 底层原生行为不破坏：`showModal()` 焦点陷阱、ESC 关闭、`method="dialog"` 提交关闭、关闭按钮 `value="cancel"`。
- `[hidden]` 仍被显式关掉（`styles.css` 699/708 的历史坑），隐藏字段不漏出。
- 每个状态只给当前有效主操作；完成态不残留「等待确认」与旧错误。
- 与 V2 页面计划 §六 的编译、单测、冒烟、提交/发版纪律一并满足。
- 现有守门保持绿：`test_super_agent_frontend_guard.py`（含 `#superAgentRecipeDialog [hidden]` / `#superAgentCreateDialog [hidden]` 两条 ID 规则，改 DOM 不得改这两个 ID）、`test_mobile_topbar.py::GhostDialogTests`（`dialog:not([open]) { display:none; }` 无条件、无 `!important`；弹层 `display` 规则不得带 `!important`）。

## 七、风险与边界情况（评审重点）

- **R-1（最重要）`.writer-dialog` 是全局基础类**：`styles.css` 5741 的 `.writer-dialog` 不只被任务总管使用，织书台、拆书匠等弹窗也带这个 class。直接改它会波及其它模块。**推荐**：新增限定类（预览里是 `.sa-dialog`）或限定在 `body[data-app-view="super-agent"]` 下覆盖，不动全局基础类。这是预览用新类名的原因。
- **R-2 原生 dialog 语义**：`superAgentCreateForm` 用 `method="dialog"`、关闭按钮 `value="cancel"` 是提交语义；改 DOM 不能把按钮挪出 form 或改成普通 button 而破坏关闭行为。
- **R-3 基线漂移**：真实代码正在变动，本文行号与结构读取后可能已变。实施前必须重新读一遍 5 个 dialog 与相关样式，不能照抄本文表格动手。
- **R-4 别把「有样子」当「有能力」**：预览里的播放/下载按钮是占位。真正可播放需要后端给产物补 `output.type`（`recipes.py:914` / `runner.py:841`），属功能整改，是否纳入需拍板（§八 Q3）。双模式互斥、草稿隔离、反推请求数为 0 同理，是前后端契约，不是 CSS。
- **R-5 内容层不等于容器层**：A16「审批只给按钮不给正文」、A05「空提示词走到最后才拒」、A06「改完才告知不能保存」发生在弹窗/确认卡里，但根因在内容与校验逻辑。容器改版不能顺手宣称这些已修（§八 Q4）。
- **R-6 `backdrop-filter` 与 `color-mix()`**：WebView2 现有版本已依赖 `color-mix`，风险低；遮罩模糊需深浅两态实测，不能只看浅色。
- **R-7 短类名污染**：预览里的 `.btn / .field / .group / .batch` 是演示简写，落地须映射到现有 `.control-button` 体系或加前缀并限定作用域。
