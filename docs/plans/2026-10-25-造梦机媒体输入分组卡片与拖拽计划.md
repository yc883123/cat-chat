# 造梦机媒体输入分组卡片与拖拽计划

日期：2026-10-25
基线：`a23a09a`（3.7.5-beta，远端 master 与本地一致；最新已发布 tag = v3.7.5-beta）
状态：**待评审**（视觉口径以 `_mockup_media_group.html` 为准，未开工）

## 1. 目标与边界

用户最终要求：

- 造梦机（ComfyUI）中间栏的媒体输入不要每个节点散成一行碎按钮；**一种媒体类型一个 UI 框**。
- 工作流节点不是唯一的：必须兼容任意数量、任意命名、任意端口映射的媒体节点。
- 工作流**首次上传（导入）时就要默认渲染**媒体输入。
- 支持**拖拽文件**上传（桌面）。
- **手机**上也要能用。

本次边界：

- **只改前端渲染层**（`public/js/24-comfyui.js`、`public/styles.css`）。后端不动、提交数据结构不动
  （`collectMediaInputs()` 的 `node_id + field_name` 身份键不变）、**不推进 `PARAMS_SCHEMA_VERSION`**（现为 6），
  因此**已有工作流无需重新导入、不会触发重扫迁移**。
- 不顺带修改媒体候选下拉、预览灯箱、任务卡片、批量任务、上传去重或版本号。
- 以下两项**列入二期，本次不做**（见 §4.6）：
  - 从会话历史缩略图拖入槽位（需后端支持直接引用受管文件）；
  - 扩大媒体节点识别覆盖率（其他视频工作流的加载节点）。

## 2. 当前问题

1. `public/js/24-comfyui.js` 的 `renderSlot()` 把每个媒体槽单独渲染成一行
   「`14 · 载入音频 : audio → ref_audios.ref_audio_1` + 状态字 + 选择按钮」。H3 这类工作流十几个
   媒体槽，就刷成十几行碎按钮，节点一换行数和叫法全变（§现状 mockup 第①栏）。
2. 「首次导入是否默认可见媒体」这条**已经成立**，不需要改：`visibleKeySet()` 两条分支都强制合并
   媒体槽 key（未保存 → `defaultVisibleKeys()` 含 `MEDIA_FIELD_TYPES`；已保存 → 也把媒体 key 补回），
   「编辑参数」里同样默认勾选。真正难看的是**默认态本身**。
3. 桌面端没有拖拽：只能点按钮选文件。
4. 触屏没有 hover：现有「替换 / 清除」依赖鼠标悬停才浮出，手机上拿不到。

## 3. 展示方式

**前端外观以 `_mockup_media_group.html` 的新方案栏为准，按该 HTML 的卡片层级、视觉密度、颜色、边框与圆角、间距、字号、媒体块形态和交互状态实现。** 不只复刻功能，也不另起一套视觉样式；桌面与手机窄屏在保持同一视觉语言的前提下适配。

### 3.1 分组卡片

渲染时按槽位的媒体类型（`field_type` ∈ `image` / `audio` / `video`）动态归堆，**每种类型一张卡**：

- 卡片头：`图标 + 类型名 + N 个输入 + 已选 x/N`（0/N 用灰色），右侧折叠箭头；
- 卡片体：缩略块网格 `grid-template-columns: repeat(auto-fill, minmax(96px, 1fr))`；
- **没有该类型节点 → 不生成该类型的卡片**（例如没有视频节点就不出视频卡）；
- 卡片位置沿用现有 `slotRank()`（媒体 rank 4，排在模型之后、无角色参数之前）。

### 3.2 三种类型的块形态

| 类型 | 形态 | 理由 |
| --- | --- | --- |
| 图片 | 64px 缩略图满铺 | 一眼认图 |
| 视频 | 64px 海报 + 播放按钮 + 右下时长角标（`00:12`） | 同类素材光看文件名分不清，时长最快区分 |
| 音频 | 40px 扁平小条 + 三角图标 + 文件名 | 音频没画面，放大图是浪费；H3 一次 5 个 ref_audio 才排得下 |

块内右上角状态角标沿用现有四态语义，不改变判定口径：

| 情况 | 角标 / 文案 |
| --- | --- |
| 本次已选 | 绿色「已选」+ 文件名 |
| 未选，全部相关输入可省略 | 「未选即跳过」 |
| 无法确认可跳过、工作流原值为空 | 「请选择文件」 |
| 无法确认可跳过、工作流保留原文件 | 橙色「沿用原文件」+ 原文件名 |

### 3.3 节点与端口映射

- 节点号、节点名、目标端口**不再占主视觉**：收进块底一行小字（9.5px，省略号截断，悬停/长按看全称）。
- 「节点不唯一」的兼容性由此而来：卡与块都按 `field_type` 归堆，与节点号、节点名、端口名完全解耦。
- 整行完整映射仍保留在 `title` 与「编辑参数」清单里（沿用 3.7.5 的口径，不缩短、不删）。

### 3.4 首次导入默认态（第③栏）

- 卡片**默认展开**；折叠只是省滚动，不是「隐藏媒体」（要隐藏仍走「编辑参数」）；
- 空槽照渲染成虚线块，**不隐藏、不塌成一行**；
- 工作流原值有文件名的槽，直接标「沿用原文件 + 文件名」；
- 于是一导入就看到「图片 0/5 已选」这类卡片，无需去「编辑参数」勾选。

### 3.5 拖拽（桌面，第②栏）

| 落点 | 行为 |
| --- | --- |
| 某个具体块 | 进那个槽（已选块 = 替换） |
| 卡片空白处 / 卡片头 | 按槽位顺序依次填进前 N 个空位 |
| 文件数 > 空位数 | 多出的拒绝 + 提示「请拖到具体块上替换」 |
| 类型不匹配（mp3 拖图片卡） | 拒绝 + 提示「这是音频，请拖到音频卡」 |
| 多文件 | 串行上传，沿用现有 `comfyui.uploadingSlot` 单槽锁 |

拖拽基建已存在，本次只是接线：

- `public/js/15-bind-events.js` 1552-1559 行有 document 级 `dragover` / `drop` 兜底，
  拦住 WebView2「把拖入文件当 URL 导航走整个页面」；
- 输入区拖拽范式见 1560+ 行（`dragover` 高亮 / `dragleave` 判断 `relatedTarget` / `drop` 取值）。

媒体块只需自己 `preventDefault` 即可收到 `drop`；高亮用 `.dragover` 类，与现状 CSS 同名复用。

### 3.6 手机 375px（第④栏）

触屏不派发 HTML5 drag 事件，所以**点选是主路径、拖拽只是桌面增强**：

1. 点空块 → 唤起系统选择器（`<input type=file>` + 按类型的 `accept`）；
2. **触屏没有 hover** → 「替换 / 清除」按钮在 `@media (hover: none)` 下**常驻显示**；
3. 375px 下 96px 网格自动排 3 列；卡片照常展开（折叠会掩盖「还没选文件」）；
4. 卡片头点击折叠，方便收起长列表。

## 4. 实现步骤

### 4.1 渲染层：媒体槽归堆成卡片

涉及：`public/js/24-comfyui.js`。

- 在 `renderParamForm()` 里把媒体槽从逐槽渲染改为分组渲染：
  - 收集本次可见槽位中的媒体槽（判定沿用现有 `slot.control === "media" || MEDIA_FIELD_TYPES.has(field_type)`），
    按 `image` / `audio` / `video` 分三组，组内保持 `orderedSlots()` 的原顺序；
  - 三组按 `ROLE_ORDER` 现有顺序（图片 → 音频 → 视频）依次插到媒体 rank 的位置；
  - 非媒体槽照旧逐槽渲染，顺序与现在完全一致。
- 新增 `renderMediaGroup(kind, slots)`：卡片头（图标 / 名称 / 数量 / 已选进度 / 折叠按钮）+ 卡片体网格。
- 折叠状态存 `comfyui.mediaGroupsCollapsed`（内存态即可，不落盘、不进 `visible_params`），
  默认全部展开。

### 4.2 槽位块

涉及：`public/js/24-comfyui.js`、`public/styles.css`。

- 新增 `renderMediaTile(slot, key)` 取代 `renderMediaPicker()` 的旧三件套（预览 + 长状态行 + 按钮）：
  - 已选块：缩略图/海报/音频条 + 状态角标 + 常驻或悬停的「替换 / 清除」+ 文件名 + 端口小字；
  - 空块：虚线格 + `＋ 选择X`，点击等价于现在的「选择X」按钮（内部仍用隐藏 `<input type=file>`）；
  - 视频块点击播放按钮 → 走现有灯箱放大播放，不就地内嵌 `<video>`（块只有 96px 宽，内嵌控件没法用）。
- 状态文案与 `slot.media_optional` 判定**完全沿用现状**，四态文案一字不改。
- 保留 `renderMediaPicker()` 里的上传逻辑 `onMediaPicked()`，仅把入参从「槽」扩展为「文件 + 槽」，
  供点选与拖拽共用。

### 4.3 拖拽接线（桌面）

涉及：`public/js/24-comfyui.js`。

- 卡片体与每个块上挂 `dragover` / `dragleave` / `drop`，三个事件都 `preventDefault()`
  （不声明「这里可以放」就收不到 drop）；
- dragover 高亮：块级 `.dragover`，卡片级 `.media-tiles.card-drop` + 底部提示行；
- drop 处理：
  1. 取 `event.dataTransfer.files`，按扩展名与卡片类型比对（`MEDIA_ACCEPT` 已有按类型清单）；
  2. 落点是块 → 单槽上传；落点是卡片 → 按组内顺序填空位，多的拒绝；
  3. 多文件串行 `await`，沿用 `comfyui.uploadingSlot` 锁，**全部完成后只重绘一次**，
     避免批量上传时逐槽重绘造成的闪烁；
  4. 类型不符 → 一次 toast 指明应拖到哪张卡，不做任何写入。
- 不做目录拖放（媒体槽只收单文件；目录按现有提示口径直接拒绝，不进文件夹索引那套链路）。

### 4.4 触屏与窄屏适配

涉及：`public/styles.css`。

- `@media (hover: none)`：`.media-tile .t-actions` 常驻显示，按钮命中区 ≥22px；
- 网格 `minmax(96px, 1fr)`，窄屏自动降列，不写死列数；
- 音频块在窄屏保持扁平条（不做 64px 图块）；
- 卡片头点击折叠，折叠时保留卡片头（含 0/N 计数），不整卡消失。

### 4.5 默认渲染与后向兼容

涉及：`public/js/24-comfyui.js`（不改调用契约）。

- 媒体槽的可见性判定**完全沿用 `visibleKeySet()`**，不新增任何规则，保证：
  - 首次导入（无 `visible_params`）→ 媒体槽可见 → 卡片默认出现；
  - 老工作流（有 `visible_params`）→ 媒体 key 已被强制合并 → 卡片同样出现；
  - 「编辑参数」里取消勾选某媒体槽 → 对应块消失（卡片若无块则不生成）。
- 提交路径不动：`collectMediaInputs()` 产出的结构、`/api/comfyui/media` 上传接口、
  执行前转传与未选移除逻辑（`naiba/comfyui/runner.py` 的 `input_is_optional()`）一律不动。

### 4.6 二期（本次不做，待定）

- **媒体节点识别覆盖率**：当前仍只认 `naiba/comfyui/params.py` 的 `_MEDIA_NODE_FIELDS`
  白名单 4 项（`loadimage` / `loadaudio` / `loadvideo` / `vhs_loadvideo` 及指定字段）。
  其他加载节点（例如 `VHS_LoadVideoPath`）默认不出媒体卡，保留原参数控件；确认真实 API 工作流中的
  节点类名、字段名、媒体类型及上传协议后，再逐项扩充白名单。此项不做运行时声明驱动或额外
  `/object_info` 查询，避免在线导入等待及将遮罩、辅助 `upload` 字段误判成媒体。
- **会话内拖拽**：从聊天历史缩略图拖进槽位（`03-media.js` 拖时带 `application/x-naiba-file-path`
  与 `text/uri-list`）。需要后端支持「直接引用已有受管文件」——现状 `/api/comfyui/media`
  只收 multipart（`naiba/http.py:661`），属后端改动。

### 与计划的偏差

1. **`visibleKeySet` 补了 v2 标记**：计划假设「编辑参数取消勾选 → 块消失」在现有 `visibleKeySet()` 下已成立；实际旧代码对已保存显示集**无条件**合并媒体 key，取消勾选不生效。本次为保存过的显示集打 localStorage 标记（按工作流 id），带标记按实际勾选执行，无标记（旧工作流首次打开）仍合并——首次导入默认可见的行为不变。
2. **flex 收缩修复**：`.comfyui-media-group` 的 `overflow: hidden` 会让 flex 自动最小尺寸归零，表单超高时整卡被压成约 6px 高；补 `flex: none` 修复（其它参数行有 min-content 下限本就不受影响）。
3. **375px 实测 2 列**（约 144px 宽的块）而非 mockup 手机栏的 3 列：`repeat(auto-fill, minmax(96px, 1fr))` 在实际面板内边距下的自然结果，机制与计划一致。
4. 触屏 `(hover: none)` 常驻替换/清除按钮以 CSS 规则断言覆盖（IAB 无法模拟触屏指针），未做真机触摸验证。
