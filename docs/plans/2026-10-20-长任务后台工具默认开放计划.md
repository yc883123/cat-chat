# 长任务后台工具默认开放实施计划

## 1. 目标与决定

让任务型内置 Agent 在新会话中能够把预计耗时较长的命令、脚本或生成任务提交为后台 Job，并继续当前对话。用户可通过任务面板或 Job 查询工具查看进度、读取结果和停止任务。

决定：**复用现有 `run_in_background` 工具和 Job 系统**，在标准、长会话、ComfyUI 工具预设中默认开放；补齐模型提示词及使用手册。长会话预设继承标准预设的后台工具。导演 Agent 继续优先使用 `comfyui_batch` 提交 ComfyUI 工作流；`run_in_background` 用于其他支持的后台任务。

不新增第二套后台任务工具，不按运行时长自动接管已经启动的同步命令。`pwsh` / `run_skill_script` 保持现有同步执行语义；模型应在开始长任务前选择后台入口。

## 2. 现状与原因

- `run_in_background`、`job_output`、`job_status`、`job_wait`、`job_kill` 和 Job 注册表已经存在。
- 标准预设未含 `run_in_background`；长会话模式基于标准预设；ComfyUI 预设目前有 `comfyui_batch` 和部分 Job 查询工具，但没有通用后台创建工具。
- 内置 Agent 通过预设固化 `tool_scope`，新会话再固化 `enabled_tool_ids`。仅增加提示词无法令模型调用未声明工具；已固化的会话也不会因预设变化而追溯扩权。
- 当前提示词在部分 Job 工具可用时会提及 `run_in_background`，需要按实际可用入口精确引导。
- 使用手册声称 AI 会自动后台运行长任务，容易被理解为同步命令超时后会被应用接管；需要改成“模型在启动前选择并提交”。

## 3. 实施范围

### 3.1 预设与内置 Agent 工具集

- 标准预设加入 `run_in_background` 及完整依赖 `job_output`、`job_status`、`job_wait`、`job_kill`。
- 长会话预设保持“标准预设 + 历史工具”的关系，自动包含同一组后台工具。
- ComfyUI 预设加入 `run_in_background` 与完整依赖；保留 `comfyui_batch` 原有工具及依赖。预设列出的工具数必须等于套用后的集合。
- 标准、长会话、ComfyUI 预设所绑定的任务型内置 Agent（全能、编程、Skill、导演）在新会话中获得相应工具。只读教程 Agent 与提示词优化 Agent 不扩大工具权限。
- 若实现中涉及已有用户配置的内置 Agent 覆盖，只对可确认未被用户改过的出厂工具集做幂等补齐；自定义 Agent 和用户调整过的工具集保留原样。不得修改已有会话的 `enabled_tool_ids`。

### 3.2 提示词与文档

- 仅当 `run_in_background` 和查询依赖实际可用时，才建议模型用它启动预计耗时较长的任务，并在启动后用真实 Job ID 查询、验证终态与产物。
- ComfyUI 指引优先推荐 `comfyui_batch` 处理工作流批量提交；避免只因 ComfyUI 或其他 Job 查询工具可用，就提示模型调用不可用的 `run_in_background`。
- 更新 `docs/manual/README.md` 和生成后的 `docs/manual/index.html`：说明任务在启动前提交为后台 Job；同步/已运行命令不会自动转后台；ComfyUI 工作流走专用批量工具。

## 4. 验收标准

- 新建标准、长会话、ComfyUI 预设 Agent 会话时，`tools_available` 包含 `run_in_background`、`job_output`、`job_status`、`job_wait`、`job_kill`。
- 导演 Agent 的 ComfyUI 工作流仍走 `comfyui_batch`；其他适用长任务可由 `run_in_background` 创建 Job。
- Job 创建后可在任务面板观察状态，并可通过查询工具拿到终态输出；停止操作仍能取消运行中的 Job。
- 当前会话工具快照不因更新而改变；用户自定义工具集不被覆盖。
- 提示词只引用本轮真实可用的创建和查询工具；手册源文件与生成 HTML 一致，不再承诺运行中的命令会自动转后台。

## 5. 验证

- 更新并运行 `tests/test_agent_cards.py`，覆盖预设成员、依赖闭包、预设数量和前后端依赖规则一致性。
- 更新并运行 `tests/test_builtin_agents.py` 与 `tests/test_prompt_gating.py`，验证内置 Agent 工具范围和提示词门控。
- 运行涉及配置合并、会话工具固化和 Job 的相关测试；如变更触及这些契约，按维护说明提升到全量单元测试。
- 运行文档编码检查、JavaScript 静态检查及维护说明要求的静态守门。
- Playwright 前端冒烟：验证页面可加载且无页面/控制台错误；在桌面和 375px 视口检查任务入口/任务面板仍可用。通过对应 Job 冒烟验证后台创建、状态查询、输出和停止链路。

## 6. 明确不做

- 不按固定秒数把任意正在运行的 `pwsh` 或脚本进程移交给 Job。
- 不新增与 `run_in_background` 重复的通用后台工具。
- 不改写旧会话的工具快照，不给只读或提示词优化 Agent 默认增加执行权限。
- 不把“模型可选择后台提交”描述成“应用必然自动判断并接管所有长任务”。
