## 本轮交付

### 1. 持久预算与验收判定（v34）

- `naiba/storage/goals.py::migrate_goal_extensions` 独立 v34 迁移：chat_goals 增加 limits/stop_code/sources/stages/manual_items/completion_policy/wait_binding；chat_goal_rounds 补时间、原因、起止用量与白名单证据摘要；新增 `chat_goal_budget_receipts` 幂等回执表。旧目标 criteria 非空=machine_all、空=manual，用量不清零。
- `reserve` 在数据库内用 JSON 限额比较；`bind_next`/`claim` 校验轮次与期限；`transition` 支持 stop_code/wait_binding/stages 且保持版本 CAS。运行时 `_MAX_MODEL_REQUESTS` 等常量仅在非默认（旧夹具收紧）时参与，正常以持久限额为准。
- 完成策略：machine_all 全部机器条件通过才自动完成；mixed/manual 即使机器条件全过也进待验收。模型不能删改条件或自报验收。

### 2. 追加额度与时限

- `GoalStore.extend`：request_id 幂等 + 版本 CAS + 回执同事务；只增不减，单次 ≤ 默认限额，总期限 ≤ 创建后 24 小时；追加不自动恢复运行，不清用量，终态/取消中拒绝。
- 运行时 `GoalService.extend` 原样透传，统一由存储层严格校验。HTTP `POST /api/goals/<id>/extend`。

### 3. 引用计划快照（`naiba/run/goal_plan.py`）

- `preview(message, sources, workspace, attachments)` 只读明确来源：原始字节 SHA-256 冻结、parser 版本、来源行号、确定性提取验收文件行/`goal-criteria` 围栏/标题阶段/checklist 人工项；主观正文保守 mixed；不扫描目录、不执行计划命令、不产生授权。
- `verify_sources_current` 提交时复核字节；guard 每轮复核冻结源，变化即停（stop_code=source_changed）；冻结源文件禁止被 GOAL 写入（path() 拒绝）。
- `POST /api/goals/plan-preview` 冻结并返回去原文的计划；提交核对 plan.message 与目标正文一致，不一致拒绝。前端 GOAL 草稿态显示「解析计划」按钮与摘要条（机器/人工项数、阶段、验收方式）。

### 4. 固定本地验收（`naiba/run/goal_checks.py`）

- 内置三项版本化检查：file（哈希/内容）、json_structure（受限 schema：type/required/properties/items，深度≤8、节点≤256）、file_count（固定清单计数，不扫描）。`normalize_criteria` 严格拒绝未知字段。
- `capture_inputs` 冻结有界只读输入快照并算指纹；`execute` 只读快照字节，输出整体 passed + 逐项 evidence；`verify_snapshot_current` 复核输入未变。
- 原子登记：`ChatStorage.create_run` 新增 `job_bind` + `initial_checkpoint` 同事务参数；`GoalStore.bind_check` 事务内 CAS 转 waiting_tool 并结算轮次摘要；`JobRegistry.start_registered` 事务成功后才启动 `goal_check` worker（不入全局 worker 表，恢复由 GOAL 调度器接管）。pytest/unittest 等执行工作区代码的命令未伪装成只读检查。

### 5. GOAL 专属 Job 等待

- GOAL_TOOLS 加入 job_status/job_output/job_wait，仍与会话已启用工具求交；`GoalCycle._job` 只允许本目标绑定或创建时显式指定的 job_ids（提交时校验归属），等待绑定持久化（wait_binding）。
- 完整工具组闭合后经 agent.py 收尾点转 `wait_tool` 结算 → `_settle` 转 waiting_tool；`_tick_waiting` 只轮询持久状态（复用 `run/job_waits.resolve_wait_target` 只读查询与结果摘要），等待期间零模型请求、不登记普通续答、不新增用户消息。
- 终态分类：completed → 回 queued 续办（模型自行复查结果）；failed/cancelled/interrupted → blocked（job_failed）；missing/未知 → needs_user（job_missing），绝不重发。暂停/取消不取消用户引用的既有任务。
