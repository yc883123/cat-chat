## 二、4A 分块续写

### 2.1 取证（启元）

| 做法 | 位置 | 内容 |
|---|---|---|
| 长文分块续写 | `nv_main.js:4064` | 超 `MAX_SEND` 时按段落切分、顺序续写，「杜绝静默丢内容」 |

| 截断不自动写回 | `:3458` / `:3476` / `:3510` | 截断场景提示「只对应前半段」，不静默替换 |
| 分段进度 | `:2883` | 「分段进度 n/total」可见 |
| 断点续写状态 | `:2889-2908` | 未完成可继续，完成后合计字数 |

### 2.2 本侧设计

- 单章超上限（沿用阶段二正文槽 3000 字，可配）时，**不截断**，改为按段落切成多块顺序生成，逐块拼接。
- 每块带上：前一块尾段 + 大纲槽 + 人物槽（保持连贯）。
- UI 显示「第 n/N 块」，可中途取消；取消保留已生成部分为 `result_partial`。
- **任何情况下不静默截断**：若最终仍超限，明确说明「只覆盖到第 X 段」。

### 2.3 改动

| 文件 | 改动 |
|---|---|
| `naiba/novel/prompts.py` | 分块切分（按段落/按句）+ 块间上下文组装 |
| `naiba/novel/service.py` | `stage` 支持分块模式：生成多任务或单任务内多轮（**开工时定**） |
| `public/js/25-novel.js` | 分块进度显示与取消 |

**待定**：分块是「一个任务内多轮调用」还是「多个任务串联」。前者 UI 简单但不可单块重试；后者可重试但任务列表会变多。倾向前者（用户视角是一次生成）。

## 三、4B 知识图谱

### 3.1 取证（启元）

| 做法 | 位置 | 内容 |

| 图谱反哺生成 | `:1544-1547` | Top-20 实体（名称 + 一句话描述）注入系统提示词；**翻译不注入**（会污染字面） |
| 章节指纹 | `:95` | 判断图谱是否还对应当前小说，换书即失效 |
| 换书重置 | `:7803-7830` | 换小说时 KG 存盘重置为空，避免旧人物关系残留 |
| 从要素建图 | `:7450` | 要素缺失时提示「从要素建图」 |
| 关系上限 | `:84` | `KG_MAX_EDGES = 300`，超出按 weight 降序截断 |

### 3.2 本侧设计（两小步，可只做第一步）

**4B-1 反哺生成（建议先做）**
- 从作品的 `characters/scenes/props` 取 Top-20 实体（名称 + 一句话）。
- 注入阶段二/三的**系统提示词**（不是用户消息，避免污染正文语气）。
- 翻译类（若将来有）不注入。

**4B-2 可视化图谱（可选）**
- 存 `kg{nodes,edges}`，画布渲染。
- 换书/换章节要按**章节指纹**失效（照 `:95`），否则旧关系残留。
- 边数上限 300，超出按权重截断。

> 提醒：4B-2 是纯前端大工程（力导向图、缩放、点击），投入不小。**若只为一致性，4B-1 就够了**。

## 四、4C 分镜生图

### 4.1 复用优先

工作台**已有 ComfyUI 分页**（`public/js/24-comfyui.js`、`data-studio-page="comfyui"`），H3 / RunningHub 能力也在。所以 4C 的正确做法是**从剧本跳转到已有能力**，而不是重写一套生图。

### 4.2 设计

| 步 | 内容 |
|---|---|
| 1 | 剧本场次 → 分镜提示词（每场一条，含场景、人物、动作、景别） |
| 2 | 提示词交给模型润色为出图提示词（可复用模块库 `h3` 分类模板） |
| 3 | 交接给造梦机（ComfyUI 分页）：把提示词批量带过去 |
| 4 | 出图结果回写到场次下（可选，需图片存储与引用保护） |

### 4.3 风险

- **跨页交接**：小说页 → 造梦机页的数据传递方式（URL 参数 / 临时存储 / 直接调接口）需单独设计，别做成复制粘贴。
- **参考图绑定**：启元取证到「多图编辑时提示词里没有显式图号标记，指令落不到对应图上」（`_bind_ref_tokens`）——若出图要带角色参考图，必须显式写「图一/图二」对应的 `<imageN>` 标记，否则人物长相对不上。
- 图片落盘要接引用保护（studio 任务已有一套 `referenced_upload_paths`）。
