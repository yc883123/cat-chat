## 三、零 AI 脚本拆分（本计划新增）

### 3.1 为什么单独做一条

AI 工具路径要「起服务 → 建会话 → 模型判断 → 调工具」，只想把一本书拆成文件时太重；
且模型在长会话里可能自作主张改参数。脚本路径是**确定性**的：同一本书、同一参数，
结果永远一致，不烧 token，也不需要应用在运行。

### 3.2 载体：已有的 `--run-skill-script` 入口

| 事实 | 位置 |
|---|---|
| 冻结版可只执行脚本、不启动主程序 | `launcher.py:1413 _run_skill_script()` |
| 该入口**在实例锁之前**拦截，不会触发「已在运行」冲突 | `launcher.py:1477-1482` |
| 父进程按 UTF-8 解码子进程输出（脚本中文输出需注意编码） | `launcher.py:1402` 注释 |

两种跑法：

```bash
# 源码模式（本机就是源码运行）
./.venv/Scripts/python.exe scripts/split_novel.py "D:/books/某小说.txt" --out ./out

# 冻结模式（exe 用户，无独立 python）
dist\naiba-chat.exe --run-skill-script scripts\split_novel.py "D:/books/某小说.txt" --out ./out
```

### 3.3 脚本设计

文件：`scripts/split_novel.py`

| 参数 | 默认 | 说明 |
|---|---|---|
| 位置参数 `file` | — | 要拆的 TXT |
| `--out DIR` | `<文件名>_chapters/` | 输出目录 |
| `--format txt\|md\|json` | `txt` | 每章一文件 / 单 md / 索引 json |
| `--max-len N` | 6000（算法默认） | 单章上限，超长章再切 |
| `--encoding auto\|utf-8\|gb18030\|big5` | `auto` | 关掉自动嗅探、指定编码 |
| `--dry-run` | 关 | 只打印索引，不写盘 |

输出与退出：

- 摘要行打印：`书名 / 章数 / 总字数 / 编码 / 拆分级别（heading·sep·single·even）`——
  **拆分级别必须明示**，降级到符号分节或等分时让用户知道不是常规识别。
- `--format txt`：每章 `0001_<安全标题>.txt`；标题做非法文件名字符替换。
- 退出码：0 成功；2 文件不存在/不可读；3 编码无法识别；4 无内容可拆。
- 覆盖已有输出时**先提示再写**（默认不加 `--force`），不静默覆盖。

### 3.4 依赖边界（零 AI 的硬保证）

- 只 import：`naiba.core.novel_split`（纯算法，不吃 IO）、`naiba.tools.providers.novel.read_text_auto`（编码嗅探）。
- `naiba/tools/providers/__init__.py` 只有文档串、无副作用导入，可安全引入。
- **禁止** import：`naiba.app`、`naiba.llm.*`、`naiba.run.*`、`naiba.jobs`、任何会话/Run/模型模块。
- 守门测试（新增）：AST 扫 `scripts/split_novel.py` 的 import 列表，出现上述模块即判红；
  并断言脚本可在**不启动服务**的前提下子进程实跑完成一次拆分。

## 五、设计（工作台侧）

### 5.1 落盘

位置：`data_dir/studio/novel/<book-id>/`（与 studio 现有数据同根，便于缓存清理与引用保护统一处理）。

```
data_dir/studio/novel/
└── book-20261025-<hex>/
    ├── book.json      # {id, title, source:{name, encoding, bytes, split_level, max_len}, created_at, updated_at}
    └── chapters/
        ├── 0001.json  # {i, title, len, content}
        └── ...
```

- 单章一个文件：避免改一章重写整本；坏文件不拖累其它章。
- 写路径一律 `_safe_path` 式校验（id 白名单正则 + `is_relative_to`）与 tmp + `os.replace` 原子写，**照 `custom.py:69-76,109-120`**。
- 注意（memory 已记录）：`tests/test_sqlite_write_retry.py` 的 AST 守门只扫 `naiba/storage/store.py` 的 `ChatStorage`，**studio 下新写路径不在守门内**，需自觉沿用原子写范式。

### 5.2 接口契约（新增 `/api/novel/*`，不碰既有 `/api/studio/*`）

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/novel/import` | multipart `file` 或 `{path}` | `{book_id, name, encoding, total, split_level, chapters:[{i,title,len}]}`（**不含正文**，不落库） |
| POST | `/api/novel/books` | `{title, book_id?, picked:[i...]}` | `{book}`，201 |
| GET | `/api/novel/books` | — | `{books:[{id,title,chapter_count,total_len,updated_at}]}` |
| GET | `/api/novel/books/<id>` | — | `{book, chapters:[{i,title,len}]}`（**仍不含正文**） |
| GET | `/api/novel/books/<id>/chapters/<i>` | — | `{i,title,len,content}`（单章按需取） |
| PATCH | `/api/novel/books/<id>/chapters/<i>` | `{title?, content?}` | `{chapter}` |
| DELETE | `/api/novel/books/<id>/chapters/<i>` | — | `{ok:true}` |
| DELETE | `/api/novel/books/<id>` | — | `{ok:true}` |

**两段式是硬契约**：`import` 与 `books/<id>` 都只回索引，正文只有 `chapters/<i>` 给（沿用 `test_outline_has_no_body` 传统）。

### 5.3 算法与读盘如何复用

- 上传的文件落到临时位置 → 调 `load_book(path, max_len)`（`providers/novel.py:90`）→ 只回索引。
- 缓存与工具层共用同一份（LRU 4 槽、签名含 max_len），**不另起**。
- 若后端希望脱离 providers 包读盘，则把 `read_text_auto` / `load_book` **上提**到 `naiba/core/novel_io.py` 供脚本与后端共用——**二选一的实施细节**，开工时按依赖干净度定；算法本体不动。
- 脚本侧（§三）与后端侧共用同一批函数，保证「脚本拆的结果 = 工作台拆的结果」。
