## 一、结论

“添加当前步骤”不是点击事件失效，而是写作任务默认选择“从设定到成稿”，添加按钮却只接受单阶段，点击后被前端主动拒绝。现有提示没有说清楚当前选择、拒绝原因及控件位置，造成按钮不能用的体验。

整条链路并非完全失效：选择有效单步骤、聊天使用“单次执行”时，添加、移除、五类步骤混排、提交创建、节点依赖和重复提交去重均通过定向双视口检查。但发现五项需要整改的问题，不能仅改一句提示后宣布整个链路正常。补充检查确认：聊天使用“自动检查并继续”会把已添加清单和按钮一起隐藏，形成步骤丢失的外观；数据仍在，切回“单次执行”可以恢复显示。

| 编号 | 问题 | 影响 | 当前证据 |
|---|---|---|---|
| A | 默认整链模式与添加入口冲突，提示含糊 | 用户点击后无法加入清单，不知道应去哪里调整 | 源码与桌面、375px 手机浏览器复现 |
| B | 正文步骤只认可当前已存在章节，不识别前序拆章 | 无法编排“先拆出新章节，再写该章正文” | 当前 JS 函数执行与双视口复现 |
| C | 切换后台任务清除共享立即开始勾选 | 整套任务的启动选择被某个步骤类型覆盖 | 当前 JS 函数执行与双视口复现 |
| D | 步骤清单不展示阶段与范围 | 同作品不同阶段显示相同文字，难以确认是否加对 | 双视口复现 |

## 二、问题详情与代码依据

### A 添加被模式限制拦截，提示缺少上下文

入口默认值位于 `public/index.html:1741`：“做到哪一步”默认选项为“从设定到成稿”。串联面板及按钮位于 `public/index.html:1773`。

`public/js/28-super-agent.js:769` 已绑定点击事件。`createDomainThread` 在 `:674` 检查到整链模式后直接返回：

> 添加到步骤清单前，请先选择“只做一个步骤”。

问题不在于这句话完全错误，而是它没有说明：

- 当前选择的是整套流程，而按钮要添加的是一个阶段。
- “只做一个步骤”位于上方“做到哪一步”下拉框，不是当前串联面板里的按钮。
- 改为单步骤后还需要选择具体阶段。
- 本次没有添加任何步骤，也没有创建或启动任务。

此外，模式判断晚于作品、模型及章范围校验；表单同时存在多个问题时，用户可能先被无关字段提醒挡住。`verify/super_agent_v1_ui_smoke.cjs:438` 原有测试还将“整链点击后被拒绝”当作预期成功条件，因此测试通过不代表交互合理。

### B 前序拆章不能为后续正文提供计划章节

位置：`public/js/28-super-agent.js:640`。

复现：作品尚无第 2 章，先添加“拆章：第 2–3 章”，再添加“单章正文：第 2 章”。结果第二步被拒绝：

> 正文目标章不在作品中，请先到工作台拆章。

前端只查询 `createState.chapters`，没有检查清单里同作品的前序拆章范围。子代理另以空章节作品复现了“拆章 1–20 章 → 第 1 章正文”同样被拒绝。

这不意味着应该无条件允许不存在的章节。实际运行时，`naiba/writer/pipeline.py:197` 起仍会校验大纲与真实章节是否存在；创建计划时可认可明确的前序生产步骤，运行时必须继续核验其真实结果。

### C 单步骤类型覆盖整套任务的立即开始选择

位置：`public/js/28-super-agent.js:427`、`:579`。

切到“关联已有后台任务”时，`renderCreateMode` 禁用并清空 `superAgentCreateAutostart`。但 `submitMixedDraft` 创建整套任务也读取同一控件。

复现：原先勾选“创建后立即开始”，切换到后台任务后，勾选变为否且无法操作。JS 执行捕获的整套提交载荷为 `autostart: false`。此问题是用户选择丢失，不是后台任务被重复执行。

### D 清单缺少阶段与参数摘要

位置：`public/js/28-super-agent.js:549`、`:615`。

清单只显示领域与任务标题；默认标题不含阶段。对同一作品分别添加“全部设定”和“全部大纲”，浏览器读到的两行文本完全相同。代码还重复拼接领域名称，进一步降低辨识度。

应让用户直接核对作品、阶段、范围和模型，而不是依赖添加时的短期记忆。

### E 自动检查聊天隐藏已有清单并造成操作死角

用户补充：从织书台切换到对话后，原步骤消失，而且对话不能添加步骤；随后确认对话执行方式为“自动检查并继续”。首轮检查覆盖了单次聊天混排，未覆盖这个模式组合。

直接原因在 `public/js/28-super-agent.js::renderCreateMode`：当领域为 chat 且 `superAgentCreateExecutionMode` 为 supervised 时，将 `superAgentCreateMixedOptions.hidden` 设为 true。这个容器同时包含已有清单、添加按钮、移除按钮和整套提交按钮，因而它们一并消失。`loadCreateResources` 切换任务类型时不重置聊天执行方式；此前选过自动检查，再切回聊天会沿用该选择。

桌面和手机实际复现过程相同：

1. 聊天选“自动检查并继续”，切到织书台，以单阶段方式真正添加一个步骤，清单显示 1 行。
2. 切回聊天：清单 DOM 仍为 1 行，但可见行数为 0；添加按钮不可见。
3. 填写有效完成标准并点“创建任务”，出现“自动检查任务须独立创建，请先移除已添加的步骤。”，但移除按钮也不可见。
4. 改回“单次执行”：原织书台步骤原样出现；再添加聊天步骤后清单有 2 行。
5. 创建整套任务，真实 HTTP 返回 201，载荷和节点依赖均保留“织书台 → 聊天”，没有丢掉第一步。

因此，本次确认的是“隐藏而非删除”，不是声称用户没有遇到问题。真正清空清单只发生在成功创建整套任务后；逐条删除由移除按钮触发。步骤仍只是当前页面内存草稿，不能据此承诺刷新页面或重启后还可恢复。

“自动检查并继续”不能添加到混合清单也并非只有显示问题：`createDomainThread` 明确拒绝，后端 `naiba/super_agent/runtime.py::create_mixed` 同样拒绝 supervised 节点。仅取消隐藏或放开按钮不能实现这个功能。

另外，“从设定到成稿”的四阶段计划预览与真正“已添加步骤”是两个控件；切换到聊天会清空该预览。这是另一个容易产生丢失印象的入口，但不代替上述已确认的自动检查模式问题。

## 三、添加到执行的链路核对

| 环节 | 入口 | 本次结论 |
|---|---|---|
| 点击、构造步骤 | `28-super-agent.js::createDomainThread` | 事件正常；模式与计划章节校验存在 A、B 问题 |
| 暂存、移除 | `mixedDraft`、`renderMixedDraft` | 单次模式下可加入和移除；D 导致摘要不清，E 将已有清单及移除按钮隐藏 |
| 提交整套任务 | `submitMixedDraft`、`submitCreateBody` | 发送 `domain: mixed`、`nodes` 与稳定请求标识；启动策略存在 C 问题 |
| HTTP 创建 | `naiba/app.py::api_super_agent_create_thread` | 真实接口返回 201，重复载荷返回同一任务和节点 |
| 后端线性编排 | `naiba/super_agent/runtime.py::create_mixed` | 先准备节点，再创建线性依赖；首节点 ready，后续 blocked |
| 字段传递 | `runtime.py:417`、`:438` | 检查到模型选择、领域引用与 start_request 保留；未发现这些字段静默丢失 |
| 派发及接力 | `runtime.py::_tick_thread`、`domain_adapters.py` | 源码区分首步 autostart 与后续 auto_advance；Writer 使用原流水线入口 |

浏览器实际创建了“聊天 → 子助手 → 织书台 → 拆书匠 → 已有后台任务”的五步链，验证顺序、节点类型、依赖和去重；补充检查创建了从隐藏状态恢复的“织书台 → 单次聊天”两步链。这些用例为只创建，不启动模型执行，且不支持自动检查聊天混排，不能据此声称五种执行器从头到尾已全部实跑。

## 四、修复计划

### 第一阶段 修顺模式选择与提示

建议保留“单阶段加入混合清单”的现有语义，不在本轮自动把整套流程展开，也不静默改成第一个阶段。

优先修复 E 的操作死角：已有步骤清单与当前步骤表单分开显示，切换到不支持混排的模式时也保留清单、数量和移除入口，不能通过隐藏已有草稿来表达模式冲突。提示明确说明原步骤仍保留，提供由用户点击的“切换为单次执行并继续添加”入口；不默默删除草稿，不静默改变聊天执行方式，也不在修复显示问题时放开后端执行限制。

自动检查模式建议提示：

> 已保留 N 个步骤。“自动检查并继续”目前只能独立创建，不能加入这套步骤。若要继续串联，请将“如何处理这项任务”改为“单次执行”；原有步骤不会删除。

若产品要求“织书台 → 自动检查并继续的聊天”也可串联，应另行设计混合链内自动检查节点的执行、审批、失败和恢复语义，并配套后端测试；不能当作解除前端隐藏即可完成的小修。

1. 将整链模式检查放到添加操作的早期，避免先出现模型或范围的无关报错。
2. 在添加按钮附近显示当前状态与明确提示，提供“去选择单个步骤”的引导按钮。
3. 用户点击引导后切换为单步骤，展开并定位“阶段”选择；不自动添加、不自动启动。
4. 模式或阶段修正后清除过期提醒；添加成功后显示“已添加第 N 步：阶段和范围”。
5. 将“整套流程预览”和“已添加 N 个步骤”明确区分，后者属于整套任务，不应随当前编辑类型变化而消失。

建议提醒全文：

> 当前“做到哪一步”选的是“从设定到成稿”，包含多个阶段，不能作为一个步骤加入清单。请将上方“做到哪一步”改为“只做一个步骤”，再选择具体“阶段”，然后点击“添加当前步骤”。本次尚未添加步骤。

串联面板常驻说明可改为：

> 每次加入一个步骤，按清单顺序执行。写作任务需先选择“只做一个步骤”和具体阶段；添加后可切换任务类型继续添加。

### 第二阶段 修复计划章节依赖

1. 添加正文时，允许“真实已有章节”或“被同作品前序拆章范围覆盖”的目标章。
2. 不允许跨作品、后置拆章、范围外章节绕过校验。
3. 给依赖未来拆章的正文步骤标明“等待前序拆章生成”，不要展示成已存在章节。
4. 提交整套任务前再次检查最终清单；移除前置拆章后，原来依赖它的正文必须重新报错并定位该步骤。
5. 执行时仍使用流水线的真实章节、大纲和结果校验。前序失败或未生成目标章不得继续正文。

### 第三阶段 分离整套策略并完善步骤摘要

1. 将整套任务的“立即开始”和“自动继续”与当前编辑步骤的类型状态分离；默认仍关闭，不能因为修复而自动勾选。
2. 关联已有后台任务只影响该步骤的动作说明，不清除整套策略；仍不得重新运行既有后台任务。
3. 摘要示例：“织书台｜作品名｜拆章：第 1 部，第 1–20 章｜模型名”。正文显示目标章；拆书匠显示原文章范围；聊天和子助手显示关联会话及简短目标。
4. 摘要从已加入清单的请求快照读取，切换当前表单不得改写旧步骤；用户文本必须继续转义。

### 第四阶段 补回归并验收

重点修改范围为 `public/js/28-super-agent.js`、`public/index.html` 以及对应测试；样式仅在就近提示与移动端定位确有需要时调整。优先不改后端持久化结构或公共接口；如确需新增跨模块字段，先登记契约。

| 场景 | 验收标准 |
|---|---|
| 默认整链点击添加 | 准确说明原因、控件位置和未添加结果；可引导选择阶段 |
| 有效单步骤 | 一次点击新增一行，显示阶段和范围，不隐式运行 |
| 织书台切单次聊天 | 原步骤数量、顺序、参数不变；聊天可追加；真实提交保留两类节点 |
| 织书台切自动检查聊天 | 已有清单保持可见；明确说明模式不兼容，不能隐藏后再要求移除 |
| 自动检查切回单次 | 原清单可继续编辑和提交，不清空、不重复加入、不自动启动 |
| 预览与清单区分 | 预览切换不被误认为删除；成功添加有数量和阶段反馈 |
| 拆章后正文 | 同作品前序范围内可规划；跨作品、范围外、移除前置时拒绝 |
| 后台任务切换 | 保留整套立即开始选择，不重复执行已有任务 |
| 修改当前表单 | 已加入的步骤参数和摘要保持原快照 |
| 混合创建与重试 | 顺序正确、首步就绪、后续阻塞；重复提交不产生新链 |
| 运行与审批 | 前序成功才接力；失败、取消、等待确认均阻止越级执行 |
| 桌面和手机 | 1280px 与 375px 可见、可点、可定位，无横向溢出和脚本错误 |
