# 桌面顶栏补齐「轮次跳转」下拉 + 顶栏窄宽溢出修复 —— 计划

> 状态：**已实施完毕**，随 Cat Chat 3.1.3 Beta 发布。
> 诊断日期：2026-10-06。
> 改动面：`public/index.html`、`public/styles.css`、`tests/test_turn_jump.py`、`tests/test_topbar.py`、
> `tests/test_mobile_topbar.py`、`verify/mobile_shell_smoke.cjs`。后端零改动、无数据库迁移。

---

## 1. 需求与结论

手机端早有一个「第 N 轮 · 摘要」的轮次跳转下拉（顶栏操作区行首），桌面端只有消息区右缘那道
26px 刻度轨（`.turn-rail`）。本次要让**桌面端也拿到同一个下拉**。

选型对比后取**方案 A**：不新开模块、不搬动 DOM，直接复用既有的 `#turnJumpSelect` 元素与
`renderTurnJump` / `scrollToTurn` 逻辑，把它从「仅手机」改成「手机 / 桌面共用」，桌面落点选在
**顶栏左段中段——Agent 之后、[文件] 之前**。代价是必须给顶栏腾地方：API 选择器此前过宽
（`max-width: min(480px, 45vw)`），收窄到 `min(240px, 24vw)` 后左段余量交给操作区，中段才有位置。

## 2. 落点为什么是「左段中段」

- 顶栏是 `justify-content: space-between` 的两段布局：左段 = 工作区 + 模型 + Agent，右段 = `.topbar-actions`（文件 / 任务 / 卸载 / 刷新）。
- 下拉放进 `.topbar-actions` 内、作第一个子元素，靠 `margin-right: auto` 把它钉在操作区行首。
  `auto` 余量先于 `justify-content` 分配，所以它稳定落在「Agent 之后、[文件] 之前」，不受右段 justify 影响。
- 不额外占宽：它吃的是 API 选择器让出来的那部分余量。

## 3. 具体改动

### 3.1 `public/index.html`

`#turnJumpSelect` 去掉 `.mobile-only` 类（否则桌面端也会被隐藏），保留 `hidden` 初值。

### 3.2 `public/styles.css`

- `.topbar { min-width: 0 }`：顶栏是 `.chat-main` 网格里的单项，默认 `min-width:auto` 取 min-content——
  下拉一显示（min-content 含它 266px 的 max-width），顶栏就被撑到比单元格更宽、越过窗口右缘，
  把刷新键顶出可视区（1024 / 900 实测）。置 0 后顶栏回到单元格宽度。
- `.model-control { flex: 0 1 auto }` + `.model-control select { max-width: min(240px, 24vw) }`：
  API 控件此前 `flex: 1 1 180px` 独吞左段余量、把 select 撑到 480px；改为不 grow + 收窄上限。
- `.agent-control { min-width: 0; flex: 0 1 170px }`。
- `.topbar-actions { flex: 1 1 auto; min-width: 0; justify-content: flex-end }`：操作区接管左段余量、
  可被压缩；右侧按钮 `flex: none` 保形、贴右缘。
- 桌面端下拉基态规则（`.turn-jump-select`）：`display: inline-block; flex: 0 1 auto; min-width: 0; margin-right: auto;`
  + `[hidden] { display: none }` 成对规则。
- `@media (min-width: 761px) { .topbar-actions > .turn-jump-select { flex: 0 100 260px } }`：
  **flex-basis 必须写死**——`<select>` 在 Chromium 下 `auto` 基准取「上次渲染宽度」，窗口一缩被压到 0
  后即使再放大也回不来（实测 1440→1100→1440 恒为 0）。
- `@media (min-width: 761px) and (max-width: 999px) { .topbar-actions > .turn-jump-select { display: none } }`：
  窄桌面顶栏被 API + Agent + 4 个按钮占满，下拉会被压成「第 1 …」甚至一根箭头（900px 实测 75px、800px 仅 27px）——
  与其留一根看不懂的废桩，不如收掉；桌面端刻度轨恒在，跳轮功能不丢。
- 顺带修一个既有 bug：`.file-reopen-button:not([hidden])` 的作者样式 `display: inline-flex` 会压过
  UA 的 `[hidden] { display: none }`，导致 `updateFileTabsButton()` 里 `button.hidden = true` 不生效——
  **没开过文件的空会话也常驻一个 78px 的「文件」按钮**。补一条同特异度成对规则 `.file-reopen-button[hidden] { display: none }`。
- 手机端形态完全不动：显示规则仍写在既有 `@media (max-width: 760px)` 块内。

### 3.3 守门测试

- `tests/test_turn_jump.py`：改判据——`#turnJumpSelect` 不得再挂 `.mobile-only`；桌面端（第一个手机块之外）
  必须有基态显示规则且带 `margin-right: auto`；断言 `flex: 0 100 260px` 与窄桌面 `display: none` 块；
  手机端显示规则仍在 760 块内。
- `tests/test_topbar.py`：操作区由 `flex: none` 改判 `flex: 1 1 auto` + `min-width: 0`；新增
  `test_file_button_hidden_really_hides`（钉住 `.file-reopen-button[hidden]` 那条，并反例护栏要求
  `:not([hidden])` 那条也在）。
- `tests/test_mobile_topbar.py`：同步操作区 `flex: 1 1 auto` + `min-width: 0`。

### 3.4 冒烟 `verify/mobile_shell_smoke.cjs`

- A 段桌面分支改判：`≥1000px` 下拉可见（落在左段中段）、`761–999px` 下拉收起；刻度轨桌面恒可见。
- 三处鲁棒性修补（都是冒烟自身的环境问题，非产品回归）：
  1. 首启引导弹窗 `<dialog open>` 会拦截 pointer 事件（冒烟常跑在全新隔离数据根上），先关掉再进点击类断言。
  2. `console.error` 过滤 `Failed to load resource`——未配置供应商时 `POST /api/providers/models` 返回 400
     的浏览器噪音，不是 JS 异常。
  3. 新增 `waitForScrollSettle()`：轮次跳转用 `behavior:'smooth'`，几十轮跨距要 ~1.5s 落点，
     固定 `waitForTimeout(1200)` 会读到中途位置（选中项还挂在半路的轮次上）——改为等 `scrollTop` 稳定。

## 4. 边界与安全

- 纯前端 + 测试/冒烟改动；后端、协议、数据格式一处未动，无数据库迁移。
- 桌面端下拉与刻度轨共用同一套 `collectTurns()` / `scrollToTurn()`，不复制算法、不新开模块。
- 窄桌面（<1000px）收起下拉是**有意的功能取舍**，刻度轨补位，跳轮能力不丢。

## 5. 验证

- 全量单测（含 `test_turn_jump` / `test_topbar` / `test_mobile_topbar`）通过，数字见更新说明。
- `verify/mobile_shell_smoke.cjs` 五档视口（375 / 640 / 760 / 900 / 1440）A/B/C/D 四段全绿且确定性通过。
- 桌面真机读数（播种 40 轮会话）：1440 → 下拉 260px 可见；1024 → 147px 可见；900 → 收起（display none）。
  全程无横向滚动、≥761px 无重叠。
