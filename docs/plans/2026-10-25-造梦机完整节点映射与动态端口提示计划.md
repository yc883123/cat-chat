# 造梦机完整节点映射与动态端口提示计划

日期：2026-10-25  
基线：`9004486`（3.7.4-beta）  
状态：已实施（2026-10-25）。`PARAMS_SCHEMA_VERSION=6`；代码、自动化测试与隔离实例页面验证已完成，随 3.7.5-beta 发布。

## 1. 目标与边界

用户最终要求：

- 恢复「节点号 · 节点名 · 字段 → 输入端口」的标签，不使用“参考图 1”“图片输入”等短名称替代映射；箭头后只写目标输入端口，不重复目标节点号与目标节点名（2026-10-25 图例确认）。
- 所有参数对应的节点，都应可靠展示其输出连接到哪些输入端口；同一来源的多条连接逐一列出，不能只报第一个端口或“等 N 处”。目标节点信息内部保留，只在端口重名需要消歧时补显示。
- 对动态可选参考输入，明确告诉用户不选择不会阻塞生成，但提示必须简短。
- 保留已实现的“按本次选择处理可选媒体”行为，不要求占位素材、不要求每次手动修改工作流。

这次只处理映射呈现、媒体提示与旧参数缓存更新。不顺带修改下拉框、预览、批量任务、上传去重或版本号。

## 2. 当前问题

1. `naiba/comfyui/params.py` 的 `_short_media_label()` 把媒体槽完整标签替换成短名称，来源节点号、节点名、原字段和目标端口都因此不可见。
2. `_media_port_label()` 只保留第一个下游字段，多连接时只显示数量，其余目标端口看不到。
3. 前端媒体提示仍可能写“未选则沿用工作流素材”，但可选消费者连接实际会在本次未选时被移除，文字与执行行为不一致。
4. 当前 `PARAMS_SCHEMA_VERSION = 5`。仅改扫描代码不会更新已导入工作流的缓存标签，需要推进版本并走已有懒升级。
5. 参数存在用途角色时，前端会使用“LoRA 模型”等用途文字替换可见标签。补映射时必须检查这条渲染分支，不能让完整节点信息只存在于悬浮提示里。

## 3. 展示方式

### 单目标媒体输入

来源保持工作流里的「节点号 · 节点名 · 字段」，目标只显示输入端口；箭头后不重复目标节点号与目标节点名。例如：

```text
43 · 載入圖片 · image → ref_images.ref_image_3
未选即跳过
[选择图片]
```

- 节点名优先使用工作流里的 `_meta.title`，没有标题则使用 `class_type`。
- 目标端口使用 API 工作流里的原始字段名（如 `ref_images.ref_image_3`），不改写成“参考图 4”这类序号名称。
- 窄屏允许换行，不把端口名截掉。

### 多目标或多输出

- 同一来源的每一条下游连接逐一列出，不用“等 N 处”代替；每一行仍然只写目标端口。
- 一个节点有多个输出时，在来源行标明 API 输出索引，避免把图像输出与遮罩输出混成同一条映射。示例：

```text
51 · LoadImage · image
输出 0 → ref_images.ref_image_0
输出 1 → mask
```

- 如果不同目标节点恰好使用相同端口名，结构化连接数据仍保留目标节点号；仅在这类无法靠端口名区分的情况下，才在端口后补目标节点号，平时不显示。
- 这里展示的是该节点输出的直连关系，不表示 `image` 这个文件参数本身是输出端口。

### 其他参数节点

同样保留来源节点号、节点名、参数字段及全部实际下游端口；有用途名称时可以补充用途，但不得覆盖映射。没有下游连接时只保留来源信息，不编造目标。

映射依据保存的 API 工作流；不尝试从中还原原 UI 图已经折叠掉的 Set/Get、分组状态或隐藏连线，也不把图上的后续间接依赖说成直连端口。

## 4. 实现步骤

### 4.1 扫描完整连接

涉及：`naiba/comfyui/params.py`。

- 删除 `_short_media_label()` 及其专用正则导入，恢复 `_slot_label()` 产生的完整来源标签；媒体槽标签再拼 `→ 下游端口字段`（如 `43 · 載入圖片 · image → ref_images.ref_image_3`）。
- 从 API prompt 各节点的 `inputs` 建立反向连接索引。每条记录保留来源节点号、输出索引、目标节点号、目标类名/标题和目标字段；目标节点信息只用于内部区分与重名消歧，不进入常规显示标签。
- 连接必须符合 API 节点引用的结构，不把任意数组误认为连线。
- 将结构化连接信息用于所有参数槽；显示的来源与目标都从连接数据生成，不能从已经缩短的中文标签反向推断。常规标签只显示来源节点号/节点名/字段与目标端口；不显示目标节点号/节点名，端口重名时按需补节点号。
- 保留工作流原顺序，不重编号、不修改 prompt；同一目标节点不同字段的连接分别保留。

### 4.2 确认未选时能否跳过

涉及：`naiba/comfyui/schema.py`、`params.py`；必要时让 `runner.py` 共用输入声明解析，避免提示与执行判断分叉。

- 用目标节点 `/object_info` 的 required/optional 声明判断，不通过 H3 名称或 `ref_*` 字段名猜测。
- 对 Autogrow 动态输入核对组声明、模板字段/前缀、编号范围和最小数量。必须确认当前字段允许省略，才给予跳过提示；仅字符串前缀相似不算证据。
- 若媒体加载器有多个消费者，只有全部相关连接都确认可省略，才允许对整个素材槽提示“未选即跳过”。混有必需或未知消费者时，不能承诺整份素材会跳过。
- 可选性查询只补充显示元数据，不修改保存的工作流或已创建任务。
- schema 获取失败、节点缺失或字段无法匹配时保守处理，不显示确定性的跳过承诺。

### 4.3 简短提示与映射渲染

涉及：`public/js/24-comfyui.js`、`public/styles.css`。

- 主表单与“编辑参数”列表都保留完整来源标签和全部目标端口映射。
- 使用独立连接数据生成文本，不依赖短名称，也不只放在鼠标悬停的 `title` 中；标签形如 `43 · 載入圖片 · image → ref_images.ref_image_3`。
- 长映射允许换行；多个目标逐项展示，手机也能看全。
- 媒体状态文案保持简短：

| 情况 | 提示 |
| --- | --- |
| 本次未选，且全部相关输入明确可省略 | 未选即跳过 |
| 本次已选 | 已选：文件名 |
| 无法确认可跳过，工作流原值为空/None | 请选择文件 |
| 无法确认可跳过，工作流保留原文件名 | 未选沿用原文件 |

- “清除”按钮的说明与相同判断一致：确认可跳过时提示“清除后跳过”，其余情况说明回到原文件状态；不再一律宣称会沿用旧文件。
- 只调整显示，不更换媒体槽身份键 `node_id + field_name`，不丢失当前上传选择或可见参数勾选。

### 4.4 更新已有工作流

涉及：`naiba/comfyui/__init__.py`、`service.py`。

- 将 `PARAMS_SCHEMA_VERSION` 从 5 升至 6，使用现有详情读取时重扫机制。
- v5 条目第一次打开时重新生成完整标签、连接信息及可选性元数据；保留原工作流、名称、可见参数配置和任务快照。
- 重复打开不重复迁移，也不要求重新导入 JSON。
- 若升级时 ComfyUI 离线，先恢复完整映射；可选性未查到不能永久假装已确认。验证连接恢复后的现有刷新机制能否补齐；若不能，补一个仅针对未确认媒体元数据的重试，不重置用户参数设置、不在每次任务轮询里查 schema。

## 5. 验收与测试

### 自动化

- 图片、音频、视频、配套音频均恢复「节点号 · 节点名 · 字段 → 输入端口」的来源与端口标签，不再输出“参考图 N”替代标签，标签里不出现目标节点名。
- 通用非 H3 节点也能返回连接映射；单目标、多目标、同一节点多个输入、多个输出索引、无连接均正确。
- 同一来源的全部下游端口逐一保留；端口名相同的多个连接不合并、不丢失，需要区分时补目标节点号。
- 测试普通 optional、Autogrow 可省略输入，以及必需输入、最小数量约束、未知 schema 和相似但不匹配字段。
- 一个媒体加载器同时连接可选与必需输入时，不显示“未选即跳过”的错误承诺。
- v5 短标签条目升级后恢复映射；再次读取保持幂等，可见参数配置和 prompt 不变；离线升级后允许补齐元数据。
- 前端用代表性槽位实际渲染，断言来源节点号/节点名/字段、目标端口与相应短提示均可见；不以“源码里包含某字符串”代替界面行为验证。
- 运行造梦机相关 unittest、导航回归、JS 语法检查与 `git diff --check`。

### 页面检查

源码服务可用时，用已有工作流做桌面和手机窄屏检查，不提交新生成任务：

1. 对照图中的节点号和连接，确认图片、音频、视频标签显示为「节点号 · 节点名 · 字段 → 输入端口」，标签里没有目标节点名。
2. 检查多目标映射与长端口名换行，没有被省略号隐藏。
3. 选文件、替换、清除时映射保持不变，状态提示简短且与可选性一致。
4. 切换工作流或重新打开详情后，旧短标签已更新，用户勾选仍保留。

## 7. 实施结果（2026-10-25）

- `naiba/comfyui/params.py`：删除短标签与“等 N 处”，按来源节点建立完整反向连接索引；所有参数槽标签恢复「节点号 · 节点名 · 字段 → 全部目标端口」，多输出标出输出索引，端口重名时补目标节点号消歧；媒体槽输出 `media_optional`。
- `naiba/comfyui/schema.py`：解析 `COMFY_AUTOGROW_V3` 的 `prefix`/`names`/`min`/`max`/模板 required 归属，新增 `input_is_optional()`；精确字段、Autogrow 范围与最小数量都核对，模糊情况返回未知。
- `naiba/comfyui/runner.py`：未选媒体连接移除改用同一套 `input_is_optional()`，提示与执行判断不再分叉。
- `naiba/comfyui/service.py`：v5→v6 懒升级恢复完整映射；ComfyUI 离线升级后，下次打开详情只补未确认的媒体可选性并落盘，不重扫、不动用户参数配置。

- 自动化：造梦机模块 92 项、全量 **3020** 项通过；`node --check public/js/24-comfyui.js` 通过。
- 页面验证：隔离实例（宽屏 + 375px）实测 H3 工作流，出现 `43 · 載入圖片 · image → ref_images.ref_image_3` 等完整映射；四种未选状态、编辑参数清单、选择与清除均符合预期；未提交真实 ComfyUI 生成任务。
